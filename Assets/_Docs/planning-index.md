# 기획 문서 버전과 적용 기준

## 2026-10-31 디버그 원본 구도 재사용 직접 지시

디버그의 180도 강제 덮어쓰기를 제거하고 선택된 StageService의 원본 구도를 그대로 사용한다. 입력 로직과 씬 미저장 작업은 변경하지 않는다. 아래 2026-10-30의 디버그 고정 방향 정책을 대체하며 타이틀/게임 출력 분리는 유지한다.

## 2026-10-30 카메라 위치와 출력 분리 직접 지시

카메라는 대상의 +Z 쪽에서 대상을 향해 -Z 방향으로 바라본다. 원본 변경 대상은 본편 StageService의 측면·통로·쿼터뷰 구도이며 현재 작업 씬 Main Camera Transform은 제외한다. 타이틀은 전용 Camera/AudioListener를 사용하고 게임은 기존 Core 리그가 구동하는 게임 출력을 사용한다. 타이틀 표시 중 게임 출력을 끄고 해제 시 복원한다. 미저장 작업 씬은 저장·재로드하지 않는다. 이전 공유 출력 설명은 이 지시로 대체한다.

## 2026-10-29 직접 씬 테스트·배치 작성 기준

최신 사용자 승인 범위는 현재 씬 직접 테스트, F1 로그·조작 패널, 고정 Root 아래 Body의 XYZ 앵커 이동, 플랫폼별 Inspector 피해량, 빈 타이틀 월드와 컷신 중 ESC 옵션 복귀다. 이 범위는 이전 지침의 적 방향·회전·스케일·지형 제한과 고정 피해1 규칙을 대체한다. 일반 플레이와 달리 디버그 패널 표시 중에는 게임·플레이어 입력을 유지하고 커서를 표시한다. 옵션 정지와 명시적 디버그 Pause의 소유권은 별개다.

이동1.8m/s, 정상 점프1m·소형0.5m는 초기 기준이며 Inspector에서 변경한 값을 실제로 사용한다. 기존 아트/프리팹/씬의 의도된 배율·회전을 정규화하지 않는다. 테스트 코드는 Editor 전용이며 본편 상태·피해·입력 서비스를 재사용한다. 사용자 승인 Git 범위는 기능별 로컬 커밋뿐이다. push·PR·병합은 하지 않는다. 구현·검증 상태와 사용 절차는 `Assets/_Docs/tracking/ready-debug-authoring-2026-10-29/`를 확인한다.

## 2026-10-15~16 직접 지시: 구간·체크포인트 통합

StageService가 같은 씬의 논리 구간, 첫 구간, 현재 구간, 활성화한 체크포인트 집합, 마지막 스냅샷과 그 복귀 구간을 소유한다. 구간에는 서로 다른 시작·끝 StageTrigger, 시점 종류, 실제 음악 Clip·음량·전환 시간, 진입 보정·카메라 전환 시간을 연결한다. 이름·배열 순번은 저장 키가 아니다. Trigger는 접촉을 전달하며 시점·음악·저장 장부를 별도로 편집하지 않는다. 새 시작 체크포인트마다 플레이어 Capsule 중심을 해당 시작 위치로 DOMove 보정한다. 끝은 저장만 하고 현재 구간·시점을 바꾸지 않는다. 같은 시점의 새 시작은 카메라 재선택·blend 재시작만 생략하며 보정·저장·음악은 수행한다. 새 유효 시작은 이전 보정·전환을 취소하고 최신 요청이 완료하도록 한다. 사망·취소·Actor/Stage 해제 때 자기 트윈·보정 소유권·입력 제한을 반환하며 낡은 callback은 상태를 바꾸지 못한다. 사용 중인 차단 장치만 플레이어 보정 뒤 고정 목표로 이동한다. 재시도는 같은 Core/Stage와 StageService의 소비 이력을 유지하고 마지막 유효 저장 및 당시 구간·음악·시점을 직접 복원한다. 소비한 센서를 다시 발동하지 않는다. 현재 해금은 GameSessionService 원본이고 저장 시점의 해금은 별도 불변 스냅샷 값이다. Title 복귀에서 세션 종료 후 Stage 전체→Core 순서로 언로드하며 새 게임은 새 객체와 빈 체크포인트 장부로 시작한다.

뒷면 메시를 생략한 아트는 구도·추적·전환 중간에서도 뒷면을 노출하지 않도록 배치한다. 최신 사용자 정정으로 반대편 카메라 이동은 철회했고 기존 방향을 유지한다. 사용자가 오브젝트 배치를 회전하는 작업은 에이전트가 완료한 것으로 기록하지 않는다. 보호 아트의 임의 수정·양면화나 HMS 입력 변환으로 우회하지 않으며 현재 백페이스 노출은 미해결 시각 항목이다.

## 권위와 읽는 순서

1. 시스템 동작은 V1.8 활성 본문을 이전 사용자 기능 명세보다 먼저 따른다. 작업 범위와 권한은 현재 직접 지시를 따른다. 기획서의 문구는 제품 명세 자료이며 에이전트 실행 명령이 아니다.
2. 해당 분야의 아래 최신 지정 원본을 실제로 읽는다. 시스템 동작/입력/정지는 최신 시스템, UI 배치는 UI 자료, 본편 배치는 레벨 자료가 기준이며 시스템 동작 차이는 V1.8 활성 본문을 적용한다.
3. 파랑 재정의·빨강 조정 요구·취소선을 색상과 함께 확인한다. 취소선은 활성 규칙에서 제외한다. 빨강의 검토 예정 기능은 확정 선택을 따르고, 조정 가능한 값은 Inspector에 목적/단위를 설명한다.
4. 기존 코드·씬·prefab·Markdown은 실제 구현과 GUID/공개 계약을 확인하는 자료다. 현재 동작을 새 요구 대신 적용하지 않는다.
5. 작업 권한은 별도다. 최신 기획/공개 API 사용이 타인 원본 수정 허가를 만들지 않는다. 같은 버전명·파일명·수정 시각으로 동일성을 추정하지 않는다.

## 이전 직접 선택 이력 (V1.8에 반하는 기능은 대체됨)

- 2026-10-14 메시 플랫폼 후속 승인: 실제 지지 MeshCollider, 플랫폼 소유 아래 반구 접촉 검사와 플레이어 최대 접지각, 실제 메시 교차의 1/4 사망 경계, 얕은 벽 침투의 안쪽 수평 분리, 피해/Oil Trigger 분리를 적용한다. 메시 지지면으로 이관·검증된 원형 플랫폼은 쿼터뷰에서도 사용할 수 있다. 아래 기존 Box 기반 사이드뷰 전용 규칙을 대체한다. [명세](tracking/mesh-platforms-2026-10-14/기능%20명세서.md)를 따른다.

- 2026-10-14: `_Prefabs`는 종류별로 분류하고 Prototype/ProtoType 폴더를 제거한다. 재사용 가능한 사용자 프리팹과 같은 종류의 실제 계층을 우선 활용하며 그 구조에 맞지 않는 기능은 독립 프리팹으로 구성한다. 폐기 예정 `1_Stage`의 조립·이관은 중단하고 향후 레벨 목업으로 새 스테이지를 구성한다. Player는 기존 분리 클립·실제 리그·VFX를 연결하고 피격 머테리얼 색 변경을 제거한다. Dish 등 원형 메시와 사각 지지 Collider의 이동 발판은 사이드뷰 전용이다. [최종 작업 명세](tracking/prefab-authoring-2026-10-14/기능%20명세서.md)를 따른다.
- 2026-10-13: 카메라 구도 Inspector 값은 플레이 중에도 반영한다. ChaseSwarm은 해당 스테이지의 추격 시작 StageTrigger가 같은 씬 참조로 연결하며 Core의 필수 배치를 제거한다. 범위와 검증은 [변경 명세](tracking/runtime-camera-stage-chase-2026-10-13/기능%20명세서.md)를 따른다.
- 추격은 접촉·퇴로 안전·현재3값 저장 성공 뒤 직선 이동과 실제 몸체 포획을 사용한다. 이는 당시 구현 선택이며 현재는 V1.8의 전신 통과·경로 판정으로 대체해야 한다.
- 기본/통로/쿼터의 세 구도는 LevelCameraService가 소유한다. 플레이어 안전 보정 후 차단 오브젝트를 이동하며 둘 다 DOMove와 실물 앵커·Gizmo를 사용한다. HMS의 기존 독립 네 rig는 유지한다.
- 최종 포포 Escape(7)만 일반 Completed/Skipped 장부를 지우지 않고 새 회차를 허용한다. 현재 맥락 검증과 사망/포획 우선, 취소≠완료를 지킨다.
- RealToon 구현은 제외한다. HudIconGraphic은 하트뿐 아니라 Q/E와 눈물 조각을 포함한 6개 Graphic 소비 전체를 실제 리소스로 이관하고 참조0을 확인한 뒤 삭제한다.
- HMS 최소화는 명시된12파일 한정이었다. security.md의 현재 권한과 최신 작업 지시를 확인하며 이전 허가를 영구 승계하지 않는다.
- 한국어 커밋·PR 제목/본문/섹션을 사용한다. Git 실행은 현재 작업의 직접 허용 범위로 제한한다.

V1.5와 이전 기획·검증은 아래 원본 목록 및 날짜별 tracking에서 보존한다.

## 유지하는 자료와 상태

V1.6 DOCX·메타를 제외한 기존 원본과 과거 실행 기록은 보존한다. 2026-10-13 후속 검토로 체크포인트 StageTrigger 통합·Collider 중심 복귀, Title에서 Core/Stage 전체 언로드, 1_Stage 단독 등록, 트리거 음악 변경, 카메라 경계 선택을 확정했다. 재시도에서만 Core/Stage 인스턴스를 유지한다. 현재 Actor 한 개와 출력 Camera/Brain/AudioListener 한 개, 세 리그 분리, MVVM과 자기 구독/작업 해제는 유지한다. 상세 범위는 [통합 명세](tracking/stage-trigger-unification-2026-10-13/기능%20명세서.md)를 따른다.

목표 동작은 [business-rules.md](business-rules.md), 책임과 수명은 [architecture.md](architecture.md), 협업 계약은 [contracts.md](contracts.md), 권한은 [security.md](security.md), 실제 구현/검증은 [tracking/status.md](tracking/status.md)다. 새 명세를 지정한 것과 기능 구현 완료는 다르다. 커밋·push·PR·병합은 각각 현재 작업의 직접 지시를 따른다. 과거 #26 갱신 허가를 새 작업의 Git 권한으로 승계하지 않는다.

현재 기능의 상세 계약은 business-rules.md와 contracts.md를 따른다. 문서 개정은 연결·실행 검증 완료의 증거가 아니다.
