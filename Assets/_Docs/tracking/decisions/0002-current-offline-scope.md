# 현재 구현과 오프라인 범위

## 배경

과거 설명과 현재 게임 자산의 흐름·추격 규칙이 다르다. 오래된 설명을 적용하면 명세에 따라 만든 현재 기능을 의도와 다르게 바꿀 수 있다.

## 결정

현재 프로젝트의 실제 코드·씬·프리팹·설정을 기준으로 한다. 사용자는 현재 구현이 모두 의도된 사항임을 확인했다. 구버전 README를 현재 규칙의 근거로 사용하지 않는다. 변경할 부분은 이후 사용자가 따로 지정한다.

현재 서버·네트워크는 필요하지 않다. 로컬 세션 상태와 로컬 음량 저장을 기준으로 한다.

## 비교한 방식과 결과

과거 기획과 구현을 섞어 규칙을 복원하는 방식은 현재 의도를 훼손하므로 배제한다. 미래 네트워크·영속 진행 저장을 미리 요구사항에 넣는 방식은 확인된 범위를 벗어나므로 채택하지 않는다.

현재 동작을 의도된 것으로 기록해도 모든 경로의 실행 검증이 통과했다는 뜻은 아니다. 직렬화나 실행 문제가 발견되면 증거와 영향 범위를 분리한다. 네트워크의 현재 불필요 판단은 향후 도입을 영구 금지하는 결정이 아니다.
