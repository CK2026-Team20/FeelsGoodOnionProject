# 리소스·씬 흐름 변경 검토

## 원인과 수정

1. Stage6구간의 music은 파일명 문제가 아니라 현재 존재하지 않는 GUID `47caefba599d56f8888acfa8ba7b6c1a`를 참조했다. 실제 `music.stage1.wav`의 GUID `429883c608d28ae44bb4ee821f4624e4`로 native SerializedObject를 통해 연결했다. 기존 모든 구간이 같은 음악을 사용하던 구성, 게인0.6, 전환0.3초를 유지한다. 제공 stage2/3 음악은 존재하지만 별도 구간 배분 지시가 없어 임의 적용하지 않았다.
2. CinematicCatalog의 openingCuts4/endingCuts4도 이전 GUID가 끊어져 있었다. 실제 Artwork/Opening_01~04.png, Ending_01~04.png의 Texture2D를 순서대로 연결했다. 문구·순서·4초 표시 시간은 유지했다. 보호 원화와 import는 수정하지 않았다.
3. 활성 Patrol의 끝점 y=1.655가 Dish 지형 상단 y≈2.82보다 아래였다. 몸체 반높이·center offset·기존 clearance0.15를 포함한 최소 안전높이3.156185에 여유0.02m를 두었다. 해당 Patrol 기능 루트만 위로1.5211848m 이동하여 시작4.936185/끝3.176185로 보정했다. 고정 앵커와 몸체를 함께 이동하므로 수직 순찰 길이와 방향은 유지한다. 원본 프리팹 수정/Apply 없이 Stage의 Transform override 한 개다.

## 책임과 변경 범위

이번 후속 작업의 제품 코드 변경은 없다. 기존 Flow/Options/Dialogue/Cinematic/Session 소유권과 MVVM 연결을 재사용했다. Stage 참조 검증과 컷신 누락 검증을 우회하거나 예외를 숨기지 않고 작성 데이터를 복구했다. 앞선 UI 작업의 코드·프리팹 변경은 작업 시작 baseline으로 보존했다.

실제 새 게임 실패, Title 복귀 후 재진입, Retry, Ending 자동 완료를 검사했다. Title에서 Core/Stage가 실제 파괴되고 새 게임에서 새 scene handle/새 session이 생성되며, Retry에서는 기존 Core/Stage/session과 새 Actor가 사용됨을 비교했다.

PrototypeAudioCatalog는 작업 시작 때 이미 수정되어 있던 파일이다. 현재 참조는 검증했으며 이 후속 작업이 해당 카탈로그를 편집했다고 주장하지 않는다. 기존 TMP 자동 변경, 아이콘 import 변경, ProBuilder 설정 변경도 보존했다. Git 작업은 수행하지 않았다.

## 검증 도구의 오류와 복구

합성 키보드는 GameView 비활성 시 입력이 폐기되어 별도 메모리 InputSettings 복제본에서 검증했다. 영구 ProjectSettings는 수정하지 않았다. 첫 통합 검사 종료 시 InputSystem.settings setter가 기존 HideAndDontSave 기본 설정을 파괴한다는 계약을 놓쳐 검증 스크립트 복원 예외가 발생했다. 패키지 InputManager의 setter를 확인하고 원래 설정 JSON으로 복원하도록 검증 스크립트를 수정했다. 이후 메모 검사 종료와 기본 설정 상태 재실행을 확인했다. 이 테스트 정리 오류와 제품 흐름 오류를 구별한다.

메모 첫 시도는 전환 직후 입력 억제 프레임에서 API를 호출해 거절됐다. 실제 유저 입력 가능 시점까지0.3초 기다린 최종 검사는10/10 통과했다. 의도된 입력 억제를 제거하지 않았다.

## 후속 커밋·푸시 요청의 분류

사용자가 UI 레이아웃·기능의 Ver2.1 필수 참조 지침 추가와 종류별 커밋·푸시를 요청했다. 루트 AGENTS/CLAUDE, UI 지역 지침, planning-index에 반영한다. 새 커밋은 리소스 import·TMP 자동 변화, UI 표시·입력 구현, 음악/컷신/Stage 복구, 기획 원본·지침, 검증 문서, 기존 ProBuilder 설정으로 나눈다. UI 변경과 실제65개 검사 결과는 앞선 실행 상태를 사용하며 문서·Git 작업을 위해 동작 검사를 불필요하게 반복하지 않는다.

이 후속 작업 시작 때 Ver2.1 PDF와 메타가 이미 추가되고 구 UI1.0 PDF 및 시스템2안/V1.1/V1.5/확정V1.1 DOCX와 메타가 이미 삭제되어 있었다. 직접 삭제하지 않고 현재 로컬 문서 정리를 별도 커밋에 승계한다. 삭제 전 자료는 Git 이력에 남으며 planning-index의 과거 링크를 해당 커밋으로 교정했다. 기존 미푸시8커밋은 병합·아트 이력으로 그대로 유지한다. ProBuilder 설정의 SelectMode2→4 및 편집 캐시 항목 축소도 이번 단계의 신규 편집이 아닌 작업 시작 변경이다.
