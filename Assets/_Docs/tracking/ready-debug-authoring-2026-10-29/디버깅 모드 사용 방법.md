# 디버깅 모드 사용 방법

2026-10-29 · 현재 소스의 메뉴·필드·명령에 따른 사용 안내입니다. 이 문서는 컴파일·Play·빌드 검증 완료 기록이 아닙니다. 실제 검증 결과는 같은 폴더의 `테스트 및 검증 항목.md`에서 별도로 확인합니다.

## 1. 테스트할 작업 씬과 시작점을 준비합니다

1. Unity Editor에서 테스트할 씬을 열고 활성 씬으로 선택합니다. 완성된 레벨, Title, StageService, 전체 구간·체크포인트를 먼저 구성할 필요는 없습니다.
2. 현재 씬에 빈 GameObject를 만들고 플레이어를 생성할 위치에 배치합니다. 이 Transform은 플레이어 **CapsuleCollider의 월드 중심**을 맞출 시작점입니다. 발바닥 위치 기준이 아닙니다.
3. 시험할 객체가 있으면 같은 씬에 배치합니다. 시작점만 있어도 직접 테스트 진입을 구성할 수 있지만, 바닥이 없으면 플레이어는 중력으로 떨어집니다. 이동·착지를 시험하려면 필요한 바닥 Collider를 추가합니다.
4. 활성 플레이어를 따로 미리 생성하지 않습니다. 테스트 진입이 실제 플레이어 프리팹과 테스트 전용 출력·Cinemachine 리그를 생성합니다. 같은 씬의 기존 화면 출력 Camera·연결된 Brain·활성 AudioListener는 테스트 동안만 꺼지고 종료 시 원래 활성 상태로 복원됩니다. GameObject 전체와 Transform은 변경하지 않습니다. RenderTexture 출력 Camera와 원래 꺼져 있던 컴포넌트는 그대로 둡니다.

## 2. Editor 전용 설정을 추가합니다

1. 시작점 Transform을 선택한 상태에서 **Cooked → Testing → 현재 씬 테스트 설정 추가**를 실행합니다.
2. `Direct Scene Test Settings` 루트가 생성되며 태그는 `EditorOnly`입니다. 설정이 이미 있으면 기존 설정을 선택합니다. 현재 씬에는 설정을 하나만 둡니다.
3. 선택했던 Transform이 같은 씬이면 자동으로 시작점에 연결됩니다. 선택한 Transform이 없으면 설정 루트 자체가 시작점이므로 위치를 확인하거나 별도의 시작점으로 바꿉니다.
4. Inspector의 `DirectSceneTestSettings`를 다음과 같이 설정합니다.

| Inspector 필드 | 사용 방법 |
|---|---|
| 플레이어 시작점 | 현재 씬의 시작점 Transform을 연결합니다. 필수입니다. |
| 플레이어 프리팹 | 비활성 PlayerRoot 프리팹을 연결합니다. 비우면 `Assets/_Prefabs/Characters/Players/Main/PlayerRoot.prefab`을 사용합니다. |
| 초기 조각 | 기본 0, 범위 0~5입니다. 생성·재생성 시 적용합니다. |
| 초기 능력 | 기본 `None`으로 모두 잠겨 있습니다. 필요한 경우 `FormChange`, `Tear`를 선택합니다. |
| 추가 이동 지점 | 이동 버튼으로 선택할 현재 씬의 실제 Transform들을 연결합니다. 비워도 됩니다. |
| 보관할 로그 수 | 기본 200개입니다. 최소 1개이며 오래된 메시지부터 제거합니다. |
| 초기 카메라 시점 | 측면·통로·쿼터뷰 중 시작 시점을 선택합니다. 기본은 측면입니다. |
| 구도 원본 스테이지 | 현재 씬의 StageService를 선택하면 본편 구도 값을 복사하여 사용합니다. 비우면 같은 씬에 StageService가 하나일 때 자동 선택합니다. 원본 회전·거리·시야각을 그대로 사용하며 별도 각도 보정을 하지 않습니다. 원본은 바꾸지 않습니다. |
| 측면·통로·쿼터뷰 테스트 구도 | 구도 원본이 없거나 여러 개여서 자동 선택할 수 없을 때 사용합니다. 반경·회전·화면 위치·감쇠·시야각은 본편과 같은 ViewSettings 형식입니다. |

테스트 설정 추가 메뉴는 직접 테스트 모드도 선택합니다. 메뉴가 씬을 자동 저장하지는 않습니다. 설정을 다음 편집에도 보존하려면 사용자가 씬을 저장합니다. 테스트 전용 설정 루트 아래에 본편에 필요한 바닥·게임 객체를 넣지 않습니다. `EditorOnly` 루트는 빌드에서 제외되는 대상입니다.

## 3. 현재 씬을 직접 실행합니다

1. **Cooked → Testing → 현재 씬 직접 테스트**를 선택합니다. 해당 메뉴의 체크 표시로 선택 상태를 구별합니다.
2. Editor의 Play를 누릅니다. 타이틀·오프닝·선행 구간 대신 현재 작업 씬에서 직접 테스트 세션을 시작하도록 구성되어 있습니다.
3. 초기 플레이어는 기본 폼·최대 체력이며 조각과 해금은 위 설정을 사용합니다. 배치된 적·플랫폼 등은 실제 기능 경계에 연결됩니다. 배치하지 않은 선택 기능을 위해 가짜 객체를 만들 필요는 없습니다.
4. 생성 오류가 표시되면 먼저 설정이 하나인지, 시작점이 현재 씬에 있는지, 활성 플레이어가 중복되지 않았는지, 카메라 구도 값이 유효한지 확인합니다. 잘못 작성한 선택 객체의 오류와 테스트 세션 진입 오류를 구별합니다.

### 실행 중 카메라 시점을 변경합니다

1. F1을 눌러 디버그 패널을 엽니다. 플레이어 준비가 끝나면 카메라 버튼이 활성화됩니다.
2. 조작 패널 오른쪽의 카메라 영역에서 **측면 / 통로 / 쿼터뷰** 버튼을 누릅니다. 위쪽에는 현재 시점이 표시됩니다.
3. 시점은 즉시 전환됩니다. 측면에서는 X 이동, 통로·쿼터뷰에서는 XZ 이동을 사용하며 이동 모드와 수치는 본편 PlayerMovementModeController가 적용합니다. 구간 진입 보정이나 체크포인트 저장은 발생하지 않습니다.
4. 사망하거나 플레이어를 재생성해도 선택한 시점은 유지되고 새 플레이어 CameraAnchor를 추적합니다.
5. F1로 패널을 숨겨도 선택한 시점은 유지됩니다. 테스트 종료·타이틀 복귀·초기화 실패 시 임시 출력이 정리되고 기존 카메라 상태가 복원됩니다.

2026-10-31 최신 지시: 디버그의 180도 강제 회전·롤 초기화·수직각 제한을 제거했습니다. 선택된 StageService의 원본 구도를 그대로 복사합니다. StageService가 없는 씬은 Inspector의 테스트 구도를 그대로 사용합니다. 신규 설정의 쿼터뷰 기본각은 프로토타입과 같은 (20, -30, 0)이며 기존 씬에 작성된 값을 자동으로 덮어쓰지 않습니다. HMS 입력 로직은 변경하지 않았습니다.

### 메모·오븐 트레이를 테스트합니다

1. 테스트할 기존 메모 또는 오븐 트레이 프리팹을 현재 작업 씬에 배치합니다. 각 객체의 실제 Collider, InteractionPromptAnchor의 안내·조작 지점, 트레이의 이동 참조는 해당 프리팹의 작성 설정을 사용합니다.
2. 메모에는 실제 이미지가 연결된 MemoModel을 지정합니다. 이미 연결된 메모 화면은 유지하며, 화면 담당이나 화면 부모가 비어 있으면 테스트 진입 시 기존 UI 프리팹으로 임시 연결합니다. 원본 프리팹이나 씬에는 저장하지 않습니다.
3. 현재 씬 직접 테스트를 실행하고 객체를 바라보며 2.5m 이내로 접근합니다. 본편과 같은 전방·거리·차폐 판정을 통과하면 객체 위에 F 안내가 표시됩니다.
4. F로 메모를 열고 다시 F로 닫습니다. 트레이도 F로 실제 이동 기능을 실행합니다. 별도 디버그 상호작용 버튼이나 거리 우회는 없습니다.
5. 재생성 시 새 플레이어의 기존 상호작용 서비스에 안내와 메모 닫기 경로를 다시 연결합니다. 종료 시 임시 화면을 제거하고 임시로 채운 참조만 되돌립니다. 미설정 메시·Collider·앵커·메모 이미지를 임의로 생성하거나 추정 연결하지 않습니다.

## 4. F1로 화면을 열고 로그를 읽습니다

1. Game 뷰에 입력 포커스를 둔 뒤 **F1**을 누릅니다. 처음에는 숨겨져 있던 로그와 버튼 패널이 함께 표시됩니다.
2. 패널을 열어도 게임은 계속 진행하며 플레이어의 이동·점프·능력·상호작용 입력은 잠기지 않습니다. 마우스 포인터는 표시되고 잠금이 풀립니다. 버튼은 마우스로 조작하며 키보드 탐색·Submit용으로 사용하지 않습니다.
3. 좌측 상단의 검은 로그 영역은 **Unity `Debug.Log`, Warning, Error, 예외 메시지를 구독하여 표시하는 별도 인게임 View**입니다. Unity Editor Console 창을 여는 기능이 아닙니다.
4. 로그 위에서 마우스 휠로 스크롤합니다. 하단을 보고 있을 때만 새 메시지를 따라가며, 위쪽을 읽을 때는 스크롤 위치를 유지합니다. 보관 상한을 넘은 오래된 메시지는 제거됩니다. 장문은 메시지당 최대 2,048자로 제한합니다.
5. 검색·명령 입력·콘솔 입력창·복사·필터·로그 삭제 버튼은 없습니다. F1로 숨겨도 상한 내 수집은 계속됩니다. F1은 체력·해금·무적·위치를 초기화하거나 명시적 일시정지를 해제하지 않습니다.

## 5. 상태 표시와 11개 버튼을 사용합니다

패널 상단에는 현재 HP, 기본/작은 폼, 조각 수, 해금 능력, 실제 적용 이동속도와 점프 높이가 표시됩니다. 이 영역은 읽기 전용입니다.

| 번호 | 버튼 표시 | 동작 |
|---|---|---|
| 1 | 체력 회복 | 현재 플레이어의 체력을 회복합니다. |
| 2 | 조각 채우기 | 현재 플레이어의 최대 조각 수까지 채웁니다. |
| 3 | 능력 모두 해금 | FormChange와 Tear를 현재 세션에서 해금합니다. |
| 4 | [OFF] / [ON] 디버그 무적 | 디버그 무적을 켜거나 끕니다. OFF는 별도의 피격 후 무적 타이머를 취소하지 않습니다. |
| 5 | 시작점 이동 | 플레이어 Capsule 중심을 시작점으로 이동합니다. |
| 6 | 지점 선택 ▶ 지점 이름 | 시작점과 추가 이동 지점을 차례로 선택합니다. 선택만으로 이동하지 않습니다. |
| 7 | 선택 지점 이동 | 선택한 Transform으로 플레이어를 이동합니다. |
| 8 | 플레이어 재생성 | 플레이어를 테스트 초기 위치·조각·해금·체력·폼으로 다시 생성합니다. 같은 씬의 붕괴 발판은 일반 플레이와 동일한 ResetForRetry로 복원합니다. 적·다른 장치는 일괄 초기화하지 않습니다. 사망 후 재생성에도 동일하게 적용됩니다. |
| 9 | 피해원 선택 ▶ 이름 / 피해량 | 씬에 배치된 피해 플랫폼을 차례로 선택하고 실제 피해량을 표시합니다. |
| 10 | 선택 플랫폼 피해 적용 | 선택한 실제 플랫폼을 플레이어 피해 경로에 전달합니다. |
| 11 | 일시정지 / 재개 | 디버그 패널이 소유한 월드 정지 권한을 켜거나 해제합니다. |

추가 지점이 없으면 시작점만 선택할 수 있습니다. 피해 플랫폼이 없거나 비활성 상태이면 해당 피해 적용 버튼을 사용할 수 없습니다. 사망·재생성·타이틀 전환 등 현재 플레이어가 명령을 받을 수 없는 동안에는 플레이어 명령이 비활성화되거나 거절됩니다.

일시정지 상태에서도 F1과 마우스 UI를 사용합니다. F1로 패널을 숨긴 채 정지했다면 다시 F1로 열어 **재개**를 누릅니다. 옵션이 별도로 정지 권한을 갖고 있다면 디버그 재개만으로 옵션의 정지는 풀리지 않습니다. 디버그 무적을 켠 상태는 플레이어 재생성 후에도 새 Actor에 다시 적용되므로, 일반 피해를 시험하려면 명시적으로 끕니다.

## 6. 피해 플랫폼의 구체 타입과 Inspector 피해량을 시험합니다

1. 시험할 배치 객체에 맞는 `PotDamagePlatform`, `GratangDamagePlatform`, `BurnerDamagePlatform` 구체 컴포넌트를 사용합니다. 원본 보호 프리팹을 임의로 수정하거나 Apply하지 말고 승인된 소유 객체·배치 범위에서 구성합니다.
2. 해당 컴포넌트의 **피해량**을 Inspector에서 설정합니다. 일반 예시는 1, 큰 피해 예시는 9999입니다. 0은 피해 없음이며 음수는 허용하지 않습니다.
3. 실제 접촉도 시험하려면 **피해 감지 영역**에 루트 또는 자식의 피해 Trigger를 연결합니다. 지지면 Collider와 구별하며, 메시 Trigger는 Convex 조건을 확인합니다. 영역을 비워두면 접촉 피해를 감지하지 않습니다.
4. 패널의 **피해원 선택**으로 실제 컴포넌트를 고른 뒤 표시된 피해량을 확인하고 **선택 플랫폼 피해 적용**을 누릅니다. 별도 피해량 입력창은 없습니다. 패널 버튼 시험과 실제 Trigger 접촉 시험은 서로 다른 검증 항목입니다.
5. 피격 후 무적 또는 디버그 무적 중에는 9999도 거절됩니다. 일반 피해를 시험할 때는 디버그 무적을 끄고 피격 무적이 끝난 뒤 적용합니다. HP가 0이 된 피해는 기존 사망 표현 완료 경로를 사용합니다. 플랫폼에서 애니메이션 클립을 선택하지 않습니다.

## 7. 실제 Inspector 이동·점프 값을 조절합니다

1. 초기 작성 기준은 **이동속도 1.8m/s, 기본 폼 점프 높이 1m, 작은 폼 점프 높이 0.5m**입니다. 실행 중 이 값으로 강제 고정하는 규칙이 아닙니다.
2. 재실행에도 남길 설정은 수정 권한이 있는 테스트용 플레이어 프리팹의 Inspector에서 편집하고 **플레이어 프리팹** 필드에 연결합니다. 보호된 공용 원본을 자동으로 변경하거나 Apply하지 않습니다. Play 중 생성된 Actor를 편집한 값은 임시 실행 값이므로 Play 종료·재생성 이후 보존된다고 가정하지 않습니다.
3. `PlayerMovementModeController`의 **Side Move Speed**(`sideMoveSpeed`)와 **Quarter Move Speed**(`quarterMoveSpeed`)가 각 모드의 속도 원본입니다. 쿼터 속도에는 사이드 속도 이하 제한이 있습니다. 모드가 적용되면 `CharacterMovement`의 `moveSpeed`에 전달되므로, 현재 유효값과 모드별 편집 원본을 구별합니다. Back 계열은 별도의 `backMoveSpeed`를 사용합니다.
4. `PlayerFormController`의 **Normal Jump Height**(`normalJumpHeight`)와 **Small Jump Height**(`smallJumpHeight`)를 각각 편집합니다. 폼 적용 시 현재 `CharacterMovement.jumpHeight`에 전달됩니다. 실행 중 해당 원본 필드만 편집했다면 폼 재적용 또는 다시 실행한 뒤 실제 표시값을 확인합니다.
5. 일시적인 현재 값 시험은 실행 중 생성된 플레이어의 `CharacterMovement`에서 `moveSpeed`, `jumpHeight`를 편집하여 수행합니다. 패널은 현재 이 두 직렬화 값을 읽습니다. 이후 시점/폼 전환이 원본 설정을 다시 적용할 수 있습니다. 패널 표시값은 현재 설정값이지 실제 점프 궤적의 측정 결과는 아닙니다.

Side의 X 이동과 Corridor/Quarter의 XZ 이동을 구별합니다. 수치 시험을 위해 축 제한이나 기존 루트·메시 Scale을 일괄 변경하지 않습니다.

## 8. 옵션과 본편으로 돌아갑니다

1. 테스트 중 **ESC**로 기존 옵션을 열고 닫습니다. F1과 ESC는 별개이며 옵션은 기존 입력 제한·정지 계약을 사용합니다. 디버그 패널을 숨겨도 옵션이 열려 있으면 커서 표시 사유가 유지됩니다.
2. 실행 중 본편 타이틀로 돌아가려면 옵션의 **타이틀 이동** 버튼을 누릅니다. 테스트 세션을 정리하고 직접 테스트 선택을 해제한 뒤 기존 Bootstrap을 로드하는 경로입니다. 패널이 옵션을 가린다면 F1로 숨긴 후 조작합니다.
3. 편집 상태에서 본편 경로를 선택하려면 Play를 종료한 뒤 **Cooked → Testing → 본편 실행**을 선택하고 다시 Play합니다. 메뉴에서 실행 경로를 바꾸는 작업은 Play 중에는 제공되지 않습니다.
4. 다시 직접 시험하려면 작업 씬을 활성화하고 **현재 씬 직접 테스트**를 선택합니다. 테스트 설정은 Editor용이며 일반 Player 빌드용 기능이 아닙니다. 빌드 제외 여부의 실제 확인은 메인의 빌드 검증 항목으로 남깁니다.

임시 런타임·로그 구독·화면은 테스트 수명 종료 시 정리하도록 구현되어 있습니다. 이 안내의 절차 설명을 실제 실행 성공 또는 빌드 통과 증거로 취급하지 않습니다.
