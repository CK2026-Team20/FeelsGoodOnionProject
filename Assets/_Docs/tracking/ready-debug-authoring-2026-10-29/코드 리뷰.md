# 구현 코드 리뷰

2026-10-29. 승인된 구현과 기존 미커밋 자료를 분리해 검토했다. 기능 구현과 실행 검증 완료는 구별한다.

## 설계·범위

- 직접 씬 테스트는 실제 SessionActorHost·PlayerBridgeService·GameSessionService·GameplayControlService를 조립한다. 타이틀/컷신/전체 Stage 등록이 필요 없는 Editor 전용 진입 어댑터다.
- 화면은 DebugPanelViewModel 명령·상태에 바인딩한다. View는 피해·회복·해금 판정을 소유하지 않는다. 로그 수집은 별도 제한 버퍼이며 Unity 스레드 로그를 잠금으로 보호한다.
- F1은 커서 표시 이유만 전달한다. 옵션/디버그 Pause는 독립 토큰으로 해제하며 숨김은 게임 상태를 바꾸지 않는다.
- 적 방향·지형·축/단위 배율 제약 소비자를 함께 제거했다. 실제 Body/앵커 참조와 유한 수치 검사는 남긴다. 보호 prefab·기존 변환은 유지한다.
- 피해 플랫폼은 구체 타입과 정수 피해만 전달한다. PlayerBridgeService에서 무적을 먼저 판정하고 기존 사망 연출 경로를 재사용한다. 타입 판정에 리플렉션/이름 문자열을 사용하지 않는다.
- TitleScenePresentation은 기존 앱 Camera/Brain을 빌려 고정 구도를 적용·반환한다. 타이틀 전용 출력 Camera를 중복 생성하지 않는다.
- Inspector 편집은 HMS 설정 원본과 실제 적용값을 함께 변경한다. 보호 HMS 소스/프리팹을 변경하거나 실행 때 기준값을 강제하지 않는다.

## 후속 씬 전환 순서 검토

기존 Title 선행 언로드에서 네이티브 GPUResidentDrawer/ObjectDispatcher 충돌을 재현했다. 렌더 설정 변경은 채택하지 않았다. GameFlowService는 페이드 뒤 Core·Stage를 먼저 로드하고 Title을 해제한 뒤 InitializeSession을 실행한다. 프레임 대기 실험 코드는 제거했다.

독립 검토에서 차단 결함은 발견하지 못했다. 부분 로드는 실제 로드 씬을 Recover에서 정리하며, 기존 Title 재사용은 sceneLoaded를 다시 발생시키지 않아 중복 바인딩하지 않는다. Title 언로드 시 빌려 쓴 Brain 상태를 반환한 후 세션 카메라를 바인딩한다. 이 예외 경로의 검토를 실패 주입 실행으로 표현하지 않는다.

원본 렌더 설정에서 실제 오프닝 복귀9항목을 두 번 통과했고, 오프닝 Skip→Playing→ESC 복귀7항목 및 서비스 취소8시나리오도 통과했다. Unity6000.6.0f1과 렌더 설정을 유지한다. 빌드 중 자동 생성된 렌더 자산 직렬화는 output에 백업하고 복원했다.

## 보존

기준선 대비 _Art·_Prefabs·Tech_HMS·Packages·ProjectSettings 보호 파일1,218개 변경0. Prototype의 기존 Transform 블록과 위치·회전·스케일 override 동일. 본편 씬 변경은 피해 컴포넌트 연결/중복 비활성화/폐기 필드 override 제거에 한정한다. 소유 Title 씬에는 빈 월드·구도 기준점을 추가했다. 원본 prefab Apply/Unpack·재생성은 하지 않았다.

## 2026-10-30 로그 글리프·표시 경계

기존 로그는 IM_Hyemin-Bold SDF 정적 폰트를 직접 사용했고 fallback이 없었다. Native API 확인에서 U+2713 체크 기호가 없었다. 기존 CookedKorean SDF는 source=null·character0 상태라 그대로 대체할 수 없었다. 따라서 존재하는 Noto 원본 Font에서 임시 로그 폰트를 생성한다. DebugLogFont는 글리프 지원 검사·표시 변환·자원 수명을 담당하고, Session이 생성/해제를 소유하며 View는 빌려 사용한다. 원본 로그와 Model은 변경하지 않는다. 누락된 문자를 TMP에 반복 전달하여 누락 경고가 로그로 재유입되는 경로를 차단한다. 리플렉션·전역 TMP 설정·렌더 설정·프로젝트 버전 변경은 없다.

사용자 미커밋 DirectSceneTestSettings.cs 및 PeriodicPlatform.prefab은 이번 수정에 포함하지 않는다. Stage_4 미저장 씬을 저장·전환·Play하지 않는다.

## 2026-10-30 붕괴 발판 복원 연결 검토

사망과 버튼은 기존 RespawnRoutine을 공유한다. Actor 제거 후 disposed 검사를 통과한 경우에만 같은 씬의 발판을 복원한다. 발판 상태·Collider·외형 복원 규칙은 ShatteredPlatform.ResetForRetry가 계속 소유하며 디버그 코드에 복제하지 않는다. 일반 플레이의 StageService도 동일 메서드를 사용한다. 다른 씬이나 다른 장치를 초기화하지 않는다.

## 2026-10-30 테스트 카메라 책임·수명 검토

카메라 생성·대여 출력 복원은 DirectSceneTestCamera에 분리했고 Runtime은 생성·Tick·Actor 연결·해제를 조정한다. 구도 계산과 이동축 매핑은 본편 코드를 재사용한다. StageService의 체크포인트/입력 잠금/위치 보정을 모방하지 않는다. 사용 중이지 않은 Cinemachine 채널로 기존 가상 카메라와 분리한다. 재생성 전에 Follow를 해제하고 새 Actor에 재연결하며, 초기화 실패도 생성 자원 정리와 기존 활성 상태 복원을 수행한다. 사용자 작성 Settings의 임시 카메라 코드만 요청에 따라 대체했다. 기존 staged UI·주기 발판 변경은 수정하지 않는다. 버튼은 기존 ViewModel Run 경로를 사용하며 표시 상태는 Changed 구독으로 갱신한다. 반복 Dispose와 실패 정리는 별도 Native 검사로 확인했다.

## 2026-10-30 월드축·상호작용 책임 검토

카메라 원본 ViewSettings와 실행 복사본을 분리하여 원본 회전을 변경하지 않는다. 모든 시점은 수평 +Z이며 HMS의 기존 월드 X/Z 입력을 유지한다. Main Camera 임시 비활성화·복원 계약은 유지한다.

메모 화면 연결은 명시적 BindScreen/ConfigureScreen 계약으로 처리하며 리플렉션을 사용하지 않는다. 메모의 화면 누락 진단을 Start로 이동해 AfterSceneLoad 세션 주입을 허용한다. 기존 F 대상 선택·거리·차폐·트레이 실행 코드는 중복하지 않는다. 월드 안내는 기존 WorldPromptViewModel/View를 사용하며 구성 객체가 표시용 데이터를 전달한다. 리스폰 시 플레이어 서비스만 재연결하고 화면의 수명은 테스트 세션이 소유한다. 기존 작성 참조 보존·해제 후 복원을 Native 검사로 확인했다.
