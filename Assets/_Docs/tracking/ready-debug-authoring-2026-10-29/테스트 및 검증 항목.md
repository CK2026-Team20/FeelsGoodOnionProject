## 실패 후 수정·재실행

- 최초 합성 이동 검사는 프로젝트의 방향키 대신 A를 사용해 실패했다. 실제 키 바인딩에 맞춰 수정 후 통과했다.
- ESC는 공통 루트 비활성화 문제를 수정 후 통과했다.
- 사망 재생성 검사는 Actor generation 변경 순간의 Despawn을 완료로 오인했다. 새 Actor 준비까지 기다리도록 검사 조건을 수정 후 통과했다.
- 초기 카메라 도구 캡처는 Overlay UI를 포함하지 않아 화면 검증 자료로 쓰지 않았다. native ScreenCapture로 `final-debug-panel.png`를 확보했다. 이 캡처에서 긴 피해원 글자 겹침을 발견해 보완했으며 최신 final-debug-panel.png를 다시 촬영해 긴 글자 겹침 해소를 확인했다.
- 전체 `git diff --check`는 Unity 기본 직렬화의 빈 `m_Name: ` 뒤 공백을 보고했다. 승인되지 않은 YAML 텍스트 보정은 하지 않는다. 코드·Markdown 범위는 별도로 검사한다.

## 후속 실행과 렌더 설정을 유지한 수정

- 사용자 후속 지시에 따라 복구 창을 직접 조작하고 백업을 보존했다. 복구 자료는 `output/Tech_SYM/DebugTesting/Recovery/`에 보관했다.
- 이전 순서(Title 언로드 → Core 로드)에서 GPUResidentDrawer/ObjectDispatcher 네이티브 충돌이 재현됐다. 프레임 대기는 해결하지 못했다. 임시 렌더링 복사본의 GPU Resident Drawer 비활성화는 진단에서만 통과했으며 사용자 지시에 따라 영구 수정으로 채택하지 않았다.
- 최종 구현은 페이드가 덮인 상태에서 Core·Stage 로드를 끝낸 뒤 Title을 해제하고 세션을 초기화한다. 공유 표시 자산을 사용하는 씬 사이에 공백이 생기지 않도록 수명을 겹친다. 엔진 내부 결함의 근본 원인을 확정했다는 뜻은 아니다.
- Unity **6000.6.0f1**, 원본 `PC_RPAsset`의 **GPU Resident Drawer Instanced**를 유지했다. ProjectVersion·Packages·최종 렌더 설정 변경은 없다.

## 미실행·남는 검증 범위

- 실제 엔딩 화면에서 ESC로 복귀하는 전체 통합 경로. 서비스 취소8시나리오로 대체 완료 처리하지 않는다.
- Core 로드 중 취소·Stage 로드 실패·Title 언로드 중 취소를 실제 엔진에 주입하는 복구 검사. 독립 코드 검토에서는 차단 결함이 없었으나 실행 검증은 아니다.
- 실제 마우스 클릭/휠의 전체 조작, 회전·배율 적의 자연 물리 접촉, E로 적 기절, 전체 본편 자연 동선·백페이스·성능 QA.
- 완성 타이틀 배경 아트 및 피해원별 미제공 애니메이션 클립은 이번 구현 범위 밖이다.

준비 단계 자료는 `output/Tech_SYM/Documents/ready-debug-authoring-2026-10-29/verification.json`에 보존한다. 과거 미실행·실패 기록을 현재 성공으로 일괄 치환하지 않는다.
