# 코드 리뷰

## 결론
기존 실행 로그의 직접 실패는 SessionActorHost.Spawn의 활성 프리팹 거절이다. 사용자가 직접 수정한 현재 PlayerRoot prefab은 activeSelf=false이므로 그 실패 조건은 해소됐다. 현재 직렬화/비 Play 계약 검사에서 새 초기 진입 차단 원인은 발견하지 못했다. 실제 Spawn/Awake/Start/Cinemachine 완료는 실행하지 않았으므로 성공 보장은 아니다.

## 과거 실행 실패 증거
2026-10-15 04:28:11, 04:28:13, 04:28:14 KST의 로그(seq1181/1187/1193)는 동일한 `Actor prefab must be saved inactive so dependencies exist before Awake.`를 기록했다. Stage 직접 진입 및 Title의 NewGame 모두 LoadingGame → 예외 → Recovering → Title(busy=false)로 복구됐다. 실패 위치는 SessionActorHost.cs:76이며 Instantiate보다 앞이다. 메모 에러는 이전 기록에 존재하지만 가장 최근 세 시도에는 없다.

이 예외는 GameFlowService에 전달된 Debug.Log 콜백으로 기록되므로 Console의 Error 필터만으로는 놓친다. 현재 Error=0 또는 컴파일 성공을 게임 흐름 성공으로 해석하면 안 된다.

## 현재 해소된 항목

- StageService 1개. 시작 트리거, 음악 music.stage1 및 소속 연결. Stage.RebuildRegistry와 InitialPose 조회 통과.
- StageTrigger 10개: 체크포인트6, 해금2, Fall1, Escape1. 모두 소속 Stage 참조·Trigger 설정 및 Actor와 Layer 충돌 허용 확인.
- Stage에는 PlayerFacade/출력 Camera/AudioListener가 없다. 앞선 중복 위험은 현재 배치에서 제거됐다.

- 설치·Entry는 새 Stage 하나. Bootstrap/Title은 Title 진입, Core/Stage는 직접 Stage 진입으로 해석된다.
- Core의 세 카메라/활성 PositionComposer와 기본 수치 유효. Bootstrap 출력 Camera/Brain/Listener/EventSystem 각1개.
- 연출 원화·문구·시간 검증: Opening4컷/Ending4컷. Escape의 DialogueTable/POPO 선택 검증 통과. 소리 목록 검증 통과.

## 현재 남은 문제
### P1: 구간 카메라·이동 모드 전환 미작성
Stage에 CameraZoneTrigger가0개다. 최초 시작은 Side 체크포인트이므로 CoreWorldBinding.cs:119~135에서 Side fallback을 선택한다. 체크포인트 접촉 저장 자체는 이동 모드 변경을 호출하지 않는다. 그런데 StageTriggerPoint (8)의 복귀 기본 시점은 Quarter다. 따라서 그 지점 최초 통과와 재시도 복귀의 이동 모드가 달라질 수 있다. 깊이 Z 이동이 필요한 구간은 Side 상태로 진입하면 진행 제약이 생긴다. 의도된 경계에 실제 Sensor/Alignment를 갖춘 CameraZoneTrigger 작성이 필요하다. 초기 로드 실패와는 다른 진행 문제다.

### P2: Small 충돌체가 Normal보다 큼
PlayerRoot.prefab의 ActorBody Capsule 반경0.1/높이0.23, 배율1이다. PlayerFormController smallRadius=0.25, smallHeight=1이다. ApplyForm은 이 값을 그대로 사용하므로 Small 전환 때 반경2.5배·높이약4.35배로 커진다. 통로 통과·침투·폼 복귀 검사에 영향을 준다. 올바른 크기는 현재 아트/레벨 규격과 함께 정해야 하며 임의 보정하지 않았다. 초기 흐름 예외의 원인은 아니다.

### 설계 확인: 시작점과 해금 배치
시작·폼 해금·눈물 해금 센서의 중심(-0.96,3.78,0), 크기(1,1,1)가 같다. Entry 초기 능력은 비어 있지만 Playing이 된 후 접촉으로 두 능력을 즉시 얻을 수 있다. 순차 습득을 의도했다면 배치가 맞지 않는다. 현재 의도 확인 항목이며 결함으로 단정하지 않는다.

### 추격과 엔딩
Chase 트리거/Driver가0개다. Escape/POPO는 존재한다. StageService는 hasChase=false이면 추격 승인 없이 Escape를 허용하므로 추격 부재 자체가 엔딩을 차단하지 않는다. 추격을 포함한 전체 명세 구현은 미완성이나 이번 초기 진입 실패 원인은 아니다.

### 빌드 경로
전역 EditorBuildSettings에는 01_Samples만 있다. 그러나 SceneService는 Editor에서 미등록 씬 로드 대체 경로를 사용하며 IntegrationBuildPipeline은 설치 기준4씬을 명시 전달한다. 따라서 현 Editor 실패의 원인이 아니다. 일반 Build 버튼과 전용 통합 빌드를 혼동하면 다른 실행 파일을 만들 수 있다. 빌드는 미실행.

## 검증 한계
비 Play에서 실제 Actor를 활성화하거나 실행 흐름을 시작하지 않았다. 다음 실행에서만 HMS Awake/Start 완료,10초 준비 대기, Cinemachine Brain readiness, UI 입력, 실제 물리 접촉, Ending/Title 언로드를 확인할 수 있다. 최신 실행 로그에 Playing,busy=False가 나타나는지와 다음 예외를 확인해야 한다.
