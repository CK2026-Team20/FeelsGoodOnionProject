# 플레이 가능성·레벨 작성 검수 범위

2026-10-15 사용자 요청: 버튼 cap/body 분리, 카메라 전환과 경계 제한, 플레이어 수치의 직관성, Stage 시스템 활용도, 앵커/안전 보정/회전축을 먼저 검토한다. 이번 작업은 제품 수정 전 검수이며 공식 Unity 플러그인으로 실제 Editor Play를 사용한다. 기존 씬·prefab·HMS 원본은 수정/저장하지 않는다. 검수 문서와 output 증거만 작성한다.

참고: 최신 직접 지시, V1.6 원본, 현재 Stage/Core/PlayerRoot, 실제 물리·화면·직렬화 참조, PressurePlatePlatform/KinematicPlatformMotion/PlatformContacts, CameraZoneTrigger/LevelCameraService, HMS 이동·폼 설정 소유권.

완료 기준: 활성/비활성 시스템 전수 목록, 버튼 물리 눌림 재현, Zone 보정과 축 지원 구분, 카메라 경계 영향 계측, 플레이어 크기/속도/점프 계측, 체크포인트 복귀 위치 검수, 필요한 객체/연결·변경 방향과 미검증 범위를 분리한다. Play 종료 후 원래 씬·파일 상태를 확인한다.

후속 답변: 레벨 작성 기준은 체크포인트 위치이며 카메라 전환·보정 작성이 별개 Zone 앵커에 흩어지지 않도록 종속시키길 원한다. 직관적인 대안도 비교 검토한다. 아래 제안은 구현 완료가 아니다.

## 권장 작성 구조

`CheckpointRoot`의 Transform을 복귀 시 플레이어 Capsule 중심과 레벨 작성 원점으로 사용한다. Root에는 체크포인트 책임을 두고 자식 `Sensor`에 감지 Collider를 둔다. 감지 범위는 Root를 움직이지 않고 조절할 수 있게 한다. 카메라 구도는 같은 Root 아래의 `CameraPose` Transform 하나로 작성한다. 실제 출력 카메라/Brain을 체크포인트마다 추가하지 않는다.

- Root 이동: 감지 영역과 카메라 작성 구도가 함께 이동한다.
- 일반 접촉: 체크포인트 저장 → 해당 구도로 블렌드 → 이동 모드 확정. 플레이어를 다른 좌표로 강제 이동하지 않는다.
- 초기/재시도: 같은 구도를 즉시 적용한다. 평상시 접촉 블렌드와 복귀 Cut을 구분한다.
- CameraPose는 작성용 상대 위치·회전의 단일 원본이다. 편집 미리보기는 Root의 플레이어 모형을 기준으로 보이고, 실제 추적은 현재 플레이어 CameraTarget을 기준으로 같은 상대 구도를 적용한다. 체크포인트 월드 위치에 출력 카메라를 고정하는 뜻이 아니다.
- Scene 핸들로 위치 이동과 타겟 중심 궤도 회전, 화면 미리보기를 제공한다. Inspector의 거리·가로회전·세로회전·기울기는 같은 pose를 편집하는 도구여야 하며 서로 다른 중복 저장값이 되어서는 안 된다.
- 바운더리 제한은 사용자 지시대로 제거 대상이다. Stage 참조, Confiner 연결, 최종 ClosestPoint 제한, 검증·설명을 함께 정리해야 한다. 검사만 해제하고 숨은 제한을 남기지 않는다.
- 안전 보정은 일반 시점 전환과 분리한다. 실제 문/차단체가 있는 특별 장치만 명시적으로 사용한다. 필요한 보정 축·좌표 기준·경로·거절 이유를 Gizmo와 Inspector에 표시한다.
- 감지 범위와 복귀점을 분리하되 별도 체크포인트 ID나 중복 상태 소유자를 만들지 않는다. 현재 StageTrigger가 Collider와 같은 객체를 요구하는 계약은 Sensor relay로 조정해야 하며 기존 프리팹 이관을 검토한다.

단순 대안은 기존 Zone을 체크포인트 자식으로 옮기는 것이다. 그러나 Checkpoint Cut과 Zone Blend의 이중 경로, 사용되지 않는 SafeAnchor, 서로 다른 보정 규칙이 남으므로 권장안보다 작성 혼란이 크다.
