# 체크포인트 검사 초기화 순서 수정

## 원인과 목표

사용자 실제 진입 로그에서 LoadingGame → SpawnAnchor 스폰 배치 불가(발바닥 ±0.05m에 지면 없음) → Recovering → Title이 반복됐다. 편집 씬의6개 앵커는 검사에 통과했다. CoreWorldBinding.PrepareStage는 초기 배치를 재설정한 뒤 Stage 루트를 비활성으로 남기고, 기존 BindActor가 ActorReady 이후에야 루트를 켰다. 추가한 RegisterInitialCheckpoint/Host의 물리 검사 시점에는 지형 Collider가 꺼져 있었다. 이전17/43검사는 이 실제 초기화 순서의 검증이 아니었으며 이번 결함을 놓쳤다.

## 수정 및 리뷰

CoreWorldBinding.ActivateForSpawn이 선택 Stage만 활성화하고 Physics.SyncTransforms를 수행한다. CoreComposition이 기존 재준비 콜백과 함께 이 명시적 수명 콜백을 주입한다. GameSessionRuntime.Begin은 초기 체크포인트 등록 전에, SpawnActorAtCheckpoint는 최초/Retry Actor 생성 전에 호출한다. ActorReady는 준비된 월드의 이벤트/카메라 연결을 담당한다. 활성화 책임은 기존 월드 조립자에 유지하며 도메인/Host가 씬 루트를 검색하지 않는다. 기존 충돌/지면 검사·발바닥 기준·대체 위치 없음은 유지한다. 씬/앵커 좌표·보호 자산은 이번 수정에서 변경하지 않았다.

## 검증

공식 Unity 도구로 저장된 Tutorial에서 실제 Editor Play를 실행했다. 초기 LoadingGame → Playing,busy=False 확인. frame1에서1377로 진행하고 Player 존재/ActorViewReady=true 확인. PlayerBridgeService.ForceDeath(Vector3.zero,true) API로 사망 처리 후 Retrying → Playing,busy=False, ActorGeneration2→5와 새 Actor/카메라 준비 완료를 확인했다. 수정 후 같은 지면 없음 예외는 발생하지 않았다. 자연 입력 전체 플레이/다른 구간 진입/Player 빌드 검증은 아니다.

검증 도중 CLI status 호출이 Pipeline에 지원되지 않는 'editor status' 명령을 보내 도구 오류1건이 기록됐다. 게임 진입 오류와 구별하며 Console 전체0이라고 주장하지 않는다. 컴파일 실패 없음, 변경3파일 diff 공백 검사 통과. Play 종료 후 원래 Tutorial 편집 상태로 복귀하고 runInBackground의 이전 값을 복원했다.
