# 체크포인트 발바닥 스폰

## 목표·참고·제약·완료 기준

사용자 지정4항목: 발바닥 기준, 에디터 가능 파랑/불가 빨강, 스폰 검사, 대체 위치 없음. StageTrigger/StageService, SessionActorHost, LevelCameraService, GameSessionRuntime 및 기존 체크포인트 상태 계약을 참조했다. 보호 플레이어·아트·원본 프리팹을 변경하지 않고 실제 Collider를 참조한다. 현재 미저장 Tutorial은 저장/재로드하지 않는다. 완료 기준은 좌표 변환·충돌/지면 거절·저장 원자성·초기 무음 회귀와 실제 배치 검사다.

## 계약

- CheckpointSpawnPoint는 체크포인트의 고정 Root 아래 빈 SpawnAnchor에 둔다. Transform 위치는 발바닥, 회전은 수평 방향이다. 시각 모델/Trigger 중심과 분리한다.
- 실제 복귀 플레이어 프리팹의 Normal Capsule을 연결한다. 생성 없이 치수를 읽어 에디터와 저장 시 검사한다. 실제 생성 시에는 생성된 Capsule로 다시 검사한다.
- 스냅샷의 Position은 발바닥 월드 좌표다. Fragments/UnlockedAbilities와 합계3값을 유지한다. 추격의 현재 위치 저장도 중심이 아닌 발바닥으로 변환했다. 추격 시작선 모델 전체 변경은 이번 범위가 아니다.
- 시작 체크포인트 무음 등록과 새 저장 전에 지점 검사. 실패 시 새 저장/소비 장부를 갱신하지 않는다. 이미 수락한 저장은 이후 장애물 등장으로 삭제하지 않는다.
- Host는 비활성 생성 직후 및 Normal 준비 후 실제 Capsule로 검사/중심 변환한다. 실패는 기존 생성 정리·세션 오류 경로로 전달하며 대체 좌표를 찾지 않는다. 구간 진입 보정도 현재 폼 높이로 발바닥을 목표에 맞춘다.
- 기존 직접 씬 테스트의 별도 StartPoint는 명시적인 Capsule 중심 계약을 유지한다. 이 값은 체크포인트 앵커가 아니며 기존 직접 테스트 배치를 몰래 변환하지 않는다.

## 검사와 표시

발바닥 ±0.05m 이내 지면, 플레이어 접지 허용각, 실제 레이어 충돌 규칙과 IgnoreCollision을 검사한다. 지면 경계 접촉에는0.002m 여유를 둔다. Trigger·검사 플레이어 자신을 제외하며 벽/천장/지면 침투, 지면 없음, 잘못된 참조·치수·기울기·움직이는 앵커는 불가다. Capsule Y축/양수 배율/수평 회전을 요구한다. 검사 후보128개가 가득 차면 안전을 확정하지 않고 거절한다. 수직 지면 확인은 발바닥 중심 기준이며 발 전체의 지지 면적 보증은 아니다.

Gizmos를 켜면 발바닥 표시·방향·Capsule 범위를 가능=파랑, 불가=빨강으로 표시하고 이유를 라벨로 보여준다. Collider가 없는 장식 메시의 시각적 겹침은 물리 검사로 알 수 없으므로 화면 검토가 필요하다.

## 현재 씬 배치와 사용

현재 열린 Tutorial의 CP_A_S/CP_A_E/CP_B_S/CP_B_E/CP_C_S/CP_C_E에 SpawnAnchor를 추가했다. 시각적 깃대 겹침을 피하도록 체크포인트 Renderer의 좌/우 경계에서 Capsule 반경0.1m + 여유0.05m 떨어진 X 위치에 배치했다. Z는 기존 동선을 유지하고 해당 위치의 지지면 높이에 맞췄다. 실제 Normal Capsule로6개 모두 통과했다. CP_C_S/CP_A_S는 왼쪽, 나머지는 오른쪽이다. CP_A_E는 옆 물체 상단(약Y3.958)에 있으므로 레벨 동선/복귀 구도는 실제 플레이 확인이 필요하다. 이는 편집 시의 명시적 최초 배치이며 런타임 바닥 탐색/대체 위치 이동 기능이 아니다. Undo 그룹: 체크포인트 발바닥 스폰 지점 연결 / 체크포인트 외형 옆 스폰 여유 배치. 기존 사용자 작업과 함께 미저장 상태로 남겨 두었다.

Hierarchy에서 각 CP의 SpawnAnchor를 이동하면 판정이 갱신된다. Trigger Inspector의 발바닥 스폰 지점 참조와 Anchor의 복귀용 Normal Capsule을 확인한다. 새/다른 씬의 체크포인트에도 두 참조가 필요하며 누락 시 기존 Trigger 중심으로 자동 복귀하지 않는다. 현재 씬 편집을 디스크에 유지하려면 사용자가 씬 저장을 해야 한다.
