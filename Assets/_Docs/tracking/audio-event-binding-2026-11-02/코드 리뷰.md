# 코드 리뷰

- 도메인 컴포넌트는 AudioSource나 오디오 관리자를 소유하지 않는다. 수락된 상태 변화만 통지하고 AudioRuntimeHost가 출력과 구독의 수명을 소유한다. GameplayEvent는 관측자 예외를 기록하고 나머지 관측자를 계속 호출한다.
- EnemyActor.StunStateChanged는 상태 표시용으로 유지하고, 매 피격 성공은 별도 StunApplied로 분리했다. 기존 기절중 재적중을 놓치지 않는다.
- PlayerBridgeService.AcceptedDamage에 실제 EnemySource와 적용 넉백 여부를 포함한다. EnemyContactSensor는 새 DamageFromEnemy 경로를 사용하며 기존 위치 기반 피해 API는 유지한다.
- 발소리 간격은 FootstepCadence가 소유한다. 착지 뒤 기본 간격 대기, 정지 후 이동 시작 즉시 재생, Pause 중 시간 미진행을 구별한다.
- CoreWorldBinding의 예전 효과음 재생 코드를 제거하고 중앙 Host에 연결/해제를 위임한다. 직접 테스트는 같은 PlayerAudioBinding/WorldAudioBinding을 재사용한다.
- 장치의 소리 위치는 고정 Root 대신 연결된 물리 몸체/지지면을 우선한다. 환경 Loop는 피해 Trigger의 중심과 Transform 상대 오프셋을 유지한다.
- 공간음의 감쇠는 카메라 AudioListener의 거리로 이중 적용하지 않고 PC 위치로 계산한다. Source 자체는3D 방향감을 유지한다. 개체별 Loop 핸들은 풀 재사용 후 오래된 핸들이 새 음성을 멈추지 않도록 증가하는 ID를 쓴다.
- UI는 VM 명령의 수락 결과에만 주입된 피드백을 호출한다. View가 전역 오디오 서비스를 검색하지 않는다. 키보드/자동 입력은 마우스 클릭으로 위장하지 않는다.
- 음원27종 참조는 유지했다. 미확보3종은 호출만 연결했으며 해당 음원의 실재/청취까지 완료했다고 표현하지 않는다.

## 남은 검수

실제 플레이에서 모든 배치의 최대 청취 거리·볼륨, 많은 적의 동시 피격 음량, 이동/기름 전환의 자연스러움, 버너의 활성 상태와 시각적 점화 상태 일치 여부를 확인해야 한다. 새로 동적 생성된 적/장치를 도입하면 현재 Bind 시 한 번 검색하는 계약을 명시적 등록 계약으로 확장해야 한다. 기존 작성된 Stage와 Retry 재연결 범위는 처리한다.
