# 22~24 튜토리얼 UI·사운드 구조

## 후속 정정: 원본 참조와 자산 위치

목표는 불필요한 PNG 사본을 없애고 기능별 자산 위치를 바로잡는 것이다. 원본 시트의 Sprite 30개, 기존 프리팹4개·AnimationClip4개·Controller4개를 대상으로 한다. 원본 및 import 설정과 씬 배치를 보존하고 AssetDatabase 이동으로 GUID를 유지한다. 프리팹은 공용 Assets/_Prefabs/UI/Tutorial, 애니메이션은 Assets/_Animations/Tech_SYM/Tutorial에 둔다. 원본 Sprite 참조·40프레임 간격·GUID 보존·사본 참조0을 완료 기준으로 한다. 초기 Image 크기는 원본 Sprite rect 크기를 사용한다.

## 목표와 근거

2026-11-02 사용자가 승인한 대화 내 계획을 구현한다. 튜토리얼은 최초 접촉 때 한 번 등장하고 사망·재시도에도 표시를 유지한다. BGM은 Bootstrapper에서 씬별 사전 바인딩한다. 최초 스폰은 체크포인트를 유지하며 무음 초기 등록한다.

참조: planning-index의 시스템 V1.8/UI Ver2.1, 이번 직접 지시, AudioFlowBinding/AudioService, StageService/StageTrigger, CoreWorldBinding/GameSessionRuntime, _Art/UI/Tutorials, [사운드 명세](../../Audio/사운드%20리소스%20상세%20명세.md).

## 동작과 책임

- TutorialProgress는 GameSessionRuntime 수명의 장부다. 객체별 런타임 identity token을 사용하고 저장 파일·이름·배열 순번을 키로 삼지 않는다. Actor 교체 시 장부는 유지하고 새 게임은 새 장부를 만든다.
- TutorialPrompt는 현재 Actor와 Flow가 Playing/비전환/입력 허용인 실제 접촉을 VM 명령으로 전달한다. Sensor는 접촉만 전달한다. VM은 상태를 노출하고 View 참조를 갖지 않는다. View는 자기 구독·확대 tween과 Canvas/Animator만 관리한다.
- 네 프리팹: Move(A/D 4장), Jump(Space 2장), Tear(E 8장), Form(Q 16장). AnimationClip Samples=60, 서로 다른 스프라이트 교체는 0·40·80…프레임. 마지막 39번째 프레임에 동일 스프라이트 유지 키를 두어 Unity의 1프레임 길이 계산을 보정한다. 총 주기는 장수×40/60초다.
- 최초 등장 0.3초 OutBack 확대, 이후 고정 월드 위치에서 반복 재생. 카메라를 향하며 상하 부유 운동은 없음. 재접촉/재바인딩은 등장 재시작 없음. 옵션 정지 중 애니메이션과 등장 tween 정지.
- AudioCueCatalog의 stages: SceneReference·Clip·음량·전환 시간. Host가 이를 AudioFlowBinding에 주입하고 Integration은 StageId만 전달한다. 구간 음악 필드·콜백 제거. 기존 씬의 잔존 직렬화 음악값은 읽지 않으며 보호 씬을 재저장하지 않았다.
- StageService.RegisterInitialCheckpoint는 저장값·현재 구간·활성 장부를 한 번 무음 등록한다. 최초 회전은 유지하고 일반/추격 실제 저장 이후 복귀는 기존 identity 회전 규칙을 유지한다.
- CheckpointSoundPolicy: SectionDefault(시작 재생·종료 무음), Play, Silent. 초기 등록과 이미 활성화된 지점은 이벤트 자체가 없어 정책과 관계없이 무음이다.
- BGM Pause/Resume은 PresentationPaused를 따른다. 일반·추격·타이틀 Loop, 오프닝·엔딩 One Shot. 페이드 취소 revision으로 낡은 완료를 차단한다. 재시도 Playing 진입 시 Respawn을 한 번 요청한다.

## 제약과 완료 기준

기존 작업을 보존하는 현재 checkout에서 공식 Unity 플러그인으로 작성한다. 공유 Editor 하나이므로 자산 작성·컴파일·실행은 순차 수행하고 리뷰는 읽기 전용으로 분리했다. 이번 승인 계획이 작업 범위이며 DryForge의 별도 브랜치/커밋·정리 절차로 범위를 확대하지 않는다.

_Art/원본 .meta/HMS/공용 prefab/Packages/ProjectSettings 직접 수정 없음. Tutorial 씬 배치·진입 설정 수리·Git 작업은 제외. 사용자는 프리팹을 직접 배치한다. 코드/자산 자동 검사와 실제 Play 관찰·수동 플레이를 분리한다.

완료 기준은 [테스트 및 검증 항목](테스트%20및%20검증%20항목.md), 실제 사용은 [배치 및 연결 가이드](배치%20및%20연결%20가이드.md) 참조.
