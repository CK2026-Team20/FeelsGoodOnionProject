# 코드 리뷰

2026-10-15 현재 실제 Editor와 저장본 기준이다.

## 추가
StageManager 빈 루트에 StageService 1개를 추가했다. initialCheckpoint는 기존 StageTriggerPoint를 연결했다. cameraBounds는 선택 사항으로 비워 두었다. 기존 객체나 prefab 원본은 편집하지 않았다.

## 씬별 책임 확인
Bootstrap Preview에서 AppComposition의 설치·옵션·페이드·오디오·출력 카메라 참조를 확인했다. TitleView의 NewGame/Quit/Settings가 연결됐다. Core Preview에서 CoreComposition의 actor/dialogueView/cinematic/entries/ui/cameraService가 연결됐다. CoreUiBinding의 HUD/Prompt/WorldCanvas/DialogueMount와 세 카메라 리그도 연결됐다. 이 객체를 Stage에 중복 배치하지 않는다.

## 기존 객체 오류 및 제한
|항목|실제 관측|영향 및 필요한 후속 조치|
|---|---|---|
|StageTriggerPoint 및 (1)~(5)|6개 모두 stage=null, BoxCollider.isTrigger=false|소속 StageManager 연결 및 Trigger 설정 필요. 이번에는 기존 객체 수정 금지로 보존|
|시작 StageTriggerPoint|music=null|StageService.RebuildRegistry는 첫 구간 음악을 필수 요구. 실제 AudioClip 선택·연결 필요|
|PlayerRoot|활성 ActorBody/PlayerFacade가 Stage에 배치됨|Core SessionActorHost가 별도 Player를 생성하므로 통합 실행 중 이중 Actor/입력 위험. 기존 객체 비활성/제거 여부 결정 필요|
|Camera|enabled=true, AudioListener 1개|Bootstrap 출력 카메라·Listener와 중복 가능. 기존 객체 처리 결정 필요|
|해금·최종 흐름|현재 StageTrigger 종류는 Checkpoint 5개와 Fall 1개. UnlockForm/UnlockTear/Chase/Escape 및 CameraZoneTrigger 없음|해금·추격·포포 Ending·구간 카메라 전환이 작성되지 않음. 위치·퇴로·대화 선택 등 레벨 의도가 필요하므로 임의로 기존 트리거 종류를 바꾸지 않음|

추가한 관리자의 initialCheckpoint 참조만으로 역방향 stage 참조가 채워지지 않는다. InitialPose 실제 조회는 기존 트리거의 소속/Trigger 누락으로 실패했다. 통합 플레이 가능 상태로 완료 처리하지 않는다.

## 관측 중 변동
ArchitectureInstallation.stageScenes[0]는 최초 디스크 조회에서 비어 있었으나 이후 실제 Editor와 디스크 모두 올바른 새 Stage 참조로 확인됐다. 이 작업에서 해당 자산을 수정하는 API는 실행하지 않았다. 현재 결함으로 단정하지 않는다.

검증 말미 현재 Stage의 isDirty=true가 관측됐다. 관리자 저장 직후 이후 변경의 원인은 확정하지 않았으며, 추가 저장·닫기·복원을 수행하지 않았다. 검증 결과는 관리자 추가를 저장한 파일을 Preview로 다시 읽은 기준이다.
