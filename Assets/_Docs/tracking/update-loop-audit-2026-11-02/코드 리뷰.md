# 프레임 루프 정리 코드 리뷰

## 책임과 변경 경계
고정 배치의 유효성은 Awake/Start/Prepare/재생 요청이 담당한다. 프레임 루프는 이동·접촉·시간 진행을 담당한다. 기존 상태 소유자를 유지했으며 전역 캐시나 새 추상화 계층은 도입하지 않았다.
InteractionPromptAnchor는 같은 루트의 상호작용 계약을 Awake에 저장한다. Runtime에서 해당 컴포넌트를 교체하는 계약은 없다. CanInteract는 파괴/비활성/앵커 소실을 계속 반영한다.
효과 소유자 등록은 CancelMotion에서 제거되므로 재시도 후 재등록 시 초기 검증을 다시 거친다.
상호작용 임시 컬렉션은 서비스 전용이며 외부 Changed 통지 전에 비운다. 종료 시에도 비운다.
Debug ViewModel은 View 참조를 새로 갖지 않는다. 기존 Changed/VisibilityChanged 연결을 유지하고 입력 F1 한 번의 열기에서 중복 Refresh를 제거했다.

## 유지한 검사와 남은 비용
- EnemyContactSensor의 ComputePenetration, PlatformContacts의 지지면 판정, 압력판의 Heavy/폼 확인은 실제 물리 상태다.
- LevelCameraService의 보정 중 경로 검사와 차단체의 BoxCast/Overlap은 동적 충돌을 막는 게임 동작이다.
- PlayerInteractionService의 OverlapSphere/RaycastAll 및 충돌 후보의 GetComponentInParent는 상호작용 대상/시야 판단에 필요하다. 이 물리 쿼리의 결과 배열 할당까지 0으로 만들었다고 주장하지 않는다.
- StageService의 전체 구간 검사와 SceneComponentLookup.IsFixedPoint는 초기화/체크포인트 수락/Retry/일부 Gizmo에서 남는다. 적 코드에서는 호출하지 않으며 수정한 두 발판의 정상 FixedUpdate 경로에서도 호출하지 않는다.
- ChaseRetreatGate의 플레이어 Collider 수집은 차단문 닫기 직전 실제 겹침 검사다. 레벨 전체 검색과 구별하여 유지했다.
- 유한 수치·정지·현재 Actor·피해 중복 방지는 실제 실행 조건이므로 일괄 제거하지 않았다.

## 보호 원본 발견 사항
- Tech_HMS/Occlusion/OcclusionFadeController.OnCamera: 0.5초마다 playerRoot.GetComponentsInChildren(true, playerRenderers)를 반복한다. 루트 변경뿐 아니라 타이머만 지나도 다시 수집하며 Player 미연결 시 태그 검색을 재시도한다. 이번 읽기에서 확인한 별도 계층 탐색 후보다. 캐시 갱신을 Actor/폼의 실제 renderer 구성 변경 시점에 연결할지 HMS 담당 검토가 필요하며 원본 수정은 하지 않았다.
- RealToon CustomShadowResolution.Update는 매 프레임 GetComponent<Light> 후 해상도를 쓴다. 같은 컴포넌트 조회 반복이지만 레벨 계층 탐색은 아니다. 보호 외부 코드로 유지했다.
- RealToon SmoothObjectNormalHelper, ShadowTSDFModeHelper, PerspectiveAdjustmentController는 매 프레임 shader 이름 분기 후 효과 파라미터를 쓴다. SmearEffectHelper는 위치 이력을 갱신한다. 두 FrameByFrameRendering 스크립트는 요청/구간 기반 화면 캡처다. 전체 자식 수집은 해당 helper의 초기화 경로이며 LateUpdate에서 매번 호출하지 않는다.
- 보호 코드의 실제 현재 씬 활성 여부와 비용은 이번 정적 감사만으로 단정하지 않는다.
