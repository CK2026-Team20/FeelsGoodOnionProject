## 원본 비교 결과

시스템 2안과 확정 1.1을 문단별 비교한 결과, 본문의 변경은 1.1 기본 조작·1.2 크기 전환·1.3 눈물 스킬에 집중되어 있으며 수정 이력이 추가되었다. 파란색은 재정의, 빨간색은 방향키/Q 키의 추후 QA 조정, 이동 속도·점프 높이 Inspector 설정, 카메라 전환 시간·눈물 범위/기절 시간 조정 요구다. 이것은 이번 두 파일을 비교한 결과이며 이후 버전이 동일하다는 주장으로 일반화하지 않는다.

1.4 이후의 이전 E/F 분리, 눈물 최대 1개, 눈물 길 열기, 적 추격/밟기, 복구형 붕괴, 만화 컷 설명이 확정본에도 남아 있다. 이번 직접 지시 또는 같은 확정본의 명시적 파란색 재정의에 의해 변경할 항목으로 기록한다. 제공된 기획서 자체를 편집하거나 새 확정 버전을 만들어 내지 않는다.

UI PDF 7쪽 모두 렌더해 확인했다. 2~4쪽은 흐름/화면 종류, 5쪽은 좌측 세로 게임시작·설정·종료와 타이틀/팀명, 6쪽은 세 음량 슬라이더와 우측 상단 X·종료 암전, 7쪽은 상단 HP 세 칸·눈물 0/5, 하단 좌측 스킬 안내와 게임 옵션이다. 메모·대화·컷신의 상세 배치 그림은 이 7쪽에 없다. 없는 시안을 문서에 있다고 주장하지 않는다.

레벨 PPTX는 14슬라이드의 텍스트·표·노트를 추출해 범위를 확인했다. 11~12슬라이드의 스테이지별 상세 구성은 작성 예정으로 남아 있다. 현재는 프로토타입 배치를 강제하지 않는 참고 자료이므로 실제 레벨의 완성된 상세 설계로 취급하지 않는다. 전체 슬라이드 렌더 검수는 하지 않았다.

## 2026-10-05 후속 답변으로 확정한 사항

1. 눈물 F / 상호작용 E / 형태 Q. 문서의 눈물 E와 기존 F 상호작용은 변경 대상이다.
2. 메모·옵션·대화/로그·컷신에서 월드를 정지하고 상시 HUD는 제외한다. UI 자체는 진행하며 옵션이 겹치면 대화·컷신 진행도 멈춘다. 대화 자체의 월드 정지를 옵션 정지로 오인해 자기 문장 진행까지 멈추는 순환 차단을 만들지 않는다. UI 타이머는 월드 시간과 분리하고 자신에게 적용되는 정지 이유만 관찰한다.
3. 프로토타입 스테이지는 새롭게 구성한다. 사용자가 이후 상세 레벨 디자인 기획서를 제공하므로 이번 배치를 본편의 최종 레벨로 고정하지 않는다.
4. 지정된 Bootstrapper·Title·Core·1_Stage·2_Stage·3_Stage에만 Editor 부트 진입점을 제공한다. 나머지 씬은 에디터에서 별도 Play 가능해야 한다.

## 후속 확인으로 해결한 자산·권한 경계

1. 사용자가 “새 씬을 첫 스테이지로 등록 (권장)”을 선택했다. 기존 `03_1_Stage.unity`를 보존하고 새 `Assets/_Scenes/Tech_SYM/Architecture/Prototype/1_Stage.unity`를 지정 여섯 씬의 첫 스테이지로 등록한다. 등록에서 빠진 기존 씬은 독립 Play 대상이다.
2. 사용자가 “껍질 회수키는 별도의 키가 지정되지 않습니다 특히 상태 전환에 의해 껍질이 자동 횟수 가능하므로 별도의 키를 지정하지 않도록 합니다 해당 규칙 변경 허용을 이번 세션에서만 일괄 적용합니다.”라고 답했다. 요청한 HMS `PlayerInputReader.cs`의 입력 규칙 및 `PlayerFormController.cs`의 상태 전환에 따른 회수/복귀 규칙 변경을 이번 세션의 예외로 기록한다. 별도 회수 입력은 만들지 않는다. 다른 HMS·공용·아트 파일의 포괄 수정 권한으로 확대하지 않는다.

## Editor 진입 요구의 실제 변경 지점

- `Foundation/Editor/BootstrapPlayModeHook.cs`의 `Arm`은 설치 자산 존재만으로 `EditorSceneManager.playModeStartScene`을 Bootstrap으로 지정한다. `ExitingEditMode`도 실제 활성 씬의 대상 여부를 확인하기 전에 통합 진입 설정을 적용한다. 따라서 매핑 함수만 바꾸면 비대상 씬이 여전히 Bootstrap으로 이동한다.
- `Foundation/BootstrapEntryRoute.cs`는 Stage/Core뿐 아니라 기존 `03_InGame`, `01_BrokenablePlatformTest`, `02_MultiFuncPlatformTest`까지 직접 게임 진입으로 매핑한다. 이 별칭들은 새 대상 집합에서 제외한다.
- 대상 여부는 정확한 자산 경로로 판정한다. 편집 중 활성 씬이 비대상이면 통합 진입을 예약하지 않고, 이 코드가 설정해 둔 Bootstrap 시작 씬과 임시 진입 옵션을 남기지 않는다. 다른 사용자 설정을 영구 변경하지 않는다.
- 지정 씬 내부의 기존 경로는 별도 변경 지시가 없으므로 유지한다. Bootstrap/Title은 제목, Core는 첫 스테이지, Stage는 해당 스테이지로 부트 경유 진입한다. 직접 스테이지 진입 시 오프닝 생략과 해당 진입 설정을 사용하는 기존 계약은 유지한다.
- 활성 씬 선택을 기준으로 진입 대상을 판정하고, 비활성으로 함께 열린 대상 씬만으로 독립 씬을 강제 전환하지 않는다. 대상/비대상 전환·컴파일 후 재등록·Play 취소·Stop에서 원래 Editor 씬 구성과 미저장 상태를 보존한다.
- `Integration/Editor/VerificationBatchService.cs`의 `Run All Eleven Editor Entries`는 11개 모두 통합 진입을 전제로 한다. 지정 여섯 씬의 양성 검사와 기존 테스트 씬/무관 씬의 비개입 검사로 기대값·명칭을 갱신한다. 비대상 씬의 자체 게임 로직을 새 통합 흐름으로 개조하는 작업은 요구하지 않는다.
- `IntegrationEntrySettings.cs`에는 `[Range(0,1)]`과 `fragments > 1` 거절이 있다. 눈물 조각 5개 변경 시 자산 값만 바꾸지 말고 이 SYM 경계의 검증과 직접 진입 테스트도 함께 갱신한다.
- `GameSessionRuntime.SpawnActorAtCheckpoint`에는 Stage 2 이름으로 깊이 이동을 설정하는 기존 경로가 있다. 새 트리거/체크포인트 기반 이동 모드와 이 경로가 충돌하지 않도록 통합 계획에 포함한다.
- 현재 `GameFlowService`는 등록된 Stage를 모두 추가 로드한다. 새 프로토타입의 활성 플레이 범위와 기존 Stage 2/3 보존을 동일 개념으로 취급하지 말고, 첫 스테이지 구성 결정 후 로드·레지스트리·재시도·빌드 목록을 일관되게 정한다.

그 외 확인된 직접 지시는 다시 승인을 묻지 않고 계획에 반영한다. 실제 모델/클립 연결 제외에 맞춰 누락 클립이 게임 진행을 잠그지 않는 기존 계약을 유지하며, 애니메이션이 없는 현재 프로토타입에 임의의 연출 길이를 필수 대기로 추가하지 않는다.
