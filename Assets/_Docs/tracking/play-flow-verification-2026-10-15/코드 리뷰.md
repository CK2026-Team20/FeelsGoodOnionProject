# 실제 Play 결함 수정 리뷰

2026-10-15. 최신 직접 지시로 Play 금지를 철회하고 공식 Unity 플러그인으로 현재 Editor를 실행했다. 기존 미커밋 변경을 보존했으며 아래는 이번 작업의 순변경이다.

1. `PlayerRoot.prefab`: 최상위뿐 아니라 ActorBody도 비활성이라 Host가 Root를 활성화해도 HMS Start/모드 준비가 실행되지 않았다. Root 비활성은 유지하고 ActorBody activeSelf만 true로 복원했다. 백업 대비 m_IsActive 한 줄 변경. Apply·삭제·재생성 없음.
2. `GameSessionRuntime` / `CoreWorldBinding` / `LevelCameraService` / `StageTrigger`: 체크포인트 저장 통지는 효과음만 호출했고 시점은 최초/복귀 연결에서만 적용됐다. 실제 CP8 접촉 후 저장은 CP8인데 이동 모드는 Side였다. 저장 성공 이벤트가 해당 StageTrigger를 전달하고 WorldBinding이 카메라 서비스에 요청하도록 변경했다. 현재 Stage/Actor/Flow를 검사하고 기존 전환의 자기 보정 소유권을 해제한 뒤 Cut으로 선택한다. Brain 완료 후 HMS 이동 모드 확정·입력 잠금 해제를 수행한다. 추격 직전 저장의 null 출처는 시점을 변경하지 않는다. Inspector 설명도 접촉·복귀 양쪽 의미로 정정했다.
3. `PlatformContacts`: 상승 시 적분 전 충돌점과 적분 후 캡슐을 비교하여 정상 접점이 거절됐다. 측정에서 radius=0.1m, 접점 거리=0.12867m, normal.y=1인데 거절됐다. 이전 지지 캡슐의 물리 스텝 시작 자세를 기록하여 해당 스텝 충돌점 판정에 사용한다. 다음 HMS 검사에는 같은 표면·캡슐·점·법선·유효 수명의 승인만 재사용한다. 각도/반지름을 확대하거나 플레이어 위치를 중복 작성하지 않는다. Reset/Disable은 두 캐시를 함께 해제한다.

저장 소유자는 Session, 카메라 소유자는 LevelCameraService, 플레이어 접지·속도 소유자는 HMS를 유지한다. CheckpointCaptured 소비자는 CoreWorldBinding 하나이고 Dispose에서 같은 핸들러를 해제한다. 관찰자 실패로 완료된 저장을 취소하지 않는 기존 계약을 유지한다. UI ViewModel·바인딩은 수정하지 않았다.

작업 전 SHA-256 대비 제품 변경은 위 SYM 소스5개와 PlayerRoot prefab1개뿐이다. 통합 씬/HMS/Packages/ProjectSettings 변화0. 기존 아트/공용 원본은 수정하지 않았다. 현재 Stage의 CameraZoneTrigger0개와 Small/Normal 충돌체 크기 역전은 별도 배치·밸런스 문제로 유지한다. 전체 동선/빌드 QA 완료를 뜻하지 않는다.
