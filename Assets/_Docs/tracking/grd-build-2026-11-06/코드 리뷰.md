# GRD 빌드 수정 리뷰

Core.hlsl → Input.hlsl → UnityInstancing.hlsl에서 DOTS 조건을 먼저 정의하고, 이후 Lighting.hlsl → EntityLighting.hlsl을 포함한다. 이에 배열 라이트맵 함수 선언과 호출이 같은 타입 분기를 사용한다.

공통 RT_URP_Core.hlsl에 include1줄과 설명2줄 추가, 파일 끝 개행. RealToon Default 및 HMS Generated Fade가 같은 코어를 사용하므로 각각 복제 수정하지 않는다. GBuffer 경로는 원래 GBufferCommon→Core가 선행하며 include guard가 중복을 막는다. 비-DOTS/legacy 조건 분기는 유지한다.

이전 임시 stripper는 GRD가 비활성인 상태만 허용하여 기존 GRD 구성에서 빌드를 막았다. 이를 삭제하여 사용자 GRD 설정을 유지한다. 이전 검증 중 임시값0을 프로젝트 기존 기준처럼 설명한 것은 정정한다. HEAD에서 이미 GRD1이다.

독립 읽기 전용 검토: 타입 선언 순서 및 양쪽 셰이더 소비, 비-DOTS 경로, stripper삭제, GRD1/APV1을 확인했고 구체적 블로커 없음. 실제 빌드 결과는 정적 검토와 별도로 판정한다.

## 원본 수정 경계에 대한 후속 확인

사용자가 RealToonCore 직접 수정을 지적했다. Core.hlsl은 원래 DeclareDepthTexture.hlsl에서 간접 포함되지만 Lighting보다 늦었다. 이번 한 줄은 포함 순서를 앞당기는 수정이며 새 계산 기능 추가가 아니다. 기술적인 필요와 보호 원본 수정 허용 여부는 구분한다. 이 직접 수정을 승인된 최종 결과로 확정하지 않았다. 현재 진행 중인 빌드는 해당 변경의 검증 결과로만 기록한다.
