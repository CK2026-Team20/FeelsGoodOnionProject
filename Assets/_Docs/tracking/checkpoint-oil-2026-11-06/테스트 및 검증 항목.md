## 깃발 바닥 VFXS 앵커

사용자 지시로 CP_Variant의 Visuals/bg_checkpoint 아래 Transform만 가진 VFXS를 추가하고 기존 ActivationVFX를 그 하위로 이동했다. 원본 메시 정점의 최하단 2mm 범위(18정점)의 XZ 범위 중심과 최저 Y를 바닥 접촉 앵커로 사용한다. 이 계산은 제작 시 1회이며 런타임 자동 bounds/레이캐스트 보정은 없다. VFXS가 깃발의 자식이므로 씬별 깃발 위치 오버라이드를 따라간다. VFXS 방향은 프리팹 Root 기준으로 맞추고 이펙트 자체의 기존 회전·배율을 유지했다. 메시 피벗·텍스처·원본 VFX·트리거·SpawnAnchor는 수정하지 않았다.

튜토리얼 저장본을 다시 열어 6개 인스턴스의 바닥 중심과 VFXS 위치 오차가 0.000004m 미만임을 확인했다. 기존 -0.8/-0.5 깃발 Z 오프셋, 개별 SpawnAnchor Y, Collider size(0.1,5,10)/center(0,0,0)를 유지한다. effect 참조와 부모 연결 정상, Missing Script 0개. Editor 파티클 0.2초 시뮬레이션 3개 확인. 이번 계층 변경 후 Play는 실행하지 않았다. 메시가 교체되거나 변형되면 VFXS를 새 받침 바닥에 다시 맞춘다. 이 앵커는 메시 받침 기준이며 지형 자동 스냅은 수행하지 않는다.

## SpawnAnchor 중복 제거 대상 정정

사용자 의도는 CP_Variant에서 직접 정의한 SpawnAnchor를 유지하고, 이전 StageTriggerPoint에서 씬 인스턴스의 Added GameObject Override로 남은 앵커만 제거하는 것이다. 앞선 전체 삭제는 잘못된 해석이었다. 복원 완료 상태에서 다시 조사한 결과 Tutorial 6개 각각 SpawnAnchor 이름 오브젝트/CheckpointSpawnPoint가 1개이며 모두 CP_Variant 원본 연결이 있고 Added GameObject Override=false다. StageTrigger는 각각 이 프리팹 소속 앵커를 참조한다. 이전 추가 앵커는 이미 삭제되어 추가 삭제 없이 유지한다. VFXS는 이펙트 앵커로 별도 유지한다.


## 스폰 충돌 검사 Edit Mode 전용 보완

저장/리스폰 자체는 이미 충돌 검사 없이 좌표를 사용했으나 LevelCameraService.EnterSection과 FixedUpdate의 구간 진입 보정에는 IsCorrectionPathSafe 및 HasSupport가 남아 있었다. 해당 목적지/이동 경로/지지면 런타임 검사를 제거하여 지정 앵커로 보정한다. 차단 장치 자체의 이동 경로 검사는 별도 기능으로 유지한다. SpawnPlacement.Check, CheckpointSpawnPoint.CanPlace, StageAuthoringDiagnostics.Inspect는 Play 중 물리 질의를 실행하지 않도록 명시적으로 차단했다. 에디터에서는 기존 파랑=배치 가능/빨강=겹침·지면 없음 표시, 플레이어 캡슐 크기 와이어 및 원인 문구를 유지한다. 일반 플레이 Rigidbody 충돌/중력은 유지하므로 앵커가 실제 벽/바닥 내부이면 배치 이후 물리 밀림까지 방지하는 변경은 아니다.

CheckpointSpawnChecks Editor API 검사 17통과/0실패. 실제 Play 진입 보정/사망 리스폰은 이번 변경 후 실행하지 않았다. 앞선 격리 Play 결과를 이번 수정의 Play 통과로 승계하지 않는다.
