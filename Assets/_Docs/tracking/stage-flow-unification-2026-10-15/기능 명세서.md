# 스테이지 흐름·카메라·프리팹 작성 명세

2026-10-15~16 사용자 직접 요구. 대상은 기존 01_Stage_Prototype과 소유 SYM 구현·프리팹이다. 시스템 원본 V1.6의 변경되지 않은 규칙은 유지한다. 구현·실행 판정은 같은 폴더의 코드 리뷰와 테스트 및 검증 항목으로 구분한다.

## 구간과 상태 소유권

StageService가 논리 구간 목록, 첫 구간, 현재 구간, 소비한 체크포인트 집합, 마지막 CheckpointSnapshot과 복귀 구간을 소유한다. 구간은 같은 씬의 서로 다른 시작·끝 StageTrigger, 시점 종류, 실제 음악 Clip·음량·fade 시간, 플레이어 보정 시간·카메라 전환 시간을 참조한다. 통로도 구간이다. 편집 이름·배열 순번은 저장 키가 아니며 새 체크포인트를 반드시 다음 순번으로만 제한하지 않는다.

StageTrigger는 현재 살아 있는 Actor와 센서의 접촉을 검증해 서비스에 요청한다. Trigger가 시점·음악·SafeAnchor·Alignment·저장 장부를 중복 소유하지 않는다. 처음 수락하는 시작·끝 모두 접촉 순간의 세 값과 소비 이력을 콜백 전에 확정한다. 이미 사용한 체크포인트는 역주행·재방문·Disable/Enable·사망·Actor 교체·Retry·표현 취소에도 재발동하지 않는다. 새 게임의 새 Stage에서는 새 이력을 사용한다.

## 저장과 복귀

| 값 | 의미 |
|---|---|
| Position | 접촉한 체크포인트 Transform의 유한 월드 위치. 플레이어 CapsuleCollider 중심 기준 |
| Fragments | 접촉 순간 보유 조각 정수0..5 |
| UnlockedAbilities | None0 / FormChange1 / Tear2 / Both3 |

HP·폼·껍질·카메라·음악·시간·월드 상태는 payload에 추가하지 않는다. 체크포인트와 당시 활성 구간 참조는 StageService의 복귀 맥락이다. 첫 저장 전에는 첫 구간 시작과 Entry 초기 값을 사용한다. 추격 직전 저장만 기존대로 현재 플레이어 Capsule 중심을 사용한다.

수락 전 검증 실패는 이전 저장을 유지한다. 수락 후 사망·취소는 이미 저장한 스냅샷과 소비 이력을 유지한다. Retry는 같은 Core/Stage에서 새 Normal·HP3 Actor에 세 값을 복원하고 구간·시점·음악을 직접 준비한다. 소비된 트리거를 재무장하지 않는다. Title에서는 세션 종료 후 Stage 전체와 Core를 언로드한다.

## 시작·끝·카메라

새 시작마다 플레이어 Capsule 중심을 정확한 시작 위치로 DOMove 보정한다. 끝은 저장만 한다. 다음 새 시작을 만나기 전까지 구간 시점을 유지한다. 같은 시점이 연속되면 카메라 재선택·blend만 생략하고 구간·보정·저장·음악 요청은 진행한다. 새 요청은 이전 전환을 취소하며 낡은 callback은 현재 구간·축·저장 상태를 바꾸지 않는다. 사망·취소·Actor 해제 시 자기 보정·트윈·입력 제한만 반환한다.

StageService의 세 공통 구도에서 피사체 중심 반경, 수평각·수직각·Z롤, 시선 오프셋, 화면 위치·감쇠·시야각을 편집한다. 별도 Zone 센서·SafeAnchor·정렬 피벗과 카메라 위치 바운더리·Confiner를 제거한다. 플레이어 CameraAnchor는 추적 중심으로 유지한다. Side는 X 이동, Corridor/Quarter는 XZ 이동이다. 같은 Clip 요청은 음악 재생을 다시 시작하지 않는다.

## 레벨 작성

1. 시작·끝 Transform을 고정 위치에 놓고 StageService 구간에서 연결한다. 같은 트리거를 두 구간에 배정하지 않는다.
2. 센서 BoxCollider의 Center/Size로 진입 범위를 조절한다. 저장 Transform과 센서 중심은 서로 다른 역할이다. 점프·Small과 실제 지지면의 접촉 범위를 확인한다.
3. 구간의 시점과 음악·보정 시간을 선택하고 세 공통 카메라 구도를 조절한다. 미리보기와 실제 프레임에서 결과를 확인한다.
4. 플레이어 보정은 현재 폼의 Capsule 중심을 사용한다. 완료 순간과 이후 중력에 의한 접지 낙하를 혼동하지 않는다.

뒷면 메시를 생략한 아트는 카메라에서 뒷면이 보이지 않도록 배치해야 한다. 사용자는 반대편 카메라 이동 요청과 HMS 입력 변환을 철회했다. 기존 방향을 유지하며 사용자 배치 회전을 에이전트 완료 작업으로 취급하지 않는다. 현재 백페이스 노출은 해결 완료가 아니다.

## 프리팹과 밸런스

버튼은 빈 Root 아래 움직이는 Cap Rigidbody·충돌체·Visual과 고정 Body 충돌체·Visual을 분리한다. 캡의 장식 기둥은 지지 hull에서 제외하고 렌더링은 유지한다. 참조 없는 빈 SupportCollider만 삭제하며 선택형·실제 센서는 보존한다. 고정 Start/End는 움직이는 발판 몸체 밖에 둔다. 기존 물리 계약을 빈 Root 예시만으로 임의 재작성하지 않는다.

현재 PlayerRoot 모드 속도1.8m/s, 정상/Small 점프 설정1/.5m, 중력12m/s², Normal Capsule 높이.23m·반경.1m와 Small 높이.115m·반경.05m를 사용한다. 실제 Renderer 높이는 애니메이션 자세에 따라 다르다. Stage의 Linear6개는.6m/s다. 이 값은 조절 가능한 현재 배치 수치이며 다른 레벨의 고정 목표값이 아니다.

## 완료 판정 경계

실제 Editor Play의 입력·물리·UI·수명 결과로 검증한다. API 위치 준비, 합성 Keyboard가 기존 Reader를 통과한 동선, 사람의 직접 조작, 빌드·Player 실행은 구분한다. 미저장 편집을 자동 저장·버림하지 않으며 최종 clean 상태를 위해 원복하지 않는다. HMS·아트·Packages·ProjectSettings 원본 수정이나 Git 작업은 이번 범위에 포함하지 않는다.
