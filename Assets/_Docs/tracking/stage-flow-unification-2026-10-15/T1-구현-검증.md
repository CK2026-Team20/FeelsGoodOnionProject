# T1 구간 소유권·접촉·복귀 구현 결과

2026-10-15. 범위: 승인된 T1(R1/R2/R3/R4/R8의 소스 통합). 기존 feature/core/prototype 체크아웃에서 미커밋 상태를 보존했다. Git 변경 명령과 씬/prefab/HMS/_Art/Packages/ProjectSettings 수정은 수행하지 않았다.

## 기능 명세와 구현

StageService가 구간 배열, 첫 구간 참조, 현재 구간, 소비된 체크포인트 집합, 마지막 CheckpointSnapshot 및 체크포인트·구간 실행 맥락을 소유한다. 수락 시 세 값과 이력을 콜백 전에 확정한다. 끝 접촉은 저장만 하며 현재 구간을 바꾸지 않는다. 목록 순서와 관계없이 새 체크포인트를 수락한다. 재시도·Actor 교체·Disable/Enable·표현 실패는 이력을 비우지 않는다.

StageTrigger 체크포인트 경로는 현재 Actor의 활성 Capsule과 실제 센서 ComputePenetration을 확인하고 StageService로 전달한다. 기존 Fall, Chase, 해금, 일반 대화, 최종 Escape 경로는 유지한다. CameraZoneTrigger 접촉 함수는 비활성화했고 CoreWorldBinding의 Zone 바인딩·포함 검색을 제거했다.

GameSessionService는 초기 Entry 설정과 현재 능력 상태만 유지한다. 저장 payload 원본과 Capture/RestoreCheckpoint API를 제거했다. GameSessionRuntime은 StageService.ResolveRestore로 payload를 받아 Session.RestoreAbilities 후 기존 Host.Spawn으로 Capsule 중심을 복원한다. 추격 직전 현재 Capsule 중심 저장도 StageService를 거친다.

LevelCameraService.EnterSection은 StageService 선택만 표현한다. 모든 새 시작은 실제 Rigidbody DOMove로 Capsule 중심을 정확한 시작 위치에 보정한다. 같은 시점은 카메라 재선택/blend 재설정을 생략한다. 새 시작은 진행 중 작업을 취소하고 최신 요청으로 교체한다. 보정 경로·목표 침투, 현재 크기의 지지면, 선택 차단체 경로를 검사한다. 차단체는 플레이어 보정 후 이동한다. 사망/Actor/Stage 해제는 자기 트윈·보정 소유권·입력 lease를 반환한다. 수락 후 표현 실패는 소비 이력과 스냅샷을 유지한다.

## T2 공개 API

StageService:
- Sections: IReadOnlyList<StageService.Section>
- FirstSection / CurrentSection / RestoreSection: Section
- InitialCheckpoint / ActiveCheckpoint: StageTrigger. ActiveCheckpoint는 마지막 접촉 참조이며 추격 예외 저장 시 변경하지 않는다.
- HasCheckpoint / Checkpoint / ActivatedCheckpointCount / IsActivated(StageTrigger)
- ValidateSections()
- ResolveRestore(CheckpointSnapshot initial): 마지막 payload 또는 첫 시작 위치+Entry 조각/능력 반환. 현재 구간을 저장 당시 맥락으로 직접 복원.
- BindSectionPresentation(Action<Section,bool> enter, Action<AudioClip,float,float> music). bool=true는 초기 등장/복귀의 직접 구도 준비.
- RestorePresentation()
- CheckpointCaptured 이벤트: Stage가 이미 수락한 접촉에 대한 SFX 관찰 경계.
- TryCaptureBeforeChase(PlayerFacade)
- ViewFor(CameraMovementMode): 현재 LevelCameraService.ViewSettings 타입의 Stage 소유 설정.

Section은 StageService 내부 [Serializable] 데이터다. 읽기 API는 DisplayName, Start, End, View, Music, MusicGain, MusicTransitionSeconds, CorrectionSeconds, TransitionSeconds, BlockerBody, BlockerGoal, BlockerSeconds다. 참조/설정은 private SerializeField로 Inspector에서 작성한다. 외부 진행 상태 setter는 없다.

LevelCameraService:
- EnterSection(StageService.Section section, bool restore): 현재 Stage가 선택한 구간만 수락.
- State / IsTransitioning / IsViewReady / TransitionFailure는 표현 실행 결과다.
- ViewSettings를 public으로 바꾸고 StageService가 sideView/corridorView/quarterView를 소유한다. T2에서 orbit 모델로 확장할 때 이 타입과 ViewFor/Settings 소비를 함께 수정하면 된다.
- 기존 EnterCheckpoint/EnterZone 실행 경로는 제거했다. TryEnterZone은 false를 반환하며 legacy 접촉을 실행하지 않는다.

IGameSessionService/GameSessionService:
- RestoreAbilities(CheckpointSnapshot)만 복귀 시 현재 능력을 변경한다.
- HasCheckpoint, Checkpoint, TryGetCheckpoint, CaptureCheckpoint, RestoreCheckpoint는 세션 계약에서 제거했다.
- CheckpointSnapshot payload는 Position/Fragments/UnlockedAbilities 정확히 세 속성으로 유지했다.

## T4 직렬화 이관 경계

새 StageService 작성 필드:
- sections 배열과 firstSectionStart(첫 구간의 Start 실물 참조)
- 각 section: displayName/start/end/view/music/musicGain/musicTransitionSeconds/correctionSeconds/transitionSeconds/blockerBody/blockerTarget/blockerSeconds
- StageService.sideView/corridorView/quarterView

보존한 legacy 데이터:
- StageService.initialCheckpoint: HideInInspector, 런타임 선택에서 사용하지 않음.
- StageTrigger.checkpointView: HideInInspector, 런타임 사용 없음.
- StageTrigger.music/musicGain/musicTransitionSeconds: 숨겨진 이관 자료만 유지한다. 독립 Kind.Music(8)의 접촉·공개 접근자·Inspector·콜백 경로는 검토 후 제거했다. 전체 Assets의 씬/prefab/asset에서 Kind.Music 직렬화 소비는 0이었다. T4 음악 이관 후 필드를 제거한다.
- LevelCameraService.sideView/corridorView/quarterView: HideInInspector, 이전 작성값 보관. 런타임 Settings는 StageService.ViewFor를 사용.
- CameraZoneTrigger 전체 기존 컴포넌트/GUID/직렬화 필드는 유지. Core 연결과 Contact 실행은 제거. T4가 mode/transitionSeconds/playerMoveSeconds/blockerBody/blockerTarget/blockerMoveSeconds 등을 새 Section에 이관한 뒤 참조 검수와 함께 컴포넌트를 제거한다. alignmentPoint/safeAnchor는 새 런타임에서 사용하지 않는다.
- StageService.cameraBounds와 LevelCameraService의 기존 bounds/Confiner/ClosestPoint 표현은 T2의 명시적 제거 범위로 남겼다. T1에서 자산/구도 경계 변경을 확대하지 않았다.

기존 Stage 자산에는 sections/firstSectionStart가 아직 없다. ValidateSections/FirstSection은 T4 이관 필요 오류를 발생시킨다. legacy 필드에서 자동으로 구간을 추측하는 병행 정책은 구현하지 않았다. 따라서 이 상태의 제품 NewGame 통합 플레이를 완료로 간주하면 안 된다. T4는 기존 사용자 구도 수치를 새 Stage 필드로 옮겨 기본값으로 덮이지 않게 해야 한다.

## 코드 리뷰와 반환 상태

진행 상태는 StageService 한 곳에서 수락하며, 표현 실패를 저장 실패로 되돌리지 않는다. 세션 변경 통지/카메라 접촉으로 저장을 재발행하는 경로를 제거했다. 기존 소스 GUID와 제품 자산을 유지했다.

독립 명세 검토는 최초 diff에서 독립 음악 경로와 작성 진단 누락을 지적했다. 음악 경로 수정 후 공식 recompile/recompile_status 오류0 및 Green.cs 26/26을 다시 확인했다. 후속 변경은 t1/review-music에 보존했다. 독립 검토자는 최초 diff와 후속 diff를 합산하여 T1 런타임 경계 pass를 반환했다. 센서 겹침·보정 경로·지지면 작성 진단은 T2 편집 화면 구현과 검증으로 추적한다. 이 결과는 T2 이후나 제품 QA 완료를 의미하지 않는다. t1/final-status.json의 소스 해시는 최초 구현 반환 시점 자료이며 후속 음악 수정 전이다.
