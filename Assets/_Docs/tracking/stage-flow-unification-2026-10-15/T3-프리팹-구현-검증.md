# T3 프리팹 구현·코드 리뷰·검증

2026-10-15. 범위: 승인된 `.dryforge/plan.md` T3, R6/R7/R8. T2 PASS 이후 현재 checkout에서 실행했다. 기존 dirty 상태를 보존했고 Git 작업은 하지 않았다. 이 문서는 T3 자동 기능 검사 결과이며 독립 리뷰 PASS 또는 T4 이후 제품 통합 QA 완료를 뜻하지 않는다.

## 결과와 변경 경계

제품 변경을 동결했다. 기존 파일 10개(코드 1, prefab 9)를 수정하고 소유 충돌 Mesh 2개와 Unity 생성 meta 2개를 추가했다. 기존 prefab GUID/meta는 모두 유지했다. Stage/Core를 포함한 씬 파일 저장은 하지 않았다.

- `PressurePlatePlatform.cs`: 눌림 벡터를 이동 몸체의 **고정 부모** 로컬 -Y에서 월드로 변환한다. 기본/버튼 직렬화 깊이는 0.08m(배율1 기준), 전체 눌림 시간은 기존 3초다. 배율0.5이면 0.04m, (1.4,0.6,0.8)이면 0.048m다. Tooltip에 단위와 좌표계를 명시했다.
- `Button.prefab`: 빈 기능 Root 아래 Cap(Rigidbody + PlatformContacts + Convex MeshCollider + Visuals)과 Body(고정 non-convex MeshCollider + 기존 body Visuals)를 분리했다. 실제 압력은 Cap의 지지면 접촉에서만 나온다.
- `ButtonPlatforms.prefab`: 압력 이동자는 Button/Cap Rigidbody, 연동 이동자는 기존 유일 활성 CuttingBoard_L Rigidbody를 명시적으로 참조한다. 다른 선택형과 시작/목표 앵커는 유지했다.
- `CuttingBoard_L/S`, `Lock&LockOblong/Square`, `Button`: Collider/Rigidbody/자식이 없고 surfaces가 비어 있는 PlatformContacts 전용 빈 SupportCollider 자식 5개 원본을 제거했다. 중첩 포함 26개가 사라졌다. 실제 표면·피해 센서는 삭제하지 않았다.
- `DamageablePlatforms.prefab`: Pot의 null 피해 참조를 해당 nested Pot에 이미 존재하는 Box Trigger 2개로 연결했다. root와 Burner/Pot/Gratan 선택형은 보존했다.
- `LinearPlatforms.prefab`, `FloatingPlatforms.prefab`: 모든 선택형 비활성 + physicsBody=null인 신규 배치 결함을 수정했다. CuttingBoard_S를 기본 활성 몸체로 선택하여 연결하고 다른 네 형상은 비활성으로 보존했다. 현재 Stage의 Linear 6개가 모두 이 형상을 쓰는 것을 읽기 전용으로 확인했다. Floating은 Stage 사용 인스턴스가 없어 같은 계열의 정상 배치 기본형을 선택했다.

## 코드 리뷰

압력 판단, 시간 진행, 중간 해제/재입력, HeavyState와 정상/소형·껍질 구분은 기존 코드를 유지했다. 변경은 위치 목표 계산 경계에 한정했다. 움직이는 cap Transform 위치를 다음 기준으로 누적하지 않고 KinematicPlatformMotion.RestPosition과 고정 부모 TransformVector를 사용한다. 따라서 비균일 배율을 반영하면서 누적 위치 오차를 만들지 않는다. 실제 Rigidbody 작성자는 여전히 KinematicPlatformMotion 한 개다.

KinematicPlatformMotion, PlatformContacts, PressureLinkedPlatform, LinearShuttlePlatform, FloatingPlatform, DamageFloorPlatform 소스는 작업 시작 해시와 동일하다. 기존 아래 반구/접지각·물리 단계 접점 캐시·탑승자 속도 전달 개선을 보존했다. HMS는 수정하지 않았다.

공개 API를 추가하거나 변경하지 않았다. 기존 직렬화 필드 `pressDepth`의 의미만 월드Y 거리에서 **실제 이동 몸체 부모 기준 로컬 거리**로 바뀌었다. T4/T5가 과거 씬 override 값을 검토할 때 이를 적용해야 한다. 저장된 0.2 override가 있다면 자동으로 0.08로 바뀌지 않는다. 별도 중복 설정, 새로운 Bind 계층, fallback 정책은 추가하지 않았다.

## 충돌 메시와 시각 판정

처음 cap 전체를 Convex로 만들었을 때 숨은 기둥까지 hull에 포함되어 body와 겹쳤다. `green-initial.json`의 기존 39개 체크는 승객–고정 body만 검사했으므로 그 통과 수를 cap/body 침투 통과로 해석하면 안 된다. 당시 maxBodyPen은 배율1/0.5/비균일에서 각각 0.07910078/0.03955039/0.04746046m였다. 이 기록은 삭제하지 않았다.

최종 소유 `Button_Cap.asset`는 원본 cap의 실제 상부 형상(로컬 Y 0.16965..0.22605)을 복사한 90 triangle 메시이며 Convex hull이 하단을 닫는다. 내부로 슬라이딩하는 기둥은 렌더링에 그대로 남고 cap 지지 충돌체에서는 제외했다. `Button_Body.asset`는 기존 body 형상을 복사한 고정 non-convex 충돌 메시다. _Art 메시/머테리얼/import는 수정하지 않았다. 기존 Button_Root 충돌 자산은 이번 삭제 범위가 아니므로 보존했으며 새 Button에서는 소비하지 않는다.

최종 검사에서 cap–body와 승객(플레이어/껍질)–고정 body 침투를 **별도 체크**로 판정했다. 세 배율 모두 측정 최대값 0m다. 비균일 배율 실제 눌림 화면에서 cap 윗면 0.08763077m, body 윗면 0.01735144m, 차이 0.07027933m다. 윗캡은 body 위에 보이고 고정 body는 움직이지 않으며 해제 후 원상 복귀한다.

화면: `visual-nonuniform-released.png`, `visual-nonuniform-pressed.png`, `visual-nonuniform-restored.png`. 이는 runtime fixture 카메라와 실제 제품 아트이며 최종 Stage 카메라/백페이스 전체 QA는 아니다.

## 피해 root 유지 근거와 Pot 수정

`damage-scene-consumers.json`은 Unity OpenPreviewScene으로 실제 Stage의 직렬화 참조를 읽은 결과다. `DamageablePlatforms (8)`의 **root DamageFloorPlatform**에 Gratan/SupportCollider와 Gratan/SupportCollider (1) 두 활성 Trigger를 연결하는 씬 override가 있다. root를 삭제하면 이 소비가 끊기므로 유지한다.

원본 root의 기본 배열은 비어 있어 다른 빈 인스턴스에서는 no-op이다. 이를 기능 보유의 추정 근거로 삼지 않았다. 실제 Gratan 소비가 유지 이유다. Burner와 Pot은 자기 자식의 별도 센서를 소비하므로 해당 root와 같은 영역을 중복 수락하는 구조가 아니다. ButtonPlatforms/ShatterdPlatforms의 root 제거 override도 확인했다.

nested Pot은 원본 Pot의 Mesh Trigger와 달리 기존 두 Box Trigger를 가진 변형이었지만 damageTriggers[0]이 null이었다. 현재 두 실제 Box를 연결했고, 실제 PhysX 접촉 smoke에서 HP 3→2를 관측했다. 같은 위치의 두 Box는 기존 작성 형상이며 삭제하지 않았다. DamageFloorPlatform의 기존 물리 단계당 중복 제한 코드는 바꾸지 않았다.

## 65개 감사와 보존 판단

`native-before.json` / `native-after.json`은 모든 비활성 자식까지 포함한 컴포넌트·Transform·직렬화 참조 구조다. `native-structure.diff.json`은 세션 종속 native EntityId를 제외한 구조 차이다. 직접 수정 prefab9개와 중첩 전파를 포함해 구조 영향 asset은11개다. `prefab-audit-final.json`은 65개별 GUID, 의존 자산, 실제 구성 타입, 비활성 선택형, Collider 소유 계층, 명시 접촉면, 이동/피해 연결과 유지·수정 이유를 기록한다.

- 플랫폼의 실제 고체 지지면 PlatformContacts는 일반 접지 필터/운반/착지 소비가 있으므로 유지했다. 이름이 SupportCollider인 실제 센서까지 일괄 삭제하지 않았다.
- 바닥의 Rigidbody 없는 static Collider는 이동 몸체 유효성 검사 대상과 다르며 유지했다.
- 플레이어/HMS와 계단·오븐 등의 기존 물리 계약은 실제 컴포넌트 귀속을 보존했다. 예시 빈 Root 규칙만으로 다른 Rigidbody를 이동하지 않았다.
- 선택형 비활성 형상과 독립 기능/시스템/UI/원경 prefab은 현재 씬에 없다는 이유로 삭제하지 않았다.
- CoreLevelCamera의 legacy Confiner 등 T4 이관 대상은 T3에서 제거하지 않았다.
- PreviewScene 또는 비활성 객체의 attachedRigidbody가 null인 관측은 runtime 결함 판정으로 사용하지 않았다. 정적 귀속은 실제 조상 Rigidbody/명시 표면으로 확인하고, runtime 귀속은 실행한 fixture 범위에서만 통과로 기록했다.

빈 Support 삭제는 이번 실행에서 새로 조회한 컴포넌트 계약으로 대상을 찾았다. 이전 이름 변수에 의존하지 않았다. 26개 중첩의 컴포넌트/GameObject/Transform ID를 Assets의 prefab/unity/asset/anim 전체에서 다시 검색해 잔존 참조0을 확인했다. 기존 사전 감사의 코드·애니메이션 미소비 근거와 함께 보존한다. 기능상 필요한 Burner/Pot 센서는 삭제 후보에서 제외했다.

## 보호·검토 자료·T4 인계

시작 기준 1,710파일 SHA-256을 저장했다. _Art660, HMS98, Packages2, ProjectSettings29, 씬397파일 모두 변경0이다. 기존 prefab meta 변경0이다. 보호 원본 비교는 `protection.json`, 기존 파일 전후 해시는 `changed-hashes.json`, 추가 파일을 포함한 최종 동결 해시는 `frozen-manifest.json`을 따른다.

원본 prefab 복사본은 `before/Assets/_Prefabs/`, 코드 전후는 `PressurePlatePlatform.before.cs`와 `after/Assets/_Code/.../PressurePlatePlatform.cs`에 있다. 수정 원시 코드/실행 스크립트는 `Migrate.cs`, `CapCollisionFix.raw.cs`, `MovingMigration.raw.cs`, `Physics.cs`, `PhysicsFinal.cs`, `VisualAndPot.cs`, `MovingPhysics.cs`, `Audit.cs`, `FinalAudit.cs`다. mutation 스크립트는 일회 실행 증거이며 재실행용 idempotent 도구로 제공하지 않는다.

T4는 새 Button/Cap 이동 몸체 및 고정 Body 구조, pressDepth 로컬 의미와 과거 씬 override를 확인한다. Linear/Floating 새 기본형은 CuttingBoard_S이며 다른 형상을 선택할 때 활성 선택형과 physicsBody를 함께 연결한다. 실제 Stage Gratan root 피해 override는 유지한다. Stage/Core 자산 이관·관련 legacy API 제거는 T4 범위로 남겼다.

최종 상태는 `final-status.json`에서 확인한다. 원래 01_Stage_Prototype을 stopped/clean 상태로 열어 반환한다. 독립 리뷰는 부모가 수행하며 이 문서는 자체 구현/검증 근거다.
