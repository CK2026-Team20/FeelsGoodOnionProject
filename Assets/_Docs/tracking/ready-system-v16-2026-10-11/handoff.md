# V1.6 전수 리팩터링 실행 인계

2026-10-11. 문서 검토 후 실행하는 준비 결과다. 제품 코드·씬 이관·push·PR 갱신은 별도 실행 단계다.

## 문서 역할과 위치

| 문서 | 역할 |
|---|---|
| `.dryforge/handoff.md` | 실행 경계와 인계 |
| `.dryforge/spec.md` | 확정할 동작·권한·완료 기준 |
| `.dryforge/plan.md` | 작업 대상·검증·순서와 의존 관계 |
| `Assets/_Docs/tracking/ready-system-v16-2026-10-11/handoff.md` | 공유용 동일 인계 사본 |
| 같은 폴더 `spec.md`, `plan.md` | 공유용 동일 실행 명세/계획 |
| 같은 폴더 `코드 리뷰.md`, `카메라 검토.md`, `전수 검수 대상.md`, `테스트 및 검증 항목.md` | 원본 조사·실제 결과와 미실행 범위 |

활성 세 문서와 공유 사본은 각각 바이트 일치시킨다. `.dryforge/`는 기존 ignore 상태를 유지하며 `.gitignore`를 바꾸지 않는다. 최종 공유 문서는 Assets/_Docs에서 커밋한다. `.dryforge/status.json`의 기존 initialized와 001/002 보관본은 유지한다. 새 프로젝트 기초 설계를 재생성하지 않는다.

최신 사용자 직접 지시→spec의 동작 기준→plan 순서로 따른다. plan은 HOW와 순서이며 spec의 WHAT을 바꾸지 않는다. 제품 동작·권한 변경은 사용자와 해결하고 계획 내부 조정은 근거를 남겨 의존 관계를 재검증한다. 이전 코드/문서는 참고 자료이며 V1.6 또는 후속 직접 결정을 덮지 못한다.

## 현재 시작점

- 브랜치 `feature/core/systems`, 조사 시작 HEAD `8663958`. 시작 미커밋은 Prototype/1_Stage 씬과 한글 SDF 폰트다. 준비 과정에서 V1.6 원본·문서/지침을 추가·갱신했다. 실행 시 최신 diff로 재확인한다.
- 기존 원격 초안 PR #26: `https://github.com/CK2026-Team20/FeelsGoodOnionProject/pull/26`. 새 중복 PR을 만들지 않는다.
- SYM104개는 목록 확보 상태이며 전부 최종 검수했다고 주장하지 않는다. 네 씬의 중첩 프리팹은 native 확장 확인이 필요하다. 월드 루트 외부 목표점16개가 확인됐다.
- 현재 Unity Play/Player를 실행하지 않았다. 준비 문서의 정적 발견과 과거 Play/빌드 증거를 혼합하지 않는다.

## 실행 형태

전체 검수→공통 앱/한 판 수명 통합→화면/지역 기능/세 시점·통로 차단→HMS 최소화→실제 씬 참조 이관→비 Play 검증/문서→한국어 커밋·push·PR 갱신의 9작업이다. 공통 조립·계약 연결과 Unity 자산 쓰기는 단일 담당이 직렬 실행한다. 같은 의미의 상태 writer가 늘어나면 통합 목적에 어긋난다.

## 넘지 않을 경계

1. 실제 실행 전에 사용자 검토를 받는다. `ready`는 문서 준비이고 구현 실행은 `go` 단계다. 후속 push·PR까지의 요청은 실행 계획에 이미 포함하며 같은 권한을 반복 확인하지 않는다.
2. 수정 owner는 Tech_SYM. 보호 HMS는 spec의 정확한12파일 누적 변경 최소화 범위만이다. 목록 밖 원본/meta/import/_Art/공용/Packages/ProjectSettings의 수동 변경을 확대하지 않는다.
3. Editor Play·PlayMode API/CLI/pipeline/batch·Player 실행 금지. 실제 비 Play 검사만 수행하며 자연 동선·물리·화면 평가는 사람이 한다. QA/FunQA를 요청 없이 작성하지 않는다.
4. 미저장 씬·사용자 변경을 덮거나 강제 종료하지 않는다. 시작 미커밋 및 자동 저장도 diff와 원인을 분류해 최종 커밋에 포함하되 기존 ignore는 유지한다.
5. 기존 프리팹 삭제·재생성·Apply·Unpack·자동 Builder·아트 제작 금지. 소유 배치와 필수 참조 이관만 하고 물리/GUID·중첩 관계를 검증한다.
6. 통로는 카메라 구도와 이동축을 분리한다. 플레이어와 차단물 **둘 다 DOMove**, 트리거 내부 실물 앵커, 같은 목표의 Gizmo, 자기 트윈 정지/취소를 적용한다. 플레이어 보정 후 차단 이동을 시작한다.
7. 추격 접촉/직선/물리 포획, CP3필드, 최종 포포만 재회차, Prototype 한 판, 등록 독립 진입을 유지한다.
8. RealToon 위치는 확인했지만 이번 셰이더 구현은 제외한다. HudIconGraphic은 실제 하트 리소스 연결까지 예외 유지한다.
9. 새 커밋·PR 설명은 한국어. 타입 접두사와 코드 식별자는 유지한다. 기존 이력 재작성·force-push·main 병합은 하지 않는다.
10. 필수 자동 검증의 실패나 평가하지 못한 항목을 통과로 쓰지 않는다. 파일 수 감소·helper 컴파일·과거 로그만으로 완료를 선언하지 않는다.

## 실행 준비 확인

운영 절차는 `Assets/_Docs/operations.md`를 따른다. 아래 두 명령과 실제 Editor 조회가 모두 필요하며 포트 존재만으로 연결됐다고 판단하지 않는다.

```powershell
unity status --project-path 'F:\CK2026_Project\Project\FeelsGoodOnionProject' --format json
unity pipeline list --format json
```

컴파일/실제 조회 API는 현재 pipeline/tool이 지원하는 비 Play 명령으로 선택하고 사용 명령·실제 결과를 기록한다. 삭제된 과거 검증 메뉴를 실행 명령으로 복사하지 않는다. 검증 보조 산출물은 `output/Tech_SYM/`의 기능별 하위에만 두고 상세 결과를 공유 Markdown에도 요약한다.

## 의도 보존

리팩터링 목적은 단순 파일 수 감소가 아니라 사람이 조립·교체할 때 읽을 수 있는 책임과 씬 구조다. 작고 실제 역할이 있는 물리·취소·외부 연동 계약은 이유를 적고 유지할 수 있지만, 대체 가능한 전달 wrapper를 남기는 것으로 삭제 요구를 우회하지 않는다. 구체 카메라 배치는 사용자 조절값이며 에이전트가 임시 리소스 제작으로 최종 완성을 대신하지 않는다.
