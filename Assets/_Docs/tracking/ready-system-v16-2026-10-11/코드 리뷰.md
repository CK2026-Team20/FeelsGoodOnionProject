## 자산 검토와 해결한 결함

소유 자산 25파일을 Unity native 저장으로 이관했다. 기존 프리팹 삭제·재생성·Apply·Unpack은 하지 않았고 기존 GUID를 유지했다. 관리자·출력 Camera·Canvas·완성 월드 객체는 독립 씬 루트다. Prototype의 외부 기준점 16개는 소비 14개를 내부로 이관하고 비소비 2개를 제거했다. 다른 소유 씬의 재귀 배치도 함께 연결했다.

독립 리뷰에서 MultiFuncPlatforms의 중첩 ShatteredPlatform이 이전 Root의 Contacts를 가리키고 자동 BoxCollider를 생성한 결함을 발견했다. 실제 지지 자식 Contacts로 연결하고 불필요 Root Contacts/Box를 제거했다. 독립 붕괴 씬의 직접 배치 하나도 기존 두 물리 컴포넌트 ID를 유지한 채 Collider 자식으로 옮겼다. 전체 7배치의 `physicalContacts.Surface == supportCollider` 및 빈 Root 계약을 다시 검사했다. 단순 Missing=0만으로 기능 연결 성공을 선언하지 않는다.

EditorJsonUtility의 instanceID 0으로 추정했던 메모 연결 누락은 실제 SerializedProperty 조회에서 정상으로 확인됐다. 중복 수선은 하지 않았다. 초기 참조 검사에서 발견한 54건은 아직 저장되지 않았던 두 독립 씬의 외부 앵커였으며 실제 저장 후 해소했다. 선택적 필드 null 3,034건은 별도 소비 검토로 구별했고 SYM 선언 152개 중 실제 필수 누락은 없었다.

## 보존 및 한계

12개 소유 씬의 기존 물리·렌더 1,030개를 ID·원본 ID·월드 자세·설정·참조로 비교했다. ProBuilder의 비영속 Mesh는 생성 컴포넌트 존재와 단위별 저장 전후 geometry hash를 비교했으며 과거 Mesh 바이트까지 동일하다고 주장하지 않는다. HMS 기준 씬의 40개 물리 구성은 읽기 전용으로 보존 확인했다. 그 씬의 기존 PlatformManager Missing Script와 기존 Shattered 접촉 미연결은 보호 원본이므로 수정하지 않았다.

소스/자산 독립 리뷰의 결함은 수정·재검사했다. 보정 중 적·피해바닥·주기발판·추격 접촉이 취소→물리 복원→피해/포획으로 이어지는 소스 경로는 확인했으나 자연 충돌 결합 실행은 사람 확인으로 남긴다. 구체 리소스·화면 조작감·전체 한 판의 Play 성공은 이 리뷰 판정에 포함하지 않는다.
