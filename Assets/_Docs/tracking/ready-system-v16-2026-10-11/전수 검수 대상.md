### F1 · P2 · 오디오 Dispose가 첫 채널 예외에서 나머지 채널 정리를 중단

앱 종료/부분 조립 해제 때 먼저 파괴된 AudioSource 또는 출력 장치 예외가 있으면 뒤쪽 채널을 Stop하지 못한다. StopMusic는 먼저 CancelCrossfade를 부르므로 정상 DOTween Cancel까지 성공한 경우 트윈이 계속 돈다고 단정하지 않는다. 문제는 전량 정리·terminal 상태·crossfade.Dispose 보장이 없다는 것이다. 정적 예외 경로로 확인했으며 native 재현은 미실행.

근거:

## 중요 발견 상세

### W01 [P1] 세 시점·전환 수락 계약 미구현

근거: `LevelCameraService.cs:9,95,140,201,203`.

CameraMovementMode와 Validate/ResolveMode가 Side1·Quarter3만 수락한다. EnterZone은 CancelTransition 후 다른 요청으로 교체하며 LateUpdate는 Side Z를 직접 Lerp하고 Transform/Rigidbody에 각각 쓴다. V16 R5/R6의 세 구도·교체 금지·두 DOMove와 다르다.

처리 계약: 구도 Side1/Corridor2/Quarter3와 HMS 이동 Side/Quarter를 분리. 전환 중 요청은 미수락하고 완료 뒤 실제 현재 접촉을 다시 판정. 기존 수동 정렬을 안전앵커 DOMove 소유 작업으로 대체. 초기 Cut/ready 및 자기 lease 해제는 보존.

### W02 [P1] Root 아래 앵커 이관은 이동 writer와 검사 이관이 선행

근거: `EnemyMotor.cs:36,186; EnemyActor.cs:59,72,126,129; SceneComponentLookup.cs:61`.

EnemyMotor는 owner.transform을 움직인다. EnemyActor는 Body direct child/localPosition0와 controller pose를 검사·복원한다. SceneComponentLookup은 EnemyActor가 조상이면 무조건 고정점 거절한다. 단순 재부모화하면 앵커가 움직이거나 준비 실패한다.

처리 계약: 고정 EnemyRoot 아래 Body와 Anchors를 형제로 배치. Body를 이동 진실로 삼아 초기 pose·patrol 원점·sweep pose·centerOffset·Gizmo·retry를 모두 이관. SceneComponentLookup은 실제 이동 Body 계층만 거절. 사용자 최신 알림과 일치; 메인이 수정할 경계.

### W03 [P1] HMS 입력 차단만으로 DOMove 단일 writer를 확보할 수 없음

근거: `PlayerFacade.cs:522; CharacterMovement.cs:129,169; KinematicPlatformMotion.cs:291`.

SetInputBlocked는 입력만 비우고 CharacterMovement 물리 갱신을 중단하지 않는다. CharacterMovement.enabled=false는 외력·접지·대기 넉백까지 비우므로 무해한 임시 잠금으로 취급할 수 없다. Rigidbody DOMove 도입 시 물리 및 운반 writer와 경합할 수 있다.

처리 계약: 현재 Actor·Stage·세대의 이동 요청 소유권을 Bridge의 기존 실제 Body 경계와 합의. 보정 동안 변경할 물리 설정/운동 복구를 명시하고 죽음·넉백을 취소 원인으로 처리. 세계 정지·무적 추가 금지. 새 pass-through 서비스 대신 기존 소유자에 계약 추가.

### W04 [P1] Prototype 밖 기존 직렬화 소비 누락

근거: `LinearPlatform.prefab; 01_PlayerMovementTest.unity; PatrolEnemy/PatrolXEnemy/PatrolYEnemy/OilPatrolEnemy.prefab`.

LinearPlatform prefab 본문에는 travelOffset만 있고 현 startPoint/endPoint가 없다. Prototype override에서는 유효 목표를 공급한다. 순찰 prefab에도 patrolDistance 잔재만 있고 실물 순찰점이 없으며 Prototype의 두 순찰 인스턴스는 override로 공급된다. HMS 테스트 씬 Shattered에는 physicalContacts가 없어 현 Awake 필수 조건을 만족하지 못한다.

처리 계약: 소유 prefab 필수 참조 최소 이관과 다른 인스턴스 override 전수 확인. 보호 HMS 씬은 읽기 보고만 하며 메인에게 별도 권한/사용자 수동 조립 항목으로 전달. Missing Script0는 Awake 구성 유효성 증거가 아니다.

### W05 [P2] 16개 중 고정 적 순찰점 2개는 현재 실행 비소비

근거: `Stationary.asset kind:0; EnemyActor.ValidateSetup; EnemyMotor bounded; Prototype override`.

16개 모두 실제 직렬화 연결이 있으나 StationaryEnemy 두 점은 kind0 분기에서 Origin/End가 initialPosition을 사용하여 실행 목표가 아니다. 나머지14개는 2 pressure+2 linear+6 drawer+4 patrol 목표다.

처리 계약: 14개 기능 Root 내부로 이관. Stationary 두 연결을 null로 이관하고 해당 씬 내 다른 소비 없음 확인 후 두 앵커 제거 가능. 종류를 바꾸려는 별도 계획이 있으면 내부 보존하되 현재 실행 소비라고 쓰지 않음.

### W06 [P2] 실제 역할 없는 보조 API/캐시만 좁게 제거

근거: `PlatformContacts.ContactVelocity; PlatformPresentation.Blink; KinematicPlatformMotion.TryRotateTo; PeriodicPlatform.ShapeBounds; OvenTrayObject.Accepted`.

ContactVelocity는 외부 소비가 없고 dictionary 쓰기만 존재. Blink/IsValid/TweenCompleted/TweenExists는 Shattered에서 호출하지 않는다. 회전은 TryTweenPose가 실제 경로다. ShapeBounds는 실제 교차 InspectCapsuleBox에서 쓰지 않는다. Accepted 이벤트는 실제 Interaction이 구독하지 않고 OperationEnded만 구독한다.

### W07 [P2] 같은 물리/논리 객체의 중복 Inspector 연결 축소

## Root/Body 실제 변경 계약

1. **Enemy:** 고정 `EnemyRoot(EnemyActor)` / `Anchors(Start,End)` / `Body(BoxCollider Trigger, EnemyContactSensor)`를 구성하고 Visual/VFX를 Body 아래에 둔다. 현재 body direct child 계약은 그대로 유지할 수 있지만 Body.localPosition=0은 초기 작성 조건과 이동 후 조건을 분리한다. Motor는 Body Transform을 유일하게 쓴다. 중심 offset은 Collider 중심과 Body pose 사이에서 구한다. Actor reset은 고정 Root를 옮기지 않고 최초 Body pose를 복원한다. 모든 초기검사·Gizmo·순찰선분 검사는 실제 Body 중심/원점을 사용한다. 기존 무회전·단위배율·Rigidbody 없음·X/Y 허용축·Trigger 접촉을 유지한다. `SceneComponentLookup.IsFixedPoint`에 실제 Body 하위 판정을 노출하고 EnemyActor 조상 일괄 거절을 제거한다. 단순 타입 삭제로 모든 적 자식을 고정점으로 허용하면 안 된다.

2. **선형/압력:** `LinearRoot(LinearShuttlePlatform,KinematicPlatformMotion)` / `Anchors` / `Body(Rigidbody,BoxCollider,PlatformContacts,Render)`로 연결한다. ShellGate는 이미 바깥 논리 Root가 있으므로 Body의 controller/motion을 그 Root로 이관하고 `Body_startPoint/targetPoint`를 형제 Anchors로 옮긴다. 압력판도 동일 조립 원칙을 적용하되 Linked의 pressurePlate를 새 컴포넌트로 다시 연결한다. 기존 지지 법선·탑승/관성·재압력 진행·초기 world pose를 보존한다.

3. **서랍3개/트레이/문:** 각각 독립 `DeviceRoot(OvenTrayObject,KinematicPlatformMotion,InteractionPromptAnchor)` / `Anchors(ClosedPose,OpenPose)` / `Body(Rigidbody,Collider,Contacts,Render,PromptPoint,InteractionPoint)`. 두 pose는 Body 밖이고 안내점은 Body 안이다. 기존 F 수락·진행 중 거절·완료/취소 이벤트와 독립 상태를 유지한다. 힌지는 실제 Body 원점과 두 pose 위치가 일치해야 한다. 빈 Root 추가만으로 prefab 생성/Apply/Unpack 허가를 얻는 것은 아니다.

4. **보존할 다른 계약:** Periodic/붕괴의 지지 Collider 및 표현 위치는 별도로 연결한다. 눈물은 Root 전체와 Sensor가 같이 움직이는 기존 계약을 유지한다. Chase는 실제 포획 Box와 외형 bob을 분리한 현재 동적 추격 객체이며 순찰 앵커를 새로 만들지 않는다. HUD/씬 카메라/관리자 밑으로 월드를 묶지 않는다.

5. **메인 이관 완료 증거:** source prefab GUID, 소유 씬 instance/source object fileID, m_Modifications.target/propertyPath/objectReference, 원래 world position/rotation/lossyScale, Rigidbody/Collider 설정, Visual/Prompt 세계 위치를 전후 비교한다. 16개만 없애고 종속 prefab이 필수 목표 없이 남으면 완료가 아니다. 다른 소유 원본은 별도 수정 허가 없이 변경하지 않는다.
