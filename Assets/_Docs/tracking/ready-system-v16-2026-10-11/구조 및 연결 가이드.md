# 씬과 기능 객체의 구조 및 연결

2026-10-12. V1.6 및 후속 직접 지시를 반영한 현재 조립 구조다. 소유 씬 12개·프리팹 61개의 실제 로드 검사와 기존 물리·렌더 1,030개 컴포넌트 보존 검사를 수행했다. 자연 물리·입력·화면 연출의 플레이 통과를 뜻하지 않는다.

## 씬을 구성하는 순서

`Architecture/01_Bootstrapper`는 앱 조립, `02_Title`은 제목 화면, `03_InGameCore`는 한 판의 조립과 표시, `Prototype/1_Stage`는 현재 응집형 게임 공간을 담당한다. 경로는 `Assets/_Scenes/Tech_SYM/` 기준이다. 기존 독립 기능 씬과 등록 Stage도 남아 있다. Stage1→2→3 자동 진행은 추가하지 않았다.

1. 관리자·출력 Camera·Canvas·완성된 월드 기능 객체를 각각 씬 루트에 놓는다. 월드 전체를 Bootstrapper나 CoreComposition 아래로 묶지 않는다.
2. 앱 출력에는 Camera·CinemachineBrain·AudioListener를 각 하나만 둔다. `BootstrapCamera`에는 통합용 HMS PlayerCameraController를 더 이상 붙이지 않는다. HMS의 별도 PlayerMovementTest는 기존 네 리그를 사용하는 다른 구성이다.
3. CoreComposition에 ActorHost·UI·연출·LevelCameraService·추격 등 실제 조립 대상을 연결한다. CoreUiBinding은 표시 참조를, 한 판의 Runtime과 WorldBinding은 서비스 연결·해제를 소유한다. 같은 객체의 컴포넌트를 다시 입력하던 필드는 제거했다.
4. StageService에 초기 CheckpointMarker·음악 목적·CameraMovementBounds의 BoxCollider를 연결한다. Marker와 카메라 정렬점은 자신의 기능 객체 내부 자식으로 만든다.
5. 비활성 PlayerRoot 프리팹은 Host가 생성·주입한 뒤 활성화한다. HMS ActorBody에 붙은 실제 Rigidbody·Capsule·Facade·Movement·입력 조립을 일반 계층 예시 때문에 분리하지 않는다. CameraAnchor는 실제 플레이어를 따라간다.
6. 아래 기능 객체를 배치하고 Inspector의 실물 참조를 연결한다. 숫자는 시간·속도·높이·방향을 조절하는 데 쓰며 목표 위치를 대신 입력하는 키나 좌표 필드는 사용하지 않는다.

## 움직이는 기능 객체

```text
기능 Root                         ← 빈 고정 객체, 컨트롤러·상태
├── Anchors                       ← 고정 기준점
│   ├── 시작 / 닫힘 / 순찰 시작
│   └── 끝 / 열림 / 순찰 끝
└── Body                          ← 실제 움직이는 몸체
    ├── Visual                    ← 표시
    ├── 안내 지점
    └── 조작 지점
```

기존 Root·Rigidbody·Collider·Renderer·소스 GUID를 유지하고 필요한 컴포넌트만 자식으로 옮겼다. 원래 배치·배율과 중첩 override도 유지했다. 새 제작에서는 Root를 기준점으로 두고 Body를 움직인다. 움직이는 Body 아래에 목적 앵커를 넣으면 목표 자체가 따라 움직이므로 허용하지 않는다.

| 기능 | Root의 책임 | Body·필수 연결 | 재준비·주의점 |
|---|---|---|---|
| 선형 발판 | LinearShuttlePlatform + KinematicPlatformMotion | Body의 Rigidbody·BoxCollider·PlatformContacts, Root 내부 startPoint/endPoint | 같은 Rigidbody에 다른 이동자를 추가하지 않는다. 기존 기본 프리팹의 local 끝점은 +X 1.5이며 배치별 override는 유지했다. |
| 부유 발판 | FloatingPlatform + KinematicPlatformMotion | 같은 Body의 Rigidbody·BoxCollider·PlatformContacts | 높이·주기 조절값과 초기 몸체 자세를 사용한다. 별도 월드 앵커는 필요 없다. |
| 압력판·연결문 | 각각의 PressurePlatePlatform 또는 PressureLinkedPlatform + KinematicPlatformMotion | 판과 문은 각각 독립 Body, 문은 내부 startPoint/targetPoint | 판/문을 같은 이동 컨트롤러 한 개로 합치지 않는다. 기존 Shell 묶음 안에서도 PlateRoot·GateRoot를 구분한다. |
| 오븐 문·트레이·서랍 | OvenTrayObject + KinematicPlatformMotion + InteractionPromptAnchor | 실제 Body, 내부 closedPose/openPose, Body를 따르는 안내·조작 지점 | 각 서랍은 독립 상태다. 원본 Tray 기본 열림은 local -X 1.5, 기존 배치의 실물 자세는 보존했다. 힌지는 실제 몸체 원점을 사용한다. |
| 적 | EnemyActor | 실제 MotionBody 아래 Collider·센서·Visual·VFX; 순찰형만 Root 내부 patrolStart/patrolEnd | 초기 위치·기절 상태를 몸체 기준으로 복구한다. Stationary/Idle의 비소비 순찰점은 비워 둔다. 기존 회전·크기·지형 판정 계약을 보존한다. |

KinematicPlatformMotion의 `physicsBody`는 필수 외부 자식 참조다. `platformContacts`는 Inspector에서 중복 입력하지 않으며 연결된 몸체에서 얻는다. Enemy의 고정 Root를 이동시켜 순찰점을 함께 움직이는 방식은 사용하지 않는다.

## 정적 발판과 물리 예외

- ShatteredPlatform: Root에 상태 컨트롤러, `Collider` 자식에 기존 BoxCollider와 PlatformContacts, 기존 `Plane_Visual`은 형제다. supportCollider·physicalContacts·visual의 실제 참조를 유지한다.
- PeriodicPlatform: Root에 주기 상태, `Body` 자식에 기존 BoxCollider·MeshFilter·Renderer를 둔다. 현재 정적 프리팹의 선택적 motion은 비어 있다.
- 눈물 조각은 수집 Root와 센서가 함께 움직이는 계약을 유지한다. HMS ActorBody 동거와 실제 껍질 물리 Root도 유지한다.
- 적 센서, PlatformContacts 및 트리거 컴포넌트는 물리 콜백을 받는 위치에 둔다. 모든 스크립트를 기계적으로 최상위로 옮기지 않는다. 이들은 Root의 상태 owner에 결과를 전달하는 물리 경계다.

## 카메라와 통로 차단

```text
LevelCameraService                ← 완성된 카메라 리그 객체
├── Side                          ← CinemachineCamera + PositionComposer + Confiner3D
├── Corridor                      ← 같은 구성
└── Quarter                       ← 같은 구성

전환 Root                         ← 독립 월드 기능 객체
├── 진입 Volume                   ← 고정 BoxCollider Trigger + CameraZoneTrigger
│   └── 기존 정렬점
├── PlayerSafeAnchor              ← 플레이어 실제 몸체 목표
├── BlockerTarget                 ← 차단 몸체 목표
└── BlockerBody                   ← Kinematic Rigidbody + 비 Trigger BoxCollider
    └── Visual
```

세 가상 카메라·설정은 LevelCameraService에 연결한다. 씬 출력 Camera는 리그 객체와 별도의 루트다. Stage의 CameraMovementBounds는 카메라 이동 범위이며 플레이어 벽이 아니다. Trigger로 설정한다. 현재 경계는 기존 지형 크기에서 여유를 둔 초기값으로, 최종 화면 구도와 가장자리 가시성은 사람이 조절한다.

CameraZoneTrigger에는 mode, 기존 alignmentPoint, safeAnchor, blockerBody, blockerTarget, 각 이동 시간·Ease·전환 시간을 작성한다. 차단물 없는 시작 구간은 차단 참조 세 개를 비워 둘 수 있다. 차단물 있는 전환은 두 앵커와 몸체를 같은 고정 Root 내부에 연결한다. 플레이어는 안전 지점까지 DOMove로 이동하고, 실제 도착 뒤 차단물의 DOMove를 시작한다. 둘과 카메라 전환이 끝나야 입력을 반환한다.

Side=1은 X축, Corridor=2와 Quarter=3은 X/Z축 이동이다. 통로를 HMS Back의 Z축 전용 이동으로 해석하지 않는다. 구도·각도·거리·감쇠·전환 시간은 Inspector 조절값이며 뒤돌기만으로 카메라를 회전시키지 않는다. 화면 Y 비율은 아래 0%·위 100%다. Gizmo의 청록은 플레이어 보정, 주황은 차단물 이동이며 실제 참조 목표를 표시한다.

Prototype의 CorridorA·QuarterA·CorridorB·QuarterB에 차단 기능을 연결했다. 안전 앵커는 기존 통로·차단체와 겹치지 않는 대표 지상 배치로 잡았고, 실제 Capsule·Box를 사용한 네 구간 각 404개 표본의 침투 검사를 통과했다. 이는 모든 점프·접촉 자세의 연속 충돌 검증이 아니다. 리소스 병합 후 몸체 크기나 바닥을 바꾸면 다시 조정해야 한다.

옵션은 세계·표시·두 DOMove의 남은 진행을 함께 멈추고 같은 위치에서 재개한다. 전환 자체는 세계를 멈추거나 무적을 추가하지 않는다. 사망·피해·Actor/Stage 해제·취소 시 자기 작업과 잠금만 반환한다. Retry는 문 초기 자세와 구간 상태를 초기화하고 저장한 체크포인트 위치에서 구도를 다시 선택한다. 카메라·문 상태를 체크포인트 필드로 추가하지 않는다.

## 화면·리소스 인계

View는 주입된 ViewModel의 상태·명령만 사용하며, 재Bind·Unbind는 자기 구독만 정리한다. TitleUiRoot의 같은 객체 View와 ChaseRuntimeDriver의 같은 객체 presentation은 별도 Inspector 입력이 아니다. Core의 연출 표시 부모는 실제 CinematicHost를 사용한다. 메모의 screenRoot/viewPrefab 연결은 실제 SerializedProperty 조회로 정상임을 확인했다.

HudIconGraphic은 사용자 예외로 유지한다. 하트 3칸·Q/E·눈물 표시 총 6개 저장 소비를 실제 리소스로 모두 이관한 뒤 소스와 참조를 제거한다. 실제 Player 애니메이션 클립, 최종 카메라 배치, 아트 프리팹 교체는 사람이 담당한다. RealToon은 `Assets/RealToon`에 있지만 이번 가림 셰이더 연결은 구현하지 않았다. 새 임시 아트나 자동 Builder로 완성 상태를 대신하지 않는다.
