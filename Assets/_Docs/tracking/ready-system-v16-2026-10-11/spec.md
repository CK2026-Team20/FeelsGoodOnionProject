## R2 책임과 의존성 구조

앱 시작/조립/종료, 한 판 진행/재시도, 실제 Stage 기능, 화면 표현, 외부 Unity/오디오/설정 연동을 구분한다. 같은 고수준 조정의 분산된 소유는 합치되 앱·Core 씬·한 판·Actor의 서로 다른 수명을 합치지 않는다. AppComposition과 Bootstrapper의 시작/해제 중복은 앱 소유자로 통합하는 우선 후보다. 필드만 옮기는 partial 분할이나 새 pass-through wrapper로 삭제 수를 채우지 않는다.

HP·폼·운동·스킬의 원본은 HMS, 현재 해금과 체크포인트 snapshot은 세션, 대화 완료 장부는 대화 담당이다. MVVM을 유지하고 View는 상태 표시/입력 전달만 하며 ViewModel이 View를 직접 참조하지 않는다. 생성한 구독·트윈·코루틴·취소 토큰은 소유자가 해제하며 빌린 객체를 파괴하지 않는다. 재Bind 중복, 해제 후 호출, 부분 초기화 실패, 정상 앱 종료를 검증한다. 초기 조립의 준비→소비자 연결→Boot 순서를 유지하고 종료 중 언로드 Stage를 다시 탐색하지 않는다.

모든 직렬화 필드는 실제 필요한 설정/연결만 남기고 한국어 표시명과 간단한 Tooltip을 제공한다. 같은 객체에서 확실히 얻을 수 있는 내부 컴포넌트 참조는 중복 Inspector 입력 여부를 검토한다. 외부 대상은 명시적인 연결 계약을 유지하며 삭제 대신 전역 검색에 의존하게 만들지 않는다. 위치·대상은 실물 Transform/컴포넌트/자산으로 연결하고 속도·시간·높이·방향은 조절 가능한 수치/선택으로 둔다.

## R3 기능 객체와 씬 계층

씬 관리자·출력 카메라·Canvas·완성된 월드 기능 객체는 서로 독립된 씬 루트다. 게임 흐름 관리자 하위에 월드 전체를 묶지 않는다. 한 기능 객체의 빈 고정 Root 안에는 고정 앵커/피벗과 실제 이동 Body를 함께 구성하며 Render/Collider/안내 지점은 해당 몸체와의 실제 관계를 따른다.

OvenTray/서랍의 열림·닫힘 자세, 발판 시작/끝점, 적 순찰 지점은 기능 객체 밖의 독립 월드 루트로 남기지 않는다. 이동 목표점은 이동 Body의 자식이 되어 목표가 따라 움직이면 안 된다. 조작/안내 지점은 움직이는 손잡이/몸체를 따라간다. 현재 Prototype의 확인된 외부 목표점 16개를 모두 이관하거나 소비가 없으면 제거하고, 전수 검사에서 더 발견되는 대상도 처리한다.

PlayerMovementTest의 PlayerCharacter와 통합 PlayerRoot의 실제 몸체/추적점 관계를 참고한다. HMS ActorBody 동거·실제 물리 Root·눈물 수집 Root와 센서 동시 이동 계약을 일반 예시 때문에 깨뜨리지 않는다. Enemy는 현재 controller transform 이동과 직계 Body 검사를 함께 이관하여 고정 루트/이동 몸체를 분리한다. 기존 허용축/물리 판정을 임의 새 동작으로 바꾸지 않는다.

기존 프리팹 삭제·재생성·Apply·Unpack·자동 Builder 실행과 아트 제작은 하지 않는다. 소유 씬 배치 및 참조 이관을 수행하고, 기존 소유 프리팹의 필수 직렬화 소비 이관은 GUID를 보존하여 최소 범위로 처리한다. 보호 원본은 읽기 참조와 소유 배치 연결만 한다. 기존 월드 pose·배율·Rigidbody/Collider·중첩 override를 전후 비교한다. 이동 후 새로운 씬을 사람이 만들 때 필요한 Root/Body/앵커/연결 순서를 기능별로 안내한다.

## R4 유지할 게임 흐름과 진행 상태

Bootstrap→Title→새 게임→Opening→응집형 Prototype 한 판→최종 포포 대화 Completed/Skipped→Ending→Title을 유지한다. 등록 Stage와 기존 독립 진입은 보존하며 Stage1→2→3 자동 연결을 추가하지 않는다. Core/등록 Stage 씬 유지와 한 판/Actor 재생성을 구별한다. 출력 Camera/Brain/AudioListener는 각 하나다.

체크포인트는 현재 ActorBody의 유한 월드 위치, 조각 정수 0..5, 해금 마스크 0/1/2/3의 정확히 세 항목을 원자 저장한다. 첫 저장 전 초기 상태와 유효 snapshot을 구분하고 같은 실제 Marker 재접촉으로 갱신하지 않는다. 사망은 같은 Stage 초기 복원 뒤 마지막 세 값을 복원한다. 카메라·문 상태를 별도 저장 필드로 추가하지 않는다.

추격은 트리거 접촉·퇴로 안전 확인→현재 세 값 저장 성공→직선 추격/문 차단이다. 실제 몸체 충돌로 포획하고 V1.6 3.2의 전신 통과·경로 거리 판정은 적용하지 않는다. 해당 원문 차이는 수정 요청으로 기록하며 원본 DOCX를 고치지 않는다. 최종 포포와 동시 포획/사망이면 사망이 우선한다.

일반 대화 Completed/Skipped 장부는 보존한다. 최종 포포 Escape(7)만 재접촉/재시도 후 새 회차를 허용한다. 현재 Stage·Trigger·선택 객체·Table·Code·Actor 세대·Round·Session이 일치하는 정상 완료/전체 Skip에만 Ending을 한 번 예약한다. 취소·낡은 callback은 완료가 아니다. Auto/Log/Options의 잔여 시간, 입력 간격, 자기 차단 해제를 보존한다.

## R5 세 시점 카메라

카메라 구도는 기본·통로·쿼터뷰의 세 가지다. 기본 이동은 월드 X와 점프/낙하 Y, 통로와 쿼터 이동은 X/Z와 점프/낙하 Y다. 카메라 구도와 HMS 이동 모드는 서로 다른 계약이며 HMS Back의 Z 전용 이동으로 통로를 구현하지 않는다. 작성용 구도 값은 Side=1, Corridor=2, Quarter=3이며 기존 Side/Quarter 직렬화 의미를 보존한다. 기존 자산의 값2 사용 여부를 이관 전에 검사하여 과거 다른 의미를 조용히 새 통로로 해석하지 않는다.

일반 추적은 미리 정한 회전·렌즈를 유지한다. 캐릭터가 화면상 허용 범위를 벗어날 때 부드럽게 위치 추적하고 다시 범위 안에 오면 부드럽게 멈춘다. 기본은 화면 기준 위치 40%/50%, 허용 폭/높이 10%/10%; 통로는 50%/55%, 10%/10%; 쿼터는 50%/50%, 15%/10%를 초기 조절값으로 제공한다. 세로 비율은 초기 구현에서 하단 0%·상단 100%로 명시한다. 카메라 각도·거리·감쇠·개별 전환 시간은 사용자가 Inspector에서 조절한다. 전환 약 0.6초는 초기값이며 강제 상수가 아니다.

기본→통로 입구 전환→통로 직접 이동/점프→통로 출구 전환→쿼터뷰를 지원한다. 일반 통로 추적에서 캐릭터가 뒤돌았다는 이유로 카메라까지 회전하지 않는다. 전환 중 이전 일반 추적은 중단하고 지정 구도의 위치·회전·필요한 거리 변화가 우선한다. 실제 전환 구간이 끝난 뒤 새 이동 허용축/추적과 입력을 적용하며 이전 버튼 입력을 다시 실행하지 않는다.

전환 진행 중 다른 구간 요청으로 현재 전환을 교체하거나 여러 전환을 동시에 실행하지 않는다. 완료 후 현재 Actor와 실제 접촉 조건을 다시 평가한다. 사라진 접촉을 예약 실행하지 않는다. 초기 진입/재등장은 해당 Stage의 실제 위치에 맞는 구도를 가려진 화면에서 즉시 복원하고 사망 지점에서 이동하는 모습을 보여주지 않는다. CP에 카메라 snapshot을 추가하지 않고 실제 배치와 초기 설정에서 결정한다.

씬의 실제 카메라 이동 범위를 참조로 지정하고 경계에서 카메라 위치를 제한한다. 이 경계가 화면 추적보다 우선하지만 플레이어 이동을 임의 제한하지 않는다. 경계에서 화면 이탈이 가능한 배치는 기획/레벨 조정 대상으로 명확히 표시한다. 허용 범위만으로 모든 화면 이탈을 보장했다고 주장하지 않는다.

## R6 전환 트리거와 통로 복귀 차단

전환 트리거의 컴포넌트가 안전 보정 앵커와 차단물 목표 앵커, 실제 차단 오브젝트를 실물 참조로 제공한다. 앵커는 이 완성된 전환/차단 기능 객체 내부에 두고 이동 대상 하위에 두지 않는다. 진입 Trigger Volume은 위치를 유지하고 이동 대상은 **플레이어 실제 몸체와 차단 오브젝트**다.

수락 순서는 현재 생존 Actor의 유효 접촉 확인→참조/목표 안전 검사→플레이어를 안전 앵커로 DOTween DOMove 보정→보정 완료 즉시 차단 오브젝트를 목표 앵커로 DOTween DOMove 이동이다. 두 이동을 카메라 전환 구간 안에서 소유하고 완료 전에는 조작을 풀지 않는다. 종료 시 이동 대상의 물리 위치와 표현 위치를 일치시킨다. Rigidbody와 Transform을 서로 다른 갱신자가 동시에 쓰지 않으며 이동 요청은 하나의 소유자로 조정한다.

플레이어 목표는 통로/차단체와 겹치지 않아야 한다. 잘못된 참조나 안전하지 않은 목표는 이동 시작 전에 거절하고 구성 오류를 드러낸다. 플레이어 보정 실패·취소·사망·Actor 교체·Stage 해제·Title 복귀가 발생하면 차단 후속 작업을 시작하지 않고 자기 트윈/예약을 취소한다. 오래된 OnComplete가 다음 Actor나 새 전환을 움직이지 못하게 한다. 정상 동작 중 예외를 성공으로 처리하지 않는다.

같은 진입을 복수 Collider 또는 OnTriggerStay가 반복 보고해도 한 번만 실행한다. 이미 차단이 완료된 동일 기능의 반복 접촉으로 차단/플레이어 보정을 중복하지 않는다. Stage 초기 재준비에서는 차단물 초기 위치·동작 상태를 복원하고 현재 작업을 취소한다. 복구된 CP에서 정상 진행이 가능해야 하며 retry 직후 잘못된 낡은 예약으로 문을 다시 닫지 않는다.

플레이어 보정과 차단물 각각의 현재/초기 위치, 목표, 연결 경로를 다른 색 Gizmo로 표시한다. 실제 DOMove 목표와 Gizmo는 같은 Transform을 사용한다. 초기 색은 플레이어 청록·차단 주황, 안전 범위/차단 범위는 Wire 표시로 제공하고 Tooltip에 설명한다. 시간과 easing은 조절값이며 앵커 대신 수기 월드 좌표 필드를 제공하지 않는다.

조립 계약은 명시적 Bind/Unbind, 현재 Actor·Stage·세대·요청 출처를 검증하는 수락 메서드, 취소/초기 복원이다. 실행 결과는 수락 여부와 진행 결과를 구별한다. 중복·낡은 접촉은 미수락이며, 수락 후 진행 상태는 보정→차단→완료 또는 취소/실패다. 취소는 완료 callback을 발생시키지 않는다. 상태를 외부가 직접 수정할 수 없으며 별도 범용 이벤트 버스·중계 서비스로 전달만 하는 층을 추가하지 않는다. 외부 관찰에는 기존 작업 결과/이벤트 계약을 재사용하고 정확한 메서드명은 구현과 호출처를 함께 이관한다.

## R7 시간과 입력의 경계

카메라 전환과 통로 보정/차단 중에는 gameplay 입력만 차단하고 세계 시간은 진행한다. 적·발판·환경을 전환 때문에 멈추거나 플레이어 무적을 임의 추가하지 않는다. 안전 앵커와 진입 구조로 위험을 피하고 물리 안전은 사람 확인 항목으로 남긴다.

전환 중에도 Esc/옵션 진입을 허용한다. 옵션은 세계, 카메라 전환, 두 DOMove의 잔여 진행, 진행 중 화면 시간을 함께 정지한다. 닫으면 멈춘 위치와 남은 시간부터 재개하며 다른 대화/전환/메모의 조작 차단은 유지한다. 장면 로드/화면 전환 busy와 카메라 구도 전환을 같은 옵션 차단 조건으로 만들지 않는다. 전체 DOTween을 Kill하거나 남의 토큰을 해제하지 않는다.

## R8 HMS와 자산 권한

HMS 누적 변경의 검토/최소화 대상은 `Assets/_Code/Core/Tech_HMS/Features/`의 다음 12파일이다: `CharacterMovement.cs`, `PlayerAnimationController.cs`, `PlayerAnimationPlayback.cs`, `PlayerAnimationSet.cs`, `PlayerAnimationTypes.cs`, `PlayerAnimatorOutput.cs`, `PlayerCameraController.cs`, `PlayerFacade.cs`, `PlayerFormController.cs`, `PlayerInputReader.cs`, `PlayerSkillController.cs`, `TearSkill.cs`.

각 hunk의 기능·필요성·실제 SYM 소비를 확인하고 불필요한 변경만 제거한다. 필요한 피해/사망/회수/애니메이션/스킬 계약은 근거와 함께 유지한다. 이 목록 밖 파일·보호 meta/import·공용·_Art·Packages·ProjectSettings 수동 수정은 허용하지 않는다. 기존 독립 PlayerMovementTest와 PlayerCharacter의 동작 계약을 유지한다. 새 통로 카메라 때문에 HMS 이동 모드 의미를 뒤집지 않는다. 실행 중 범위 밖 파일 변경이 정말 필요하면 그 파일과 구체 diff를 제시한다.

RealToonShader는 `Assets/RealToon`을 향후 가림 처리 자산으로 기록하되 **이번 반투명 셰이더·감지·재질 연결 구현은 제외한다.** 실제 아트·프리팹 제작과 카메라 구체 배치 확정도 사람이 담당한다.

## R9 검증과 완료 판정

완료 기준은 104개와 최종 추가/삭제 소스의 전수 판정, 네 씬 및 종속 소비 이관, 삭제 타입/GUID 참조 누락 없음, 불필요 외부 기준점 없음, 실제 Runtime/Editor 컴파일, 변경 기능의 비 Play 검증, 독립 코드 리뷰다. 결과를 `코드 리뷰.md`와 `테스트 및 검증 항목.md`에 실제 증거와 함께 기록한다.

검증은 순수 계산 복제가 아니라 입력/수명/결과 계약을 관찰한다. MVVM 한 입력 한 명령·중복 구독 없음·해제 후 호출 없음, 전환 중 재접촉·옵션·사망/취소·retry, 프리팹/씬 직렬화 참조, 초기/종료 순서를 포함한다. Editor 연결과 dirty 상태를 먼저 확인하며 네 실제 씬 대신 임시 검증 씬만으로 연결 성공을 선언하지 않는다. 일회성 검사 파일을 Assets 제품 소스로 남기지 않는다.

Editor Play·PlayMode API/CLI/pipeline/batch·직접 플레이·Player 실행은 금지한다. 컴파일/정적 참조와 실제 비 Play 엔진 결과, 사람이 할 전체 흐름·자연 물리·카메라 조작감·아트 재생을 구분한다. 요청 없는 QA/FunQA 문서를 생성하지 않는다. Play 금지로 남는 사람 확인은 명시하고 자동 통과로 채우지 않는다.

## R10 문서와 Git/PR

기획 인덱스와 공통 지침을 V1.6 기준으로 최신화하고 기존 코드 설명과 목표 명세를 구별한다. 최종 구조 안내는 기능마다 Hierarchy와 연결 대상, 필수/선택 필드, 재시도·해제, 알려진 미연결 자원을 설명한다.

새 커밋 제목·본문 및 PR 제목·설명·섹션은 한국어로 작성한다. 저장소의 타입 접두사와 코드 식별자는 원문을 유지한다. 기존 공개 커밋의 메시지를 바꾸기 위한 이력 재작성이나 force-push는 하지 않는다.

기존 초안 PR #26을 갱신하고 초안 상태를 유지한다. 중복 PR을 만들지 않는다. 본문에는 무엇을 진행했는지, 왜 추가/변경했는지, 주요 변경점, 최종 구조, 참고 사항, 확인할 점을 순변경 기준으로 설명한다. 기존 유효한 이미지/참조를 보존하고 과거 검증을 이번 통과로 승계하지 않는다. main 병합은 하지 않는다.
