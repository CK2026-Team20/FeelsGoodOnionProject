# 테스트 및 검증 항목 — READY와 구현 후 검증 구분

## 이번에 실행한 범위

원본 DOCX XML 추출(색/취소선/삭제/버전 이력), C#·GUID·Inspector 정규식 목록, 소유 씬 YAML 계층 조사, 이전 HMS exact Git patch 읽기, 독립 의도 검토를 수행했다. 최종 문서 coverage/graph/경로/source 보호 검사는 `evidence/document-checks.json`에 실제 결과를 저장한다.

문서 기계 검사 24개 항목이 통과했다. 요구사항 누락·고립된 작업·깨진 로컬 링크는 0건이다. 실행 그래프는 소비자 스키마에 제한한 YAML 파서로 읽고 순환 의존이 없음을 확인했다. 174개 소스/128개 SYM 판단, 201개 추출 필드의 처리, 23개 삭제 후보의 경계, 원본과 사본의 SHA-256 일치, `.dryforge`와 검토 사본의 바이트 일치, Git 작업 트리와 HEAD 보존을 확인했다. 이는 문서와 텍스트 목록의 검사이며 Unity 기능 테스트가 아니다.

제품 구현0, source삭제0, scene/prefab변경0, Unity Editor 조작0, import/compile/EditMode test/build/Play/실제 리소스 재생/QA/FunQA는 **미실행**이다. Git 읽기만 했고 commit/push/PR은 없다. 과거 검증 결과를 이번 통과로 옮기지 않았다.

## 결과 기록 형태

각 결과에 source/commit 식별, 사용 명령 또는 사람이 확인한 시나리오, 실제 통과/실패/미실행, 로그·해당 field/자산 경로, 남은 담당·조건을 적는다. 정적 문서 검사와 사람 Play의 결과를 같은 칸에 섞지 않는다. 불가한 compile/build는 이유를 적고 후속 확인으로 남긴다. 삭제는 실제 제거 수와 잔여 소비를 기록한다.
