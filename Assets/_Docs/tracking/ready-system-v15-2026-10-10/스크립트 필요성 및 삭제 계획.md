# 스크립트 필요성 및 삭제 계획

2026-10-10 READY의 현재 소스 조사다. C# 174개(SYM 128/HMS 41/공용 Interfaces 5)를 현재 작업 트리에서 확인했다. 파일 수는 성능 지표가 아니다. 아래 판단은 책임·상태 원본·수명·실제 소비·대체 가능성으로 한다.

호출 언급은 주석/Editor 참조를 포함하는 보수적 텍스트 검색이고 컴파일러의 정확한 호출 그래프가 아니다. 자산 참조는 `Assets` 내 텍스트 직렬화 자산 161개에서 조사했다. Package·바이너리·외부 저장소까지 참조가 없다는 증명은 아니다. 삭제 직전 범위를 다시 검사하고 Unity 비 Play import/compile에서 확인한다.

## 삭제 순서와 사람이 할 일

기존 프리팹을 먼저 전부 지우라는 요구가 아니다. 사람이 구조를 이해하고 새 리소스로 만들 수 있도록 [제작 가이드](<씬 흐름과 수동 프리팹 제작 가이드.md>)를 먼저 제공한다. 현재 프리팹 원본 삭제/재생성/Apply는 에이전트가 하지 않는다. 소유 씬·자산에서 필요한 컴포넌트/참조의 최소 이관은 가능하나 보호 원본과 중첩 원본은 건드리지 않는다.

1. 아래 참조표로 이전 타입·GUID를 사용하는 씬/프리팹/Editor를 확인한다.
2. 새 소유 컴포넌트로 코드와 저장 참조를 이관한다. 새 프리팹 제작 시에는 최종 컴포넌트만 넣는다.
3. 현재 소비의 GUID 참조가 0이고 C#·Editor 호출이 0인 것을 확인한다. 사람이 보관/교체 중인 참조가 남으면 해당 소스는 삭제 대기로 표시한다.
4. 소유 `.cs`와 해당 `.meta`를 함께 삭제하고 import/compile에서 Missing Script/호출 실패가 없는지 확인한다.
5. 하트 리소스 연결 전 HudIconGraphic은 보존한다. 실제 Sprite로 이관한 뒤 삭제한다. 무자료 placeholder를 만들어 삭제 수량을 맞추지 않는다.

삭제 대상은 자동 제작 도구 12개와 런타임/계약 11개, 총 23개다. 그중 HudIconGraphic은 사람의 실제 하트 리소스 연결이 선행 조건이다. 이번 READY에서는 0개 삭제했다. 신규로 필요한 편집 어댑터가 생길 수 있으므로 최종 파일 수를 완료 기준으로 고정하지 않는다.

이전 READY와 다른 점: SceneComponentLookup은 씬 루트 분리 후 여러 소유자가 공유하는 씬 탐색/단일성 검증에 필요하므로 유지·확장한다. CoroutineOperationRunner와 SessionShutdownOperation은 실패 시 해제 책임이 실제로 있어 유지한다. Periodic의 5/2/3초 필드는 폐기하지 않고 V1.5의 편집 가능 수치로 살린다.
