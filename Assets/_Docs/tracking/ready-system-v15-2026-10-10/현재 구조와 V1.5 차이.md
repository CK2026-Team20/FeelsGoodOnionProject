## 현재 책임과 수명

HP·폼·조각·물리 원본은 HMS Actor, 마지막 CP·현재 해금은 GameSessionService, Stage 배치와 각 기믹은 실제 owner, 일반 대화 완료 장부는 DialogueService다. 화면은 ViewModel 상태·명령에 연결한다. 로케이터는 scoped 등록/조회/역순 해제, App/Core 조립자는 실제 생성·Unity 참조 연결·부분 실패 회수다. 파일마다 새 인터페이스/팩토리를 만들지 않았고 실제 외부 자원·비동기·교체 경계만 유지했다. [스크립트 필요성 및 삭제 계획](<스크립트 필요성 및 삭제 계획.md>)에 각 파일과 합치지 않은 이유를 적었다.

## 누락과 외부 작업을 구분

- T15 HudIconGraphic 삭제는 사람이 실제 하트 Sprite·Image3개와 Q/E·조각 표시 소비를 이관한 뒤 가능하다. 현재 Native 소비12개/raw 저장6곳을 보존한다.
- 순찰 적4종/Linear/OvenTray template의 필수 외부 배치12개는 새 Scene 인스턴스에서 사람이 Marker를 드래그한다. Stationary 두 template의 순찰4개 빈 슬롯은 미사용이다. 실제 작성 Stage의 필수 참조 누락과 다르다.
- 실제 애니메이션·아트·하트 표시와 자연 Rigidbody 접지·충돌·전체 게임 동선은 사람이 Play로 검증한다. 에이전트는 Play 버튼·API·pipeline·batch PlayMode·직접 플레이를 실행하지 않았다.
- Stage1→2→3 본편 연결, 서버/네트워크, 디스크 이어하기, 적 HP/처치/기름 드롭, 붕괴 같은 시도 자동복구는 현행 범위가 아니다. 기능 누락으로 간주해 임의 구현하지 않는다.

최종 비 Play 결과와 빌드, 남은 사람 확인은 실제 명령·Source/DLL/BuildReport 식별로 기록한다. 이전 Play·QA·clip 검증 결과는 새 V1.5의 통과로 승계하지 않는다. 현재 계획을 구현 완료로 바꾸는 것은 최종 실행 증거가 있는 항목에 한정한다.

## 최종 검토에서 보완한 센서 책임

체크포인트와 포포 도착은 '한 시도에 한 번' 값과 관계없이 재접촉 규칙을 따른다. 같은 체류에서 수락은 한 번이며 완전히 나간 뒤 다시 요청한다. CP 저장 서비스는 마지막 Marker 재접촉을 거절하고 A→B→A에서는 새 현재 위치·조각·해금을 저장한다. 포포 최종 대화만 일반 Completed/Skipped 장부를 보존한 새 회차를 허용한다. 데드존은 실제 몸체별 중복을 막고 다른 종류는 기존 once 설정을 따른다.

StageTrigger는 체류/실제 몸체 중복만 소유하고 CP 마지막 Marker·최종 대화 장부/회차 판단은 기존 서비스로 전달한다. contactKind/contactActor는 종류·Actor 교체 뒤 낡은 센서 수락을 버리는 일시 기록이며 저장 원본이 아니다. B03 Quarter 설명은 고정 Transform 필수/Side만 Z정렬이라는 현행 Source 계약으로 수정했다. 현재 Source a192d2a7의 컴파일158/158/11·Player204·Native201·6씬 빌드 오류0/경고48과 남은 미평가는 검증 기록을 따른다.
