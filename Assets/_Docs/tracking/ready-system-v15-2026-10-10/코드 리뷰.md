# 코드 리뷰 — V1.5 READY

이번 검토는 현재 source/저장 자산 분석과 구현 계획 검수다. 수정된 게임 코드의 승인 리뷰나 실행 통과 보고가 아니다. branch `feature/core/systems`, 시작 HEAD `cd528ce`, 제품 코드·씬·prefab 변경0인 상태에서 수행했다.

## 실제 결함/명세 차이

우선 교정할 현재 source는 2항목 CP·Stage 출처 reset·추격 저장 누락, Periodic의 MTD/몸높이 혼용·얕은 침투 무처리·껍질 소유자 사망·Visual만 이동·시간 강제, Tear Render만 이동, manager child 탐색, target/ID 수기 작성, 피해원별 넉백, Skip View/VM 미연결과 Completed 전용 최종 종료다. 각각 실제 source 경로/영향은 [차이 분석](<현재 구조와 V1.5 차이.md>)에 있다. 사용자가 보고한 게임 증상을 직접 Play로 재현한 결과는 아니다.

## 독립 의도 검토와 반영

DryForge의 첫 독립 검토는 사용자 요청·질문/답변 원문과 결정 목록을 읽고 진행했다. 신규 사용자 미결 결정0건, 근거 수정1건을 반환했다. 검토자가 source나 문서를 수정하지 않았다.

수정한 근거는 능력 재잠금과 안내 대화 완료 기록의 분리다. V1.5 P0237은 능력 재해금, P0425는 완료 대화 재실행 금지다. 이전 Stage reset 안내 forget 경로를 그대로 승계하지 않는다. 따라서 CP로 해금/HUD는 복원하지만 Completed/Skipped 장부는 유지, Cancelled만 재시작 가능하게 spec에 반영했다.

이후 직접 답변으로 HMS2파일 최소 권한과 한 응집형 Stage의 프로토타입 범위가 명확해졌다. Stage간 자동 연결을 이번에 넣지 않고 각 씬 독립 진입은 유지했다. SceneComponentLookup과 실패 해제 helper의 유지, 조절 수치 보존 등 현재 V1.5에 필요한 차이도 이전 READY에서 다시 평가했다.

## 문서 정합성과 실행 전 확인

- CameraZoneData는 value struct다. 컴포넌트처럼 drag하라고 설명하지 않는다. CameraZoneTrigger가 실제 모드/정렬점을 작성하고 Marker는 그 Trigger를 연결한다.
- Player/Shell/Platform의 실제 physical Root와 빈 prefab wrapper를 구별한다. 메시·Collider 형제 배치가 자동으로 함께 움직인다고 설명하지 않는다.
- V1.5 P0076은 실제 Root 배율 유지다. Form Collider 전환에 Root scale 축소를 추가하지 않는다.
- 현재 등록6씬과 Stage1→2→3 자동 진행은 다르다. 현재 Prototype에는 추격/포포/기믹이 응집되어 있고 자동 순차 진행 API는 연결되어 있지 않다.
- 미래 새 prefab 제작과 source 삭제의 순서는 참조 해소 조건으로 명시한다. 사람이 기존 prefab을 이미 삭제했다고 가정하지 않는다.
- scene asset에 다른 Scene의 Component를 저장하지 않는다. 설치/직접 진입은 SceneAsset, 로드된 Stage가 자기 초기 Marker를 제공한다.
- 필수 물리 설정/자산 연결과 runtime service 생성은 구별한다. PlayerSkill 실행 객체·ViewModel·Locator를 Add Component하지 않는다.

최종 독립 3문서 검수와 기계 검사는 `evidence/3doc-review.md`, `evidence/document-checks.json`의 실제 결과를 확인한다. 문서 검사 통과는 Unity compile/Play/build를 증명하지 않는다. 후속 source diff 리뷰는 구현 후 같은 구조로 결과와 남은 조건을 갱신해야 한다.

이번 READY의 최종 결과는 기계 검사 24개 통과, 요구사항 누락/고립 작업 0건, 대화 이력 없이 수행한 독립 3문서 검수의 차단 항목 0건이다. 제품 소스와 저장 자산은 변경하지 않았다. 실행 승인 전에 검토할 수 있는 명세·계획·제작 안내가 완성된 상태다.
