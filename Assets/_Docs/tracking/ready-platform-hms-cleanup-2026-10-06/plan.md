# 플랫폼 설정·HMS 조립·소스 정리 실행 계획

2026-10-06. `기능 명세서.md`의 R1~R8을 실행하기 위한 계획이다. 아직 제품 구현·삭제·커밋을 수행하지 않았다. 실제 공유 파일·Unity 상태를 변경하는 단계는 메인이 한 흐름으로 조정한다.

## 실행 흐름

먼저 기존 변경과 구형 직렬화 데이터를 보존하고, 확정된 테스트·더미·대체 중복을 정리한다. 이후 선형 발판·트리거 정렬·붕괴 Controller를 구현하고 소유 자산을 연결한다. 최종 코드에 맞춰 Tooltip·지침·실행/QA 문서를 갱신한 뒤 결합 검증·새 빌드·독립 검토를 끝낸다. 마지막으로 기존 변경을 포함한 최종 diff를 기능별 커밋하고 yeet으로 push와 PR 반영을 확인한다.

실제 자산 저장·씬 전환·Play·빌드는 병렬 실행하지 않는다. 기능 코드가 독립적으로 작성되더라도 아래 소유 자산 연결은 메인이 직렬 수행한다. 작업자 수나 역할 수는 고정하지 않는다.

## T1. 기준점 보존·책임 감사·이관 자료와 커밋 분류

**목표:** R1/R2/R3/R5/R8의 변경 대상을 참조·동작 근거로 확정하고 구형 설정을 잃지 않는다.

**대상:** SYM C# 전체와 저장 씬/프리팹/설정; HMS 공개 기능의 읽기 대조; 현재 250개 미커밋 변경; `output/Tech_SYM/planning/platform-hms-cleanup-2026-10-06/`의 기준점·조사 데이터; 같은 tracking 폴더의 코드 리뷰/검증 문서.

**계약:** 코드/자산/보호 원본/기존 staged 상태를 실행 직전에 다시 확인하고 현재 사용자 작업을 보존한다. 삭제 목록마다 사용 기능·소스/GUID/메뉴/동적 참조·HMS 대체 위치·차이를 기록한다. LinearShuttlePlatform의 방향·속도·시간과 CameraZoneData의 Origin/Legacy/소유 Transform을 변경 전 읽어 실제 월드 기준점으로 보관한다. 소유 배치·prefab override·체크포인트·조립 도구를 빠뜨리지 않는다. 이 자료는 임시 증거 경로로 저장하고 기존 자산을 다시 생성하지 않는다.

기존 250개 항목의 의미를 검토하고 입력·폼, HMS/카메라/진입, UI·수명, 적·메모, 자산, 문서, 기존 설정별로 분류한다. 기존 보호 파일의 커밋 포함은 이번 실행에서 그 원본을 고치는 권한과 구분한다. 실질 diff가 없는 줄바꿈 항목은 별도 기능 변경으로 설명하지 않는다.

**통과 기준:** 이관 대상과 삭제 후보의 증거 목록 존재, 보호 기준점·Git 상태 보존, 최종 커밋 분류의 초기 목록 작성. 현재 사전 감사의 37개 테스트 후보와 ActorFacingPresentation을 기준으로 추가 확인한다. 이 단계 자체는 기능 실행 PASS가 아니다.

## T2. 더미·테스트 소스·HMS 대체 중복과 빈 폴더 정리

**목표:** R5/R6의 전면 정리 요청을 실제 소비 계약에 따라 적용한다. 구형 테스트가 이후 설정 변경을 불필요하게 묶지 않도록 먼저 정리한다.

**대상:** 사전 코드 리뷰의 테스트·검증 전용 37개 및 대응 `.meta`; `Architecture/Session/ActorFacingPresentation.cs`와 `.meta`; `Session/Editor/HmsActorCameraAuthoring.cs`의 이전 타입 참조; T1에서 추가 확인된 SYM 더미·중복; 삭제로 빈 SYM 폴더.

**계약:** HMS Visual을 사용하는 소유 객체가 유지되는지 확인하고 대체 중복을 삭제한다. 테스트 타입·런타임 검증 입력 경로·검증 메뉴·전용 가짜 구현을 Assets에서 제거하며 코드 참조를 함께 정리한다. 정리 결과를 삭제/대체/유지 근거별로 기록한다. 실제 Editor 진입·빌드·편집 도구는 유지한다. HeavyState, 세션 입력 라우터/Bridge, 여러 기믹이 사용하는 물리/접촉 책임을 근거 없이 없애지 않는다.

새 검증은 외부 일회성 실행으로 수행할 수 있도록 필요한 과거 실행 절차를 증거로 확보한다. 제거할 테스트를 프로젝트에 다시 복사하거나 무관한 전체 코드 정리를 하지 않는다. 전용 원본·메타 삭제와 잔존 참조를 함께 확인한다. 빈 폴더 삭제 대상의 절대 경로가 SYM 소유 경계 안인지 검증한다.

**통과 기준:** 삭제 타입의 실사용·직렬화 참조 0, 정상 컴파일, 소유 객체의 HMS Visual 유지, 삭제·유지 판단과 비어 있는 폴더 목록 기록. T1의 기존 보호 바이트와 staged 상태를 보존한다.

**계약:** 경고 Tween → 지지 Collider 해제 → Animator 붕괴 상태 → 완료/기존 제거·복구 정책의 흐름을 구현한다. Controller의 준비/붕괴/완료 상태와 클립 Motion 연결 계약을 마련하되 `.anim`/가짜 클립은 만들지 않는다. 클립 미연결 시 물리 붕괴·외형 숨김과 명확한 경고를 수행한다. 클립 없음과 필수 구성 오류를 구분한다. 중복·정지·비활성화·늦은 콜백 정리와 Prototype 비복구/기존 독립 복구 정책을 유지한다.

**통과 기준:** Controller 구조·실제 Animator 참조·필수 상태 검증, 가짜 클립/추가 시험 자산 0, 현재 클립 미연결 경로에서 종료·정리 가능, 정상 컴파일. PC-05/06은 T7에서 실제 물리로 검증한다. PC-07은 자산 연결 이후 인계다.

## 소유 자산 연결: 메인의 단일 저장 단계

T3/T4/T5의 코드와 최종 설정이 준비된 뒤 메인이 T1의 이관 자료를 사용해 소유 자산을 직렬 저장한다. 각 기능 작업은 같은 prefab/scene에 독립적으로 덮어쓰지 않는다. 전체 Builder를 돌려 과거 자산을 다시 생성하지 않고 필요한 컴포넌트·설정·연결만 수정한다.

기존 LinearPlatform/MultiFuncPlatforms와 소유 선형 배치, ShatteredPlatform과 Prototype/독립 붕괴 배치, 기존 구간/체크포인트를 저장하고 다음을 확인한다: 예전 기준점 보존, 새 계층 변화에 따른 로컬 계산 일치, Animator가 Collider 없는 Visual을 사용, 필수 참조·Missing 0, 자기 소유 씬 `isDirty=false`, 보호 원본/기존 GUID 불변. 실제 소유 파일을 옮긴 경우 원본과 `.meta`를 함께 이동하고 GUID를 보존한다.

이 연결은 병렬 기능 작업의 공유 자산 쓰기를 하나로 모으는 메인 절차다. 독립 구현 작업으로 배정하지 않는다. T6/T7을 시작하기 전에 끝낸다.

## T7. 최종 기능 결합 검증·새 빌드·독립 검토

**목표:** R7 및 앞선 모든 기능 요구의 관찰 가능한 결과를 검증하고 R8 커밋을 위한 최종 근거를 만든다.

**대상:** 현재 기존 Prototype과 소유 독립 씬/프리팹, 설치의 여섯 씬, T1의 원본·Git 기준점; `테스트 및 검증 항목.md` PC-01~PC-12와 QA Excel; 결과 경로 `output/Tech_SYM/verification/platform-hms-cleanup-2026-10-06/`.

**실행 도구:** `unity status --project-path <project> --format json`, `unity pipeline list --format json`와 실제 Editor 질의로 연결을 확인한다. 자동 기능 검사 파일은 구현 시 해당 output 폴더의 `RunPlatformAndIntegrationChecks.cs`로 일회성 작성하고 `mcp__unity__run_script`의 `file`/`entry`/`timeout_ms`로 실행한다. 이 파일은 현재 존재하는 검증 도구가 아니며 이번 실행에서 작성·검증·제거할 대상이다. 완료를 비동기로 기다리는 검사는 짧은 상태 조회로 결과를 수집하고 실행 수명·취소·원래 씬/시작 설정 복원을 확인한다. 결과 JSON·명령·해시·오류를 기록한 뒤 임시 C#을 삭제한다. Assets에 테스트 코드를 다시 넣지 않는다.

**계약:** 컴파일·전체 소유 자산 참조/삭제 GUID/Missing·기즈모와 로컬 좌표·무게 접촉·왕복/탑승/점프·Brain/정렬/정지·해제 뒤 콜백·진입/재시도/두 게임의 입력·Actor/UI 수명 결과를 필요한 회귀 범위에서 확인한다. 기존 통과를 이번 실행으로 복사하지 않는다. 임시 조작은 런타임에만 만들고 시험용 씬/자산을 남기지 않는다. 미저장 사용자 작업이 있으면 자동 저장·폐기하지 않는다.

## T8. 기존 변경을 포함한 기능별 커밋·실제 push·PR

**목표:** R8/PC-12의 실제 저장소 반영을 완료한다. 이 단계는 메인이 직접 yeet으로 수행한다.

**대상:** 기존 250항목과 이번 최종 변경의 reviewed diff, 현재 `feature/core/systems` 브랜치와 origin, 해당 브랜치의 PR, 최종 커밋 목록/원격 확인 기록.

**계약:** gh 설치/로그인과 현재 브랜치를 다시 확인한다. 최종 제목·본문·파일 범위를 사용자에게 표시한 뒤 기능·종류별 커밋을 만든다. 이미 받은 커밋·push·yeet 허가를 반복 요청하지 않는다. 예시 분류는 아래와 같으며 실제 제목/범위는 최종 net diff를 보고 결정한다.

- `feat` 입력·폼 자동 회수, HMS/세션·카메라 조립, 3차원 선형 이동 설정, 붕괴 Controller 준비.
- `fix` 로컬 정렬/기즈모, 입력·메모·적·수명 관련 기존 수정.
- `refactor` HMS 대체 중복·더미·테스트 소스/빈 폴더 제거.
- `docs` Tooltip·조립/병합 규칙·현재 기능/QA·검증 근거.
- `chore` 기존 Editor 직렬화/설정의 검토된 실질 변경.

변경이 결합된 같은 파일은 안정된 중간 상태를 유지할 수 있는 범위로 묶는다. 임시 소스·무관한 생성물·비밀·출력 파일을 정리하고 분류 전 `git add -A`로 무조건 일괄 커밋하지 않는다. 이전 HEAD의 역사와 과거 기획·증거를 삭제하지 않는다. 기능별 이력을 만든 후 실제 push, 원격 HEAD 일치를 확인한다. 현재 브랜치의 PR이 없으면 yeet의 신규 Draft PR, 있으면 현재 draft/ready 상태를 보존해 갱신한다. 생성/작업 PR을 현재 chat에 연결한다. merge는 하지 않는다.

**통과 기준:** 종류·기능별 SHA/본문/범위와 실제 push 성공 기록, 로컬/원격 최종 HEAD 일치, 최종 git 상태·PR 링크/상태 확인. 미실행 원격 반영을 완료로 기록하지 않는다.

## 2026-10-06 실행 중 사용자 추가 지시: 자동 저장 변경

사용자 직접 지시: “자동으로 추가된것도 앞으로는 전부 커밋 하십시오.” Unity/Editor가 자동 저장한 변경은 발생 원인과 실제 diff를 확인하여 유지하고 종류별 커밋에 포함한다. 실행 전 보호 기준점은 삭제하거나 새 값으로 덮어쓰지 않는다. 자동 변경의 이전/이후 해시·원인·포함 판단을 별도로 기록해 승인된 자동 저장과 에이전트의 직접 수정을 구분한다. 이 지시는 타 작업자 원본의 수동 코드 수정·Apply·삭제 권한을 확대하지 않는다.

이번 재컴파일에서 ProBuilder가 추가한 `editor.autoRecalculateCollisions=false`는 유지·커밋 대상으로 승인되었다. 기존 “보호 바이트 변경 0” 완료 기준은 **승인된 자동 저장 변경 이외의 보호 원본 변경 0**으로 적용한다. 실제 빌드 실행 전후 설정 차이도 숨기지 않고 발생 원인과 승인 여부를 기록한다. 이 예외 때문에 실행 결과를 허위로 원본 바이트 불변이라고 표기하지 않는다.
