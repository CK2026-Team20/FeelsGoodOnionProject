## 목표와 이유

레벨을 부모 계층 아래에 배치해도 이동 발판의 경로와 카메라 전환 정렬 위치를 Inspector에서 직관적으로 설정할 수 있게 한다. 방향 목록 대신 3차원 상대 이동량을 사용하고 Scene 기즈모가 실제 위치 계산과 일치하게 한다.

붕괴 경고 이후의 표현은 Animator에서 실제 클립을 재생하는 구조로 준비한다. 지금은 Controller와 연결 체계만 만들고 실제 클립은 자산을 받아 연결할 때 적용한다. SYM이 임시로 만든 더미·중복·테스트 전용 코드를 책임과 참조에 따라 정리하고 HMS 기능을 가능한 곳에서 직접 재사용한다. 쉬운 Tooltip과 조립·정리 기준을 지속적인 에이전트 지침으로 반영한다.

최종 실행에는 기존 미커밋 변경도 포함해 기능별로 검토·분류하고, 종류별 커밋 이력과 실제 push를 남긴다.

## R1. 부모 기준 3차원 이동 발판

선형 이동 발판의 Inspector는 **부모 기준 도착점 이동량(X/Y/Z)**과 **이동 속도(m/s)**를 설정한다. 이동량은 단순 방향 벡터가 아니라 시작점에서 끝점까지의 전체 거리다. 이동량을 정규화해 입력한 길이를 잃지 않는다. 방향 열거·편도시간은 독립적인 경로 원본으로 남기지 않는다.

실행 시작 시의 부모 로컬 시작점과 상대 이동량으로 두 끝점을 정한다. 부모가 없으면 같은 값을 월드 기준으로 해석한다. 부모의 위치·회전·배율을 반영해 월드 끝점을 계산하며 부모 계층의 변화가 기즈모와 실제 경로에 동일하게 적용된다. 편도시간은 실제 경로 길이와 속도에서 계산된다. Inspector 경로 설정의 실행 시작 시 적용 계약은 유지하며 부모 Transform 변화와 경로 설정값 변경을 혼동하지 않는다.

기존의 일정 속도·끝점 무대기 왕복, 탑승 속도 전달, 점프 이탈, 정지·재개와 비활성화 시 접촉 정리 계약을 유지한다. 위치 적용자는 하나다. 같은 발판에 HMS MovingPlatform과 SYM 이동 드라이버를 중복 설치하지 않는다.

이동량이 0이면 시작점에 머무르고 0으로 나누지 않는다. 속도는 유한한 양수이며 기존 최소값 0.01m/s를 유지한다. NaN/Infinity와 범위를 벗어난 수치는 경계에서 명확히 처리하고 이상 좌표를 Rigidbody에 전달하지 않는다.

현재 저장 자산의 방향·속도·편도시간에서 기존 월드 끝점을 먼저 추출하고, 소유 계층의 부모 기준 이동량으로 이관한다. 현재 저장 배치의 두 끝점이 의도 없이 바뀌지 않았는지 확인한다. 이관 이후 지속적인 숨은 이전 방향·시간 필드나 미사용 호환 코드를 남기지 않는다.

HMS MovingPlatform은 월드 이동량과 끝점 대기를 제공하며 부모 기준 이동량의 공개 계약이 없다. 이번 요구를 그대로 대체할 수 없으므로 SYM의 필요한 경로 책임을 유지한다. 원본 private 필드에 런타임 주입하거나 HMS 코드를 복제해 우회하지 않는다.

## R2. 트리거 로컬 정렬 위치와 기즈모

CameraZoneTrigger의 플레이어 정렬 기준은 **트리거 자신의 로컬 오프셋**이다. 트리거 Transform으로 로컬 위치를 월드 기준점으로 변환한다. 부모의 위치·회전·배율과 트리거 자신의 Transform이 변환에 반영된다. Inspector에서 월드 절대 위치를 다시 입력하게 하지 않는다.

트리거 접촉에서 전달하는 정렬 기준점과 `OnDrawGizmos`의 기준점은 같은 계산을 사용한다. Scene 배치 중 선택 여부와 관계없이 기즈모가 표시되며, **파란색** 기준점과 현재 정렬 축/평면을 식별할 수 있다. Tooltip은 이 값이 플레이어 정렬 기준이며 파란 기즈모로 표시된다고 설명한다.

Side 전환은 변환한 기준점의 월드 Z로, 통로 전환은 월드 X로 플레이어를 보간 정렬한다. 이 값은 전체 XYZ로 순간이동하는 목표가 아니다. 쿼터뷰에는 별도 평면 정렬을 추가하지 않는다. HMS가 소유한 모드별 월드 이동축은 유지한다. 좌표를 설정하는 방법의 개선과 모드별 이동축 변경은 다른 작업이다.

실제 Brain 블렌드와 물리 정렬이 모두 끝난 뒤 HMS 모드를 확정한다. 같은 구간 중복 요청 억제, 다른 구간의 최신 요청 수락, 옵션 정지·재개, Disable/Destroy/Actor 제거 시 자기 전환·차단만 해제하는 계약을 유지한다. 초기 체크포인트의 즉시 카메라 적용은 기존처럼 플레이어 위치를 추가 정렬하지 않는다.

현재 구간·체크포인트의 `Origin` 월드 위치를 해당 소유 Transform의 로컬 값으로 이관한다. 현재 소비되지 않는 수동 카메라 위치·시선·범위 자료는 참조와 저장 자산 이관 후 제거한다. Legacy 모드가 남아 있는 소유 데이터를 명시적 Side/Corridor/Quarter로 옮긴 뒤 미사용 해석 분기를 정리한다. 초기 진입 코드와 실사용 조립 도구도 최종 계약을 사용한다.

설정 데이터는 구간 ID·명시적 이동 모드·로컬 정렬 오프셋을 구분한다. 월드 정렬점은 요청 경계에서 계산한 실행 데이터이며 독립적인 Inspector 원본이 아니다. 구간 ID의 유일성·동일 구간 중복 억제 의미는 유지한다.

## R3. 붕괴 Animator 연결 준비

경고 흔들림 Tween은 유지한다. 경고가 끝나면 지지 Collider를 끄고 **실제 Animator의 붕괴 상태**로 전환한다. 실제 클립이 연결되어 있으면 해당 상태의 재생·완료를 기준으로 외형 숨김과 기존 제거/복구 정책을 진행한다. Tween의 축소·타이머를 실제 애니메이션이 재생되었다는 근거로 삼지 않는다.

지금 만들 자산은 **Tech_SYM 소유 Animator Controller**다. 실제 `.anim`이나 가짜·시험용 클립은 만들지 않는다. 소유 붕괴 프리팹과 실제 배치의 Collider 없는 Visual에 Animator와 Controller를 연결한다. 물리 루트를 애니메이션으로 이동시키지 않는다. 기존 같은 객체의 BoxCollider 요구는 기록된 배치 예외로 유지한다.

Controller는 준비 상태, 붕괴 상태, 완료 상태와 붕괴 요청을 위한 계약을 제공한다. 붕괴 상태의 Motion에 실제 클립을 연결하면 추가 코드 작성 없이 동작해야 한다. 실제 클립의 루트 경로·완료 전환·정지 시간축과 연결 절차를 문서화한다. _Art/HMS에서 받아온 원본 클립이나 import 설정은 수정하지 않고 소유 Controller에서 참조한다.

**클립 미연결은 허용된 준비 상태**다. 경고 완료 후 Collider 해제와 외형 숨김으로 물리 붕괴를 진행하고, 해당 실행에서 연출 미연결 경고를 명확히 남긴다. 무한 경고 출력·끝나지 않는 대기·애니메이션 재생 성공 허위 판정은 허용하지 않는다. Controller/Animator/필수 상태의 잘못된 구성과 단순 클립 미연결을 구분해 오류 문맥을 남긴다.

ShatteredPlatform이 접촉 판정과 진행 상태를, 표현 객체가 경고·Animator·렌더 표현을 맡는다. Animator는 View 역할의 표시 수단이며 게임 판정의 별도 권위 상태가 아니다. 경고·재생·완료·취소의 소유자가 명확해야 한다. 중복 요청을 한 번만 처리하고 해제 뒤 늦은 완료 콜백을 실행하지 않는다. 월드 정지에 따라 경고와 붕괴 재생도 정지한다.

무거운 활성 플레이어의 윗면 접촉만 시작하며, 작은 플레이어·옆면·아래 접촉은 시작하지 않는다. 시작한 뒤 플레이어 이탈은 취소 조건이 아니다. 신규 Prototype은 붕괴 후 자동 복구하지 않는다. 기존 독립 자산의 복구 설정과 비활성화/풀 재사용·스테이지 재준비 계약은 보존하며 별도 지시 없이 일괄 변경하지 않는다.

실제 클립 제작·다운로드·원본 import 수정과 실제 애니메이션 재생/품질 검증은 이번 범위에서 제외한다. 실제 자산을 연결할 때 수행할 검증 항목을 인계한다. Controller 연결·미연결 물리 경로 검증으로 지금의 시스템 준비를 완료할 수 있다.

## R4. 쉬운 한국어 Tooltip 지속 규칙

모든 신규·변경 직렬화 필드에는 비개발 직군이 이해할 수 있는 한국어 Tooltip을 제공한다. 숫자만이 아니라 bool·열거·오브젝트 참조·배열·중첩 직렬화 데이터와 Unity가 직렬화하는 public 필드도 포함한다. 단순 이름 번역으로 끝내지 않는다.

설정의 목적, 해당하는 단위·좌표 기준, 값 증가/감소·0/기본값의 의미, 연결할 대상과 영향을 쉽게 설명한다. 해당하지 않는 항목을 형식적으로 나열하지 않는다. 기즈모와 연결되는 값은 실제 색상과 표시 의미를 함께 설명한다. 예를 들어 “플레이어가 정렬될 위치를 트리거 기준으로 조정합니다. 파란색 기즈모로 표시됩니다. 사이드뷰는 앞뒤 위치, 통로는 좌우 위치를 맞춥니다.”와 같이 표현한다.

이번 변경 영역과 관련 SYM 누락을 감사·보완한다. 새 ActorCameraRig의 참조 필드도 포함한다. 보호 HMS 누락 필드는 읽기·보고만 하며 현재 포괄 지시로 원본 Tooltip 수정 권한을 넓히지 않는다.

루트 AGENTS.md/CLAUDE.md의 동일한 규칙, standards와 관련 SYM 지역 지침에 이 요구를 반영한다. 프로젝트 문서끼리 모순되는 기준을 남기지 않는다. 사용자 공통 지침의 적용과 다른 기기 동기화 여부를 혼동하지 않는다.

## R5. HMS/SYM 책임 감사와 일괄 소스 정리

SYM 소스 전체에서 기능의 상태·입력·규칙·물리·표현·수명을 구분하고 HMS의 공개 계약과 대조한다. 각 제거 후보에 기능·참조·대체 코드·설정 이관·동작 차이·최종 판단을 기록한다. 완전 대체가 가능한 SYM 중복은 HMS를 직접 사용하고 SYM 구현·참조·전용 메타데이터를 제거한다. 임시 더미와 테스트·Editor 검증에만 필요한 소스도 최종 Assets 코드에서 제거한다.

현재 확인한 테스트·검증 전용 37개와 ActorFacingPresentation은 제거 대상으로 처리하되 실행 직전에 코드·GUID·동적/메뉴 참조를 다시 확인한다. ActorFacingPresentation을 제거할 때 HmsActorCameraAuthoring의 이전 타입 참조도 함께 제거한다. 감사에서 추가로 확인된 더미·중복에도 같은 기준을 적용한다.

GameplayInputRouter/PlayerBridgeService의 세션·정지·E 입력 책임, HeavyState의 HMS 폼/껍질 계약, 여러 기믹의 KinematicPlatformMotion/PlatformContacts, 상한 소비 정책이 다른 수집 기능은 실제 사용 계약 없이 제거하지 않는다. 이름만 비슷하다는 이유로 업무 규칙을 통합하지 않는다. 필수 Editor 진입 Hook·명시적 씬 빌드 도구·실사용 자산 편집/조립 도구는 테스트 소스와 구분한다.

테스트 소스 제거가 기능 검증과 기존 증거 폐기를 뜻하지 않는다. 새 기능의 자동 검증은 일회성 외부 실행으로 수행하고 결과·요구 케이스·실패 문맥을 보존한다. 이번 실행을 위해 임시 작성한 테스트 소스는 종료 전에 제거하며 Assets 또는 커밋에 다시 남기지 않는다. 남는 호환 코드에는 실제 소비자·이유·제거 조건을 기록한다.

조립·병합 지침은 **기능 소유자 하나 → 공개 계약과 실제 동작 비교 → 소유 객체에 연결 → 설정/참조 이관 → 대체 가능 중복 제거 → 결합 검증**을 따른다. 입력과 물리 적용자를 중복 설치하지 않고 SYM에 HMS 상태·규칙을 다시 구현하지 않는다. 필요한 세션/화면 조정 책임은 좁은 어댑터로 유지한다.

## R6. 폴더·문서·QA 정리

소스 삭제로 빈 SYM 폴더와 전용 `.meta`를 정리한다. 실제 사용 파일을 이동해야 한다면 Unity 자산 API와 기존 `.meta`를 사용해 GUID를 보존한다. 범위와 무관한 전체 이름 변경·네임스페이스 재작성·폴더 재설계는 하지 않는다.

HMS·공용·아트·Packages·ProjectSettings 원본, 역사적 씬, 원본 기획과 과거 검증 증거는 임의 삭제하지 않는다. 현재 호출할 수 없는 검증 메뉴를 operations와 활성 지역 지침의 실행 방법으로 남기지 않는다. 과거 기록은 당시 증거로 보존하고 현재 실행 방식에서만 구분한다.

planning-index, business-rules, architecture/contracts의 영향 절, standards, engineering-notes, operations, 관련 지역 지침을 최종 소스에 맞춰 갱신한다. tracking/status와 findings는 실제 실행 결과·미검증·제한을 구분한다. 이 승인 검토 단계에서 과거 구현 상태를 새 기능 완료로 덮지 않는다.

기존 기능 테스트 Excel의 결과·서식을 보존해 변경 기능 케이스와 실행 환경을 갱신하고, Git으로 공유되는 케이스 Markdown도 동기화한다. QA가 작성하는 FunQA 원본·작성 양식·평가 결과를 임의로 바꾸지 않는다.

## R7. 완료를 위한 검증

같은 폴더의 `테스트 및 검증 항목.md` PC-01~PC-12를 완료 계약으로 사용한다. 핵심 자동 검증은 기존 Prototype 및 소유 독립 씬의 이동·탑승·점프·정렬·Brain·정지·붕괴 접촉/미연결·retry 결합 결과다. 별도 검증용 씬을 만들지 않는다.

변경 후 컴파일 성공, SYM 자산 Missing Script/필수 null/삭제 GUID 참조 0, 실제 로컬 끝점·기즈모 일치, 자기 구독/차단·비활성화 정리, 소유 저장 자산 clean, 기준점 이후 보호 원본 변경 0을 확인한다. 소스 정리 후 통합/독립 진입과 E/F/Q·폼·기절·카메라·세션 수명을 필요한 회귀 범위에서 확인한다.

기존 IntegrationBuildPipeline의 명시적 여섯 씬 Windows 빌드를 새 최종 소스에서 실행한다. Succeeded/errors0와 실행 전후 ProjectSettings 불변을 확인한다. 팀의 실제 빌드 플레이·UI/UX·FunQA와 실제 자산 클립 재생은 별도 인계 상태다. 이전 빌드·이전 자동 검사 결과를 이번 실행으로 주장하지 않는다.

독립 구현 검토의 차단 사항이 0이어야 커밋·push로 진행한다. 실제 실행하지 않은 검증을 통과로 기록하지 않는다.

## R8. 기능별 커밋·push·yeet

기존 250개 변경 항목과 이번 요청의 최종 변경을 함께 검토한다. 이미 승인받아 작성된 HMS Q/F 입력·폼 변경 및 기존 설정 변경의 커밋 포함과 이번 실행의 새 원본 수정 권한을 구분한다. 실질 차이가 없는 줄바꿈만으로 의미 없는 기능 커밋을 만들지 않는다.

작업 완료 후 사용자 커밋 종류 규칙에 맞춰 `feat`, `fix`, `refactor`, `docs`, `chore` 등 기능별 이력을 만든다. 입력/폼, HMS·카메라·Editor 진입, UI·수명, 적·메모, 선형 발판, 붕괴 Animator, 로컬 정렬, 중복/테스트 정리, 지침/QA와 기존 Editor 설정을 최종 diff에 맞춰 분류한다. 같은 파일의 결합된 변경은 끊어진 중간 상태가 생기지 않게 검토한다.

커밋 직전 실제 제목·본문·파일 범위를 표시한다. 요청된 커밋·push·yeet은 이미 허용되었으므로 같은 Git 행동의 허가를 반복 요청하지 않는다. yeet의 현재 브랜치 유지·실제 push·신규 Draft PR 또는 기존 PR 갱신 절차를 따른다. `git add -A` 전에 범위 검토와 임시 소스 제거를 끝낸다. 원격 브랜치 HEAD가 로컬 최종 HEAD와 같은지 확인하고 실제 커밋 SHA·PR 링크를 기록한다. 병합은 수행하지 않는다.

## 제약과 선택 이유

부모 기준 이동량과 트리거 기준 로컬 오프셋은 계층 배치에서 월드 절대값을 계산할 필요를 없앤다. Controller만 준비하는 것은 자산을 받은 뒤 실제 클립을 곧바로 연결하려는 요구에 따른다. 미연결 물리 붕괴는 자산 도착 전에도 발판 기능을 유지하면서 미제공 연출을 숨기지 않기 위한 처리다.

수정은 승인된 SYM 코드·소유 씬/프리팹/Controller·프로젝트 문서와 대응 메타데이터에 한정한다. 타인 원본 수정·삭제·Apply·GUID 변경, 원본 아트/애니메이션 제작·import 변경, 미저장 작업의 자동 저장/폐기, 무관한 프로젝트 설정 변경은 범위 밖이다. 기존 계층의 물리 계약과 공용 공개 API를 유지한다.

Unity 자산 저장·씬 전환·Play·빌드는 한 흐름으로 수행한다. 실제 자산·상태를 공유하는 작업을 동시에 실행하지 않는다. 서버·네트워크·플레이어 실제 애니메이션 연결·본편 추가 레벨 배치는 이번 작업에 추가하지 않는다.

## 2026-10-06 실행 중 사용자 추가 지시: 자동 저장 변경

사용자 직접 지시: “자동으로 추가된것도 앞으로는 전부 커밋 하십시오.” Unity/Editor가 자동 저장한 변경은 발생 원인과 실제 diff를 확인하여 유지하고 종류별 커밋에 포함한다. 실행 전 보호 기준점은 삭제하거나 새 값으로 덮어쓰지 않는다. 자동 변경의 이전/이후 해시·원인·포함 판단을 별도로 기록해 승인된 자동 저장과 에이전트의 직접 수정을 구분한다. 이 지시는 타 작업자 원본의 수동 코드 수정·Apply·삭제 권한을 확대하지 않는다.

이번 재컴파일에서 ProBuilder가 추가한 `editor.autoRecalculateCollisions=false`는 유지·커밋 대상으로 승인되었다. 기존 “보호 바이트 변경 0” 완료 기준은 **승인된 자동 저장 변경 이외의 보호 원본 변경 0**으로 적용한다. 실제 빌드 실행 전후 설정 차이도 숨기지 않고 발생 원인과 승인 여부를 기록한다. 이 예외 때문에 실행 결과를 허위로 원본 바이트 불변이라고 표기하지 않는다.
