# 붕괴 애니메이션 자산 연결

2026-10-06. 실제 자산을 받아 연결할 수 있도록 시스템과 Controller를 준비했다. 현재 Collapse의 Motion은 비어 있으며 실제 클립의 재생·블렌딩·표현 품질 검증은 자산 연결 후 수행한다.

## 연결할 위치

Controller: `Assets/_Scenes/Tech_SYM/Prefabs/Platforms/Animation/ShatteredPlatform.controller`.

기본 프리팹: `Assets/_Scenes/Tech_SYM/Prefabs/ShatteredPlatform.prefab`. SYM 소유 프리팹·씬의 붕괴 배치 7곳에 Visual Animator와 Controller, ShatteredPlatform.collapseAnimator를 연결했다. 새 배치는 같은 구성을 사용한다. 기존 독립 프리팹의 복구 설정과 Prototype의 canRegenerate=false는 서로 다른 설정이므로 배치 목적에 맞게 유지한다.

1. 자산 브랜치를 받아 실제 클립이 LFS 포인터가 아닌 Unity 자산으로 import되었는지 확인한다. 공유·아트 원본과 import 설정은 수정하지 않는다.
2. SYM Controller를 열고 첫 `Base Layer`의 `Collapse` 상태 Motion에 실제 붕괴 클립을 연결한다. `Ready`와 `Completed` Motion은 비운다.
3. 클립은 한 번 재생하며 반복하지 않고 양수 길이여야 한다. 필요한 Avatar가 있으면 소유 Visual Animator에 적합한 참조를 연결한다. 바인딩 경로가 Visual 및 실제 자식 계층과 맞는지 확인한다. 원본 rig/import 수정이 필요하면 자산 소유자에게 맡긴다.
4. ShatteredPlatform의 visual과 collapseAnimator가 같은 Visual를 가리키는지 확인한다. 그 Visual와 자식에는 Collider/Rigidbody를 두지 않는다. 기존 지지 BoxCollider와 논리는 루트에 둔다. 이는 현재 물리 접촉 계약을 보존하는 계층 예외다.
5. Animator는 Normal, Always Animate, root motion 비활성, 양수 Speed로 설정한다. 게임 시간이 멈출 때 붕괴도 멈추어야 한다. 클립으로 물리 루트나 지원 Collider를 이동·활성화하지 않는다.

## Controller 구조

| 항목 | 설정 |
|---|---|
| 기본 상태 | Ready |
| 파라미터 | Collapse, Trigger |
| Ready → Collapse | Collapse Trigger 조건, Has Exit Time 해제, Duration 0 |
| Collapse → Completed | Has Exit Time 활성, Exit Time 1, Duration 0, 조건 없음 |
| Ready/Completed Motion | 비움 |
| Collapse Motion | 실제 자산의 단일 붕괴 클립 |

실제 발판은 경고 → Collider 해제 → Collapse 재생 → 실제 완료 → 외형 숨김 → 제거/복구 순서다. 완료 후 자기 Animator를 멈춰 클립의 표시 곡선이 숨김을 덮어쓰지 않게 한다. 복구나 풀 재활성화 때 Ready와 Visual 자식의 원래 위치·회전·크기·렌더 상태를 되돌린다.

## 클립이 없는 동안

경고가 끝나면 지지 Collider를 끄고 외형을 숨긴다. 한 실행에 클립 미연결 Warning을 한 번 남기며 canRegenerate와 제거 설정은 계속 적용한다. 이 결과를 애니메이션 재생 성공으로 기록하지 않는다. 잘못된 Controller·상태·Animator 참조나 진행 정지는 별도 Error와 안전 후처리로 구분한다. 진행 정지 감시 시간은 실패 검출용이며 클립 완료 시간을 대신하지 않는다.

## 연결 후 확인

PC-07을 실제 클립으로 실행한다. 무거운 플레이어의 윗면 접촉에서 경고가 한 번 시작되고, 경고 완료 시 Collider가 해제되고, 실제 Collapse 클립 전체가 재생된 뒤 후처리가 진행되어야 한다. 짧은 클립도 완료가 누락되지 않아야 한다.

옵션 정지·재개, 도중 비활성화, 풀 재활성화, retry를 확인한다. 종료된 실행의 늦은 콜백이나 이전 자세·숨김 상태가 남으면 실패다. 실제 빌드에서 바인딩·아트 품질·완료 타이밍까지 확인하고 기존 Editor 시스템 검사와 별도 결과를 기록한다.
