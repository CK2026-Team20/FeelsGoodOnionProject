# 플랫폼과 카메라 정렬 설정

2026-10-06. 기존 42개 배치의 끝점·정렬점을 보존하면서 설정을 로컬 오프셋으로 이관했다. 선형 발판 26개, 카메라 트리거 6개, 체크포인트 10개다.

## 선형 발판

LinearShuttlePlatform의 도착점 이동량은 부모 기준 X/Y/Z 이동량이다. 예를 들어 `(4, 2, 3)`은 시작점에서 부모의 X로 4, Y로 2, Z로 3만큼 떨어진 도착점이다. 부모가 없으면 월드 축을 사용한다. 26방향 목록을 고르지 않고 원하는 3차원 경로를 직접 입력한다.

이동 속도는 초당 월드 경로 거리다. 현재 월드 거리/속도로 편도시간을 계산하고 끝점에서 기다리지 않는다. 부모 배율이 바뀌면 월드 거리와 편도시간도 바뀐다. `(0, 0, 0)`은 정지다. 선택 시 청록색 기즈모가 시작점·끝점·경로를 표시한다.

경로·속도는 실행 시작 때 캡처한다. 실행 중 같은 부모의 위치·회전·배율 변경은 반영되지만 부모 오브젝트 교체는 지원하지 않는다. 재생 중 설정을 바꾸었다면 Stop 후 다시 시작한다. 물리 이동은 KinematicPlatformMotion 하나가 담당하므로 같은 발판에 HMS MovingPlatform을 함께 붙이지 않는다.

## 카메라 전환 트리거

CameraZoneTrigger의 구간 설정은 Id·Movement·AlignmentOffset이다. AlignmentOffset은 트리거 자신의 로컬 이동량이다. `(0, 0, 0)`은 트리거 위치이며 트리거와 부모의 위치·회전·배율을 함께 따른다. 파란 기즈모는 선택 여부와 관계없이 실제 정렬점·연결선·정렬 평면을 표시한다.

| Movement | 플레이어 이동 | 정렬에 사용하는 값 |
|---|---|---|
| Side | 월드 X | 파란 점의 월드 Z |
| Corridor | 월드 Z | 파란 점의 월드 X |
| Quarter | 월드 X/Z | 위치 정렬 없음 |

각 구간은 비어 있지 않은 고유 Id를 사용한다. 실제 Brain 블렌드와 정렬이 끝난 뒤 이동 축이 확정된다. 진행 중 다른 구간 요청은 최신 전환으로 교체되고 같은 구간 접촉은 중복 시작하지 않는다. 옵션 중에는 전환 완료를 유예한다.

CheckpointMarker.CameraZone도 체크포인트 자신의 로컬 AlignmentOffset을 사용한다. bodyOffset은 플레이어 생성 위치를 위한 기존 월드 이동량으로, 카메라 정렬 설정과 목적이 다르다. 빈 ID가 있던 기존 체크포인트 6개는 초기 모드 대체 규칙을 보존했다.

## 조립과 변경 검증

설정은 SYM 소유 씬·프리팹의 Inspector나 Unity SerializedObject로 저장한다. 보호 원본에 Apply하지 않는다. 저장 후 실제 끝점·정렬점, 중복 이동 컴포넌트 유무, Missing Script와 Tooltip을 다시 확인한다. 실제 탑승·점프·정지·카메라 전환은 기존 씬에서 실행한다. 기즈모와 수치만 맞는 것으로 게임 동작 통과를 기록하지 않는다.
