## 목표·근거·확정 선택

계층 배치에서도 선형 발판과 트리거 정렬을 쉽게 설정하고, Animator Controller에 실제 클립을 연결하면 즉시 동작하는 붕괴 시스템을 준비한다. HMS 기능과 SYM 책임을 대조해 더미·중복·테스트 소스를 일괄 정리하고 쉬운 Tooltip과 조립·병합 지침을 지속 적용한다.

선형 발판은 부모 기준 전체 이동량+속도다. 정렬은 트리거 자신의 로컬 오프셋이며 실제 기준점을 파란 기즈모로 표시한다. 실제 붕괴 클립은 지금 만들지 않고 Controller/Animator/완료·취소 계약만 준비한다. 클립이 없으면 경고 후 물리 붕괴·외형 숨김과 연출 미연결 경고를 수행한다. 기존 미커밋 변경까지 최종 기능별 커밋·push 대상이다.

판단 근거가 필요한 HMS/SYM 차이는 사전 코드 리뷰에 기록했다. HMS MovingPlatform은 이번 부모 로컬 이동량의 완전 대체가 아니다. ActorFacingPresentation은 이미 HMS Visual로 대체되었다. 세션 입력·Bridge·HeavyState·여러 기믹의 물리·상한 소비 규칙은 실제 기능 책임을 확인해 보존한다.

## 실행 형태와 공유 상태

현재 체크아웃과 기존 Prototype/소유 독립 씬을 사용한다. T1 기준점/이관 감사 → T2 정리 → T3/T4/T5 기능 코드 → 메인의 소유 자산 연결 → T6 지침/Tooltip/QA → T7 기능 검증/빌드/독립 검토 → T8 커밋·push·PR 순서다. 메인 자산 연결은 T3~T5 뒤, T6 이전에 직렬로 완료한다.

작업자 인원이나 역할을 고정하지 않는다. 코드가 독립이어도 실제 Editor 자산 저장·씬 전환·Play·빌드는 한 실행자가 관리한다. 같은 프리팹·씬을 여러 작업자가 병렬로 덮어쓰지 않는다. Git 마지막 단계도 메인이 직접 수행한다.

## 실행 중 반드시 지킬 기준

1. **소유권:** Tech_SYM 코드·소유 씬/프리팹/설정/Controller와 프로젝트 문서·대응 메타데이터만 수정한다. HMS·_Art·공용·Packages·ProjectSettings 원본의 새로운 수정·Apply·이동·삭제·GUID 변경은 허가하지 않는다. 소유 배치에 HMS 공개 컴포넌트를 추가·설정·연결하는 것은 허용된 참조다.
2. **이관:** 구형 방향·시간·Origin/Legacy와 prefab override를 변경 전에 추출한다. 같은 이름으로 로컬/월드를 바꿔 해석하거나 이전 필드를 삭제해 현재 기준점을 잃지 않는다. 이관 후 불필요한 숨은 원본 필드를 남기지 않는다.
3. **정렬과 모드:** 로컬 기준점의 변환과 실제 Gizmos 계산을 공유한다. HMS의 월드 이동축·Brain 완료/물리 정렬 후 모드 확정·초기 snap 계약을 유지한다. 새 카메라 Transform 적용자를 추가하지 않는다.
4. **붕괴:** 경고 Tween만 유지하고 붕괴 표현은 Animator로 연결한다. `.anim`/가짜 클립 제작 금지. 클립 미연결 처리의 물리 결과와 진단을 확인하며 실제 재생 검증은 자산 연결 이후로 구분한다. 비활성화·풀 재사용·정지·중복·늦은 콜백을 정리한다.
5. **실사용 책임:** 테스트 후보 37개와 HMS 대체 중복의 코드/GUID/동적 참조를 확인해 제거한다. 그 외 후보도 전체 감사 기준을 적용한다. 필수 Hook/빌드/실사용 조립 도구와 세션 입력 책임을 이름만으로 제거하지 않는다.
6. **원본과 사용자 작업:** 현재 250항목 및 기존 staged diff를 기준점으로 보존한다. 미저장 씬을 자동 저장/폐기하지 않는다. 과거 세션의 미저장 폐기 허가를 이번 실행에 재사용하지 않는다. 실제 소유 수정은 검토 후 명시적으로 저장하고 종료 시 원래 씬/setup/startScene을 복원한다.
7. **검증:** 기존 씬에서 기능 전체의 결과를 확인한다. 실제 실행하지 않은 검사·새 빌드·실제 클립 재생·팀 플레이를 PASS로 기록하지 않는다. Assets에 테스트 소스를 재도입하지 않는다. 일회성 외부 검증 소스는 실행 뒤 제거하고 결과·명령·해시·오류·케이스는 남긴다.
8. **Tooltip와 문서:** 모든 신규/변경 직렬화 설정을 쉬운 한국어로 설명한다. 실제 단위·좌표·0/증감·연결·기즈모 색상과 일치해야 한다. 활성 지침/operations의 삭제된 메뉴를 갱신하고 역사 기록은 보존한다. FunQA 평가 결과를 작성하지 않는다.
9. **Git:** 사용자 지시에 따라 기존 변경도 포함해 검토·기능별 커밋·실제 push·yeet PR 절차를 완료한다. 커밋 직전 제목/본문/범위를 표시한다. 승인받은 Git 행동을 재확인하지 않는다. 현재 비기본 브랜치 유지, 실제 원격 HEAD 확인, 신규 Draft PR 또는 기존 PR 상태 보존, chat PR 연결. merge 금지.

## 2026-10-06 실행 중 사용자 추가 지시: 자동 저장 변경

사용자 직접 지시: “자동으로 추가된것도 앞으로는 전부 커밋 하십시오.” Unity/Editor가 자동 저장한 변경은 발생 원인과 실제 diff를 확인하여 유지하고 종류별 커밋에 포함한다. 실행 전 보호 기준점은 삭제하거나 새 값으로 덮어쓰지 않는다. 자동 변경의 이전/이후 해시·원인·포함 판단을 별도로 기록해 승인된 자동 저장과 에이전트의 직접 수정을 구분한다. 이 지시는 타 작업자 원본의 수동 코드 수정·Apply·삭제 권한을 확대하지 않는다.

이번 재컴파일에서 ProBuilder가 추가한 `editor.autoRecalculateCollisions=false`는 유지·커밋 대상으로 승인되었다. 기존 “보호 바이트 변경 0” 완료 기준은 **승인된 자동 저장 변경 이외의 보호 원본 변경 0**으로 적용한다. 실제 빌드 실행 전후 설정 차이도 숨기지 않고 발생 원인과 승인 여부를 기록한다. 이 예외 때문에 실행 결과를 허위로 원본 바이트 불변이라고 표기하지 않는다.
