# 프로그래머의 Play 진입 및 HMS 조립 변경 방법

2026-10-06. 승인된 변경을 적용한 현재 소스·저장 자산 기준이다. 이후 프로그래머가 진입 대상과 소유 HMS 조립을 바꿀 때 사용하는 수정 지점을 설명한다.

## 시작 씬과 도착 스테이지를 따로 설정한다

Unity의 `EditorSceneManager.playModeStartScene`은 Play가 처음 여는 씬을 정한다. Bootstrap 이후 도착할 Stage는 `BootRoute`와 `ArchitectureInstallation`의 Stage 목록이 정한다. 처음 여는 씬을 Bootstrap으로 설정해도 최종 Stage를 항상 첫 Stage로 설정할 필요는 없다.

현재 수정 지점은 다음 두 파일이다.

- `Assets/_Code/Core/Tech_SYM/Architecture/Foundation/BootstrapEntryRoute.cs`: 정확한 대상 경로와 각 경로의 도착 Stage 매핑.
- `Assets/_Code/Core/Tech_SYM/Architecture/Foundation/Editor/BootstrapPlayModeHook.cs`: 대상 씬의 Bootstrap 시작, 비대상 씬의 직접 Play, 시작 설정·일회성 route의 복원과 정리.

`BootstrapEntryRoute.IsTarget(sourcePath)`에 등록된 정확한 경로만 Bootstrap 강제 대상이다. 현재는 Architecture 아래 Bootstrapper·Title·InGameCore·Prototype/1_Stage·Stages/03_2_Stage·Stages/03_3_Stage 여섯 경로다. 기존 `Tech_SYM/01_BootStrapper`, `Tech_SYM/02_Title`, `Stages/03_1_Stage`는 별개의 경로이며 현재 목록에는 없다.

## 지정 씬에만 Bootstrap을 강제한다

Hook의 `Arm()`과 `ExitingEditMode` 분기에서 같은 `IsTarget` 판정을 사용한다. 대상은 설치 자산의 Bootstrap SceneAsset을 시작 씬으로 사용하고, 비대상은 해당 Play 진입 동안 startScene을 null로 두어 실제 활성 씬을 시작한다.

핵심 대입은 다음과 같다. 원래 설정의 기록·소유권·Stop/취소 정리는 기존 Hook에서 함께 관리해야 한다.

```csharp
// sourcePath는 Play 전 실제 편집 활성 씬의 경로다.
bool useBootstrap = BootstrapEntryRoute.IsTarget(sourcePath);
EditorSceneManager.playModeStartScene = useBootstrap
    ? AssetDatabase.LoadAssetAtPath<SceneAsset>(catalog.BootstrapPath)
    : null;
```

비대상 분기에서 단순히 기존 `RestoreStartScene()`만 호출하면 `PreviousStart`가 Bootstrap인 경우 다시 고정된다. 현재 Hook은 `ArmStartSceneForEntry(null)`로 직접 시작을 소유하며 이전값과 소유값을 구분한다. 이 helper와 Stop/취소/재로드 정리를 유지하고 원래 설정을 단순 대입으로 덮어쓰지 않는다. 비대상으로 전환할 때 DirectGame·StageId·SourcePath의 이전 값도 제거한다.

Bootstrap으로 시작하도록 만드는 것과 첫 Stage로 이동하는 것은 별개의 결정이다. 현재 `TryResolve`는 Bootstrap/Title에서 Title로, Stage에서 그 파일명과 같은 StageId로, Core에서 첫 Stage로 매핑한다. Stage2/Stage3에서 `new BootRoute(true, "1_Stage")`를 공통 반환하도록 바꾸면 요청한 현재 Stage 진입을 깨뜨린다.

## 대상 스테이지를 추가하거나 경로를 바꾼다

예를 들어 Stage N을 추가할 때 한 군데만 수정하면 설치 검증에 실패한다. 다음 연결을 같은 변경에서 맞춘다.

1. `BootstrapEntryRoute`에 실제 경로 상수를 추가하고 `IsTarget`의 정확한 경로 목록 및 `TryResolve`의 설치 대조를 수정한다. 현재 `StagePaths.Count != 3`과 각 인덱스 비교는 새 목록에 맞춰 바꿔야 한다. 이름 접두사·부분 문자열로 모든 씬을 대상화하지 않는다.
2. `Assets/_Scenes/Tech_SYM/Architecture/Configuration/ArchitectureInstallation.asset`의 Stage Paths를 실제 씬 경로로 갱신한다. Unity Inspector 또는 소유 자산용 Editor API로 수정한다. 첫 항목은 새 게임의 첫 Stage다.
3. 새 씬 `StageService.StageId`를 route의 StageId와 일치시키고 체크포인트 ID/Pose를 등록한다. 현재 매핑은 `Path.GetFileNameWithoutExtension(sourcePath)`를 사용한다.
4. 같은 Configuration 폴더의 `IntegrationEntrySettings.asset`에 해당 StageId의 직접 진입 체크포인트·조각·해금 설정을 등록한다. Pose 자체는 Stage가 소유한다.
5. `IntegrationSceneBuilder.Catalog`의 생성 기본 목록과 설치 문서의 기대 결과, 실제 외부 진입 검증에서 사용하는 정확한 경로 목록을 함께 갱신한다. 생성 코드를 그대로 두면 나중에 Builder를 실행했을 때 예전 목록이 복원된다. `IntegrationBuildPipeline`은 설치 자산의 씬 목록을 명시적으로 사용하며 일반 Build Settings를 고칠 필요는 없다. 기존 테스트 전용 클래스는 2026-10-06 정리에서 제거했으므로 이전 메뉴를 호출하지 않는다.

Bootstrap/Title에서 새 게임을 시작하는지와 각 Stage의 직접 진입을 구분해 확인한다. Stage2를 열었을 때 Bootstrap·Core·Stage2만 준비되고 Stage1이 함께 생성되지 않아야 한다. 다른 폴더의 같은 이름 씬과 개별 HMS·발판 테스트 씬은 직접 Play한다.

## HMS 기능을 소유 오브젝트에 조립한다

설정 기준은 `Assets/_Scenes/Tech_HMS/01_PlayerMovementTest.unity`의 실제 컴포넌트·직렬화 참조·PlayerCharacter prefab override다. HMS 소스 파일과 이 씬, 공유 PlayerCharacter 원본을 수정하지 않는다. 소유 씬·프리팹에 HMS 컴포넌트를 추가하고 공개 메서드와 이벤트를 연결하는 작업은 참조 허용에 포함된다.

현재 통합 PlayerRoot의 입력은 PlayerInputReader 한 개와 GameplayInputRouter 한 개가 소유한다. 기준 씬의 PlayerController나 디버그 입력 컴포넌트까지 복사하지 않는다. CharacterMovement·Facade·물리·폼 등의 ActorBody 배치는 attachedRigidbody 기반 센서 계약을 보존한다.

카메라는 Camera+CinemachineBrain 출력에 HMS PlayerCameraController와 서로 다른 Side/Quarter/Back/BackFixed CinemachineCamera를 연결한다. HMS MovementModeController와 VisualController도 같은 실제 Actor에 조립하고 기존 SYM 외형 회전·직접 카메라 Transform 갱신의 중복을 정리한다. 모델·클립 등 아트 원본을 수정하지 않고 SYM 소유 배치에서 참조한다.

private serialized 참조는 소유 프리팹 조립 시 Unity SerializedObject로 설정하고 첫 Awake 전에 준비한다. 런타임에는 HMS의 공개 TrySetMode·ModeChanged 계약을 사용한다. 재시도 시 Actor와 함께 필요한 카메라 참조를 다시 연결하고 종료 시 자기 구독·차단을 정리한다.

현재 통합 저장 자산은 `Assets/_Scenes/Tech_SYM/Architecture/Session/PlayerRoot.prefab`이다. 빈 PlayerRoot 아래 ActorBody는 HMS Facade·MovementModeController·VisualController·폼·물리를 갖고 CameraRig는 출력 Camera/Brain/PlayerCameraController와 네 CinemachineCamera를 갖는다. `HmsActorCameraAuthoring.Assemble`와 `SessionActorBuilder`도 이 구성을 만든다. CoreLevelCamera.prefab에는 구간 서비스만 남으며 CoreUiBinding의 카메라는 ActorReady에서 전달되고 ActorRemoving에서 비워진다. 첫 Awake 뒤 private 필드를 주입하지 않는다.

| Inspector 위치 | 설정할 항목 |
|---|---|
| ActorBody / PlayerMovementModeController | Initial Mode, Side/Quarter/Back Move Speed. 현재 기본은 모두 5m/s |
| ActorBody / PlayerVisualController 및 PlayerFormController | 직계 VisualRoot와 그 아래 직계 NormalVisual·SmallVisual, 폼의 debrisPrefab. VisualRoot 하위 Rigidbody·Collider 없음 |
| ActorBody / PlayerFacade | 세 skill definition. 통합은 SYM Configuration, 독립 테스트는 HMS 기준 자산 참조 |
| CameraRig / ActorCameraRig | 같은 Actor의 movementMode·outputCamera·brain·hmsController·Side/Quarter/Back/BackFixed |
| CameraRig / Main Camera / PlayerCameraController | movementModeController와 서로 다른 네 CinemachineCamera |
| CameraRig / CinemachineCamera | Side/Quarter/BackFixed Follow·LookAt은 Facade, Back은 VisualRoot |
| CoreLevelCamera / LevelCameraService | Blend Seconds. 현재 기본 약 0.6초, Side→Side·Quarter→Quarter·Corridor→BackFixed |

초기 Actor는 Start의 IsInitialized 이후 체크포인트 모드와 Brain의 선택 완료까지 기다린다. 일반 구간 전환은 실제 Brain 블렌드·평면 정렬이 끝난 뒤 TrySetMode로 축을 확정한다. CameraZoneData는 Id·Movement·AlignmentOffset이며 소유 트리거 자신의 로컬 정렬점을 Resolve로 월드 CameraZoneRequest에 담는다. 파란 기즈모는 같은 정렬점을 표시하고 실제 화면 위치·방향은 Cinemachine 카메라에서 조정한다. 이전 Offset/LookOffset·Legacy 필드는 제거했다. HMS 기준 Quarter 속도 3m/s·블렌드 0.5초와 현재 지정 기획 기본값을 혼동하지 않는다.

독립 Brokenable/MultiFunc/InGame 씬은 PlayerInputReader·HMS PlayerController 한 경로를 사용한다. 기존 primitive 렌더러는 VisualRoot/NormalVisual에 두고 SmallVisual을 폼 크기에 맞게 구성하며 원래 Facade·물리 몸체는 빈 wrapper 아래 유지한다. 이 배치는 기존 물리 계약 보존을 위한 계층 예외다. InGame의 CheckInteract.viewCamera와 월드 프롬프트 Canvas는 새 출력 카메라를 참조해야 한다. LayoutOverview는 Camera 비활성인 배치 참고용이며, MultiFunc 씬의 이전 Main Camera도 객체·Camera·AudioListener가 비활성이다. 활성 게임플레이 출력은 HMS Camera 한 개다. 플레이어가 없는 역사적 03_1_Stage는 통합 플레이를 자동 구성하는 씬이 아니다. HMS 기준 스킬 자산에는 초기 쿨다운이 있으므로 플레이 직후 입력 거절과 누락된 스킬 연결을 구별한다.

## 작업 지침에 적용할 참조 정의

아래 의미를 루트 AGENTS/CLAUDE, security·standards·contracts와 관련 SYM 지역 지침에 적용했다.

> 읽기·참조 허용은 타 작업자의 원본 코드·자산을 확인하고, 공개 API와 이벤트를 사용하며, 허용된 자기 소유 씬·프리팹·오브젝트에 그 기능의 컴포넌트를 추가·설정·연결하는 것을 포함한다. 자기 소유 배치의 prefab instance override는 해당 배치에 저장할 수 있다. 타 작업자의 코드·씬·프리팹·.meta·import 설정의 직접 수정, 보호 원본에 prefab Apply, 원본 이동·삭제·GUID 변경은 별도의 명시적 파일 허가 없이는 금지한다. _Art·공용 자산도 같은 원본 보호 원칙을 적용한다.

컴포넌트 이름이나 Inspector 슬롯의 존재만 확인하지 말고 정상 입력 한 번·모드 전환·재시도·정지/복구에서 실제 결합 동작을 검증한다. 현재 실행 절차는 `Assets/_Docs/operations.md`의 외부 일회성 Unity 검증과 최신 플랫폼 검증 항목을 따른다. 제어된 서비스 요청·위치 이동 검사와 실제 InputSystem 전체 동선을 구분해 기록하고 일회성 소스는 실행 후 제거한다. 이 폴더의 이전 검증 결과는 당시 구현의 실행 이력이다.
