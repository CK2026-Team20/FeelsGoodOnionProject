작성일: 2026-10-05. 상태: 사용자 최종 검토용. 이 문서의 작성은 구현 완료를 의미하지 않는다.

## 목표와 이유

기획자가 확정한 시스템 1.1과 UI 1.0, 이번 직접 지시를 하나의 새 플레이 가능한 프로토타입에 반영한다. 개별 시험·더미 연결을 병합된 플레이어 기능과 실제 적 프리팹 연결로 교체한다. 현재는 모든 기능을 한 스테이지에서 검증하는 단계이며, 추후 제공될 상세 레벨 기획의 최종 배치나 스테이지 분할을 미리 결정하지 않는다.

## R01. 기획 버전·권한·문서

- `Assets/_Docs/planning-index.md`의 현재 지정 원본을 읽는다. 우선순위는 최신 직접 지시, 해당 분야 최신 기획서, 기존 구현 설명 순이다. 같은 버전명·절 번호라도 갱신된 파일 내용을 다시 확인하며 구버전과 같다고 일반화하지 않는다.
- 시스템 확정 1.1의 파란색은 재정의한 규칙, 빨간색은 해당 기능 안의 조정 가능한 UX 설정이다. 현재 Q·E·F 직접 지정은 우선한다. 시스템 2안은 비교용이며 레벨 1.1은 추후 본편 설계의 참고 기준이다.
- 원본 네 문서는 수정하지 않고 보존한다. 게임 동작 변경 후 Markdown 설명·지역 지침의 해당 구획·코드 리뷰·검증 기록을 최신 상태로 맞춘다. 과거 검사 결과는 이번 실행 결과로 재사용하지 않는다.
- Tech_SYM 소유 코드·자산 및 승인된 문서가 작업 영역이다. 이번 세션에는 `Assets/_Code/Core/Tech_HMS/Features/PlayerInputReader.cs`의 입력 규칙, `PlayerFormController.cs`의 상태 전환에 따른 회수·복귀 규칙을 최소 수정할 수 있다. 해당 예외는 다른 HMS 코드·공용 Interfaces·공유 원본 프리팹·_Art·Packages·ProjectSettings로 확대하지 않는다. 두 원본의 기존 GUID를 유지한다.
- 준비 문서의 정본은 `Assets/_Docs/tracking/ready-2026-10-05/`이며 `.dryforge/`의 동명 파일은 실행 도구용 동일 사본이다. 문서는 정본에서 고치고 세 사본의 해시 일치를 확인한다. 독립적으로 다른 결정을 적지 않는다.

## R02. 상태와 연결의 단일 소유

플레이어의 체력·조각은 기존 HMS PlayerModel, 형태·껍질은 PlayerFormController, 행동 상태와 이벤트는 PlayerFacade가 소유한다. 세션은 체크포인트·해금, 스테이지는 위치·장치·구출·탈출, UI는 표시 상태와 명령, 조립 지점은 연결을 담당한다. View는 주입된 ViewModel에만 명령을 전달하며 도메인 판정·직접 저장·씬 로드를 하지 않는다. ViewModel은 View를 참조하지 않는다.

입력 판독과 실행 라우팅은 한 경로만 둔다. 통합 PlayerRoot에 기존 PlayerController나 CheckInteract를 더해 두 번 실행시키지 않는다. 바인딩 재등록은 자기 구독만 정리하며 비활성화·반환·파괴·세션 종료 뒤 콜백을 차단한다. 상태 원본을 새 SYM 모델에 복제하거나 이미 병합된 FSM·스킬·애니메이션 규칙을 다시 구현하지 않는다.

## R03. 조작

| 행동 | 입력 | 계약 |
|---|---|---|
| 좌우 이동 | 좌우 방향키 | 사이드·쿼터뷰 허용; 통로는 좌우 이동 금지 |
| 앞뒤 이동 | 위아래 방향키 | 쿼터뷰는 월드 X/Z, 통로는 월드 Z 전후; 사이드는 깊이 이동 금지 |
| 점프 | Space 새 입력 | 지상에서 한 번; 키 유지 반복·공중 추가 점프·공중 입력 착지 예약 없음 |
| 축소·회수/복귀 | Q 새 입력 | 현재 형태에 따른 한 행동; 별도 회수 키 없음 |
| 상호작용 열기/닫기 | E 새 입력 | 선택 대상 하나, 열린 메모 닫기 우선 |
| 눈물 | F 새 입력 | R05 조건에 따른 한 번의 실제 발동 |
| 옵션 | Esc 또는 옵션 버튼 | 같은 명령; 로딩/재시도 전환 중 재진입 금지 |

WASD·R·독립 회수 키를 현재 프로토타입의 병행 조작으로 남기지 않는다. 기존 소비자의 공개 속성을 즉시 없애 컴파일을 깨지 않도록 호환 영향을 조사하되, 호환 회수 입력이 실제 명령을 발생시켜서는 안 된다. 대화의 아무 키 진행은 R07의 최상위 UI 입력 정책을 따른다. 잠금 해제·화면 닫힘·씬 전환이 끝난 프레임의 이전 입력이 게임 행동으로 이어지지 않는다.

기본/작은 형태의 이동 속도는 5m/s, 점프 목표 높이는 기본 2m/작은 3m로 시작하며 Inspector 조정 가능하다. 공중 방향 변경과 발판 이륙 속도 전달을 유지하고 대각선 속도 이득은 없다.

## R04. 형태 전환·껍질

- 해금 전·사망·입력 차단 중에는 거절한다. 기본→작은 형태는 수락 시 즉시 작아지고 발밑에 소유 껍질 한 개를 만든다. 공중에서도 가능하며 껍질은 생성 당시 움직임을 이어받는다.
- 작은→기본 형태는 Q 한 번으로 처리한다. 거리나 접근 여부와 관계없이 기본 크기가 들어갈 공간을 먼저 검사한다. 공간이 없으면 작은 몸과 껍질을 모두 그대로 둔다. 나중에 공간이 생겨도 자동 복귀하지 않으며 Q를 다시 눌러야 한다.
- 공간이 있으면 껍질 회수와 형태 복귀를 하나의 성공 결과로 처리한다. 회수만 성공해 작은 몸으로 남거나, 거절되었는데 껍질이 먼저 소멸하는 부분 성공을 허용하지 않는다. 추가 껍질을 만들거나 별도 회수 명령을 사용자에게 요구하지 않는다.
- 형태 전환의 일회성 표현이 실제 재생 중이면 중복 전환을 거절한다. 별도 준비 시간·재사용 쿨다운은 없다. 현재 클립 미연결 상태에서는 R17의 건너뛰기 계약을 사용하며 없는 애니메이션을 무한 대기하거나 임의의 고정 대기로 바꾸지 않는다.
- 기본 몸과 껍질은 무게 장치를 누르고 작은 몸은 누르지 않는다. 작은 몸은 붕괴 발판의 무거운 캐릭터 조건을 만족하지 않는다. 사망/재시도 시 이전 껍질을 제거하고 기본 형태로 돌아온다.

## R05. 눈물·조각

- 해금 후 조각 5개를 가진 생존 플레이어가 F를 누르면 준비 없이 발동한다. 조각 5개를 한 번 지불해 0개가 되고, 같은 발동에서 캐릭터 중심 기본 반경 3m의 기절 가능한 각 대상에게 기본 2초 기절을 한 번씩 적용한다. 범위·기절 시간은 조정 가능하다.
- 애니메이션/VFX 요청과 기절 효과는 실제 발동 시점에 연결한다. 애니메이션 종료나 투사체 충돌을 기다리지 않는다. 발동 이후 비용·기절을 취소하거나 환불하지 않으며 무대상 발동도 비용을 돌려주지 않는다.
- 기본/작은 형태, 지상/공중에서 가능하고 사용 중 이동·점프를 허용한다. 5개 미만·사망·제어 제한 중에는 발동하지 않는다. 별도 3초 쿨다운은 제거하며 다시 5개를 모으는 조건을 사용한다.
- 동일 대상의 복수 Collider는 한 번만 처리하고 자기 자신/자식은 제외한다. 재기절은 남은 시간을 늘린다. 기절한 적은 접촉 피해를 주지 않지만 다른 정상 적·위험 발판까지 무적으로 만드는 기능은 아니다.
- 프로토타입 조각은 한 개씩, 최대 5개까지 얻는다. 실제 추가량이 양수일 때만 사라지고 가득 찼거나 사망했다면 남는다. 별도 시험용 기존 수집물 원본의 동작을 무관하게 전부 바꾸지 않는다. 저장·HUD·직접 진입 설정의 상한도 5개와 일치한다.

## R06. 새 프로토타입과 한 판의 흐름

- 새 씬 `Assets/_Scenes/Tech_SYM/Architecture/Prototype/1_Stage.unity`를 만들고 설치 목록의 첫 스테이지로 등록한다. 기존 `Architecture/Stages/03_1_Stage.unity` 및 기존 Stage 2/3 자산은 보존한다. 기존 씬의 미저장 변경을 새 씬 재구성 과정에서 저장·폐기하지 않는다.
- 새 게임은 Bootstrap→Title→GameCore→Opening→새 프로토타입 플레이→Ending→Title이다. 하나의 프로토타입에서 모든 요구 기능을 경험하고 구출·필요한 껍질 장치·마지막 추격·탈출을 완료한다. 기존 Stage 2/3를 새 게임의 필수 추가 진행 구간으로 강제하지 않는다.
- Stage 2/3는 지정 진입 씬으로 보존하며 해당 씬의 직접 테스트 진입을 지원한다. 등록된 경로 집합과 한 판에 활성화할 콘텐츠 집합을 구분한다. 새 게임에서 이전 Stage 장치·카메라·적·추격 트리거가 함께 작동하지 않아야 한다.
- 새 게임 진입은 초기 체크포인트, 체력 3, 조각 0, 미해금 상태로 시작한다. 직접 첫 스테이지 진입은 같은 초기 상태로 오프닝만 생략한다. 기존 Stage 2/3 직접 진입은 해당 기존 진입 설정의 초기 체크포인트/해금값을 유지하되 새 조각 상한과 유효성 검사를 적용한다.
- 체력 0·낙하 실패·추격 포획은 현재 체크포인트 재시도를 한 번만 요청한다. 재시도는 Core/세션을 유지하고 플레이어와 스테이지 실행 상태를 다시 준비한다. 체력은 최대, 형태는 기본, 조각은 저장 수량, 능력 해금은 같은 판에서 유지한다. 이전 속도·껍질·연출 요청은 남기지 않는다.
- 적·장치·수집물·구출 상태는 새 시도의 초기 상태로 돌아간다. 체크포인트 이전에 완료한 장치를 탈출 조건으로 다시 요구하지 않는 기존 진행 기준을 유지한다. 제목 복귀/한 판 종료는 진행을 비운다. 앱 종료 후 이어하기를 새로 추가하지 않는다.
- 전환 중 중복 명령은 거절한다. 부분 초기화·정리 실패를 성공으로 반환하지 않는다. 기존 제목 복구 시도 및 복구 실패 시 입력/가림 유지 계약을 보존한다.

## R07. 대화

기존 테이블·진행·ViewModel을 재사용하고 새 프로토타입에서도 지정 구역/NPC 상호작용으로 시작할 수 있게 한다. `Stage 2`라는 이름만으로 사용을 제한하지 않는다. 한 번에 한 대화, 같은 프레임 한 진행 명령이다.

- 일반 마우스 좌클릭 또는 키보드 아무 키의 새 입력: 문장 표시 중이면 현재 문장을 완성하고, 완성된 뒤면 다음 문장으로 진행한다. 기존 최소 입력 간격 0.3초를 유지하며 설정으로 조정할 수 있다.
- 옵션·로그·스킵·자동 버튼 입력은 해당 명령이 소비하며 일반 문장 진행과 중복 실행하지 않는다. 옵션이나 로그 위 입력은 아래 대화로 전달하지 않는다. 대화 종료 입력이 게임 스킬/상호작용까지 실행되지 않는다.
- 자동 진행은 문장 완전 표시 뒤 기본 3초 대기한다. 로그는 자동을 끄고 문장 표시/진행을 멈추며, 닫아도 자동은 다시 켜지지 않는다. 완전히 표시된 현재 대화의 문장만 로그에 넣는다. 전체 스킵은 남은 대화를 종료한다.
- 대화 중 월드와 게임 입력을 막고 UI 표시/자동 진행은 계속한다. 옵션을 열면 대화 표시/남은 자동 대기도 멈추고 닫으면 이어진다. 완료·스킵·취소·실패·파괴 시 자기 차단과 예약 콜백만 해제한다.
- JSON의 `Rows`와 행 필드 `Dialogue_Code`, `Sequence`, `Name`, `Context`, `ContextRevealDuration` 및 `contracts.md`의 타입·양수 순서·중복 거절·유한한 초 값·추가 필드 거절 계약을 유지한다. 전체 검증 성공 후에만 게시한다. 없는 코드와 잘못된 테이블은 명시적으로 실패하며 빈 대화가 성공한 것처럼 진행하지 않는다.

## R08. 컷신

Opening/Ending은 Timeline의 지정 순서대로 원화 한 장씩 전체화면 표시한다. 네 장이면 네 장을 차례로 표시하며 분할 만화 레이아웃·스케일·이동·페이드 등 컷신 UI 트윈을 사용하지 않는다. 이전 컷과 다음 컷을 동시에 겹쳐 표시하지 않는다. 기본 표시 시간은 장당 3초의 조정 가능한 설정으로 두고 원화 개수에 맞춰 종료한다. 화면 전환 서비스의 별도 로딩 가림과 원화 UI 자체의 트윈을 혼동하지 않는다.

스킵은 정상 조기 완료, 취소는 정상 완료가 아니다. Opening 완료/스킵은 플레이, Ending 완료/스킵은 제목 복귀다. 마지막 원화는 숨김까지 유지하고 다음 화면에 스킵 입력을 전달하지 않는다. 컷신은 월드를 정지하되 자신은 비정지 시간으로 진행하며 옵션 중 재생과 스킵을 멈춘다. 비활성화·폐기·재준비 뒤 이전 완료 콜백은 무효다. 아트 원본은 읽기 참조한다.

## R09. 체크포인트·해금·기믹

살아 있는 플레이어가 정상 플레이 중 새 체크포인트를 확보하면 Stage/Checkpoint ID와 현재 조각 수를 즉시 저장한다. 같은 체크포인트 반복 접촉은 조각 스냅샷을 덮어쓰지 않는다. 위치는 스테이지가 제공하고 세션은 식별자/수량/해금을 보관한다.

형태 전환과 눈물 해금은 체크포인트의 설정으로 연결한다. 첫 형태 해금은 껍질 사용을 포함하며 독립 회수 키를 해금하지 않는다. 프로토타입에는 초기·형태 습득·눈물 습득·추격 직전 지점을 구별한다. 정확한 좌표와 간격은 기능 검증용 배치값이며 상세 레벨 기획을 선점하지 않는다. 해금은 재시도에 유지된다.

눈물로 길 열기(TearStunGate)의 실행 연결·배치·설명·통과 조건은 제거한다. 직접지시의 삭제 범위를 껍질 압력판/연동 발판·구출·탈출까지 넓히지 않는다. 작은 플레이어가 소유 껍질로 압력판을 누른 상태에서 통과하는 기존 껍질 장치 규칙은 유지한다. 구출과 추격 시작 수락, 체크포인트 이후 필요한 껍질 장치를 완료한 뒤 탈출하면 엔딩으로 이어진다.

## R10. 카메라·통로

- 정상 플레이 중 시점 변경은 지정 Trigger로만 시작한다. 매 프레임 거리/최근접 구역으로 자동 전환하거나 개발용 키로 변경하지 않는다. 체크포인트 재생성 때는 저장 지점의 모드·위치로 초기화한다.
- 실제 프로토타입 경로는 사이드뷰→통로→쿼터뷰→통로→쿼터뷰다. 마지막 구간을 임의로 사이드뷰로 바꾸지 않는다.
- 통로 진입은 백뷰로 바꾸고 월드 Z축 전후 이동만 허용한다. 루트의 진행 방향을 기준으로 전방/후방을 표시하되 X축 이동과 화면 기준 대각선 이동을 허용하지 않는다. 사이드는 월드 X만, 쿼터뷰는 월드 X/Z를 사용한다.
- 전환 시간의 초기값은 약 0.6초이며 조정 가능하다. 전환 중 이동·점프·스킬/상호작용 입력을 막고 완료한 시점에 목적 모드의 이동축을 적용한다. 카메라 추적은 유지하되 같은 전환을 중복 시작하지 않는다.
- 통로 또는 쿼터뷰에서 사이드뷰로 돌아오는 연결에는 목적 사이드 평면의 Z값으로 최초 보간한다. 순간이동으로 대체하지 않는다. 현재 순방향 배치가 쿼터뷰로 끝나더라도 역방향 귀환과 사이드 진입 계약은 지원한다. 보간 중 벽/지형을 뚫지 않는 통로를 배치하고 목표 평면을 검증한다.
- Trigger는 경계/진입 방향에 맞는 목적 모드를 가지며 왕복할 때 원래 구역으로 전환한다. 같은 대상의 중복 Collider 접촉은 한 전환으로 처리한다. 옵션 정지·사망·재시도·세션 종료는 보간과 자기 잠금의 수명을 함께 관리한다.

## R11. 발판·장치·기름

프로토타입에 붕괴, 계단형 상호작용 서랍장, 주기 생성/소멸, 왕복, 부유, 피해 발판(가스버너/프라이팬 같은 위험 요소), 기름 바닥을 모두 배치한다. 각 기능의 기존 컴포넌트를 재사용하며 실제 PC가 통과·상호작용·피해/미끄러짐을 경험할 수 있어야 한다.

- 붕괴는 기본 크기의 무거운 PC의 윗면 접촉으로 시작하고 내려와도 취소되지 않는다. 초기 경고/지지 제거는 기존 자산의 1초/시작 후 1.25초를 조정 가능한 값으로 사용한다. 붕괴 후 자동 복구하지 않는다. 재시도에 스테이지를 다시 준비하는 것은 자동 복구와 별개다.
- 서랍은 E로 열기/닫기하며 열린 서랍이 올라설 계단 역할을 한다. 이동 중 추가 입력을 거절하고 탑승체 이동 전달·중단 후 상태를 관리한다. 기존 오븐 트레이/압력판 연결도 유지한다.
- 주기 발판은 접촉과 무관하게 활성 5초→소멸 2초→등장 안내 3초의 초기 주기로 반복한다. 등장 안내 중 지지 Collider는 아직 켜지지 않는다. 시간은 조정 가능하다.
- 왕복은 두 지점 반복 이동, 부유는 상하 운동과 단발 착지 반동을 제공한다. 서 있기만 해도 착지 반응이 반복되거나 옆면 접촉을 탑승으로 처리하지 않는다.
- 위험 발판은 기존 기본 피해 1/접촉 반복 간격 1초를 사용하며 조정 가능하다. 실제 피해가 양수일 때만 해당 피해 표현/넉백을 적용한다.
- 기름은 이동 가감속을 바꾸며 접촉 중 효과 시간이 갱신되고 이탈 뒤 설정 시간 지속한다. 기름 자체는 체력을 줄이지 않는다. 공유 아트 원본을 수정하지 않는다.

## R12. 메모·상호작용

동시에 선택하는 월드 대상은 하나다. 기본 범위 2.5m, 정면 좌우 약 60도, 벽 가림과 거리 조건은 기존 규칙을 사용한다. E는 대상의 열기/닫기 행동을 한 번 요청한다. 열린 메모가 있으면 그 메모 닫기가 월드 대상 선택보다 우선한다.

월드 공간 안내 Canvas와 스크린 공간 본문 Canvas 두 개를 분리한다. 본문을 여는 시점부터 월드/게임 입력을 차단하고 UI는 계속 입력받는다. E 또는 X로 닫을 수 있고 열리는 도중의 닫기 요청을 잃지 않는다. 닫힘 완료·취소·폐기 시 자기 차단만 해제한다. 메모/옵션이 닫혔어도 다른 화면의 차단이 있으면 월드를 재개하지 않는다. 일반 서랍/트레이 상호작용은 스크린 모달을 열지 않는 한 월드를 멈추지 않는다.

## R13. UI·옵션·정지

UI 1.0의 흐름/배치를 따른다. 타이틀은 타이틀 영역과 세로 게임시작·설정·종료, 팀명 표시를 둔다. 타이틀 설정은 전체/배경음/효과음 슬라이더와 X, 게임 HUD는 상단 HP 세 칸·눈물 아이콘과 현재/5, 하단 좌측 스킬 안내, 게임 옵션은 음량·닫기·제목 복귀를 배치한다. 시스템 기획의 계속하기/다시 시작 기능도 유지한다. 문서에 상세 배치가 없는 메모·대화는 기존 표현을 기반으로 필요한 입력/정지 계약을 반영하고 문서에 없는 승인 시안을 창작해 출처를 붙이지 않는다.

| 상태 | 월드/물리·적·발판·추격 | 게임 입력 | 해당 UI 진행 |
|---|---|---|---|
| HUD만 표시 | 진행 | 허용 | 진행 |
| 메모 | 정지 | 차단 | 입력/표시 진행 |
| 대화 | 정지 | 차단 | 글자 표시/수동·자동 진행 |
| 대화 로그 | 정지 | 차단 | 로그 조작; 본 대화 진행 정지, 자동 해제 |
| 컷신 | 정지 | 차단 | Timeline 진행/스킵 |
| 옵션 중첩 | 정지 | 차단 | 옵션만 조작; 대화/컷신 표시 진행 정지 |

정지 이유마다 토큰/수명 소유자가 있고 마지막 월드 정지 해제 때 이전 timeScale을 복원한다. 무조건 1로 쓰거나 다른 화면의 토큰을 해제하지 않는다. UI 타이머는 unscaled 시간과 자신의 표시 정지 이유를 사용한다. 자기 월드 정지가 자신의 대화/컷신을 멈추는 순환 조건은 금지한다.

옵션은 제목·정상 플레이·오프닝/엔딩에 열 수 있고 로딩/재시도 중에는 열지 않는다. 재시도/제목 복귀는 플레이 중에만 제공한다. 음량은 유한한 0~1, 기본 Master=1/Music=0.7/Sfx=1, 즉시 반영·닫을 때 로컬 저장·저장 실패 시 적용값 유지와 다음 저장 재시도다. 월드 정지 중 음악/UI 사운드는 유지하고 월드 효과음의 기존 정지 정책을 적용한다. 종료는 가림 뒤 앱 종료이며 Editor에서는 검증 가능한 종료 요청으로 확인한다.

## R14. 일반 적

제자리형과 순찰형을 유지하고 일반 적의 추격 상태·복귀 추적·시야각/거리 탐지 및 이에만 필요한 필드를 제거한다. 순찰은 자신의 구간 안에서 진행하며 장애물/높이 경계를 유지한다. 일반 적과 R15의 추격 무리는 별개다.

머리 Collider와 하강 밟기 처치 판정을 제거한다. 머리 참조가 없으면 초기화 실패하는 현재 검사도 함께 수정한다. PC가 위에서 닿아도 적을 죽이지 않는다. 살아 있고 기절하지 않은 적의 몸통 접촉은 기존 피해 1을 줄 수 있다. 동일 연속 접촉은 한 번, 이탈 뒤 재접촉은 다시 한 번이다. 실제 Damage 결과가 양수일 때만 접촉 소비·넉백/피격 표현을 적용한다.

기절 중 순찰/접촉 공격을 멈추고 종료 후 원래 행동을 재개한다. 기절은 직접 피해가 아니며 사망 대상에 적용하지 않는다. 적의 기존 일반 피해/사망 계약 자체를 새 공격 기능으로 확장하지 않는다. 처치 시 기름 생성 설정은 유지할 수 있지만, 밟기 제거 때문에 프로토타입의 기름 체험을 처치에 의존시키지 않는다.

## R15. 마지막 추격

프로토타입 마지막 구간에서 경로상의 거리로 무리가 전진한다. 기존 기본 시작 간격 8m와 속도 4m/s는 조정 가능하다. 매 프레임 플레이어 뒤 일정 거리로 강제 재배치하지 않는다. 보이드 알고리즘은 이번 범위에서 제외한다.

포획의 권위 있는 조건은 무리 앞의 충돌 Trigger에 살아 있는 PC가 닿는 것이다. 종전 0.8m 거리만으로 재시작하는 별도 판정을 함께 두지 않는다. PC의 자식 Collider/다중 접촉은 한 포획으로 모으고 체크포인트 재시도를 한 번 요청한다. 포획에 체력 0을 선행 조건으로 두지 않는다.

시작 전 추격 직전 체크포인트를 확보하고 퇴로문이 플레이어를 끼우지 않는지 확인한다. 추격 시작 수락 후에만 문을 닫는다. 옵션/화면 정지 중 전진하지 않고 재시도·사망·제목 복귀·탈출 시 현재 시도를 종료한다. 재시도에는 새 추격이며, 추격 시작만으로 탈출 성공이 되지 않는다.

## R16. 병합된 플레이어 기능 연결

기존 PlayerFacade의 상태 머신, 사망/넉백 우선순위, Jumped/Landed/Damaged/SkillActivated 이벤트, 일반 Heal과 명시적 TryRevive 구분을 재사용한다. 피격 실제 적용 시 한 번 통지하고 사망 뒤 일반 회복으로 부활하지 않는다. 사망/넉백은 남은 입력과 낮은 우선순위 요청을 정리한다. 리스폰의 새 객체 생성과 같은 객체에 대한 명시적 부활 API를 혼동하지 않는다.

통합 소유 PlayerRoot에서 병합 기능을 연결한다. 공유 `Assets/_Prefabs/Characters/PlayerCharacter.prefab`는 참조 기준이며 무단 Apply/수정하지 않는다. 새 SYM 복제/조립 자산에서 초기화·단일 입력·물리 센서의 attachedRigidbody/Facade 계약을 지킨다. 빈 상위 루트 아래 실제 ActorBody의 물리·Facade 배치 예외를 문서화한다.

## R17. 애니메이션 범위

기존 PlayerAnimationController/Playback/Set/AnimatorOutput의 요청·클립 설정/출력 연결 코드를 재사용한다. 사망/넉백은 일회성 요청보다 우선하며 일회성끼리는 눈물>형태 전환>착지다. 거절된 요청을 나중에 재생하지 않고 완료는 현재 요청 ID일 때만 인정한다. 완료/중단 뒤 최신 이동 상태의 기본 표현으로 복귀한다.

실제 모델·Animator·애니메이션 클립 연결, 실제 재생·블렌딩·착지 타이밍 검증은 제외한다. 설정/출력 컴포넌트와 이벤트 연결 및 누락 클립 대체·일회성 건너뛰기 논리는 검증한다. 없는 재생 자원을 기다려 플레이어가 잠기지 않아야 한다. 게임 효과를 애니메이션 종료 콜백에 종속시키지 않는다.

## R18. VFX·사운드·피격 표시

점프·착지·피격·스킬의 기존 이벤트에 표현/사운드를 연결하며 업무 판정을 표현 컴포넌트에 복제하지 않는다. 실제 모델 기반 착지 파티클 제작/연결은 이번 실제 리소스 제외 범위와 분리하고 완료로 주장하지 않는다. 피격 표시는 빨간색 머테리얼 효과로 대체한다. 실제 피해가 양수일 때만 표시하고 효과 종료·재바인딩·객체 반환 시 원래 표현을 복원한다. 기본 표시 길이 같은 수치는 조정 가능한 표시 설정이며 무적/경직 시간을 새로 만들지 않는다.

원본 공유 머테리얼을 덮어 다른 PC/적까지 빨갛게 바꾸지 않는다. Tech_SYM 소유 표현 자산이나 객체별 속성을 사용한다. 사운드는 현재 카탈로그/이벤트를 연결하며 새로운 음원 제작이나 외부 다운로드를 요구하지 않는다. 누락 연결은 이름과 기능을 식별해 보고한다.

## R19. 실제 적 프리팹의 스턴 시각 연결

`IStunState.IsStunned`와 `StunStateChanged(bool)`는 이미 존재하므로 재선언하지 않는다. EnemyActor가 상태 원본이며 표시 컴포넌트는 이를 조회/구독한다. 기존 `EnemyStunVisual`과 `Enemy_Dummy`/`StunEffect_Dummy`의 구성을 참조한다.

실제 수정 대상은 `Assets/_Scenes/Tech_SYM/Enemies/Prefabs/StationaryEnemy.prefab`, `PatrolEnemy.prefab`, `OilPatrolEnemy.prefab`다. 각 원본에 머리 위 효과 자식과 대상 Renderer·normalTexture·stunnedTexture·유효 shader 속성/슬롯을 연결한다. 이펙트의 머리 위 위치와 삭제할 머리 전투 Collider는 별개다.

최초 활성/재활성 시 현재 상태를 즉시 표시한다. 스턴 시작은 효과 켜기/스턴 텍스처, 해제는 효과 끄기/일반 텍스처다. 재기절·일시정지·비활성화·재활성화·사망·풀 반환의 구독과 표시 수명을 검증한다. 한 적의 표시 변경이 다른 적의 공유 머테리얼을 바꾸지 않는다. 연결 누락/잘못된 슬롯은 문맥 있는 오류이며 더미 예시만 완성해 실제 원본 완료로 보고하지 않는다.

## R20. Editor 진입 범위

다음 여섯 정확한 경로만 통합 부트 진입 대상이다.

| 경로(Assets/_Scenes/Tech_SYM/Architecture/ 기준) | 부트 이후 목적지 |
|---|---|
| `01_Bootstrapper.unity` | Title |
| `02_Title.unity` | Title |
| `03_InGameCore.unity` | 새 첫 스테이지, 오프닝 생략 |
| `Prototype/1_Stage.unity` | 새 첫 스테이지, 오프닝 생략 |
| `Stages/03_2_Stage.unity` | 해당 Stage 2 진입 설정, 오프닝 생략 |
| `Stages/03_3_Stage.unity` | 해당 Stage 3 진입 설정, 오프닝 생략 |

현재 활성 편집 씬의 정확한 경로로 판정한다. 비활성으로 함께 열린 대상 씬이나 동일 파일명 일부만으로 대상에 포함하지 않는다. 기존 `Stages/03_1_Stage`, `Tech_SYM/03_InGame`, 개별 발판 시험 씬, 타 작업자 씬, 이름만 같은 다른 폴더 씬, 미저장 새 씬은 비대상이다. 비대상에서는 Bootstrap으로 넘기거나 통합 route를 예약하거나 통합 검증용 객체를 넣지 않는다. 그 씬 자체의 구성으로 Play한다.

대상→비대상 이동 뒤에도 이 코드가 설정한 playModeStartScene이나 pending route가 남지 않아야 한다. 사용자 원래 설정을 영구 변경하지 않고 이번 hook이 소유한 임시 상태만 해제한다. Play 취소·Stop·재컴파일/재등록·빠른 Play의 scene reload 설정에서도 임시 변경을 복원한다. 미저장 씬을 자동 저장/폐기하거나 기존 열린 씬 구성을 임의로 재작성하지 않는다.

종전 11개 씬 모두 통합 진입 기대를 폐기하고 대상/비대상 검사로 바꾼다. 이 변경은 Editor 정책이며 독립 씬의 자체 게임 로직을 전부 리팩터링하라는 뜻이 아니다. Windows 빌드는 설치된 여섯 씬을 명시적으로 전달하며 일반 ProjectSettings 빌드 목록을 자동 수정하지 않는다.

## 필수 검증과 완료 판정

1. 정적/컴파일: 변경 코드 컴파일 오류 0, 대상 원본/씬 Missing Script·필수 참조 단절 0, 허용 외 경로 변경 0, 기존 GUID 변경 0. `git diff --check`와 변경 목록을 확인한다.
2. 도메인/연결: R03~R05·R09의 경계, R07 JSON/중복 입력, R12/R13 중첩 토큰, R14/R15 충돌, R16/R17 이벤트·폐기·누락 클립을 관찰 가능한 결과로 검증한다. 계산식을 그대로 복사한 검사로 대체하지 않는다.
3. 실제 Editor: R20 여섯 경로의 기대 목적지와 비대상 표본을 각각 Play 확인한다. 비대상 표본에는 이전 Stage 1, 기존 발판 시험 씬, 다른 폴더 동일 이름/미저장 씬의 경로 판정이 포함된다. 타인 씬은 읽기·진입 확인만 하며 수정하지 않는다. 미저장 작업이 남아 있으면 자동 저장하지 않고 검증 가능한 안전한 상태가 될 때까지 해당 실험을 차단으로 기록한다.
4. 새 실제 프로토타입: 정상 새 게임, 전체 기능, 메모→옵션 중첩, 대화/로그/자동, 컷신 스킵, 카메라 역방향/정지/리스폰, 4→5개 수집/눈물, 먼 껍질/공간 부족 Q, 적 스턴 VFX, 모든 발판, 포획/사망/재시도/엔딩 후 두 판 연속을 확인한다. 별도 가짜 검증 씬만의 통과로 대체하지 않는다.
5. 저장/빌드: 변경한 소유 자산을 저장해 dirty=false와 직렬화값을 다시 확인한다. 보호된 기존 미저장 씬은 그대로 보존한다. Windows 빌드 결과 Succeeded/errors=0, ProjectSettings 해시 불변, 실행 파일의 새 게임→엔딩/제목 복귀를 확인한다. 컴파일·Play·빌드·실행 파일 결과를 따로 기록한다.
6. 기록: 각 결과는 정적 확인/실행 통과/실행 실패/미실행/차단 중 실제 상태로 표기하고 명령·시간·대상·기대/실제를 남긴다. 독립 구현 검토와 사용자 검토용 diff를 제공한다. 실제 모델/Animator/클립 재생 제외 항목은 통과가 아니라 범위 제외다.

위 항목은 구현 이후의 완료 기준이다. 이번 ready에서는 원본 등록·대조·명세/계획 완전성·독립 문서 검토만 수행한다. 준비 승인만으로 커밋·푸시·PR·병합이나 게임 구현이 완료되는 것은 아니다.
