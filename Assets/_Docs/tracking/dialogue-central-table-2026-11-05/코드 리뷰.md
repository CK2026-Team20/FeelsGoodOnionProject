# 코드 리뷰

- 기존: DialogueSelection이 TextAsset와 code를 저장. Inspector는 트리거 원본을 파싱하고 RequireSelection은 앱에서 파싱한 원문과 트리거 원문의 내용 일치를 요구했다. null fallback은 없었다.
- 변경: DialogueSelection은 code만 보관. Bootstrap AppComposition이 DialogueTableService를 한 번 생성·파싱하고 기존 조립 주입 경로를 재사용한다. StageService는 테이블 자산 대신 중앙 서비스와 코드로 조회한다.
- 최종 대화의 선택 객체·키·서비스·Actor 세대·판·회차 검사는 유지. 제거한 것은 중복 TextAsset 비교뿐이다.
- Dialogues 최상위 배열과 기존5개 필드 엄격 검증. 실패 시 기존 유효 테이블 보존. 예전 Rows는 새 원본과 일치하지 않아 거절한다.
- Editor DialogueAuthoringSource는 ArchitectureInstallation의 Bootstrap 씬을 해석하고 열린 Bootstrap이 있으면 현재 연결을, 없으면 저장된 씬을 preview로 읽고 닫는다. 원본 캐시는 의존 해시로 무효화하고 목록 캐시는 JSON 내용 변경으로 갱신한다. 프리팹·미저장 씬 저장 없음.
- 새 키 목록은 자동 갱신되지만 기존 키의 의미상 이름 변경은 자동 추측하지 않는다. 존재하지 않는 선택은 원문을 유지하고 재선택 경고한다. 안정 ID가 없는 JSON에서 임의 치환을 막는 계약이다.
- Bootstrapper 새 JSON 연결은 작업 중 저장 상태에서 이미 확인됨. 사용자 기존 변경을 보존했다.

## 저장 및 실행 후 검토

사용자 승인으로 미저장 Tutorial 편집을 함께 저장했다. Tutorial 순변경은 사용자 편집의 구 dialogue.table 참조1개와 에이전트의 POPO→ENDING_POPO_01 키 이관1개다. 기존 EXPLORE_OVEN_01 키는 유지됐다. 삭제된 dialogue.table 필드의 과거 prefab override 직렬화는 씬에 남아 있으나 현재 컴포넌트/Inspector/런타임에서는 읽지 않는다. 이 잔존 기록을 지우기 위해 사용자의 prefab override 전체를 재작성하지 않았다. 저장 전 원본 사본은 output에 보존했다. 실행 검증 후 원래 Tutorial 편집 모드로 복원. 코드 diff 공백 검사 통과. Bootstrap 직렬화에는 Unity가 기록한 빈 value의 후행 공백이 있어 전체 git diff --check 경고와 코드 검사 결과를 구분한다. 커밋·push 없음.
