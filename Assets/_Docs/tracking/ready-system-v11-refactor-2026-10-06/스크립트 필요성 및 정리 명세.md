# 스크립트별 필요성 및 정리 대상

현재 파일 전수는 `Assets/_Code/**/*.cs` 206개다. Tech_SYM 160개, Tech_HMS 41개, 공용 Interfaces 5개다. 패키지·생성 코드·아트 리소스는 제품 스크립트 수에 포함하지 않는다. 판정은 실행 계획이며 이번 ready에서 소스/메타를 삭제한 결과가 아니다.

의존 증거: 텍스트 직접 GUID 참조와 코드 토큰 소비를 조사했고, Unity AssetDatabase의 전체 161개 scene/prefab/asset/controller/playable에 대해 재귀 의존 526건을 확인했다. 표의 숫자는 **직접 GUID / 재귀 자산 / 코드 토큰** 순서다. 메뉴·리플렉션·동적 로드·별도 소유자 외부 호출까지 없다는 증명은 아니므로 삭제 작업에서 다시 검증한다. 재귀 의존은 같은 prefab을 쓰는 scene도 세므로 직접 배치 수와 다르다. 원본 GUID/호출자 목록은 `output/Tech_SYM/planning/system-v11-refactor-2026-10-06/reviewed-script-inventory.json`에 있다.

삭제는 책임을 잃어버리는 조립이 아니다. 대체 컴포넌트/데이터를 먼저 연결하고 동일 기능을 검증한 뒤 호출·GUID·생성 메뉴·문서 참조를 0으로 만들고 `.cs`와 자기 `.meta`를 함께 제거한다. 원본/역사 자료는 보존한다. 사용자가 직접 제거할 prefab을 대신 일괄 삭제하지 않는다.

## 변경 전에 다시 확인할 항목

- 스냅샷·애니메이션·카메라의 새 계약은 기능 명세서가 정의한다. 보호 원본의 정리 후보는 권한 승인이 없는 동안 삭제 명령으로 전환하지 않는다.
- GameEventBus/ServiceLocator/VM/센서/모터처럼 수명·외부 실행·물리 콜백 경계가 실제로 다른 파일은 유지한다. 파일 수 감소를 위한 거대 컨트롤러는 만들지 않는다.
- 이동 발판의 HMS MovingPlatform, PlatformRigidbodyMovement와 SYM KinematicPlatformMotion은 현재 좌표/운반/효과 계약이 같지 않다. 같은 객체의 이동자는 하나로 조립하되 검증 없이 모든 SYM 물리를 HMS로 바꾸지 않는다.
- 필요한 파일 안의 폐기 코드도 정리한다. Back/Corridor, Prepare/Cooldown 소비, RecoverShell HUD, 옵션 Retry, 적 HP/Dead/보상, 자동 붕괴 복구, rescued/latch/tear gate, 4패널/scale, Instruction 검색, 출력 교대/Actor 자식 카메라 탐색을 계획의 담당 작업에서 제거한다.
- 기능 구현 시 채택 이유를 명세서의 상태 소유 표와 이 문서의 각 행에 연결한다. 교체 후에도 실제 소비자/독립 수명/외부 경계가 없는 새 어댑터 파일을 추가하지 않는다.
