## 씬 재로드 여부의 차이와 필요한 복귀 명령

**재로드를 없애는 것만으로 해금 문제가 해결되지는 않는다.** 사용자가 추가 질문에 선택한 정책은 **현재 스테이지에서 얻은 능력을 사망 시 다시 잠그고, 해당 해금 트리거를 재접촉하면 활성화**하는 것이다. 이전 Stage의 정상 해금은 세션 상태로 유지한다. 이 출처와 수명은 런타임 상태이며 체크포인트의 세 번째 복원값이나 직렬화 장부로 만들지 않는다. 재잠금과 HUD 음영/기능 수락 조건은 같은 원본에서 갱신한다.

한 Stage의 체크포인트는 **시작과 끝 두 곳**이다. 중간 능력 해금 지점을 체크포인트로 만들거나 추격 시작을 이유로 세 번째 저장 지점을 추가하지 않는다. 기존 Prototype의 P_FORM/P_TEAR는 독립 해금 트리거로 이관하고 중간 CP/P_CHASE 저장은 제거한다. 추격 재시도도 마지막으로 실제 접촉한 시작/끝 CP의 두 값을 사용한다.

복귀 순서는 Fade/입력 차단 → 현재 대화/메모/추격과 Actor 참조 해제 → Actor 제거 → 현재 Stage의 작업·접촉·기믹/적/조각/트리거 초기 재준비 → 현재 Stage 능력/안내 재잠금 → 저장 Position/Fragments로 Normal Actor 생성/HP·속도·무적 초기화 → 같은 Stage/Core 리그에 연결 → 표시/입력 복구다. 실패는 성공으로 게시하지 않는다.

## 데이터와 서비스의 수명

| 범위 | 소유 데이터/서비스 | 복귀/종료 계약 |
|---|---|---|
| App/Bootstrapper | 부모 없는 ServiceLocator, Flow·씬 접근·음량·전환·공통 입력/정지 제한, 출력 Camera/Brain/Listener | 사망 복귀에 새로 만들지 않음. 앱 종료에 자기 자원 해제 |

| Stage | 현재 스테이지 실행 구성, 배치/트리거·적/기믹·초기 배치값과 reset 책임 | 사망 복귀에 씬 유지/같은 Stage 객체 재준비. 초기 배치값은 저장 snapshot이 아님. 월드 DTO/상태 ID/범용 Registry 추가 금지 |

사용자가 확정한 씬 범위는 **InGameCore 최초1회 뒤 등록 Stage3개 전부 최초 additive 로드, Core/Stage는 retry·Title 복귀·다음 판에 재로드하지 않음**이다. 활성 Stage 하나만 Actor·입력·트리거·추격/외부 작업과 연결한다. Title 씬 자체의 NewGame 언로드는 허용한다. App 로케이터/영구 월드는 유지하되 Title에는 한 판 서비스/빌린 참조를 ReleaseSession으로 해제하고 다음 판에는 같은 Core에 새 App 부모 범위를 연결한다. Bootstrapper를 전역 가변 싱글턴으로 바꾸지 않는다.

획득한 조각은 성공 소비 시 비활성화한 **동일 TearFragment 객체**를 Stage 초기 재준비에서 다시 활성화한다. 원래 Visual 자식·Renderer·Collider와 소비 플래그/표시 시계를 복구하고 수집 기능/identity를 확인한다. 최대5에서 거절한 객체는 그대로 남는다. 재생성·씬 재로드/언로드·checkpoint 소비 목록·월드 DTO·객체 상태 ID를 사용하지 않는다.
