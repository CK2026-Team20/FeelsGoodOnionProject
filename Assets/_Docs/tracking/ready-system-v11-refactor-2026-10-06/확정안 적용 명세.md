# 2026-10-07 확정안 구현 기준과 씬 유지 복귀

사용자가 `dryforge:go`를 직접 요청하며 지정한 Desktop의 `시스템 정책 검토 요약.md`의 **확정안**과 같은 대화에서 받은 추가 답변을 적용한다. 원문의 권장안은 자동 채택하지 않는다. #11의 기획 문서 정리 지시는 제외하지만, 그 안의 능력 안내 확정안은 구현한다. 기존 DOCX·PDF·수정 이력의 문구를 이 작업으로 정리하지 않는다.

이 문서는 같은 폴더의 기존 기능 명세서·계획·인계에서 아래와 충돌하는 초안 문구를 대체한다. 구현·검증 완료 기록은 아니며, 실제 완료 여부는 테스트 및 검증 항목과 실행 증거로 판단한다.

## 목표 → 참고 자료 → 제약 → 완료 기준

목표는 선택한 플레이어·적·기믹·화면 동작을 기존 책임 소유자에 연결하고, 사망 복귀에 현재 스테이지 씬을 재로드하지 않도록 고치는 것이다. 현재 스테이지에서 얻은 능력을 다시 잠가 시작 체크포인트에서 구간을 건너뛰어 사용하는 문제를 막는다.

참고 자료는 사용자 확정안 원문, 최신 시스템 DOCX의 색상·취소선, 기존 AppComposition·Bootstrapper·ServiceLocator·GameFlowService·GameSessionRuntime·GameSessionService·StageService·SessionActorHost 및 실제 설치/씬/프리팹이다. 기존 구현과 이전 성공 기록은 새로운 요구를 대체하지 않는다.

제약은 체크포인트 Position/Fragments 두 값, Tech_SYM 소유 범위, 미커밋·미저장 보호, HMS의 이번 명세 한 번에 한정한 최소 확장, 원본 자산/GUID 보존이다. HMS 기존 기능의 변경·삭제·전체 정리는 금지하며, 새로운 조립에 필요한 공개 기능·참조 캐시·변수만 추가한다. 기본 독립 소비 동작을 보존한다. 보호 메타·공용 Interfaces·_Art·Packages·ProjectSettings의 수동 수정은 허용하지 않는다.

완료 기준은 새 컴파일, 사용자 기능 실행, 사망 반복 복귀의 scene handle/서비스 인스턴스 유지, 위치/조각 원자 캡처·복원, 능력 재잠금·트리거 재해금·HUD 일치, Stage의 초기 상태 재준비, 입력/Actor/출력 단일성, 화면/종료 수명, 저장된 자산의 필수 참조/Missing Script 검사, 독립 검토와 정확한 여섯 씬 Windows 빌드다. 실행하지 않은 아트 재생·팀 플레이·FunQA는 별도 대기로 기록한다.

## 씬 재로드 여부의 차이와 필요한 복귀 명령

현재 소스는 AppComposition에서 앱 ServiceLocator를 만들고 Bootstrapper에 전달하며, GameSessionRuntime이 부모를 가진 Core 범위를 만든다. 로케이터가 없는 구조는 아니다. 실제 문제는 GameFlowService.Retry가 Actor 제거 뒤 Stage Unload/Load를 실행하는 것과 저장·해금·Stage 초기화 수명의 불일치다.

| 관점 | 현재 Stage 씬을 재로드하는 경우 | 재로드하지 않는 경우 | 이번 구현 계약 |
|---|---|---|---|
| 객체/참조 | Stage 객체가 파괴되고 Awake/OnEnable/Start가 다시 실행됨. Core가 이전 객체/구독을 보관하면 끊어진 참조·중복 구독 위험 | 같은 객체·서비스 참조가 유지됨. 초기화하지 않으면 적 기절·장치 중간 위치·접촉·추격 상태도 남음 | 같은 scene handle과 Stage 인스턴스 유지. 새 Actor 연결 전에 자기 작업/접촉/제한을 정리하고 초기 배치로 재준비 |
| 능력 | Core 해금이 유지되면 새 Stage 트리거가 아직 접촉되지 않았는데 시작점에서 스킬 사용 가능 | 해금 원본을 그대로 유지해도 동일한 조기 사용 문제 발생. 트리거만 초기화하면 HUD/능력과 불일치 | 세션이 해금의 단일 소유자. 현재 Stage가 부여한 해금만 제거하고 해당 안내 완료도 다시 접촉할 수 있게 정리 |
| 체크포인트 | ID로 새 Marker를 찾으면 접촉 시 실제 위치와 다른 위치에 등장할 수 있음 | 실제 위치를 저장하지 않으면 똑같이 잘못 복귀. 초기화된 장치에 위치가 막힐 수도 있음 | Position/Fragments만 저장·복원. 처음/끝 CP는 초기 월드에서 기본 폼이 들어갈 안전 영역에 배치 |
| 자원 수명 | 씬 파괴가 일부 작업만 정리하고 Core/App 비동기·콜백은 살아남을 수 있음 | 비활성화/파괴에 기대던 정리가 저절로 실행되지 않음 | reset 명령에 취소·구독·Tween·접촉 정리를 포함하고 실패하면 입력/페이드 차단 유지 |
| 실행 비용 | 씬 IO·재생성·등록·카메라 재연결 비용과 잠깐 중복 출력 가능 | 씬 IO 없음. 명시적 초기화 경계가 빠지면 불완전 복귀 | App 출력/Core 리그 유지, Stage 초기 재준비 완료 뒤 Actor 한 개와 HUD 연결 |

**재로드를 없애는 것만으로 해금 문제가 해결되지는 않는다.** 사용자가 추가 질문에 선택한 정책은 **현재 스테이지에서 얻은 능력을 사망 시 다시 잠그고, 해당 해금 트리거를 재접촉하면 활성화**하는 것이다. 이전 Stage의 정상 해금은 세션 상태로 유지한다. 이 출처와 수명은 런타임 상태이며 체크포인트의 세 번째 복원값이나 직렬화 장부로 만들지 않는다. 재잠금과 HUD 음영/기능 수락 조건은 같은 원본에서 갱신한다.

한 Stage의 체크포인트는 **시작과 끝 두 곳**이다. 중간 능력 해금 지점을 체크포인트로 만들거나 추격 시작을 이유로 세 번째 저장 지점을 추가하지 않는다. 기존 Prototype의 P_FORM/P_TEAR는 독립 해금 트리거로 이관하고 중간 CP/P_CHASE 저장은 제거한다. 추격 재시도도 마지막으로 실제 접촉한 시작/끝 CP의 두 값을 사용한다.

복귀 순서는 Fade/입력 차단 → 현재 대화/메모/추격과 Actor 참조 해제 → Actor 제거 → 현재 Stage의 작업·접촉·기믹/적/조각/트리거 초기 재준비 → 현재 Stage 능력/안내 재잠금 → 저장 Position/Fragments로 Normal Actor 생성/HP·속도·무적 초기화 → 같은 Stage/Core 리그에 연결 → 표시/입력 복구다. 실패는 성공으로 게시하지 않는다.

## 데이터와 서비스의 수명

| 범위 | 소유 데이터/서비스 | 복귀/종료 계약 |
|---|---|---|
| App/Bootstrapper | 부모 없는 ServiceLocator, Flow·씬 접근·음량·전환·공통 입력/정지 제한, 출력 Camera/Brain/Listener | 사망 복귀에 새로 만들지 않음. 앱 종료에 자기 자원 해제 |
| Core/한 판 | App 부모를 가진 서비스 범위, Session·PlayerBridge·Dialogue·ActorHost·Side/Quarter 리그·화면 바인딩 | 사망 복귀에 범위/서비스 유지. 타이틀 종료에서 세션 정리. View는 주입된 ViewModel만 사용 |
| Stage | 현재 스테이지 실행 구성, 배치/트리거·적/기믹·초기 배치값과 reset 책임 | 사망 복귀에 씬 유지/같은 Stage 객체 재준비. 초기 배치값은 저장 snapshot이 아님. 월드 DTO/상태 ID/범용 Registry 추가 금지 |
| Actor | HMS Model/이동/폼·실제 Body와 Anchor·Actor 입력/피격/표현 연결 | Actor 제거 전 빌린 참조/구독 해제. 새 Actor에 체크포인트 두 값만 복원 |

사용자가 씬 범위를 추가 확정했다: **InGameCore를 한 번 로드한 뒤 등록된 Stage 씬 전부를 최초에 additive 로드하며, 해당 Stage 씬은 이후 재로드하지 않는다.** 기존 선택 Stage 하나만 로드하는 구현/초안을 대체한다. 비활성 Stage의 루트를 비활성화하고 활성 Stage만 Actor·입력·트리거·적과 연결한다. 이미 로드한 Core/Stage는 사망 복귀·타이틀 복귀·다음 판에서도 씬 인스턴스를 유지하고, 새 판의 서비스/플레이 상태는 해당 수명 소유자가 별도로 초기화한다. Bootstrapper의 현재 서비스 제공 방식을 전역 가변 싱글턴으로 교체하지 않는다.

획득해서 사라진 눈물조각도 해당 Stage의 초기 재준비 때 다시 등장해야 한다. 소비 성공 시 Stage가 다시 준비할 수 있는 비활성 객체로 유지하거나 기존 조립 자산으로 객체를 재생성한다. 씬 로드/언로드로 조각을 복원하지 않는다. 최대 5개에서 수집을 거절한 조각은 그대로 남는다. 조각의 실제 수집 기능과 위치/표현/충돌이 복구됐는지 확인한다. 소비 목록을 체크포인트 payload/월드 저장 DTO로 만들지 않는다.

## 추가 검증 항목

- CP 시작 접촉 → Q/E 해금 → 끝 CP 미접촉 사망 → 같은 Stage scene handle·Stage 객체·App/Core 서비스로 복귀, 저장 위치/조각 일치, 현재 Stage 능력 사용 거절/HUD 음영 → 트리거 재접촉 후 한 번 해금·활성 표시.
- 이전 Stage 능력은 유지, 현재 Stage 능력만 제거. 능력 안내가 이전 완료 장부 때문에 재접촉 시 누락되지 않음. CP 저장 구조/직렬화 데이터는 두 값뿐.
- 적 기절·작동 중 장치·소멸/붕괴 발판·획득 조각·추격 중 사망 후 초기 배치/상태 재준비. 초기화 중 남은 Tween/충돌/늦은 콜백/중복 입력 없음.
- 옵션/메모 중첩 해제 후 상대 정지 토큰 유지. 대화는 독자적으로 월드를 정지하지 않음. 메모/대화 F/Enter/영역 클릭 한 입력 한 명령.
- 포포와 포획 동시 갱신은 사망/복귀, 포포만 수락하면 추격/포획 중단 후 최종 대화 완료에 엔딩 한 번.
- HMS 기본 독립 기능과 enum/API/참조 계약 보존, 새 조립의 명시적 확장만 diff에 포함. 미승인 보호 원본/메타 수동 변경 없음.
