# 현재 프리팹 연결 계약

> 2026-10-08 현재 확정안과 저장 자산 이관을 반영한다. 미선택 모호성 문서는 구현 권한이 아니다. 실제 연결은 선택적으로 이관했으며 사용자 기존 prefab 일괄 제거·보호 원본 Apply를 수행하지 않았다. 12씬/61프리팹의 참조·Missing 검사와 자동 실행 범위를 검증 문서에서 구분한다.

눈물 연결 추가: EnemyActor에 이미 연결한 `body`를 실제 피격 몸체로 지정한다. 현재 Body는 Trigger이므로 Query에서 Trigger 전체를 무시하지 않는다. Body가 범위에 닿고 그 앞에 벽/사물 가림이 없어야 하며, 시야·상호작용·체크포인트용 Trigger나 효과 Collider는 몸체로 인정하지 않는다. Body 위에 EnemyContactSensor가 있다는 이유만으로 몸체까지 제외하지 않는다. 벽/닫힌 문/서랍/플랫폼의 차단 Collider는 실제 배치에 포함되어야 한다. Visual Mesh만 있고 Collider가 없는 벽을 자동 차단한다고 가정하지 않는다.

현재 연결은 기존 EnemyActor의 몸체 판정 함수를 PlayerBridge에서 HMS Facade/TearSkill에 주입하는 공개 계약이다. 새 공용 인터페이스나 Collider마다 별도 눈물 전달 스크립트를 기본으로 추가하지 않는다. HMS는 SYM 클래스를 참조하지 않고 공개 판정 결과의 원래 IStunnable에만 효과를 적용한다. 공개 주입/해제 API와 자기 Collider 제외·다중 후보 처리를 사용한다. 실제 E의 벽/몸체 검사와 소스 경계 검증을 통과했으며 전체 원본 배치 판정과는 구분한다. 직접 피격 전에 가림을 확인하며 이미 적용한 기절을 외부에서 취소하는 우회는 사용하지 않는다.

현재 소유 자산은 App 출력/Core 리그/Actor/Body·Contacts/단일 화면에 맞춰 선택적으로 이관했다. Idle/X/Y 적3개 data·prefab도 작성했다. 실제 애니메이션13참조는 미연결이다. 기존 prefab의 일괄 제거는 사용자가 직접 수행한다. 실행자는 삭제 전 GUID 소비를 조사하고, 남은 소유 씬의 참조를 새 prefab 또는 명시적인 연결 대기 상태로 이관한다. 필수 참조가 빈 씬을 정상 게임으로 통과시키지 않는다.

모든 자원은 Renderer가 없는 빈 Root로 묶는다. Root는 데이터·컨트롤러를, Visual은 Renderer/Animator만, Physics는 Collider/Rigidbody/물리 콜백 경계를 맡는다. 동일 객체에 이동자·입력자·상태 원본을 두 개 설치하지 않는다. 아래에 별도로 표시한 HMS 물리 예외는 현재 공개 계약을 보호하기 위한 제한이다.

## 앱, Core, Stage의 배치

```text
AppRoot                              [AppComposition, 앱 서비스 수명]
├─ Output                             [Camera, CinemachineBrain, AudioListener,
│                                      HMS PlayerCameraController]
├─ GlobalUIRoot                       [GlobalUiRoot]
│  ├─ OptionsCanvas                   [OptionsView]
│  └─ FadeCanvas                      [FadeView]
└─ AudioRoot                          [AudioRuntimeHost, AudioSource들]

CoreRoot                             [CoreComposition, LevelCameraService]
├─ ActorHost                          [SessionActorHost]
├─ CameraRig                          [빈 Root, 자체 SYM 리그 스크립트 없음]
│  ├─ Side                            [CinemachineCamera]
│  └─ Quarter                         [CinemachineCamera]
├─ GameUIRoot                         [GameUiRoot, CoreUiBinding]
│  ├─ ScreenCanvas                    [HudView, DialogueView, MemoView]
│  └─ WorldCanvas                     [WorldPromptView]
├─ CinematicRoot                      [CinematicHost, CinematicView]
└─ ChaseRoot                          [ChaseRuntimeDriver, ChaseSwarmPresentation]

StageRoot                            [StageService]
├─ Checkpoints                       [CheckpointMarker별 배치]
├─ CameraZones                       [CameraZoneTrigger별 배치]
├─ Devices / Platforms / Enemies
├─ Pickups / Memos / Hazards
└─ ChaseStart / RetreatGate / Poppo
```

App Output에 출력 Camera·Brain·AudioListener를 각각 **한 개**만 둔다. Core 리그의 두 CinemachineCamera는 출력 Camera가 아니다. Side/Quarter는 명시적인 CameraAnchor를 추적하며 Actor의 부모/자식 관계를 이용해 참조를 찾지 않는다. PlayerCameraController는 새 공개 Bind/Unbind/Preview/Commit 계약으로 두 카메라와 현재 이동 모드를 받는다. 이 API는 이번 한정9개HMS 공개 확장으로 제공되며 SYM 조립에서 명시적으로 사용한다. LevelCameraService가 전환 시작·차단·평면 정렬·실제 Brain 완료를 관리하고, HMS 컨트롤러만 우선순위를 쓴다.

AppComposition은 Output을 소유한다. CoreComposition은 두 가상 카메라와 LevelCameraService를 소유한다. SessionActorHost는 Actor를 소유한다. retry에는 출력과 Core 리그를 다시 만들지 않는다. Actor 제거 전에 목표·모드 구독을 해제하고, 새 Actor의 Awake/Start 준비 후 새 목표를 Bind한다. 준비 완료 전 월드 출력과 입력을 가린다. Title/Opening/Ending에서는 UI Overlay를 표시하며 같은 Output의 월드 표시만 제어한다.

## 플레이어

```text
PlayerRoot                           [빈 Root, GameplayInputRouter, ActorFallGuard]
└─ ActorBody                          [HMS Facade/Movement/Form/Skill/Input/Animation,
   │                                  Rigidbody, CapsuleCollider, PlatformPassenger,
   │                                  PlayerMovementModeController, HeavyState,
   │                                  CharacterSlipperyEffect, PlayerDamagePresentation]
   ├─ VisualRoot                      [HMS가 요구하는 바로 아래 두 폼]
   │  ├─ NormalVisual                 [Renderer, Animator]
   │  └─ SmallVisual                  [Renderer, Animator]
   ├─ CameraAnchor                    [Transform만, 실제 움직이는 Body의 기준점]
   ├─ VFX                             [순수 파티클/효과 자식]
   └─ SFX                             [순수 AudioSource 자식]
```

PlayerRoot에 CameraRig/출력 Camera를 넣지 않는다. PlayerInputReader는 한 개, GameplayInputRouter도 한 개다. HMS PlayerController·CheckInteract·Temporary 입력 시험 컴포넌트는 새 SYM Actor에 연결하지 않는다.

**HMS 물리 예외:** PlayerFacade·CharacterMovement·PlayerFormController와 Rigidbody/Collider는 같은 ActorBody에 유지한다. 현재 HMS는 같은 객체의 GetComponent를 사용하고, SYM 접촉 경계도 attachedRigidbody.gameObject에서 Facade를 찾는다. Facade만 빈 Root로 옮기면 조립이 성립하지 않는다. 이를 고치려고 별도 SYM 이동/폼/피격 원본을 만들지 않는다. 보호된 센서/폼 계약까지 바꾸는 전면 이관은 이번 최소 예외에 포함하지 않는다. 물리 예외를 없애려면 그 파일·소비자까지 별도 설계/허가가 필요하다.

| 연결 | 대상과 기본값 | 누락/중복 처리 |
|---|---|---|
| SessionActorHost actor prefab | 비활성 PlayerRoot, Stage 체크포인트의 Body 기준 Pose | 활성 prefab/두 Facade/두 Reader·Router를 오류로 거절 |
| GameplayInputRouter | 현재 Bridge·상호작용 서비스·제어 서비스·단일 HMS Reader | 명령을 한번만 전달; F 닫기는 열린 메모 우선, 옵션 중 무시 |
| PlayerFacade | 동일 Body의 Movement/Form/Skill/Animation, MaxHP3·조각 최대5 | 원본 HP/조각은 Model 하나; HUD에 두 번째 값을 저장하지 않음 |
| 폼 | VisualRoot 바로 아래 NormalVisual/SmallVisual, Collider 설정, 껍질 prefab | Q 기본→작은 즉시, 작은→기본 공간 실패면 둘 다 보존 |
| 스킬 데이터 | 눈물5/반경3m/기절2초, 준비/쿨다운 없음; 점프 기본3m/작은2m | 필수 값/양수 범위 검증; 별도 회수 키/범위/능력 카드는 없음 |
| 이동 모드 | Side·Quarter 초당5m, 대각선 정규화 | 보호 HMS의 Back/BackFixed는 새 SYM 제품에서 사용하지 않음 |
| Animation | 같은 Body의 요청/출력, 실제 두 폼 Animator와 PlayerAnimationSet | 장치 공통 Interact·Hit·Dead와 완료 RequestId 연결; 실제 클립 없는 상태는 별도 표시 |
| CameraAnchor | ActorBody의 자식 Transform, 배치용 로컬 오프셋 | PlayerRoot의 정지 Transform을 목표로 연결하지 않음 |
| 껍질 | 빈 Root 아래 물리 Body, HMS PlayerDebris/HeavyState 공개 계약 | 한 개만 생성, 생성 속도 상속, 회수/사망/제목 종료는 FormController 소유 |

## 발판·장치

```text
PlatformRoot                         [종류별 컨트롤러]
├─ PhysicsBody                       [Rigidbody가 필요한 종류만, Collider,
│  │                                  PlatformContacts]
│  └─ Visual                         [Renderer / 표현용 Animator]
├─ VFX
└─ SFX

DeviceRoot                           [공통 장치 컨트롤러,
│                                     InteractionPromptAnchor]
├─ MovingBody / Hinge                 [Collider, 필요한 물리 몸체]
│  └─ Visual                         [Renderer]
└─ PromptPoint                       [대상 중심 위 Transform]
```

소유 SYM 코드의 KinematicPlatformMotion/발판 컨트롤러는 Root에서 명시적 PhysicsBody/PlatformContacts 참조를 받도록 변경한다. 기존 RequireComponent/GetComponent 때문에 자동으로 Root에 물리를 추가하는 경로를 제거한다. PlatformContacts는 실제 물리 콜백이 오는 자식에 남으며 부모 로직이 점유를 읽는다. ShatteredPlatform도 Collider/Contacts/Visual을 주입받는다. 단지 계층을 맞추기 위한 종류별 센서·어댑터 파일을 늘리지 않는다. 저장 자산의 명시적 Body/Contacts 참조와 원래 GUID·형상을 실제 이관·재저장했다. 신규/재작성 결과도 같은 계약으로 검증한다.

| 종류 | 반드시 필요한 구성 | 설정/상태/동작 | 연결하면 안 되는 구성 |
|---|---|---|---|
| 고정 | 빈 Root + Visual + 고정 Collider | 스크립트 없음; 체크포인트 상태 없음 | 이름만 있는 FixedPlatform 컨트롤러 |
| 부유 | FloatingPlatform + KinematicPlatformMotion + PhysicsBody/Contacts | 기본 위치 고정, 한 착지당 눌림/반동; 연속 접촉 중 재발동 금지 | PhysicsBody를 계속 흔드는 FloatingMotion |
| 이동 | LinearShuttlePlatform + KinematicPlatformMotion + PhysicsBody/Contacts | 부모 기준 XYZ 종점 이동량·월드 m/s, 양 종점0.5초 대기 | HMS MovingPlatform/PlatformRigidbodyMovement의 중복 이동자 |
| 주기 | PeriodicPlatform + Collider/Visual 참조 | Solid5 / Absent2 / Forming3초, Forming 비충돌, 개별 시작 위상 | 표현 중 Collider를 먼저 켜는 별도 스크립트 |
| 붕괴 | ShatteredPlatform + Contacts/Collider/PlatformPresentation | 기본 플레이어 윗면만, 경고1초 종료 즉시 지지Collider 해제·붕괴, 자동 복구 없음 | 껍질·작은 폼 발동, IBrokenable, 재생성 타이머 |
| 압력판 | PressurePlatePlatform + PhysicsBody/Contacts + 연결 발판 목록 | 기본 플레이어/껍질 무게; 해제 시 복귀, 복귀 중 다시 누르면 현재 위치에서 반전 | ShellPressureLatch·탈출 퍼즐 결합 |
| 연결 발판 | PressureLinkedPlatform + KinematicPlatformMotion | 입력 센서와 다른 실제 객체; 현재 진행에서 목적지 변경 | 같은 이동을 쓰는 두 컨트롤러 |
| 오븐 문 | 공통 장치 컨트롤러 + Hinge/PromptPoint | 독립 F 토글, 문 회전/종점, 이동 중 중복 거절 | OvenHandle이 트레이를 대신 조작하는 연결 |
| 오븐 트레이 | 공통 장치 컨트롤러 + KinematicPlatformMotion/Contacts | 독립 F 토글, 로컬 이동 종점·속도, PC/일반 물체 운반 | 문과 공유하는 하나의 bool 상태 |
| 서랍장 | 빈 CabinetRoot 아래 Drawer1/2/3의 공통 장치 구성 | 각 서랍 종점/속도/PromptPoint와 독립 상태; 다른 장치 F 허용 범위는 질문 답변 적용 | Drawer1/2/3 이름 전용 스크립트 3개 |
| 기름 | 배치 OilSurface + Trigger, 필요한 Visual | 이탈 후3초 미끄러짐 갱신, 피해 없음 | EnemyOilOnDeath/EnemyOilLifetime |
| 불/끓는물 | DamageFloorPlatform의 공통 피해원 구성 + 실제 Collider/센서 | HP1, 플레이어 공통2초 무적, 접촉 방향 제한 없음 | 피해원별1초 중복 타이머/적별 넉백 설정 |

붕괴의 실제 Animator는 Visual 참조만 받으며 물리 Collider를 애니메이션으로 켜고 끄지 않는다. 경고1초 지지해제는 실제 물리 검사로 확인했고 붕괴 Motion의 실제 재생은 연결 대기다. retry에는 Stage를 초기 재준비하고 압력판 점유·탑승 Collider를 새 Actor에서 다시 수집한다. **적/장치/필드의 상태·ID·남은 시간은 체크포인트에 저장하지 않는다.**

## 일반 적과 마지막 무리

```text
EnemyRoot                            [EnemyActor, Definition]
├─ Body                              [Trigger Collider, EnemyContactSensor]
├─ Visual                            [Renderer / Animator]
├─ StunVFX                           [HMS 기절 효과 참조]
└─ SFX
```

EnemyActor가 StateMachine/Combat/Motor를 생성·연결한다. 이 순수 C# 객체를 모두 MonoBehaviour로 바꾸지 않는다. 센서는 물리 접촉을, Combat은 피해원 전달을, Motor는 충돌/지형 제한을, StateMachine은 기절/X/Y 순찰을 맡는다. EnemyModel의 HP/적 무적/사망·EnemyFloatMotion·적 사망 기름은 없다. `IStunnable`/`IStunState`는 HMS VFX에 연결한다. Body에 적 Rigidbody를 임의 추가하지 않으며 현재 비회전·양수 단위 배율의 Motor 조건을 검증한다. 새 Motor가 지원하지 않는 회전/배율을 조용히 수락하지 않는다.

EnemyDefinition은 Stationary(0)/Patrol(1)이며 Idle/X순찰/Y순찰3배치를 설정 자산과 기존 축 방향 값으로 조립한다. 추적/복귀/활동범위 필드는 없다. 기절은 FSM이 소유하고 만료 후 현재 순찰 조건을 다시 적용한다. 과거 대각/추적 배치는 명시적 X/Y 값으로 이관하며 enum 숫자를 추정해 바꾸지 않는다. 머리 Collider/처치 보상/적 HP는 새 제품에 없다.

마지막 무리는 ChaseRoot/경로/시작선/후퇴문/Poppo로 조립한다. 시작선은 전체 플레이어 Collider가 통과했을 때만 수락한다. 새 체크포인트를 캡처하지 않고 Chase.Start 수락 뒤 문을 닫는다. 8m 뒤에서4m/s, 경로상 gap<=0.8m이면 강제 사망이다. FrontContact 접촉 컴포넌트는 제거한다. Poppo 진입 시 추격을 멈추고 지정 최종 DialogCode가 완료된 뒤 Ending으로 간다. 이전 Rescue/Escape/ShellPressureLatch 조합을 추가하지 않는다.

## 메모·조각·트리거와 화면

| 자원 | 연결 | 검증 |
|---|---|---|
| 메모 | 빈 Root의 MemoObject/ID/이미지 + 자식 탐색 Collider/PromptPoint, 하나의 MemoUIController·VM·View에 주입 | ID 양수·중복 없음, F 열기/닫기, Opening 중 F닫기, Closing까지 입력 차단, 메모 자기 월드정지·입력 토큰, 옵션 중 아래F 없음·사망취소 자기토큰 해제 |
| 조각 | 빈 PickupRoot + Visual + Trigger 자식, 단일 TearFragment와 원본 Root/Visual 참조 | Trigger 콜백 경계는 현재처럼 물리 자식에 둔다는 예외를 기록; 1개 성공 때만 Root 비활성, 최대5에서는 보존, 재활성 중복 없음 |
| 체크포인트 | 빈 MarkerRoot + CheckpointMarker의 배치 ID/초기 Body Pose/CameraZoneData + 실제 StageTrigger 자식 | 현재 ActorBody 월드 위치/Fragments 두 값만 원자 저장. ID는 배치/중복 판별용이며 payload에 넣지 않음 |
| 카메라 구간 | 빈 ZoneRoot + CameraZoneTrigger 센서 자식·Side/Quarter/AlignmentOffset | 자신의 로컬 XYZ 정렬점, 파란 기즈모; side는 월드 Z 정렬, quarter는 평면 자유 |
| 데드존 | 빈 ZoneRoot + StageTrigger 센서 자식 | 무적/HP와 관계없이 HP0, Dead clip 생략, 중복 사망/복원 요청 없음 |
| 해금 | 지정 구간 StageTrigger + 해금 UI/안내 DialogCode | 체크포인트에만 종속하지 않음, Q와 회수는 하나의 능력 |
| Title | TitleUiRoot + TitleView/VM, ScreenSpaceOverlay | 새 게임/설정/종료, 이어하기 없음 |
| Options/Fade | GlobalUiRoot + Options/Fade View/VM, ScreenSpaceOverlay | Esc/X 동일 닫기, 수동 다시하기 없음; 제어/표시 토큰은 OptionsService가 소유 |
| Game HUD | GameUiRoot + HudView/VM, ScreenSpaceOverlay | HP3/0..5, 폐기 CPID·Recover·거리 Instruction 없음 |
| 월드 안내 | WorldPromptView/VM + WorldSpace Canvas, App Output 참조 | 가장 가까운 유효 대상 한 개의 중심 위 F; 메모 화면 Canvas와 분리 |
| Dialogue | DialogueView/VM + DialogueService + 검증된 JSON | 코드별1..N, Enter/창 클릭, 완전 표시 후 로그, 옵션/로그 표시 정지, 월드는 계속 진행 |
| Opening/Ending | CinematicHost/Catalog/Service/VM/View | 순서 목록의 한 원화+하단 문구, 4초 자동, 전체 Skip, 옵션 남은 시간 보존; Timeline 보정 컴포넌트 없음 |

## 작성과 인계 기준

모든 신규/변경 Inspector 필드에는 쉬운 한국어 Tooltip을 붙인다. 거리/속도/시간의 단위, 로컬/월드 좌표, 0의 의미, 참조할 자식, 기즈모 색상을 설명한다. 공개 Bind와 현재 공통 장치 필드를 사용하며 변경한 serialized 필드를 실제 저장 자산과 대조한다. 없는 animation 참조를 정상 재생으로 보고하지 않는다.

필수 참조·활성 입력 수·출력 Camera/Brain/Listener 수·Missing Script·안정 ID 중복·실제 선택된 가상 카메라와 ActorBody 위치를 Unity native API로 확인한다. 저장 직후 재로드 검사와 isDirty=false가 필요하다. 실제 클립/아트가 없으면 물리·입력·대체 완료의 결과만 검증하고 실제 애니메이션/픽셀 품질은 연결 대기로 남긴다.

## 한 판과 Stage 재준비 연결

Core/Stage3씬은 최초 로드 뒤 같은 인스턴스를 유지한다. StageService는 실제 typed 소유자 ResetForRetry로 Body/Transform·기믹·적·소비조각·트리거·추격을 초기 재준비한다. Actor를 연결한 Stage는 하나이며 비활성Stage의 외부 작업도 취소한다. CoreComposition.ReleaseSession은 Title에서 한 판의 빌린 참조를 해제하고 다음판에 새 범위를 연결한다. Stage 전체저장DTO/상태ID/저장참가자Registry를 추가하지 않는다.
