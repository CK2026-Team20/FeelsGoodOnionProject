# 최신 시스템 명세에 맞춘 리팩터링 기능 명세서

> 2026-10-07 사용자 `dryforge:go` 실행 지시와 Desktop 확정안을 반영했다. #11의 원본 기획 문서 정리는 제외하고 안내 방식은 적용한다. 최신 세부 계약은 [확정안 적용 명세](<확정안 적용 명세.md>)다. 현재 Stage에서 얻은 능력은 사망 복귀에 다시 잠그고 트리거 재접촉으로 해금한다. 이번 HMS 수정은 기존 기능을 보존한 최소 확장으로 한정한다. 구현·실행 검증 완료 여부는 별도 결과 문서를 따른다.

## 목표와 완료 결과

플레이어·기믹·일반 적·추격·메모·대화·연출·옵션을 최신 동작으로 맞추고, 같은 상태와 명령을 여러 구현이 소유하는 경로를 제거한다. 조립 가능한 기능은 기존 공개 기능에 연결하며 불필요한 전달자·소스·필드·분기를 이관 후 삭제한다. 각 유지 스크립트의 필요성, 구조를 택한 이유, 새 프리팹의 연결과 검증 결과를 문서에서 추적할 수 있어야 한다.

개수만 줄이기 위해 물리 콜백·생성/파괴·외부 실행·화면 바인딩 경계를 합치지 않는다. 파일을 나누거나 partial로 옮기는 것은 책임 정리가 아니다. 새 저장 시스템·인터페이스·팩토리·서비스를 재사용 가능성만으로 추가하지 않는다.

## 적용 범위와 경계

실행 대상은 Tech_SYM의 소스·소유 자산·관련 작성 도구와 프로젝트 문서다. App/Core/Stage 수명, 여섯 씬의 통합 흐름, 기능 응집 프로토타입을 유지한다. 본편 레벨 배치를 새로 강제하지 않는다. 기존 프리팹의 일괄 제거는 사용자가 직접 수행한다. 실행자는 남아 있는 소비 참조를 이관하고 필요한 새 자산을 명세대로 연결한다.

다른 작업자·공용 Interfaces·_Art·보호 메타·Packages·ProjectSettings 원본은 읽기 전용이다. Tech_HMS .cs는 이번 명세 1회에 한해 기존 기능을 보존하는 최소 공개 확장/참조 캐시/데이터 변수 추가만 허용된다. `보호 원본 변경 요청.md`의 PlayerInputReader/PlayerFacade/PlayerCameraController/PlayerAnimationTypes/PlayerAnimationPlayback/PlayerAnimationController/PlayerAnimationSet/PlayerAnimatorOutput/TearSkill 9개 .cs의 최소 확장에 이번 직접 지시를 적용한다. 기존 기능 변경/삭제·전체 리팩터링은 허용하지 않는다. 추가 13개 정리 후보도 별도 허가 없이는 변경하지 않는다. 같은 기능의 SYM 복제본을 만들어 이 경계를 우회하지 않는다.

기존 PDF와 원본 이력, 사용자의 미커밋·미저장 작업을 보존한다. 기존 프리팹 삭제·ProjectSettings 변경, 검토 중 관찰한 PlayerRoot 활성/카메라 위치 변경을 되돌리지 않으며 새 구현 결과와 구분한다.

## 제품 요구사항

### R01 이동과 점프

방향키로 이동한다. Side는 월드 X, Quarter는 XZ이며 기본·작은 폼 모두 5m/s다. 대각선 정규화·감속·공중 조향·마지막 바라본 방향을 유지한다. Space 새 접지 입력으로 큰 형태 3m/작은 형태 2m 점프를 한 번 실행한다. 선입력·이중 점프는 없다. 발판 이탈 때 실제 속도를 상속한다. 거리·각도 원점은 플레이어 실제 루트 중심이며 현재 루트 스케일을 유지한다. 물리 위치 작성자는 HMS Movement 한 개다.

### R02 Q 형태 전환과 껍질

Q 성공 즉시 Collider 상태를 바꾸고 뒤이어 표현을 실행한다. 작은 폼으로 전환하면 껍질 한 개를 남기며 생성 당시 속도를 상속한다. 기본 폼 복귀 전 Collider 공간 검사를 하고 부족하면 Q를 무시·불가 효과음만 재생하며 작은 상태/껍질을 보존한다. 성공한 회수/복귀는 한 행동이며 거리를 제한하지 않고 주변 효과만 재생한다. 서로 다른 크기 전환 입력 사이 1초 제한을 두며 실패 입력은 제한/표현을 시작하지 않는다. 표현 완료에 Q의 제한을 종속시키지 않는다. 이동·점프는 가능하고 별도 회수 키/능력/거리 안내는 제거한다. FormController가 껍질 수명을 소유하고 HMS 기존 판정은 공개 확장/기존 설정으로 사용한다.

### R03 E 눈물과 기절

E는 조각 5개가 있을 때 즉시 5개를 소비한다. 루트 중심 3차원 구의 기존 범위 처리는 후보 탐색이며, 루트에서 유효 적 몸체로 단순 Raycast를 실행해 그 몸체를 직접 먼저 맞혔을 때만 기절 2초를 적용한다. 앞의 벽/사물에 가리거나 대상 몸체를 못 맞히면 효과 없음이다. 다른 적 몸체의 별도 차단 정책은 새로 정하지 않고 기존 레이어 계약을 사용한다. 자기 몸체와 탐지 센서는 제외하고 실제 Trigger 피격 몸체는 검사한다. 같은 적의 여러 Collider는 한 발동 한 번만 처리한다. 일반 적만 기절하며 추격 무리는 제외한다. 기존 기절 재적용 계약을 유지하고 미선택 상한 정책을 새로 만들지 않는다. 대상이 없어도 비용은 반환하지 않는다. 두 폼·지상·공중에서 이동/점프를 막지 않고 사용한다. 투사체·준비 시간·눈물 재사용 대기는 새 조립에 사용하지 않으며 조각 4개 이하는 거절한다.

### R04 F 대상 선택과 장치 입력

F는 플레이어 루트 중심 기준 거리 2.5m·바라본 방향 ±60도·차폐 없는 대상 중 가장 가까운 하나를 안정된 동거리 순서로 선택한다. 대상 위 F 안내 하나, 두 폼/공중 동일 규칙이다. 문·트레이·세 서랍은 독립 상태이며 수락된 F 하나가 장치 작동과 Interact 표현을 시작한다. 장치 작동 중 추가 입력 차단은 현재 수락/Busy 계약을 유지하며 새 전역 Busy 정책을 도입하지 않는다. PC 이동/점프를 막지 않는다. 수락되지 않은 입력이 표현/소리를 시작하지 않는다.

### R05 메모

F로 메모를 열고 닫으며 Opening 중 F 닫기도 허용한다. Closed→Opening→Open→Closing→Closed, Closing 완료까지 자기 입력 제한을 소유한다. 메모 열림 동안 월드 시간은 정지한다. Esc는 독립 옵션 명령이다. 위에 Options가 있으면 F를 메모로 전달하지 않는다. 메모/옵션이 각각 자기 월드 정지·입력 토큰만 해제한다. 대화 자체는 월드를 정지하지 않지만 중첩된 메모의 정지를 해제하지 않는다. 세션 종료/Actor 사망에는 자기 작업/구독을 취소한다.

### R06 공통 피격

HP 최대 3, 일반 피해 한 번당 1, 공통 무적 2초다. 모든 수락된 일반 피해에는 넉백을 제공한다. 피해원 반대 수평/상향의 기존 힘과 하나의 넉백 클립 길이를 공통 조작 제한 시간으로 연결한다. 기존 시간 기반 넉백 기능을 재작성하지 않는다. 클립 미연결 때 명시한 공통 대체 시간과 연결 대기를 기록해 영구 제한을 막는다. 무적이 끝난 지속 접촉은 다시 피해를 수락한다. HP/조각 원본은 HMS Facade.Model 하나이며 Actor 사망에도 HeavyState·플랫폼 무게·외력 계약을 유지한다.

### R07 사망과 자동 재시도

일반 HP0와 추격 포획은 Dead 표현 완료→Fade→자동 retry 순서다. 데드존은 무적과 현재 HP를 무시하고 HP0으로 만들며 Dead 표현을 생략한다. 포획도 무적을 무시하지만 Dead 표현을 생략하지 않는다. 한 Actor의 사망/재시도는 한 번만 수락한다. 사망은 낮은 우선순위 표현, 메모·대화·미완료 입력을 취소한다.

retry는 HP 최대·Normal·껍질 0·속도/넉백/피격/무적 초기화다. 별도 재등장 무적을 주지 않는다. 유효 표현 완료는 현재 Actor와 RequestId에서만 수락한다. 실제 clip이 없으면 명확한 누락 결과로 완료 대체하여 영구 대기를 막고 실제 재생은 연결 대기로 기록한다.

### R08 체크포인트 저장: 정확히 두 값

CheckpointSnapshot은 Position(Vector3)과 Fragments(Int32) 정확히 두 필드다. 캡처 시 실제 플레이어 루트/물리 Body의 월드 XYZ가 유한하고 조각은 0..5이어야 한다. 두 값을 함께 검증한 후 원자 교체하며 실패 때 이전 두 값을 보존한다. Marker 고정 Pose로 실제 접촉 위치를 대신하지 않는다. 동일 CP의 반복 접촉을 억제하며 Stage 체크포인트는 시작과 끝 두 곳뿐이다. 중간 해금/추격 시작을 별도 저장 지점으로 만들지 않는다. 첫/끝 CP는 Stage 초기 상태에서도 기본 폼이 들어갈 안전 영역이다.

StageId/CheckpointId·회전·HP·폼·능력·대화·카메라·적·장치·필드·시간은 저장하지 않는다. 월드 저장 DTO·등록자·객체 상태 ID·앱 재시작 진행 파일과 제3 복원값 우회 저장을 만들지 않는다. 현재 Stage/배치 ID는 실행 문맥이다.

사망 retry는 현재 Stage 씬과 App/Core 서비스를 유지한다. 자기 Tween/작업/접촉/추격을 취소하고 Stage의 초기 배치/적/장치/수집물/트리거를 재준비한 뒤 Position/Fragments만 새 Actor에 복원한다. 현재 Stage에서 얻은 능력은 다시 잠그고 해금 트리거를 재접촉해야 활성화한다. 이전 Stage 해금은 유지한다. 해금과 부여 Stage의 출처는 세션 런타임 상태이며 체크포인트 payload/별도 snapshot이 아니다. 능력 안내의 완료 장부도 재접촉을 막지 않게 함께 정리하고 HUD/입력 수락을 동일 원본에 연결한다.

재로드하면 Core 해금/늦은 콜백이 남아 새 Stage와 불일치할 수 있다. 재로드하지 않으면 명시적 reset이 없을 때 적/장치의 중간 상태가 남는다. 따라서 씬 유지·Stage 초기화·현재 Stage 재잠금을 함께 수행한다. 자세한 비교/수명은 확정안 적용 명세를 따른다.

### R10 문·트레이·서랍

오븐 문과 트레이를 독립 F 토글로 조립한다. 서랍은 세 개이며 각각 독립된 종점/속도/상태/안내를 가진다. 공통 두 종점 작동 계약을 기존 장치 컨트롤러에 통합하며 장치 이름마다 클래스를 만들지 않는다. 문은 힌지 회전, 트레이/서랍은 이동이다. 트레이/서랍은 PC와 일반 물체를 실제 운반한다. 도어 손잡이가 트레이 동작을 대신 실행하는 경로와 공유 bool을 제거한다. 어떤 장치 상태도 체크포인트에 저장하지 않는다.

### R11 일반 적

일반 적은 기존 종류/배치 의미를 보존하며 X/Y 작성 평면의 순찰·Idle·Stunned만 갖는다. CHASE/RETURN 추적·복귀 경로는 제거한다. 세 종류의 외형/순찰 설정과 직렬화값을 실제 자산 의미로 이관하고 enum 재번호화로 추정하지 않는다. 일반 적 HP·무적·처치·머리 밟기·처치 기름을 제거한다. 기절은 FSM 단일 소유, 적용/만료 때 현재 순찰 상태로 돌아간다. 공통 플레이어 피해와 HMS IStunnable/IStunState/VFX 계약은 유지한다. 추격 무리는 별도 R12로 다룬다.

### R12 마지막 추격과 Poppo

플레이어 전체 Collider의 추격 시작선 통과와 추격 시작 수락 뒤 후퇴문을 닫는다. 추격 시작만을 이유로 새 체크포인트를 캡처하지 않는다. 경로 8m 뒤/4m/s·높이 제외 gap 0.8m 강제 사망 계약을 유지한다. 옵션 중 추격/포획 정지, retry는 Stage reset과 새 추격 모델/새 전신통과를 요구한다. 포포 자체의 트리거 수락 때 추격 이동/포획을 즉시 종료하고 최종 대화를 시작한다. 대화 Completed 뒤 게임 완료/Ending/Title로 진행한다. 별도 최종 대화 트리거를 요구하지 않는다. 같은 물리 갱신의 도착/포획은 포획 우선으로 사망/복귀하며 사망한 Actor의 늦은 완료는 엔딩으로 보내지 않는다. 이전 구출/껍질 래치/눈물 장애물 퍼즐은 제거한다.

### R13 대화

자동 대화와 해금 안내는 DialogueService 한 경로를 사용한다. JSON은 비어 있지 않은 Rows 배열 하나, 행마다 Dialogue_Code/Sequence/Name/Context/ContextRevealDuration 다섯 필드다. 코드는 공백 아닌 문자열이며 앞뒤 공백은 금지한다. Name/Context는 공백 아닌 문자열이다. Sequence는 같은 코드에서 중복 없이 1..N 연속이다. ContextRevealDuration은 0 이상 유한 초이며 0은 즉시 표시한다. 잘못된 타입·추가 필드·중복 키·후행 데이터는 문맥이 있는 오류이며 전체 검증 후 읽기 전용으로 게시한다.

상태는 Closed/Revealing/AwaitingAdvance, 종료 결과는 None/Completed/Skipped/Cancelled다. 제품에는 대화 Skip 버튼을 추가하지 않으며 Completed만 완료 장부에 기록한다. Enter/창 클릭은 현재 reveal 완성 또는 다음 행 중 한 동작만 실행한다. 입력 간격 0.3초, Auto는 완전 표시 후 3초다. 완전 표시 행만 로그에 넣는다. 로그는 Auto를 끄고 표시 진행을 멈추며 닫아도 Auto를 다시 켜지 않는다. 옵션은 남은 표시/Auto 시간을 보존한다. 대화·로그 자체는 월드를 정지하지 않는다. 메모/옵션의 자기 정지 토큰은 중첩에도 존중한다. 일반 완료 코드는 한 판에서 반복하지 않고 취소는 다음 시도에 첫 행부터 시작한다. 현재 Stage의 재잠금 능력에 연결된 안내 코드는 retry 때 완료 장부에서도 제거해 재접촉 안내를 허용한다. 메모와 중첩될 때는 R05 규칙을 사용한다.

### R14 오프닝·엔딩

Opening/Ending은 순서 있는 Cut 목록의 원화 한 장과 하단 문구를 표시한다. 기본 컷 시간은 4초, 데이터 시간은 양수 유한 초로 검증한다. 컷 수를 4개로 제한하지 않는다. 클릭/Enter 다음 컷은 없고 전체 Skip을 한 번 실행한다. 옵션은 남은 컷 시간을 보존하며 입력이 다음 화면에 전파되지 않는다.

Cut 데이터는 원화 참조·하단 문구·Duration초다. 결과는 None/Completed/Skipped/Cancelled, Prepare→Play→Hide 계약을 유지한다. Timeline Clip/Track/Bridge·4패널/Scale 호환·임시 halftone 표시는 제거한다. 실제 원화 누락은 필수 자산 오류/연결 대기로 기록한다. 다른 작업자의 Timeline·패키지를 변경하지 않는다.

### R15 옵션·음량

Esc/X는 같은 닫기 명령이다. 옵션은 월드와 모든 표시 시간을 정지하고 자기 제한만 해제한다. 제목 돌아가기는 플레이·메모·대화·추격에서 가능하고 Title/컷신에서는 사용하지 않는다. 수동 다시하기·Resume 버튼·앱 종료 후 이어하기를 제거한다. 음량은 유한 0..1, 기본 Master 1/Music 0.7/SFX 1이다. 기존 PlayerPrefs 저장을 사용하고 실패 시 런타임 값을 보존하며 다음 저장에서 재시도한다. 종료 후 화면 콜백/구독이 남지 않는다.

### R16 HUD·해금·안내

Title은 새 게임/설정/종료, HUD는 원본 HP 3/조각 0..5와 Q/E 능력 표시다. 능력은 해금 트리거 접촉 전 비활성 음영, 접촉 이후 활성 표시를 유지한다. 현재 Stage 사망 retry의 재잠금에도 음영을 갱신하고 재접촉 때 활성화한다. AbilityId는 FormChange(0), Tear(1), 별도 RecoverShell은 Q의 일부로 이관한다. CPID/독립 회수/거리 Instruction/두번째 Prompt 소비는 제거한다. View는 VM 상태/명령만 사용하고 한 입력 한 Command다. #11의 기획 문서 편집은 제외하며 이 안내 확정안만 적용한다.

### R17 단일 출력과 분리 카메라

App에 출력 Camera/CinemachineBrain/AudioListener 각 한 개를 두고 Core에 Side/Quarter 가상 카메라 두 개를 둔다. Actor에는 실제 움직이는 Body의 CameraAnchor만 둔다. retry는 App 출력과 Core 리그를 다시 만들지 않는다. Actor 제거 전 목표·Mode 구독을 해제하고 새 Actor의 준비 후 명시적으로 Bind한다.

SYM 카메라 모드 집합은 Side(1), Quarter(3)다. 기존 Corridor(2) 배치는 명시적으로 이관하며 보호 HMS Back/BackFixed 값과 독립 소비자를 무단 삭제하지 않는다. 전환은 구간 트리거로 요청하고 기본 블렌드 0.6초 및 실제 Brain/Side Z정렬 완료까지 PC 입력을 막는다. 최신 요청이 앞선 요청을 취소하며 옵션은 진행을 멈춘다. 초기 모드는 배치 구간 설정에서 결정하고 저장하지 않는다.

PlayerCameraController만 우선순위를 쓰고 Brain만 출력 Transform을 쓴다. LevelCameraService는 요청·입력 제한·평면 정렬·완료를 소유한다. Preview는 물리 축을 미리 바꾸지 않고 Commit은 실제 완료 뒤 Mode를 확정한다. 카메라는 PlayerRoot의 자식일 필요가 없다. 기존 HMS의 첫 활성화 참조 검사/재연결 부재를 고치면 생성 단위를 분리할 수 있으며, 출력 교대와 중복 우선순위 작성자도 제거할 수 있다.

### R18 씬 진입·수명

아래 정확한 여섯 경로만 통합 Bootstrap 경로로 처리하고 다른 기능 씬은 직접 Play한다.

```text
Assets/_Scenes/Tech_SYM/Architecture/01_Bootstrapper.unity
Assets/_Scenes/Tech_SYM/Architecture/02_Title.unity
Assets/_Scenes/Tech_SYM/Architecture/03_InGameCore.unity
Assets/_Scenes/Tech_SYM/Architecture/Prototype/1_Stage.unity
Assets/_Scenes/Tech_SYM/Architecture/Stages/03_2_Stage.unity
Assets/_Scenes/Tech_SYM/Architecture/Stages/03_3_Stage.unity
```

App는 출력/음량/전환, Core는 한 판의 서비스/리그/ActorHost, Stage는 같은 씬/객체를 유지하면서 retry에 초기 재준비되는 배치를 소유한다. InGameCore 1회 로드 뒤 등록된 Stage 씬 전부를 최초에 additive 로드하고 이후 Stage 씬을 다시 로드하지 않는다. 이미 로드한 Core/Stage는 유지하며 활성 Stage의 루트/Actor 연결만 선택한다. 타이틀 복귀/다음 판은 씬 유지와 서비스 상태 수명 초기화를 구분한다. 정상 세션 종료에서도 CoreComposition이 world/runtime/host/연출의 빌린 참조를 정리하며 다음 판에 새 세션 범위와 Actor를 연결할 수 있어야 한다. 비활성 Stage는 Actor를 바인딩하지 않고 자기 Tween/추격/타이머를 중지한다. 루트 비활성화만으로 외부 작업이 정리됐다고 간주하지 않는다. 획득해서 사라진 눈물조각도 Stage 재준비에 실제 객체/충돌/표현으로 다시 나타나야 하며 씬 재로드로 복구하지 않는다. 기존 03_1_Stage와 비대상 씬을 이름만으로 제거하지 않는다. Play/Stop/취소는 원래 Scene setup/active/startScene과 미저장 작업을 보호한다. NewGame·retry·Title·다음 판에도 구독/입력/Listener/Actor가 중복되지 않는다.

### R19 삭제와 필요한 코드 내부 정리

`스크립트 필요성 및 정리 명세.md`의 전체 206개 판정을 따른다. SYM 160개 중 32개는 책임·호출·GUID/메뉴/런타임 생성 참조 이관 후 실제 소스와 소유 메타를 삭제한다. 참조 수 0만으로 물리/공개 계약/자동 메뉴의 미사용을 단정하지 않는다. 보호 원본 소비를 깨뜨릴 수 있으면 삭제를 멈추고 정확한 파일 예외를 확인한다.

유지하는 코드도 폐기된 옵션 Retry·회수 능력·백뷰/두 출력·적 HP/기름·눈물 게이트/구출 퍼즐·붕괴 복구·월드 저장·표시 호환 분기/필드를 제거한다. 임시 이관 코드에는 이유와 최종 삭제 단계가 있으며 완료 산출물에 남지 않는다. 기존 공개 기능과 동작/수명이 같을 때만 통합한다. 보호 13개 후보와 독립 HMS 소비는 미승인 상태를 구분하고 전면 정리 완료로 보고하지 않는다.

### R20 객체 계층·MVVM·작성 도구·문서

새 자원은 빈 Root가 데이터/컨트롤러, Visual이 Renderer/Animator, Physics가 물리/콜백을 맡는다. 플레이어 종속 컴포넌트는 실제 Player 루트에 조립하고 HMS GetComponent/attachedRigidbody 물리 계약을 같은 루트에서 유지한다. Visual/Anchor/효과는 자식으로 분리한다. 형식적인 빈 부모 때문에 움직이는 Body와 거리 기준이 달라지지 않게 한다. 필요한 계층 예외는 실제 조립/가이드에 명시하고 보호 기능을 복제하지 않는다. SYM 발판은 명시적 Body/Contacts 참조로 실제 구현을 이관한다.

UI View는 주입된 VM의 상태와 명령만 사용하며 VM은 View를 참조하지 않는다. 재바인딩 중복 구독 0, 해제 후 호출 0, 자기 소유 구독만 해제한다. 모든 변경 Inspector 필드에 쉬운 한국어 Tooltip으로 목적·단위·좌표·0·참조 대상·기즈모 색상을 설명한다.

기본 Builder가 올바른 구조를 처음부터 만들게 하고 Prototype/사후 보정 도구를 흡수한다. 실제 작성/Play 진입/빌드 도구는 이름만으로 삭제하지 않는다. 문서의 현재 사실·새 목표·실행 결과를 구분하고 기능 명세/코드 리뷰/검증/프리팹 가이드를 함께 갱신한다.

## API와 상태 계약

현재 공개 공용 Interfaces의 수락·실제 적용량·밀리초 단위 의미는 유지한다. 새 계약은 구현 전의 목표이며 Inspector에 이미 있다고 설명하지 않는다.

| 경계 | 요구 계약 |
|---|---|
| 체크포인트 | Position/Fragments 정확히 두 필드; 생성 경계 검증; 현재 Actor 캡처; 실패 때 이전 값 보존 |
| 카메라 | Bind(현재 Mode/Anchor/서로 다른 Side·Quarter), Unbind, Preview, Commit; 자기 구독 해제; 준비 전 출력/입력 가림 |
| 피격/사망 | 현재 Facade에서 공통 Hit 수락·ForceDeath; Source와 현재 Actor 문맥; 무적 무시 사망; 단일 HP 원본 |
| 표현 완료 | RequestId/Actor 일치; Completed/Interrupted/Missing 결과; 낡은 완료 무시; 누락은 안전한 종료 대체 |
| 입력 | Reader/Router 하나; 열린 메모 F 닫기 우선, Options 중 아래 입력 없음; 성공 명령 한 번 |
| 장치 | 두 종점 작동 수락/완료/취소; Busy 제한은 R04; 파괴/세션 종료 때 제한 해제; 저장 계약 없음 |
| 대화 | 코드별 행 5필드/1..N; 검증 후 게시; 완료 장부는 일반 런타임; 취소 재시작 |
| 연출 | Cut 목록; 원화/문구/Duration; Completed/Skipped/Cancelled; Prepare→Play→Hide |
| 비동기 작업 | OperationStatus는 Pending/Succeeded/Cancelled/Failed; 실패/취소를 성공으로 바꾸지 않음 |

기존 FlowState와 자동 RetryCheckpoint 전환은 유지하며 UI에서 수동 Retry 명령만 제거한다. 전체 상태 원본은 소유 객체 하나다. 서비스 등록/버스는 실제 외부·여러 소비자 경계에서만 남기고 새 인터페이스를 구현마다 만들지 않는다.

## 필수 검증과 수락 기준

준비 문서는 원본 hash/색상·취소선, 206개 전수 판정, 32개 삭제 이관 경로, 직접 지시, 요구사항-작업 대응, 계획 순환/누락, 파일 권한/기준점, 독립 검토를 정적으로 확인한다.

구현 후 `테스트 및 검증 항목.md`의 V01..V34를 사용자 기능 단위로 실행한다. 실제 InputSystem 전체 두 판 동선/여러 retry, 실제 물리 시간/Brain 완료, compile/Console, SYM Missing Script 0, 필수 참조/입력/이동자 단일성, 저장 후 재로드/isDirty=false를 확인한다. 필요한 기능 검사가 통과하면 기존 `Cooked/Integration/Build Windows Player` 메뉴로 명시적 여섯 씬의 새 Windows 실행 파일을 빌드한다. 결과/소스/명세/exe hash를 기록한다. 단독 정식 검증 명령이 없으므로 live Editor의 일회성 검증과 이 메뉴 빌드를 실행 증거로 사용하며 기존 기록을 승계하지 않는다.

기능 케이스 Excel은 프로그래머/에이전트가 갱신한다. 팀 실제 빌드 플레이·FunQA와 실제 아트/clip 재생은 별도 판정이다. QA의 FunQA는 제공 DOCX 원본 양식을 보존한다. clip/원화가 없거나 팀 플레이가 미실행이면 해당 상태를 남기고 코드 완료와 혼동하지 않는다.
