# 기능 테스트 및 FunQA 인계 명세

## 목표

2026-10-05 사용자 직접 지시에 따라 컴포넌트 모듈 전수 검증 대신 기능 요구사항에 대응하는 결합된 사용자 기능을 검증 단위로 정한다. 중요한 정상 흐름·진행 불가·상태 손실·중복 실행·정지와 복구만 우선 케이스화해 팀 작업량과 에이전트의 반복 직접 조작 비용을 줄인다. 최종 제공물은 기능 테스트 XLSX 한 개와 Cooked! FunQA DOCX 한 개다. 최초 요청의 두 DOCX는 후속 직접 지시로 한 개로 대체됐다.

## 참고 코드·자산

- 사용자 Desktop의 202513146_김하늘_게임성분석_중간 (1).docx. 원본은 두 게임 비교 분석 보고서이며 7쪽, 본문140문단, 6표, 3차트다. Cooked! 단일 프로젝트의 두 경험 범주로 구획을 활용하고 평가 내용은 비운다.

## 제약

게임 코드·씬·프리팹·패키지·ProjectSettings·타인 파일·기존 PDF·사용자 원본을 수정하지 않는다. 기존 미커밋 변경을 기준점으로 보존한다. 루트 AGENTS/CLAUDE, Tech_SYM 상위 지침, Assets/_Docs의 검증 운영 규칙만 이번 요청에 맞춰 수정한다. 설치 DryForge 패키지 자체를 변경하지 않으며 프로젝트의 최신 직접 지시로 적용한다.

기능 케이스는 프로그래머·에이전트가 작성해 제공한다. QA가 직접 작성할 문서는 FunQA로 한정하며 별도 기능 명세 신규 작성 의무를 부과하지 않는다. FunQA는 원본 서식과 구조를 보존하고 타 게임의 사례·평가·수치·작성자 정보를 제거한다. 에이전트는 재미 평가와 테스트 통과를 추정하지 않는다. 현재 오프라인 범위에 데이터베이스/서버/네트워크 기능을 추가하지 않는다.

산출물은 output/Tech_SYM/qa-functional/xlsx 및 docx, 제작 근거·백업·렌더·검증은 같은 루트의 하위 카테고리로 관리한다. 공유 가능한 프로젝트 지침과 완료 기록은 Assets/_Docs/tracking에 둔다. 이번 작업에서 새 게임 빌드·Editor/Play 기능 테스트는 실행하지 않으며 모든 새 기능 케이스의 빌드 결과는 미실행이다.

## 완료 기준

1. 실제 명세·코드·저장 자산에 근거한 핵심 기능 케이스를 제공 이미지의 7열과 그룹 병합으로 XLSX에 작성한다. 시작 조건·조작·기대 결과·중요도·진입 위치·근거가 추적 가능하다.
2. 원본 DOCX의 페이지/스타일/문단·번호·표/차트 배치를 보존한 Cooked! FunQA 한 개를 제공한다. 타 게임 데이터·예시 평가·개인 작성자 정보가 남지 않고 모든 평가 결과는 QA 작성 대기다.
3. 루트·개발·실행 지침에서 기능 검증과 인계의 정의·역할·선정·상태가 일치하며 기존 지역 경계 검증은 보조 근거로 유지한다.
4. XLSX/DOCX 구조 검사와 실제 Office 렌더를 확인한다. 원본·기존 코드/씬/설정의 해시 보존과 이번 수정 문서의 공백/참조를 검사한다.
5. 코드 리뷰.md와 테스트 및 검증 항목.md에 이번 문서 작업의 확인 결과·게임 실행 미실행·최종 팀 검증 대기를 기록한다. Git 작업은 수행하지 않는다.

## 활성 씬 진입·HMS 결합의 후속 갱신 (2026-10-06)

이번 후속 변경 범위는 [승인 명세](ready-editor-entry-hms-2026-10-06/기능 명세서.md)와 실제 소유 구현·검증을 따른다. 위 최초 제작 작업의 게임 수정 금지·신규 Unity 검사 미실행은 그 당시 기록이며 이번 승인 작업을 대체하지 않는다.

기존 기능 엑셀의36개 QA 결과와 그룹 병합을 보존하며 카메라 완료·실제 Esc 정지·retry 연결 기대값을 갱신했다. 선택 씬 진입·start/Reload 복원·독립 HMS 결합3개를 추가해 현재7대분류·26기능·39케이스다. 추가3개 및 팀 결과는 미실행이다. Editor 자동 기능 증거와 제한13행은 별도 시트이며 QA의 P/F/B/N을 대신 채우지 않았다. FunQA DOCX는 이번 변경 전 해시와 동일하다.

읽기 전용 Microsoft Excel PDF14쪽(기능 케이스5·안내2·근거5·Editor 자동 결과2)을 렌더했다. 원래 병합 그룹이 페이지 경계에서 잘리지 않도록 page break를 조정하고 새3케이스의 조작/기대값·결과 dropdown을 확인했다. 근거는 `output/Tech_SYM/verification/editor-entry-hms-2026-10-06/qa-update-verification.json` 및 `qa-render/inspection.json`이다. PDF는 검수용이며 제공 정본은 기존 XLSX/DOCX 한 개씩 유지한다.

실제 Editor Play의10진입·6설정조합·3독립입력·camera/physics·입력 두 판·취소 결과와 native16씬65프리팹 조립은 [현재 검증](ready-editor-entry-hms-2026-10-06/테스트 및 검증 항목.md)에 기록한다. 새 Windows build/실행 파일·팀 기능 판정·FunQA 평가는 수행하지 않았다. 보호 HMS Missing1과 엔진 Hierarchy UI Assertion4는 알려진 제한으로 인계한다.

## 플랫폼·정리의 후속 갱신 (2026-10-06)

선형 발판의 부모 기준 X/Y/Z 이동량·속도·3차원 탑승/점프, 트리거 자신의 로컬 오프셋·파란 정렬점, 붕괴 Animator 연결·미연결 물리 처리·취소/재사용을 기존 기능 케이스에 반영한다. 39개 구성과 기존 결과·그룹 서식을 보존한다. 삭제한 시험 클래스는 현재 실행 명령으로 안내하지 않는다.

이번 Editor 자동 결과는 최신 플랫폼 검증 기록과 별도 시트에 추가하며 과거 자동 결과를 덮어쓰지 않는다. 새 Windows 빌드 식별과 실제 팀 판정은 구분한다. 실제 붕괴 클립은 자산을 받은 뒤 연결하므로 PC-07의 실제 재생·품질 검증은 후속 범위다. FunQA의 평가와 원본 서식은 이번에도 변경하지 않는다.
