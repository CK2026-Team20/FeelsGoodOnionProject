# 기능 객체 중심 정리 코드 리뷰

2026-10-11 사용자 직접 지시를 적용했다. 전신 통과·경로상 간격은 이번 직선 추격 요구에 필요하지 않았으며 기존 구현을 보존할 이유로 삼지 않았다. 보호 HMS 원본과 실제 리소스 제작 경계는 유지했다.

## 실제 자산 이관

Prototype/1_Stage와 등록 Stage1/2/3을 해당 작업트리의 Unity6000.6.0f1 비 Play Editor에서 수정·저장했다. Stage의 퇴로 참조2건은 Chase 트리거로 옮겼다. 구형 경로/시작점16개와 중복 Enter4개는 다른 컴포넌트 참조 및 별도 책임이 없음을 검사한 뒤 제거했다.

Core의 기존 ChaseSwarm 인스턴스 Physics BoxCollider는 크기(0.8,100,4)의 scene override를 적용했다. 이전 높이 무시 요구를 현재 구간의 점프 범위를 덮는 전면 벽으로 작성했다. 무리 Y/Z는 시작 시 고정되고 포획은 실제 Actor CapsuleCollider와 Box 접촉/상대 이동 sweep이다. 프리팹 원본 크기(0.8,2,4)는 유지된다. 다른 배치에서 같은 높이 범위가 필요하면 해당 인스턴스의 Box를 작성해야 한다.

기존 프리팹 삭제·재생성·Apply, 보호 HMS/아트 원본 수정은 하지 않았다. 씬 YAML을 문자열로 편집하지 않았으며 native SerializedObject·Transform.SetParent·EditorSceneManager.SaveScene을 사용했다.

## 독립 리뷰와 반영

- 자기 루트를 참조하던 카메라8개: strict child 검증에 맞는 자식 정렬점을 연결하고 위치 보존 검사를 다시 통과했다.
- OnDisable이 퇴로를 여는 문제: ClearContacts와 ResetForRetry를 분리했다. 접촉 기록 정리에서는 문 상태를 변경하지 않는다.
- 재활성화 시 추격 주입 유실: OnDisable에서는 보존하며 CoreWorldBinding의 Actor 해제와 OnDestroy에서 해제한다.
- 시작 중 재진입·부분 실패: Show 이후 현재 실행 회차를 확인하고 트리거의 접촉/소유자/실행기 및 Actor를 다시 검사한다. 실패 시 자신이 시작한 회차만 정리하며 새 회차를 중단하지 않는다.

반영 후 독립 정적 재검토에서 위 수명 문제 세 건의 해소를 확인했고 추가 결함은 보고되지 않았다. 이 결과를 실제 Play 검증으로 확대하지 않는다.

최종 대화의 Stage·Trigger·선택·Table·Code·Actor 세대·Round·Session 검증과 Completed/Skipped 장부는 유지했다. 같은 프레임 포획은 Driver LateUpdate(200), 포포 예약은 Stage(500) 순서다. 이 순서는 코드에서 확인했으며 실제 프레임 경합을 Play로 실행하지 않았다.

## HMS와 남은 경계

[HMS 연결 검토](HMS%20연결%20검토.md)는 Features36개를 항목별 대조했다. 주요 HMS 기능은 실제로 사용한다. 통합 PlayerController 우회는 GameplayInputRouter가 해금/모달/F 상호작용/사망 진행을 조정하기 때문이며, 이 책임을 이관하지 않은 채 Router를 삭제하지 않았다. PlayerCameraController의 빈 작성 필드는 런타임 Bind와 별도 독립 카메라 모드를 구분해야 한다.

실제 애니메이션 클립/템플릿 누락은 확인된 미완성 리소스 연결이다. 제공되지 않은 클립을 생성하거나 보호 원본에 임의 연결하지 않았다. 상세는 위 감사와 findings에 기록했다.
