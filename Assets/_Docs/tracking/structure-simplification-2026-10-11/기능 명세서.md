# 기능 객체 중심 구조 정리

## 목표
2026-10-11 사용자 직접 지시를 적용한다. 첫 작업자가 기능 객체의 설정과 실행을 가까운 곳에서 이해할 수 있도록 불필요한 중간 계층과 Inspector 입력을 줄인다. 추격 접촉 판정과 지역 설정은 트리거가, 카메라 정렬 앵커는 카메라 트리거가 소유한다. Stage는 스테이지 공통 상태와 재시작 조정을 담당한다.

## 참고 코드와 자산
StageService, StageTrigger, CameraZoneTrigger, CoreWorldBinding, Chase 관련 소스, SessionActorHost, HudView, HMS 제품 스크립트와 해당 GUID가 연결된 씬 및 프리팹을 대조한다. 현행 V1.5 원본은 앞선 분석에서 읽었으며 작업트리 SHA256 일치를 확인했다.

## 직접 지시와 제약
- 추격 시작은 현재 살아 있는 플레이어의 트리거 접촉이다. 이전 전신 통과 및 진행 경로 투영 조건을 대체한다. 얇은 트리거도 전신 통과를 의미하지 않으며 문 닫힘 안전 검사는 별도로 유지한다.
- 추격은 사이드뷰의 직선 이동과 전면 포획 영역으로 간소화한다. 높이 무시, 저장 성공 후 시작, 사망/종료 정리와 실제 현재 플레이어 판정은 유지한다.
- Stage의 미사용 적 캐시와 중복 Inspector 목록은 제거한다. 씬을 유지하는 재시작에서 적의 초기 배치 및 기절 상태 복구는 별도 필요한 동작이다.
- 완성된 기능 객체는 씬 루트, 그 객체의 앵커/피벗/정렬점은 내부 자식으로 작성한다. 이동 Body와 고정 기준점의 부모는 목적에 맞게 구분한다.
- 보호된 HMS/공용/아트 원본 및 import/Packages/ProjectSettings는 수정하지 않는다. 기존 프리팹 삭제/재생성/Apply와 리소스 제작은 사람이 한다. 기존 사용자 폰트 변경을 보존한다.
- Unity Play/Player/PlayMode 테스트는 실행하지 않는다. 씬 작성은 해당 작업트리의 연결된 비 Play Editor를 사용하며 다른 checkout의 Editor를 대신 수정하지 않는다.

## 완료 기준
1. 중복/미사용 필드와 호출 이관을 전체 코드 및 직렬화 참조에서 확인한다.
2. 시작/취소/재시작/저장 실패/포획의 관찰 가능한 계약을 비 Play 범위에서 검증하고 실제 미실행 범위를 명시한다.
3. HMS 제품 스크립트의 코드 및 자산 연결을 항목별 검토한다.
4. 코드 리뷰와 테스트 및 검증 항목에 변경 결과, 제한 및 잔여 작업을 기록한다.

## 시작 상태
작업트리 Editor는 pipeline 목록에서 실행 중으로 표시되지만 서버에 연결되지 않는다. 원본 F: checkout의 Editor는 별개이므로 자산 수정에 사용하지 않는다. 소스 작업 및 정적 연결 검토부터 진행한다.
