# 월드 프롬프트 한글 깨짐·줄바꿈 원인

## 결론
인코딩 문제가 아니라 표시 데이터와 프리팹의 계약 불일치다. 한글을 제공하지 않는 폰트에 전체 한글 안내를 넣고, 한 글자 키캡용 폭에 일반 줄바꿈을 허용하여 한 글자씩 아래로 내려간다.

## 실제 경로
- DirectSceneTestInteraction 생성자가 Assets/_Scenes/Tech_SYM/Prefabs/Interaction/InteractionPromptCanvas.prefab을 사용한다.
- Tick에서 promptModel.SetPrompt(..., "상호작용")을 호출한다.
- WorldPromptViewModel.SetPrompt는 "F  " 접두사를 붙여 최종 "F  상호작용"을 만든다.
- WorldPromptView.Refresh가 해당 문자열을 label.text에 전달한다.
- 프리팹 KeyLabel은 LiberationSans SDF Static 폰트, RectTransform85×80, fontSize68, wrapping Normal이다. 프리팹의 편집 텍스트 E는 실행 때 위 문자열로 대체된다.

## 재현 증거
실제 프리팹을 PreviewScene에 복제하고 실제 WorldPromptView/WorldPromptViewModel로 문자열을 전달한 뒤 TMP ForceMeshUpdate(true,true)를 실행했다.

- 최종 text: F 두 칸 공백 상호작용
- lineCount: 5
- F: U+0046, line0
- 상/호/작/용: 각각 누락. fallback까지 확인한 HasCharacter 결과 false.
- 최종 TMP glyph: U+25A1(□) 네 개, line1/2/3/4
- 폰트 fallback 목록: LiberationSans SDF - Fallback. 이 경로도 해당 한글을 제공하지 않는다.

따라서 첨부 이미지의 F 아래 네모 네 개가 세로로 늘어선 현상과 일치한다. 월드 스케일이나 카메라 해상도만 바꿔 해결되는 문제가 아니다.

## 수정 방향과 이번 범위
현행 Interaction/AGENTS.md 및 UI 기획서의 월드 안내는 대상 위 F 한 개 표시다. 이 기준이면 ViewModel/프롬프트 계약을 F 단일 키 표시로 맞추고 한 줄 표시를 사용하는 것이 일관된다. 만약 F와 한글 설명을 함께 표시하려면 한글을 포함한 폰트를 참조하고 키캡/설명 영역을 분리하거나 충분한 텍스트 폭을 제공해야 한다. 폰트만 바꾸거나 줄바꿈만 끄는 단독 조치로 두 원인을 모두 해결했다고 볼 수 없다.

사용자는 이번에 이유 파악을 요청했다. 따라서 프롬프트 프리팹·문자열·폰트·전역 TMP 설정은 수정하지 않았고 현상은 아직 남아 있다. 이번 UI 수정의 완료와 프롬프트 수정 완료를 혼동하지 않는다.
