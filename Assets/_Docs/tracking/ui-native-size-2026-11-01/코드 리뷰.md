# UI 원본 크기 적용 코드 리뷰

## 최종 변경
- UI 이미지 RectTransform은 원본 Sprite.rect.size, localScale은 1을 사용한다. 컷씬은 Texture2D의 실제 1920×1080 크기를 사용한다. 상위 Canvas의 기존 화면 해상도 대응과 개별 PNG 크기는 구별한다.
- HudView는 기존 HudViewModel.TearReady를 소비한다. 조각 수와 E 키 오브젝트를 상호 배타 활성화하고, Q/E 스프라이트 전환마다 원본 크기를 적용한다. 별도의 해금·조각 상태를 만들지 않았다.
- 하트는 Image 세 개의 기존 fillAmount 계약을 유지한다. 남아 있던 눈물 조각 HudIconGraphic 사용처를 제거하고 소스 및 GUID 참조 0을 확인한 뒤 HudIconGraphic.cs/.meta를 삭제했다.
- 설정 Min/Max/백분율 오브젝트와 OptionsView의 values 필드·검사·출력을 제거했다. 슬라이더 입력/저장/옵션 명령은 기존 ViewModel 경로를 유지한다.
- Slider/Scrollbar가 자동으로 변경하는 RectTransform과 표시 Image를 분리했다. FillClip은 채워지는 범위만 잘라내며 실제 Fill 그림은 501×41을 유지한다. Handle 아래 Artwork도 원본 크기를 유지한다.
- HorizontalLayoutGroup: 하트, Q/E 카드, 대화 하단 버튼. VerticalLayoutGroup: 음량 행과 항목, 대화 기록. 크기 강제 확장은 컨테이너에만 적용하고 그림에는 적용하지 않는다.
- 대화 기록은 기존 VM의 History를 말풍선으로 표시한다. View가 생성한 표시 행만 관리하며 기록 변경 시 재구성, Unbind/비활성 종료 시 회수한다. 게임 규칙이나 대화 완료 장부를 View로 옮기지 않았다.
- CinematicCatalog의 기존 문구·표시 시간은 유지하고 오프닝01~04/엔딩05~08의 원화 참조만 교체했다. 하단 문구는 V1.8에 따라 별도 TMP로 유지한다.
- MemoView는 주입되는 이미지의 실제 원본 크기를 적용한다. 기존 열기/닫기 애니메이션 수명은 유지한다.

## 자산 범위와 검토
사용자의 최신 UI 프리팹 수정 지시에 따라 기존 GameUiRoot, GlobalUiRoot, DialogueRoot, CinematicPresentation, MemoView를 수정했다. 전체 프리팹 재생성·Apply·Unpack은 하지 않았다. Bootstrap의 GlobalUiRoot에 남아 새 Fill 앵커를 덮던 이전 override 및 삭제된 UI의 잔여 override 36개를 제거했다. 해당 씬 diff는 override 144줄 삭제뿐이다. 현재 미저장 Stage_quarter는 저장·재로드·변경하지 않았다.

_Art/UI 아래 원본·메타 162개 해시가 시작 전과 동일하다. HMS·공유 인터페이스·Packages·ProjectSettings·보호 아트는 수정하지 않았다. Git 커밋·push·PR·병합은 하지 않았다.

## 검토 중 발견하여 해결한 사항
초기 슬라이더 적용에서 Unity Slider가 fillRect 앵커를 펼치면서 실제 크기가 두 배가 되는 것을 렌더 검수로 발견했다. 그림과 제어 범위를 분리한 후 0/0.5/1 상태별 크기 검사를 통과했다. 대화 기록의 기존 밝은 글자색은 새 밝은 말풍선 위에서 읽기 어려워 프리팹 텍스트를 짙은 갈색으로 수정하고 재렌더 확인했다.

## 검토 경계
메인 에이전트의 diff·실제 Unity 직렬화·프리팹 렌더 검토이며 별도 사람/하위 에이전트 독립 검토를 수행했다고 주장하지 않는다. 현재 게임 전체 Play/Player 완료 검증이 아니다. 월드 프롬프트는 아래 원인 조사 문서에 기록한 대로 미수정이다.
