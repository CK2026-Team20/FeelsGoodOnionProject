# Windows 프로토타입 빌드와 PR 인계

2026-10-16 사용자 직접 지시. yeet 및 공식 Unity 플러그인을 사용한다.

## 목표

현재 로컬 프로토타입을 Windows PC용으로 먼저 빌드하고, 성공 결과를 확인한 뒤 현재 브랜치에서 커밋·push·PR을 만든다. PR에는 HMS 소스 순변경, 이유, 관련 SYM 소비자, 기존 사용자/Editor 편집의 출처 한계를 명시한다.

## 참고와 기준

- 기준 커밋 `d79a670`과 작업 시작의 `origin/main`/`feature/core/prototype` HEAD는 일치한다. 최근 첫 부모 이력은 d79a670 아트 병합, 4f4ef2c V1.6 핵심 흐름 병합, d47253e 리소스 병합이다.
- 현재 Git diff, Stage 편집 상태, ArchitectureInstallation/IntegrationEntrySettings, 기존 단계별 명세·실행 증거를 함께 대조한다.
- 예전 HMS 누적12파일 변경은 기준 브랜치에 이미 병합된 이력이다. 이번 소스 순변경은 CharacterMovement와 OilSurface 두 파일이다.

## 변경 경계

새 게임 코드 없이 전용 Build Profile을 작성한다. 사용자의 현재 상태 빌드·커밋 요청에 따라 기존 미저장 Stage는 native 사본을 다시 남긴 뒤 원본을 저장한다. 초기 Stage 사본은 output/Tech_SYM/prototype-build-pr-2026-10-16/Stage-before-build-save.unity다. 아트·HMS 기존 로컬 변경은 삭제하거나 재작성하지 않고 기록으로 분류한다. 작성자 정보가 없는 미커밋 변경을 특정 사람에게 귀속하지 않는다. 커밋/PR은 한국어로 쓰며 기존 공개 이력 재작성은 하지 않는다.

## 빌드 계약

프로필은 Assets/Settings/Build Profiles/Cooked_Prototype_Windows.asset이다. overrideGlobalScenes=true이며 활성화된 씬 순서는 다음과 같다.

1. Assets/_Scenes/Tech_SYM/Architecture/01_Bootstrapper.unity
2. Assets/_Scenes/Tech_SYM/Architecture/02_Title.unity
3. Assets/_Scenes/Tech_SYM/Architecture/03_InGameCore.unity
4. Assets/_Scenes/Tech_SYM/Architecture/01_Stage_Prototype.unity

Windows64/Mono, Development 비활성, DetailedBuildReport 사용. 출력은 Windows 바탕화면의 Cooked!_Prototype_Build/CookedPrototype.exe다. 빌드 출력은 Git에 넣지 않는다. 글로벌 씬 목록 대신 프로필의 독립 목록을 사용한다.

## 완료 기준

BuildReport Succeeded 및 실제 exe/Data 확인 → 빌드 경고·실행 미검증 경계 기록 → HMS2파일과 전체 변경의 출처/이유 대조 → 커밋·push → 기존 PR이 없으면 Draft PR 생성/연결. 이번 빌드 성공은 과거 Editor 기능 테스트 전체 또는 Windows Player의 전 구간 QA 통과와 같지 않다. 실제 결과는 같은 폴더의 검증 문서에 기록한다.
