# 실제 프로파일 실행 결과
공식 Unity 플러그인 eval과 UnityEditorInternal.ProfilerDriver/RawFrameDataView로 실제 CPU Profiler를 기록·분석했다. Stopwatch로 Tick을 반복한 대체 벤치마크가 아니다.
- 기존 사용자 캡처 저장: user-capture.data.
- fresh-before: 게임 프레임400 전진.
- editor-detail: 게임 프레임240 전진, Editor 내부 작업 프로파일 후 원래 모드 복원.
- fresh-confirm: 게임 프레임400 전진.
- current-clean: 과거 버퍼 제거 후 게임 프레임400 전진, 프레임0..397 기록.
- 게임 프레임 진행 총1440. 로드되어 있던 Tutorial을 그대로 사용했고 별도 Play 재시작/씬 저장 없이 측정했다.
- current-clean 안정 구간390프레임, 물리 실행159프레임, Enemy2385호출, 해당 하위 할당0B.
- 각 .data, CSV, 요약은 output/Tech_SYM/enemy-profiler-2026-11-02/에 있다. CSV 열 이름에 포함 시간과 호출 수를 명시했다.
- 프로파일러 모드 전환 도중 에디터 Assert 'Unhandled profiler state transition! From 5 to 2'가1회 기록됐다. 이후 일반 모드 clean 캡처가 정상 완료되어 결과는 그 캡처를 사용한다. 런타임 게임 오류가 없었다고 전체 콘솔을 일괄 주장하지 않는다.
- 기존 CP_A/B/C 보정 경로 예외는 측정 시작 전 로그이며 이번 적 성능 원인으로 취급하지 않는다.
- 실행 범위: 현재 플레이어 위치에서 적 순찰이 진행되는 실제 Play. 이동/전투 입력 전체 시나리오, 전체 레벨 완주, standalone Player GPU/프레임률 검증은 아님.
- 이전 캡처와 현재 캡처는 동일 코드의 엄격한 A/B가 아니다. 과거 비용 감소를 이번 새 소스 변경의 성과로 주장하지 않는다. 이번 추가 런타임 코드 수정은0개다.
