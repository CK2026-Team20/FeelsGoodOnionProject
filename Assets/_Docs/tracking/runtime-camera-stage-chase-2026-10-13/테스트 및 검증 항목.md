## 실패와 후속 해결

- camera-verification.json의 첫 실패: NaN을 포함한 Vector3.Equals 비교로 반복 경고가 발생했다. 경고를 유효값 복귀까지 한 번으로 변경하고 camera-verification-02.json의 115검사로 재확인했다.
- migration.json의 첫 이관 검사 실패: 검사 도우미가 Presentation.visual의 GameObject 참조를 Transform으로 잘못 읽었다. 세 씬을 원래 바이트·Editor 구성으로 복구하고 타입을 수정했다.
- migration-02.json의 두 번째 실패: Canvas layout 확정 전후 HistoryText 계산 좌표가 달랐다. 원본 상태를 복구하고 Canvas.ForceUpdateCanvases 이후 기준을 수집하여 migration-03.json에서 통과했다. 최종 저장 diff에 UI 변경은 없다.
- 씬 검사 도우미의 컴파일 오류: Unity 6.6에서 objectReferenceInstanceIDValue가 사용 중단되어 objectReferenceEntityIdValue로 변경했다. 제품 소스 컴파일 오류와 구별한다.
- scene-verification.json / scene-verification-02.json의 실패: PreviewScene 화면 Canvas의 계산 world 좌표가 일반 Scene과 달랐다. UI는 기존 ID 및 직렬화 diff를 확인하고 3D world pose를 별도로 비교하여 scene-verification-03.json에서 통과했다.

## 사람 확인 시나리오

1. 플레이 중 Core의 LevelCameraService에서 현재 측면/통로/쿼터 구도 여섯 값을 조절한다. 구간 재진입 없이 실제 화면에 반영되고 변경하지 않은 프레임에는 추적이 계속되어야 한다.
2. 옵션과 메모를 연 상태에서 구도 값을 조절한다. 화면은 새 구도를 표시하고 플레이어·차단 장치·카메라 전환 시간은 진행되지 않아야 한다.
3. 통로 전환 중 구도를 조절한다. 기존 플레이어 보정→차단 장치 이동이 한 번만 진행되고 완료 시 입력/이동축이 정상 복귀해야 한다.
4. 두 추격 스테이지에서 저장→무리 시작→퇴로 닫기, 실제 전면 Collider 포획과 포포 접촉 우선순위를 확인한다. 사망/재시도/Title 뒤 현재 Actor만 다시 연결되고 중복 추격·구독·외형이 남지 않아야 한다.
