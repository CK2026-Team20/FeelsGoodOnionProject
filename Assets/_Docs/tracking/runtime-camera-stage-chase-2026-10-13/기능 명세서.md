# 런타임 카메라 조정과 스테이지 추격 연결

## 목표와 근거

2026-10-13 직접 요청: 플레이 중 Inspector 구도 변경을 실제 카메라에 반영하고, Core에 배치된 ChaseSwarm을 해당 스테이지의 추격 시작 트리거가 연결하도록 변경한다. 카메라 리밸런싱과 기능별 배치를 직관적으로 만드는 것이 목적이다.

현행 원본은 V1.6이며 접촉 기반 추격·월드 +X 직선 이동·실제 몸체 포획은 기존 확정 직접 지시를 유지한다. 참고 소스는 LevelCameraService, StageTrigger와 그 Inspector, CoreComposition/CoreWorldBinding, ChaseRuntimeDriver/ChaseSwarmPresentation이다. 참고 자산은 03_InGameCore, Prototype/1_Stage, Stages/03_3_Stage와 기존 ChaseSwarm 프리팹이다.

## 책임과 변경 범위

- LevelCameraService는 측면·통로·쿼터 구도의 화면 위치, 허용 폭/높이, 감쇠, 거리, 고정 각도, 시야각의 원본을 소유한다. 연결된 카메라에는 변경된 값만 LateUpdate에서 적용한다. 잘못된 런타임 수치는 마지막 유효 구도를 보존하고 원인을 경고한다.
- 구도 변경은 새 구간 요청을 만들지 않는다. 전환 상태·입력 차단·플레이어/차단 장치 Tween·이동축을 재시작하지 않는다. 일시정지 중에도 구도 변경은 반영하되 전환 시간을 진행시키지 않는다.
- 추격 시작 StageTrigger는 같은 씬의 ChaseRuntimeDriver와 퇴로를 Inspector 참조로 연결한다. 고정 센서와 움직이는 무리는 별도 오브젝트다. 움직이는 무리 아래에 시작 센서나 퇴로를 넣지 않는다.
- CoreWorldBinding은 활성 스테이지 트리거에 연결된 무리만 중복 없이 초기화하고 Actor 제거 시 연결 당시의 참조만 해제한다. 추격이 없는 스테이지는 무리를 요구하지 않는다.
- ChaseRuntimeDriver의 이동·포획과 ChaseSwarmPresentation의 표현 책임은 유지한다. CoreComposition의 필수 추격 참조는 제거한다.

기존 씬의 시작 센서는 StageTrigger와 BoxCollider를 함께 유지한다. Unity 접촉 콜백과 기존 물리 배치를 보존하는 기존 구조의 예외이며, 움직이는 ChaseSwarm은 센서의 별도 자식 루트로 배치한다. 무리 루트에는 Driver/Presentation, 그 자식에는 Physics·외형·VFX·SFX가 있다. 이 작업은 새 프리팹 원본을 제작하지 않는다. 기존 Core의 전면 Box 크기 (0.8, 100, 4) 배치 override는 두 스테이지 인스턴스에서 유지한다.

## 제약

Play/Player 실행, HMS·아트·공용 프리팹 원본 수정, 기존 프리팹 삭제·재생성·Apply, Git 작업을 하지 않는다. 기존 staged 변경과 미저장 씬을 보호한다. 씬 연결은 비 Play Unity Editor에서 처리하고 수정할 씬이 이미 dirty이면 자동 저장하지 않는다. 기존 ChaseSwarm 프리팹 인스턴스를 이관/배치하며 원본 GUID와 물리·표현 구성은 보존한다.

## 완료 기준

1. 실제 Unity 컴파일에 오류가 없어야 한다.
2. 비 Play 검증에서 세 구도의 변경값이 Cinemachine Composer/Lens/Transform에 반영되고 변경 없는 반복 갱신과 잘못된 수치 입력이 기존 유효 구도를 훼손하지 않아야 한다.
3. Core에 필수 추격 참조와 무리 인스턴스가 없어야 한다. 기존 추격 트리거 두 곳은 같은 씬 무리와 퇴로에 연결되고 저장·재열기 후에도 유지되어야 한다.
4. 변경 씬의 Missing Script/직렬화 참조, 기존 프리팹 GUID·자식 물리 구성, 부분 실패·Actor 교체 시 연결 해제를 확인한다.
5. 코드 리뷰와 테스트 및 검증 항목에 수행 범위·증거·미실행을 기록한다. 실제 플레이 화면의 구도와 전환 체감·포획은 사용자 확인 항목으로 남긴다.
