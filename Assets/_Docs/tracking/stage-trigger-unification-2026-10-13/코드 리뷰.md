# 코드 리뷰

2026-10-14. 10월13일 사용자 검토에서 확정한 범위의 구현과 비 Play 검증을 완료했다. 아래는 이번 순변경의 검토이며 앞선 런타임 카메라·스테이지 추격 변경은 유지한다.

## 책임과 변경

StageTrigger가 체크포인트 Transform·기본 시점·구간 AudioClip을 작성한다. CheckpointMarker 소스와 meta, 네 Stage의 Marker/자식 등장 앵커와 비활성 전용 초기 카메라 오브젝트를 제거했다. StageService.InitialCheckpoint를 StageTrigger로 이관하고 현재 체크포인트 참조는 GameSessionRuntime 한곳에서 변경한다. StageService는 주입된 조회 함수로 같은 참조를 읽는다. GameSessionService는 기존 세 불변값의 저장·복원만 소유하며 별도 Stage/CP ID나 카메라 상태를 저장하지 않는다.

SessionActorHost는 CapsuleCollider.center를 TransformPoint로 변환해 월드 중심을 목적지에 맞춘다. 비활성 생성에서 attachedRigidbody가 비어 있는 실제 Editor 동작을 확인하고 같은 오브젝트의 Rigidbody를 직접 확인하도록 수정했다. Normal 형태 초기화 전후 같은 정렬을 적용한다. 접촉 저장은 트리거의 고정 위치이며 추격 직전만 실제 플레이어 Collider 중심을 저장한다. Actor 교체에서 같은 체크포인트 억제 상태를 유지하고 새 지점은 갱신한다.

GameFlowService의 옵션·엔딩·취소/실패 복구는 세션 종료 뒤 실제 로드된 Stage 전체→Core 순서로 언로드한다. SceneService는 등록 해제한 보존 Stage도 종료 목록에 포함하고 언로드 후 authoredRoots 캐시를 비운다. 재시도는 같은 씬을 유지한다. 언로드가 실패하면 Title 완료로 게시하지 않는다. 설치와 IntegrationEntrySettings를 모두 Prototype/1_Stage 하나로 줄였으며 Editor 진입과 빌드 생성 목록도 네 씬으로 확인했다. Stage2/3 파일 자체는 보존한다.

음악은 StageTrigger의 실제 Clip·게인·전환 시간을 AudioFlowBinding에 전달한다. AudioService가 다른 ID의 같은 Clip도 비교하며 동일 음원 요청에서 재생·게인·fade를 건드리지 않는다. 전환을 바꿀 때 현재 envelope를 사용하고 아직 재생 중인 같은 Clip 채널은 재사용한다. 취소한 fade의 오래된 callback은 revision으로 거절한다. 오프닝 종료 후 LoadingGame으로 돌아올 때 최초 StageTrigger 음악이 지워지던 경로를 함께 수정했다. 기존 추격·타이틀·연출 우선순위를 보존한다.

Side/Corridor/Quarter 모두 빈 기능 Root 아래 Sensor와 Alignment 형제 구조로 이관했다. 감지 컴포넌트와 Trigger Collider 동거는 기존 PhysX 콜백 계약을 보존하기 위한 계층 예외다. 차단 기능은 기존 실물 앵커와 두 DOMove를 유지한다. cameraBounds는 선택이며 미연결 시 Confiner3D와 최종 clamp를 사용하지 않는다. 한국어 Inspector 설명에 외부 배경 노출 방지 용도와 비워 둘 때의 동작을 명시했다. 실제 구간 밖의 시작 구도는 Source 없는 snap 요청으로 처리하고 일반 전환은 실제 구간 접촉을 요구한다.

## 근거와 한계

실제 제품 DLL의 비 Play 핵심 검사223개와 정지 Editor 씬 수명/캐시 검사9개를 통과했다. 네 Stage 및 Bootstrap/Title/Core 재읽기에서 Missing Script/깨진 참조0, 기존 월드 Transform423개와 CP 감지 볼륨 보존을 확인했다. Marker GUID `2254035091c0ec84fac5c87775bf15e8`의 씬·프리팹·설정 참조는0이다. 저장 이관 전후 검사2215개와 재읽기 검사12146개는 자산 구조 검사이며 자연 실행의 증거가 아니다.

HMS·공용·_Art·Packages·ProjectSettings에 새 작업 diff가 없고 기존 프리팹/meta70파일의 기준 해시를 유지했다. 기존 staged75항목의 상태 목록도 동일하다. 이번에 변경한 기존 meta는 삭제 승인된 CheckpointMarker.cs.meta 하나다. 기존 사용자 미커밋 작업을 보존했으며 Git 작성 작업을 하지 않았다.

기존에 변경 중이던 CookedKorean SDF.asset은 이번 기준 해시와도 차이가 있다. 에이전트가 수동 수정한 파일이 아니며 최종 순변경에서 별도로 확인할 항목이다. Unity 저장 씬의 빈 YAML 값 공백은 native 직렬화 결과로 보존한다. 소스·문서 diff check는 통과했고 전체 diff의 이 공백을 코드 오류 통과로 기록하지 않는다.

실제 SceneManager.UnloadSceneAsync, 자연 Collider 접촉·오프닝/옵션/엔딩의 화면과 음원, 전체 한 판과 빌드는 실행하지 않았다. 검증 중 확인된 별도 미저장 프로토타입 작업은 저장·폐기하지 않았다. 마지막 Editor 조회에서는 사용자가 선택한 Prototype/1_Stage 한 씬이 clean 상태이며 Play/컴파일은 꺼져 있었다. 초기 Bootstrap setup으로 강제로 되돌리지 않는다. [검증 및 사람 확인](테스트%20및%20검증%20항목.md)에 확인 항목을 기록했다.
