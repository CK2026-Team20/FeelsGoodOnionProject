# 기능 프리팹 정리와 플레이어 리소스 연결

## 목표와 최신 직접 지시

현재 `_Prefabs` 계층·컴포넌트를 검수하고 Bootstrapper·Title·Core의 기능 객체를 종류별 프리팹으로 정리한다. 실제 Core 플레이어는 사용자가 지정한 분리 클립과 `_Art/Characters/Animations`의 리그, 기존 VFX를 연결한다. 피격 시 머테리얼 색을 바꾸는 테스트 기능은 제거한다.

처음 요청에는 `1_Stage`의 프리팹화도 포함됐으나 후속 직접 지시로 취소됐다. 기존 씬은 폐기 예정이며, 향후 레벨 디자이너가 제공할 FBX/Blender 목업과 사용자가 만든 프리팹을 기반으로 새 스테이지를 구성한다. **이번에는 스테이지 조립·이관을 하지 않는다.** 앞서 수행한 이번 작업의 Stage 프리팹화만 작업 시작 사본으로 복구한다. 이전에 완료한 체크포인트·카메라·씬 수명 변경은 이 사본에 포함되어 있으며 유지한다.

`_Prefabs`에는 `Prototype`·`ProtoType` 폴더를 두지 않는다. 사용자의 기존 Characters·Platforms·Props·StageControl·UI 분류를 기준으로 기능 종류에 따라 정리한다. 카메라·앱 서비스·VFX는 Camera·Systems·Effects의 종류 분류를 사용한다. 사용자 프리팹을 활용할 수 있으면 반드시 중첩 프리팹 또는 소유 인스턴스 override로 재사용한다. 같은 종류의 객체는 사용자가 만든 실제 계층 구조를 따르고, 그 구조로 구성할 수 없는 기능은 독립된 단일 프리팹으로 구성하고 이유를 설명한다. 기존 원본 Apply·Unpack·GUID 변경은 하지 않는다.

## 제약과 책임

1. 보호 HMS·아트·원본 import·Packages·ProjectSettings는 수정하지 않는다. 기존 사용자 프리팹 28개와 분리 클립 원본은 바이트·GUID를 보존한다. 기존 dirty/staged 작업과 사용자 미저장 씬은 유지한다.
2. 이번에 만든 리소스 미반영 Stage 프리팹은 참조를 확인하고 삭제한다. 이전 테스트 씬이 참조하는 기존 블록아웃 프리팹은 `_Prefabs`의 제품 목록에서 제외하고 원래 소유 씬 자산 경로로 되돌려 직렬화 참조를 보존한다. 새 스테이지 제작의 기반으로 사용하지 않는다.
3. 기존 사용자 발판 전체를 임의로 재작성하지 않는다. 누락된 필수 참조와 물리 소유권 문제를 실제 컴포넌트·소스로 지적한다. 임의의 활성 모델 선택, 씬 배치, 새 메시 충돌체 제작은 하지 않는다.
4. PlayerRoot는 빈 루트와 실제 ActorBody의 기존 동거 물리 계약을 유지한다. PlayerFacade·입력 Reader/Controller·Rigidbody·Capsule의 실제 소유자는 ActorBody이며 각각 하나다. Visual에는 리그·Animator·렌더러, 독립 CameraAnchor와 VFX에는 각 표현 리소스를 배치한다. 사용자 PlayerCharacter의 정적 모델 계층은 실제 폼별 본 애니메이션 리그와 다르므로 통합 Actor의 기존 물리 계약을 유지하는 독립 프리팹으로 구성한다. 껍질은 사용자 Onion_Shell을 재사용한다.
5. PlayerVfxPresenter는 HMS가 확정한 자체 이동·점프·착지·폼·사망 상태를 읽어 자기 파티클에 표시한다. 입력·이동·게임 상태를 새로 소유하지 않고 자기 이벤트 구독만 등록·해제한다. PlayerPresentationReferences는 VisualRoot와 CameraAnchor 참조만 제공한다.
6. 클립은 `_Animations/Clips/Player`의 기존 10개를 직접 사용한다. Runtime 복제 폴더를 만들지 않는다. 전환 리그는 원본 클립의 실제 본 경로에 맞춰 연결하며 원본 클립·FBX를 고치지 않는다. 없는 상호작용 클립·전용 눈물 VFX를 임의 제작하여 연결 완료로 주장하지 않는다.
7. Play/Player·빌드와 Git stage/commit/push/PR은 이번 작업에서 실행하지 않는다. 검증과 보조 출력은 `output/Tech_SYM/prefab-authoring/2026-10-14/`에 보존한다.

## 완료 기준과 확인 경계

native 인벤토리·보호 기준점 → 종류별 자산 정리와 Stage 변경 복구 → 플레이어 실제 리소스 연결 → 소스·프리팹 독립 검토 → 비 Play 검증 순서로 수행한다. Unity 자산 쓰기는 하나의 연결된 Editor에서 순차 수행하고 병렬 검토는 읽기 전용으로 제한한다.

- Bootstrapper 5개·Title 1개·Core 6개 기능 루트가 `_Prefabs` 프리팹에 연결되어 있다. Stage는 작업 시작 사본과 같은 파일·GUID이며 재조립하지 않는다.
- `_Prefabs`의 Prototype/ProtoType 폴더가 0개이고 삭제 자산의 incoming 참조가 0개다. 남기는 GUID·씬 위치·기존 서비스 참조가 유지된다.
- Core의 Host는 Main/PlayerRoot를 참조한다. 원본 분리 클립과 폼별 Animator, 사용자 Onion_Shell 및 기존 이동·점프·등장 VFX가 실제 인스턴스에 연결된다. 피격 색상 설정·구독·변경 코드는 없다.
- 실제 Unity 컴파일 결과, missing script/깨진 참조, 입력·물리 단일 소유, native Animator/파티클 평가, 구독 해제, 원본 파일 보존을 기록한다.
- 코드 리뷰.md와 테스트 및 검증 항목.md에 최종 변경·기존 사용자 프리팹 수정 권고·사람의 실제 플레이 확인을 분리해 기록한다. 이 검증은 물리 접촉·전체 게임·최종 연출 품질 검증이 아니다.
