# 종류별 프리팹과 플레이어 비 Play 검증

## 실행 조건과 최종 판정

2026-10-14 실제 연결된 Unity6000.6.0f1 Editor에서 비 Play 평가를 실행했다. Unity CLI status/pipeline 확인 뒤 실제 native 조회로 연결을 확인했으며 자산 쓰기는 하나의 Editor에서 순차 수행했다. Play/Player·빌드·실제 조작·물리 gameplay는 실행하지 않았다. 검증은 최종 직접 지시인 Stage 조립 취소, Prototype 폴더 제거, 사용자 프리팹·계층 우선 재사용과 원본 클립 사용을 기준으로 한다.

소스 컴파일·직렬화 보존·native Animator/파티클 평가와 수명 검사는 통과했다. 최초 검수에서 보고한 미연결 참조5개는 사용자 후속 설명에 따라 의도된 제작 설정으로 정정하고 결함에서 제외한다. Enemy VFX 연결2개는 별도 수정 권고다. 메모 2D/3D 경계는 후속 직접 지시로 수정했으며 아래 추가 검증에 기록한다. 이 상태를 새 레벨의 실제 작동 완료로 선언하지 않는다.

## 후속 메모 콜라이더 비 Play 검증

실제 Unity Editor에서 수정·저장 후 Memo 프리팹을 다시 읽었다. 증거는 `output/Tech_SYM/prefab-authoring/2026-10-14/memo-collider/`의 inspection.json, replacement.json, verification.json, changed-files.json과 변경 전 사본이다.

- BoxCollider2D0개, 3D BoxCollider1개, enabled=true, isTrigger=false. 같은 Collider 자식에서 부모 InteractionPromptAnchor를 찾는다.
- Collider 로컬 중심·크기가 실제 bg_memo 메시 범위와1e-6 이내로 일치한다. 메시72개 정점 중 콜라이더 범위 밖 정점0개다.
- missing script0, 실제 깨진 참조0. 의도적으로 비워 둔 memoUI와 기존 MemoModel 참조를 보존했다.
- 기존 프리팹·씬·상호작용 소스·Packages·ProjectSettings 및 실제 bg_memo FBX/meta590파일의 전후 비교에서 Memo.prefab 한 파일만 변경됐다. 프리팹 meta·GUID와 다른 직렬화 블록은 동일하다.
- 사용자의 열린01_Stage_Prototype 씬은 계속 dirty=false이며 active 씬도 같다. Play/Player·실제 F 입력·물리 시뮬레이션·빌드·Git 변경은 실행하지 않았다.

검증 보조 스크립트의 첫 평가에서 구식 objectReferenceInstanceIDValue API가 거부됐다. 제품 파일 변경 없이 EntityId API로 보조 스크립트를 수정한 뒤 재평가가 성공했다.

## 자동 변경·보존 기록

TMP native import/preview 과정의 `CookedKorean SDF.asset` 변화와 BootstrapCamera의 UniversalAdditionalCameraData 자동 추가를 보존했다. 최종 비교는 BootstrapCamera의 정확한 컴포넌트1개 추가만 허용하고 나머지 기존 컴포넌트·필드·참조를 비교했다. 변경을 지우거나 보호 폰트/import·ProjectSettings를 수동으로 수정하지 않았다. 작업 시작 전 dirty/staged 변경은 이 작업의 신규 변경으로 주장하지 않는다.

저장소 전체 whitespace 검사에서 Bootstrapper·Core의 native 저장 파일, 정확히 복구한1_Stage와 이번 작업 전부터 변경되어 있던 역사 Stage1/2/3의 빈 Unity YAML 필드가 보고됐다. 작업 소스·문서 검사와 구별해 기록했으며, 원본 복구·보존 기준을 깨는 수기 씬 YAML 정리는 하지 않았다. 전체 `git diff --check` 통과를 선언하지 않는다.

삭제 자산은 output의 별도 사본으로 복구 가능하며 원본 사용자 프리팹은 삭제하지 않았다. Unity는 최근 삭제한 GUID를 기본 AssetPathToGUID 조회에서 캐시하므로 최종 존재 확인은 `OnlyExistingAssets`, LoadAsset 결과와 실제 파일 존재로 확인했다. 최초 삭제 후 캐시 기반 판정 오류를 수정했으며 삭제를 반복 실행하지 않았다.

## 사람의 실제 플레이 확인과 향후 목업

- 새 목업 수령 뒤 기존 사용자 프리팹과 실제 계층으로 Stage를 조립한다. 현재 폐기 예정1_Stage를 수정해서 인계하지 않는다.
- 선택형 발판의 실제 몸체·지지면·서비스 참조를 연결한 뒤 이동/부유/주기/피해/압력판 연동을 실제 접촉으로 확인한다. 면별 Rigidbody가 있는 서랍은 몸체와 각 면의 이동·접촉을 확인한다.
- Dish 등 원형 메시+Box 지지면 조합은 사이드뷰 구간에만 배치한다. 쿼터뷰 오븐·서랍은 눈에 보이는 메시와 실제 밟는 면·차단 면이 일치하는지 확인한다.
- 메모의3D 검색·F 표시·열기·닫기와 UI 연결, Enemy 자식 VFX의 스턴 시작/종료를 확인한다.
- 실제 이동 지속·점프/착지·피해/사망·양쪽 폼 전환·껍질 생성/회수·정지/재등장 중의 애니메이션과 파티클 연출을 확인한다. 상호작용 클립·눈물 전용 VFX가 추가되면 해당 자산 연결을 별도 검증한다.

실제 Play/Player·빌드·전체 게임 QA·FunQA는 미실행이며 이 문서에서 통과로 기록하지 않는다. 이번 Git stage/commit/push/PR 작업은 없다.
