# 종류별 기능 프리팹과 플레이어 연결 검토

## 최종 변경과 사용 기준

최신 직접 지시에 따라 `1_Stage`의 조립·이관은 취소했다. 씬 파일은 이번 작업 시작 사본으로 정확히 복구했으며 기존 체크포인트·카메라 변경을 보존했다. 이번에 생성한 Stage 프리팹 31개와 참조 없는 이전 ShellRoot 1개를 삭제했다. 기존 테스트 씬들이 참조하는 블록아웃 11개는 원래 `_Scenes/Tech_SYM`의 자산 경로로 돌려놨다. 원본 GUID·내용·meta는 같으며 이 테스트 자산은 향후 목업 제작의 기반이 아니다.

Bootstrapper·Title·Core의 기능 루트 12개는 종류별 `_Prefabs`에 연결했다. 배경 자산 15개는 사용자의 Props 분류 아래 `Props/Background`에 정리했다. 사용자 원본 28개는 수정하지 않았고 Prototype/ProtoType 폴더는 0개다. 현재 `_Prefabs` 프리팹은 총65개다. 서비스·카메라·UI·월드는 독립 씬 루트를 유지하며, 다른 루트로 향하는 연결은 소유 씬의 instance override로 보존했다.

새 기능 구성에서는 기존 사용자 프리팹을 먼저 확인하고 활용 가능한 것은 반드시 중첩 프리팹으로 재사용한다. 같은 종류는 실제 사용자 계층을 따른다. 해당 구조에 맞지 않는 기능은 독립 단일 프리팹으로 만든다. 사람의 원본에 Apply하거나 모델만 복사한 별도 객체를 사용자 프리팹 재사용으로 간주하지 않는다. 실제 레벨 구성·활성 모델 선택·배치·시점 구간 지정은 향후 FBX/Blender 목업에 맞춰 수행한다.

## 기존 사용자 프리팹에서 연결·검토할 항목

아래는 작업 시작부터 존재한 원본의 검수 결과다. 필수 null, 선택·씬 연결 대기와 실제 깨진 참조를 구별한다. 원본 전체를 임의 재작성하지 않았다.

| 대상 | 실제 확인한 상태·영향 | 수정·조립 기준 |
|---|---|---|
| `Platforms/Movable/LinearPlatforms`, `FloatingPlatforms` | `KinematicPlatformMotion.physicsBody=null`. Linear의 Dish·밀폐용기·도마 후보는 모두 비활성이다. | 사용할 몸체 하나를 활성화하고 그 Rigidbody를 이동 몸체에 연결한다. 같은 몸체의 비 Trigger BoxCollider·PlatformContacts와 고정 종점 계약을 지킨다. 모든 후보를 동시에 활성화하지 않는다. |
| `Platforms/Interactable/ButtonPlatforms/LinkedPlatforms` | 연결 발판의 `physicsBody=null`. 버튼 자체 이동 몸체 참조는 연결되어 있다. | 연동 발판에서 선택한 실제 몸체의 Rigidbody를 연결한다. 버튼의 직렬화 Rigidbody는 dynamic/gravity 상태지만 이동 담당 Awake가 kinematic으로 설정하므로 실제 작동 불능으로 단정하지 않는다. 작성 시 물리 설정을 실행 계약에 맞추는 것이 좋다. |
| `Platforms/Damageable/DamageablePlatforms` | `DamageFloorPlatform.physicalContacts=null`. 피해 판정이 소비하는 접촉 owner가 없다. | 선택한 실제 피해 접촉면의 PlatformContacts를 연결한다. 끓는 내부 피해와 지지 면의 범위는 목록·실제 모델을 기준으로 조립한다. |
| `Platforms/Periodic/PeriodicPlatforms` | `supportCollider=null`. 고정 발판이면 `motion=null`은 허용된다. | 사용할 실제 지지 BoxCollider를 연결한다. 이동 없는 주기 발판에 불필요한 motion을 추가하지 않는다. |
| `Characters/Enemy/Enemys`의 Stationary·Patrol | `EnemyStunVisual.stunEffect`가 Project의 `_Art/VFX/Prefabs/VFX_Stun.prefab` 원본을 참조한다. 실제 `Body/VFX_Stun` 자식도 따로 있다. | 실제 자식 인스턴스를 연결한다. 이 컴포넌트는 SetActive만 호출하고 Instantiate하지 않는다. 두 실제 머테리얼의 RealToon `_MainTex`는 native HasProperty=true로 확인했다. |
| `Props/Memo/Memo` | 후속 직접 지시로 같은 Collider 자식의 BoxCollider2D를 비 Trigger 3D BoxCollider로 교체했다. 실제 bg_memo 메시의72개 정점 범위에 중심·크기를 맞췄다. `MemoObject.memoUI=null`은 의도된 씬 서비스 연결 대기다. | 현재 PlayerInteractionService의 3D 후보 검색과 타입·부모 InteractionPromptAnchor가 맞는다. 다른 구성과 미연결 참조는 보존했다. 실제 F 입력은 사람 확인 대상이다. |
| `Platforms/Interactable/StairsPlatforms` | 3개 서랍과 2개 그릴의 움직이는 Visual은 모두 해당 `physicsBody` 하위다. 고정 Start/End와 움직이는 Prompt/HandlePivot 앵커도 소스 계층 계약에 맞는다. 서랍의 앞·뒤·좌·우 면에는 별도 Rigidbody가 있다. | Visual 재이관은 필요 없다. 여러 Collider 자체를 오류로 간주하지 않는다. 면별 Rigidbody는 한 몸체의 compound Collider와 다르므로 실제 이동·attachedRigidbody·접촉을 확인한다. 단일 몸체가 의도라면 이동 Rigidbody 하나와 그 하위 Collider로 조립한다. |
| `Platforms/Shatterd/ShatterdPlatforms` | 실제 Kukudasu Visual·support·contacts가 연결되어 있다. Animator는 null이다. | 현재 소스는 애니메이션 없이 경고 뒤 숨김을 허용하므로 필수 누락으로 분류하지 않는다. 다른 모델을 선택하면 Visual/support/contacts를 같은 선택 대상으로 함께 연결한다. |
| `StageControl/Trigger/StageTriggerPoint` | stage 참조가 null인 공통 트리거 원본이다. | 향후 새 씬 인스턴스에서 실제 StageService를 연결한다. 원본 null을 missing GUID로 보고하지 않는다. |

사용자 후속 설명에 따라 플랫폼의 미연결 참조5개는 사용할 오브젝트를 선택·활성화할 때 연결하는 의도된 제작 설정이며 결함에서 제외한다. Enemy VFX의 Project 자산 연결2개는 별도 기능 문제로 남긴다. 메모의 2D/3D 경계는 메모 콜라이더만 변경하라는 후속 직접 지시로 수정했다. 서랍의 면별 Rigidbody는 실제 이동·접촉 검증 대상으로 유지한다.

## 후속 메모 콜라이더 변경 검토

이번 자산 수정 허가는 `Assets/_Prefabs/Props/Memo/Memo.prefab`의 콜라이더 한 개로 한정한다. 기존 사용자 프리팹28개의 보존 판정은 최초 정리 작업 당시 기록이며 이번 Memo 변경은 최신 직접 허가의 예외다. Unity PrefabUtility로 같은 Collider 자식의 컴포넌트만 교체했으며 메시의 정점을 Collider 로컬 좌표로 변환해 중심·크기를 계산했다. 중심은(-0.000320584, 0.025025934, 0.017826786), 크기는(0.486053348, 0.53789115, 0.06245271)이다. 프리팹 GUID·계층·기존 컴포넌트 참조·메모 UI의 의도된 빈 연결·아트 원본은 유지했다. 다른 적·서랍·씬은 수정하지 않았다.

## 시점별 물리 작성 의도

[사용자 오브젝트 목록](https://docs.google.com/spreadsheets/d/1rJwrOxkhifYShvTMHu4gTrhm-iMp20FnX71GU75DTak/edit?gid=0#gid=0)과 직접 답변을 함께 적용한다. Dish 같은 원형 메시+사각 지지 Collider 이동 발판은 **사이드뷰 전용**이다. 현재 Dish의 Rigidbody·BoxCollider·PlatformContacts는 같은 루트에 있고 Visual은 그 하위다. Box의 윗면은 메시의 원형 윤곽을 자동으로 따라가지 않는다.

PlatformContacts는 같은 객체의 BoxCollider와 실제 collision normal을, KinematicPlatformMotion은 연결된 한 Rigidbody를 사용한다. 이 소스가 메시 윤곽이나 카메라 시점을 자동 판별하지 않는다. 따라서 Dish를 쿼터뷰에서 범용 사용 가능한 발판으로 확대하지 않는다. 쿼터뷰 오븐·서랍은 사용자의 모델·몸체·면 Collider 구조와 실제 접촉면을 기준으로 조립한다. 시트에서 제작완료로 표시된 것과 물리 접촉이 검증된 것은 구별한다.

## 플레이어의 최종 책임과 리소스

Core의 `Systems/Session/SessionActorHost`는 `Characters/Players/Main/PlayerRoot`를 생성한다. PlayerRoot는 비활성 빈 루트, ActorBody는 입력 Reader/Controller·Facade·폼·운동·실제 Rigidbody/Capsule을 소유한다. 사용자의 기존 PlayerCharacter는 정적 모델이며 현재 폼별 본 애니메이션 리그와 구조가 달라서 그 입력·물리 구조를 복제하지 않고 기존 통합 Actor 계약을 유지했다. 원본 PlayerCharacter는 보존했다. 껍질은 사용자의 `Characters/Players/Shell/Onion_Shell`을 직접 재사용한다.

Normal과 Small의 실제 리그는 각각 `_Art/Characters/Animations/Size/ch_onion_Size_Small_to_Big_Peel.fbx`, `ch_onion_Size_Big_to_Small.fbx`다. 해당 전환 클립의 서로 다른 본 경로를 각 리그에 맞췄다. 모델·머테리얼·FBX·클립 import는 수정하지 않았다. Visual에는 Collider/Rigidbody가 없고 폼별 Animator가 같은 소유 controller template과 PlayerAnimations 설정을 사용한다.

PlayerAnimations는 기존 `_Animations/Clips/Player`의10개 분리 클립을 직접 참조한다. Walk/Run은 실제 PC_Runnig를 공유한다. 소유 controller의11개 상태는 HMS PlayerAnimatorOutput이 이 클립들로 override한다. Runtime 복제 클립 폴더는 제거했다. Idle/Run 등의 반복은 기존 HMS 재생 정책을 사용하며 원본의 loopTime을 수정하지 않았다. Idle/Crying에 남은 Foot IK export control 두 경로는 렌더러가 사용하는 본이 아니며 렌더 본 바인딩과 실제 Animator 평가를 별도로 확인했다.

PlayerVfxPresenter는 기존 이동·점프·등장 VFX의 자식 인스턴스만 제어한다. 살아 있고 접지한 자체 이동에 거리 먼지를, HMS 점프·착지에 burst를, 생성·Normal 복귀에 등장 효과를 표시한다. 현재 Capsule의 발점을 따라가며 죽음·비활성화 때 자기 파티클과 구독을 해제한다. 독립 검토가 지적한 최소 속도0 조건은 `speed > 0`을 추가하여 발판 운반만으로 먼지를 내지 않도록 수정하고 native 검증했다.

피격 색 변경은 삭제했다. 기존 PlayerDamagePresentation을 GUID 그대로 PlayerPresentationReferences로 이름 변경하고 VisualRoot/CameraAnchor 참조만 남겼다. targets/duration/damageColor, Damaged 구독과 MPB 변경 코드는 없다. PlayerBridgeService는 새 타입으로 참조 검증한다. 실제 Damage 호출 뒤 기존 색·다른 MPB 값이 유지되는 것을 비 Play fixture에서 확인했다. 피해 애니메이션·게임 피해 판정은 이 색 기능과 별개로 유지한다.

전용 상호작용 클립과 눈물 발사 전용 VFX는 지정 자산에서 확인되지 않았다. 해당 슬롯을 임의 클립이나 환경 효과로 채우지 않았다. Crying 클립은 눈물 동작에 연결되어 있다. 최종 연출 품질·전체 폼 전환·실제 접촉은 사람의 플레이 확인 대상이다.

## 검토와 변경 한계

독립 읽기 전용 리소스·VFX 코드 검토와 사용자 원본 구조 검토를 수행했다. 현재 연결을 막는 코드 문제는 발견되지 않았으며 최소 속도0 조건은 수정했다. Stage 매핑 조사는 취소된 씬에 적용하지 않고 향후 목업 검수 자료로만 보존했다.

native 실행 결과와 보존 판정은 [테스트 및 검증 항목](테스트%20및%20검증%20항목.md)에 기록한다. Editor의 TMP 동적 폰트 변경과 BootstrapCamera의 URP UniversalAdditionalCameraData 자동 추가는 별도로 기록하고 보존했다. 보호 원본을 수동으로 수정하거나 Git 작업을 수행하지 않았다.
