# Tech_SYM 구현 영역

기존 FeelsGoodOnion.TechSYM 기능과 Cooked 통합 구조가 공존한다. 클래스가 비슷하다는 이유로 통일하지 않는다. 시스템 기능 목표는 V1.8이 이전 사용자 명세보다 우선하며 기존 구현은 현재 사실을 확인하는 자료다.

수정은 승인된 Tech_SYM 경로로 제한한다. Tech_HMS·art_*·QA_*·_Art 참조는 원본 읽기·공개 API/이벤트 소비·자기 소유 오브젝트의 컴포넌트 추가/설정/연결과 배치 override 저장을 포함한다. 타인 원본 코드·자산·.meta·import 설정의 직접 수정과 원본 Apply·이동·삭제·GUID 변경은 별도 파일 허가 없이는 금지한다. 공용 Interfaces나 ProjectSettings를 함께 고치는 권한은 없다. 파일별 허용의 대상·기간을 하위 작업에도 전달한다. 실행하지 않은 검증은 통과로 기록하지 않으며 읽기·검증과 자산 재생성 메뉴를 구분한다.

Architecture는 앱·세션·스테이지 수명을 분리한다. 구성 지점이 구체 의존성을 조립하고 View는 주입된 ViewModel에 바인딩한다. 원본 플레이어 상태는 HMS PlayerModel이 소유하고 SYM은 공개 API와 스냅샷을 소비한다.

자동 프리팹/배경/씬 생성·Repair 도구12개는 제거했다. 새 리소스와 프리팹 제작·삭제·Apply는 사람이 담당한다. 실제 씬 진입·필수 연결 검증·명시적 빌드는 유지한다.

코드 변경은 입력 단일 처리, 상태·수명 소유권, 예외·취소, 재바인딩·폐기 후 콜백, 기존 자산 연결을 확인한다. 단순 문서 수정으로 코드·씬·패키지를 정리하지 않는다.

모든 Inspector 직렬화 필드는 Assets/_Docs/standards.md의 Inspector 설명을 따른다. HMS와 겹치는 책임은 같은 문서의 HMS·SYM 조립과 소스 정리에 따라 실제 대체 가능성을 확인하고 소유 배치의 참조를 이관한 뒤 정리한다.

테스트 범주는 사용자 요구에 대응하는 결합된 기능으로 정한다. 하위 지역 지침의 경계 항목은 해당 기능의 중요한 케이스·기존 회귀 근거로 묶고 각 컴포넌트마다 별도 케이스를 의무 생성하지 않는다. 자동 기능 검증·실제 빌드 검증·FunQA의 역할과 케이스 선정은 Assets/_Docs/standards.md의 기능 테스트와 QA 인계를 따른다. 2026-10-06 승인된 더미·중복·테스트 전용 소스는 참조 확인 후 제거하되 케이스와 실행 증거는 보존한다. 미검증을 통과로 바꾸지 않는다.

현행 지침: Inspector 위치/대상은 실물 참조, 수치는 목적·단위가 명확한 값이다. 씬 월드 객체를 관리자 자식에 묶지 않는다. 에이전트 Play 금지는 철회됐으며 공식 Unity 도구로 승인된 검증을 실행한다. 기존 프리팹 삭제/재생성/Apply·자동 Builder 실행은 해당 작업의 명시 허용 범위를 따른다. 이전 실행 관찰 수는 당시 증거이고 이번 통과가 아니다.
