# 추격

최신 적용 기준은 `Assets/_Docs/planning-index.md`와 ready의 `확정안 적용 명세.md`다. 추격 시작 새 캡처 없음·Memo 자기 WorldPause 계약을 유지한다. 최종4소스 승인과 actual chase8/POPO priority2·cancel2·completed4,9진입/Stop은 자동 범위로 확인됐고 PositionPrepare fixture와 전체 수동 동선은 구분한다. Windows 최종 수락/수동 QA/FunQA는 같은 ready 테스트 문서로 추적한다.

## 책임과 경계

추격은 경로 투영·진행 거리·포획 상태와 벌레 표현을 소유한다. Stage는 전체 플레이어 Collider의 시작선 통과, 후퇴문, Poppo와 최종 대화 연결을 소유한다. 사망·재시도는 Session의 단일 경로를 사용한다.

## 유지할 계약

한 시도는 한 번 시작한다. 현재 활성 Stage에 연결된 플레이어의 새로운 전신 시작선 통과를 확인하고 추격 시작이 수락된 뒤 문을 한 번 닫는다. 시작/끝 CP 실제 접촉만 Position/Fragments 두 값을 캡처한다. 중간 해금·추격 시작·동일CP라는 이유로 새 캡처를 만들지 않으며 사망은 마지막 실제 CP의 두 값을 사용한다. 적·기믹·HP·폼·카메라·시간·ID를 저장하지 않는다.

무리는 처음에 플레이어의 경로상 위치보다 8m 뒤에서 시작하며 4m/s로 전진한다. 높이를 제외한 경로상 간격이 0.8m 이하이면 무적을 무시하는 강제 사망을 한 번 요청한다. 기존 FrontContact의 접촉 판정은 이관 후 제거한다. 경과 시간을 버리지 않고 경로 끝으로 제한한다.

옵션은 월드/표시와 추격을 모두 정지한다. 메모는 자기 WorldPause로 월드를 정지하며 대화/로그 자체는 월드를 정지하지 않는다. 중첩 해제는 각자 토큰만 해제하므로 열린 메모/옵션의 추격 정지를 대화가 풀지 않는다. 포획 사망은 실제 사망 표현 완료 후 재시도한다. 재시도에는 새 추격 모델을 만들고 시작선의 새로운 전신 통과를 요구한다. 이미 시작선 안쪽에 복원됐다는 이유로 자동 재시작하지 않는다. Poppo에 도달하면 추격을 멈추고 최종 대화 완료 후 Ending으로 이동한다. 이전 구출/탈출 퍼즐 상태는 제거한다.

## 검증

경로 없음·비유한 좌표·전체 Collider 통과 경계·시작 거절과 문 상태·초기 간격·포획 0.8m 경계·큰 deltaTime·옵션·Actor 소실·포획 후 사망 완료·재시도 재통과·Poppo/최종 대화 취소를 사용자 기능으로 검증한다. 실제 실행 전 통과로 기록하지 않는다.
