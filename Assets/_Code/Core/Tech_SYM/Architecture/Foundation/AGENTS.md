# 앱 수명과 전환

## 책임과 경계

부팅 경로, 앱 서비스 범위, 씬 로딩, 이벤트 전달과 단일 전환 조정을 소유한다. 플레이어 모델·대화 진행·Stage 기믹은 소유하지 않는다.

## 유지할 계약

GameFlowService는 전환 시작 시 busy 상태를 동기 게시한다. Core를 활성 씬으로 만든 다음 세션 객체를 생성한다. 재시도는 같은 Core/Stage를 유지한다. 타이틀 복귀는 세션 종료→실제 로드된 Stage 전체→Core 언로드 뒤 Title을 표시한다. 취소·부분 초기화의 복구도 같은 종료 경로를 사용하며 언로드 실패를 완료로 처리하지 않는다. SceneService는 종료 후 Root 캐시를 지워 다음 새 게임의 인스턴스를 다시 읽는다.

세션 연출 참조를 앱 수명으로 캐시하지 않는다. 실패 복구까지 실패하면 입력·월드 차단을 유지한다. ServiceLocator를 View의 업무 서비스 검색 경로로 확장하지 않는다.

Editor 진입은 실제 편집 활성 씬의 정확한 경로로 결정한다. Bootstrap/Title/Core/01_Stage_Prototype 네 경로만 Bootstrap을 경유하고 다른 경로는 기존 직접 진입 정책을 따른다. 설치·Entry·빌드의 Stage 목록은 01_Stage_Prototype 하나다. 보존 Stage2/3와 구 Stage1은 종료 정리에만 허용하고 실행 등록에서 제외한다. 원래 값과 자신이 설정한 값을 구분해 Stop·취소·재로드 시 외부 변경을 덮지 않는다. 지정 통합 경로의 설치 불일치는 진입 실패이며 보호 원본의 직접 수정·Apply는 별도 허가가 필요하다.

Stop 중 Play 요청 플래그만 false가 되어도 실제 runtime/Editor Play가 남아 있을 수 있다. 씬 setup 비교와 aborted-entry 정리는 실제 Play·import·컴파일이 모두 끝난 안정 update에서 실행한다. 이를 이유로 외부 startScene 변경을 덮거나 route를 재사용하지 않는다.

## 검증

중복 요청 거절, Editor 경로 매핑, 부분 초기화 실패, 취소·복구 실패 및 Dispose 후 콜백 부재를 확인한다.

현행 지침: Inspector 위치/대상은 실물 참조, 수치는 목적·단위가 명확한 값이다. 씬 월드 객체를 관리자 자식에 묶지 않는다. 에이전트 Play 금지는 철회됐으며 공식 Unity 도구로 승인된 검증을 실행한다. 기존 프리팹 삭제/재생성/Apply·자동 Builder 실행은 해당 작업의 명시 허용 범위를 따른다. 이전 실행 관찰 수는 당시 증거이고 이번 통과가 아니다.
